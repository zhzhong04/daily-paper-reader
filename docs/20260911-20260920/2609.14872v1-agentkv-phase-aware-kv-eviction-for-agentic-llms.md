## 摘要
智能体式服务消耗的 token 数量可比聊天机器人工作负载高出若干数量级，对 KV 缓存容量与解码时带宽均造成压力。大多数 KV 驱逐方法以从最近 token 中抽取的代表性查询来为缓存键打分，其假设是未来注意力与近期注意力相似。我们表明，智能体式生成违背了这一假设：未来查询是 think、act、tool 及其他阶段的混合，主角度分析显示这些成分占据可测度上不同的查询子空间，因此基于近期性的代表会系统性地低估即将到来的阶段所需的键。我们提出 AGENTKV，它为每个阶段维护一个小型查询缓冲区，并以其并集为缓存键打分。我们进一步将 AGENTKV 实现于持久化多轮服务路径中，该路径跨轮次携带压缩后的 KV 状态，并在线压缩保留的 KV 页。在两种模型、六个任务领域以及各三种 KV 预算下，AGENTKV 相比 R-KV 平均提升任务得分 5.5 分，相比 Tri-attention 提升 5.3 分。相对于上游的全 KV SGLang，AGENTKV 将输出 token 吞吐量最高提升至 1.80 倍。代码：https://github.com/LiuTaowen-Tony/agentkv。

## Abstract
Agentic serving can consume orders of magnitude more tokens than chatbot workloads, stressing both KV-cache capacity and decode-time bandwidth. Most KV-eviction methods score cached keys against representative queries drawn from the most recent tokens, assuming future attention resembles recent attention. We show that agentic generation violates this assumption: future queries form a mixture over think, act, tool, and others phases, and principal-angle analysis shows these components occupy measurably different query subspaces, so recency representatives systematically undervalue keys that upcoming phases will need. We propose AGENTKV, which maintains a small query buffer per phase and scores cached keys against their union. We further implement AGENTKV in a persistent multi-turn serving path that carries compressed KV state across turns and compacts retained KV pages online. Across two models, six task domains, and three KV budgets each, AGENTKV improves task score by 5.5 points on average over R-KV and 5.3 over Tri-attention. Relative to upstream full-KV SGLang, AGENTKV improves output-token throughput by up to 1.80x. Code: https://github.com/LiuTaowen-Tony/agentkv.

# AgentKV：面向智能体式 LLM 的阶段感知 KV 驱逐 —— 论文深度总结

## 1. 核心问题与整体含义

- **研究动机**：智能体式（agentic）服务消耗的 token 数量可比传统单轮聊天机器人负载高出若干数量级（论文引用数据称可达 1000×），使序列长度剧增，KV 缓存容量与解码时内存带宽成为服务吞吐与延迟的主要瓶颈。
- **背景问题**：主流 KV 驱逐/压缩方法（H2O、StreamingLLM、SnapKV、R-KV 等）本质上都是"查询中心"的——它们用**最近 token 中抽取的代表性查询**来估计未来注意力，隐含假设"未来注意力与近期注意力相似"，即查询分布是平稳的。
- **关键洞察（论文核心论点）**：智能体轨迹在 **think（推理）/ act（动作生成）/ tool（工具返回）/ others（系统提示、用户问题等）** 四个语义阶段间循环切换，未来查询分布是**阶段混合分布**而非单一平稳分布。主角度分析证明不同阶段占据可测度上不同的查询子空间，因此基于近期性的代表会**系统性地低估**即将到来的非近期阶段（尤其是 tool、others）所需的 key。
- **整体含义**：该工作把 KV 驱逐从"近期注意力外推"重新定位为"阶段混合查询分布的覆盖问题"，并将算法与持久化多轮服务路径结合，兼顾任务质量与吞吐。

## 2. 方法论

### 2.1 核心思想
- 将 KV 驱逐形式化为按未来查询期望注意力对 key 排序：`A_i = E_{q∼p̂(q)}[softmax(q^T K / √d)_i]`。
- 近期代表实例化了 `p̂(q) = p_recent(q)`；AgentKV 则用**四个阶段各自的查询缓冲区之并集** `Q(e) = Q_think ∪ Q_act ∪ Q_tool ∪ Q_others` 来近似未来查询分布，`|Q(e)| ≤ q`，与近期基线保持相同代表预算。

### 2.2 关键技术细节
- **阶段定义**：阶段是语义 token 类别（而非轮次索引），基于 tokenizer 可见的 chat-template 标记做确定性解析。
- **在线阶段解析器（Algorithm 1）**：维护滚动前缀以识别被拆分到多个解码 token 的标记，如 `<|im_start|>system/user → others`、`<think> → think`、`<tool_call> → act`、`<tool_response> → tool`；无需模型侧分类器或新增特殊 token。
- **查询缓冲**：每个阶段一个固定大小的 FIFO 环，容量 `⌈q/4⌉`，默认 `q=32`，每阶段 8。
- **打分与保留**：所有候选 key 在同一池中统一打分 `A_i^(e) = (1/|Q(e)|) Σ_{q∈Q(e)} softmax(q^T K(e)/√d_h)_i`，保留 top-B；**不按阶段对 key 分区或设配额**，仅让代表查询覆盖各阶段分布。
- **阶段内采样规则**：对比 Staged-last、Multi-scale、Weighted-cov、Diverse-q 等策略后，采用 **staged-last**（每阶段最近若干位置）。
- **服务路径实现（Algorithm 3）**：保留 KV 条目经 fused gather–write 核聚合到紧凑目标槽位，页表在拷贝完成后重定向，旧槽位立即归还分配器；物理长度与单调递增的逻辑长度分离以保持 RoPE 偏移与后续前缀扩展；兼容 chunked prefill、CUDA graph capture 与常规 decode 路径。

### 2.3 诊断工具
- **主角度分析**：对每个阶段 span 做 thin SVD 取前 k=5 个右奇异向量构成正交基，计算基重叠矩阵的奇异值 `cos θ_i = σ_i(V_s,k^T V_t,k)`，得到主角度；跨阶段角度显著大于同阶段不同步骤的角度。
- **效用覆盖（Utility Coverage）**：离线 oracle 指标 `UC_φ = Σ_{i∈R_φ} U_i / Σ_{i∈K_φ} U_i`，其中 `U_i = Σ_{j>i_comp} a_{j,i}`，用于衡量各阶段未来注意力质量的保留比例（仅作诊断，不作在线信号）。

## 6. 主要结论与发现

- **质量**：AgentKV 相比 R-KV 平均提升 **5.5 分**，相比 Tri-attention 平均提升 **5.3 分**；在 `multi_turn` 上增益最大且最一致（非近期指令与工具观察需跨多次阶段切换保持相关）。
- **吞吐**：相对上游全 KV SGLang，输出 token 吞吐最高提升 **1.80×**（H100 NVL Qwen3-32B 32k/1k）；RTX A6000 Qwen3-8B 32k/1k 提升 1.76×。
- **匹配消融**：仅将近期代表替换为阶段感知代表（其余完全一致），12 个设置平均提升 **4.2 分**，直接证明增益来自代表选择本身。
- **阶段互补性**：移除任一阶段缓冲区都使准确率下降（Drop others 最严重，40.0→35.5），说明四阶段提供互补覆盖。
- **鲁棒性**：标签损坏 30% 时仍高于匹配 R-KV；更细粒度划分因每阶段代表变少而变差；四阶段方案最佳。
- **跨家族**：Nemotron 上 B=3072/4096 分别 +4.5/+4.0，但最小预算 B=2048 略降（−1.0），说明容量受限时阶段策略优势减弱。
- **机制解释**：recency 代表把 tool 阶段效用覆盖压到 0.042（B=512），多阶段代表提升到 0.175；B=1536 时从 0.117 升至 0.416。

## 8. 不足与局限

- **预算需手工指定**：KV 预算 B 由人工/验证集调参，未实现从任务级质量或延迟目标自动选择。
- **适用区间有限**：方法在**中等压缩比**最有效；预算过小时缓存容量主导、预算过大时策略趋近全缓存且执行方差主导差异。
- **场景依赖**：当任务的相关状态已由最近一次工具响应或**外部记忆**承载时，阶段感知保留收益下降（τ2 airline、BFCL memory 大量对比统计未解）。
- **重复退化轨迹问题**：重复性强或退化的推理轨迹会让阶段缓冲区保留近重复上下文，需额外引入冗余惩罚（Nemotron 实验中即与 R-KV 冗余项组合）。

- **解析器依赖模板**：标记表需针对不同 chat template 适配；论文建议在无法获取推理边界时使用更粗粒度划分。
- **覆盖范围**：仅英语 agentic 工具使用负载，未涉及多语言、多模态或非工具型长上下文场景；未报告 GPU 数量等硬件细节。
