## 摘要
长时间运行的智能体会反复调用 LLM，同时保留其大部分文档窗口、逐出旧文档并追加新文档。这些滚动更新破坏了精确前缀缓存，并促使采用带选择性重计算的非前缀 KV 缓存复用。我们表明，带选择性重计算的持久 KV 缓存复用可能具有历史依赖性：在我们的滚动智能体工作负载中，同一个未更改的提示可能因之前处理过的请求不同而产生不同答案。在匹配的 5% 重计算预算下，与文档对齐的重计算将跨请求顺序的答案变化率从 CacheBlend 的 token top-$k$ 策略的 69.0% 降至 26.1%。当每个提示在不同前置请求序列之后被评估时，与文档对齐的重计算相比 token top-$k$ 将相对完整预填充的保真度提高 34.5–52.5 个百分点，而两种策略都实现了约 5.7 倍的中位 TTFT 加速。我们的消融研究表明，在我们的滚动智能体工作负载中，连续性是与稳健的选择性重计算相关的主要因素。

## Abstract
Long-running agents repeatedly call an LLM while retaining most of their document window, evicting old documents, and appending new ones. These rolling updates break exact prefix caching and motivate non-prefix KV-cache reuse with selective recomputation. We show that persistent KV-cache reuse with selective recomputation can be history-dependent: in our rolling-agent workload, an unchanged prompt can produce different answers depending on the requests processed before it. At a matched 5% recomputation budget, document-aligned recomputation reduces answer variation across request orders from 69.0% with CacheBlend's token top-$k$ policy to 26.1%. When each prompt is evaluated after a different sequence of preceding requests, document-aligned recomputation improves fidelity to full prefill by 34.5-52.5 percentage points over token top-$k$, while both policies achieve approximately 5.7$\times$ median TTFT speedup. Our ablation study shows that, in our rolling-agent workload, contiguity is the main factor associated with robust selective recomputation.

# 论文总结：Request Order Matters: Cache-History Sensitivity in Selective KV-Cache Reuse for Rolling Agents

## 1. 核心问题与整体含义
- **研究背景**：长时运行的智能体会反复调用 LLM，并采用“滚动文档窗口”：保留大部分旧文档、淘汰最旧文档、追加新文档。
- **技术痛点**：这种滚动更新会破坏精确前缀缓存。虽然大量文档文本未变，但其位置前移、前置上下文改变，导致已缓存的 KV 状态不再等于当前提示下全量预填充得到的 KV 状态。
- **解决方向**：采用非前缀 KV 缓存复用，并配合选择性重计算，只重算一部分 token，以降低预填充延迟。
- **核心问题**：选择性 KV 缓存复用是否依赖请求历史？在固定重算预算下，重算少量连续区域是否比重算散落的高偏差 token 更稳健？
- **整体含义**：同一提示在不同先前请求序列之后，可能因持久缓存状态不同而产生不同答案。缓存复用策略不能只在“干净缓存、孤立请求”上评估，而应在真实请求序列和持久缓存历史中评估。

## 2. 方法论
- **基础框架**：使用 LMCache 的 CacheBlend 实现。系统先加载可复用 chunk 的缓存 KV，再在某一选择层比较当前 key 与缓存 key 的偏差。
- **偏差分数**：对每个可复用 token \(i\)，定义  
  \[
  d_i = \|K_i^{current} - K_i^{cached}\|_2^2
  \]
  偏差越大，表示该 token 的缓存 key 与当前提示下应产生的 key 差异越大，越应优先重算。
- **预算规则**：对 \(N\) 个可复用 token 和重算比例 \(r\)，选择  
  \[
  k = \max(1,\lfloor rN \rfloor)
  \]
  个 token 重算。主实验固定 \(r=5\%\)。
- **Token top-k 策略**：CacheBlend 默认选择 \(d_i\) 最大的 \(k\) 个 token。该策略能捕捉最大个体偏差，但选择位置可能散落在数百个不连续区域。
- **Span-level 选择性重计算**：以连续 span 为单位分配预算。对候选 span \(S_j\)，定义平均偏差  
  \[
  \rho_j = \frac{1}{|S_j|}\sum_{i \in S_j} d_i
  \]
  并按 span 排序选择。
- **四种 span 策略**：
  - **Single-window**：选择总偏差最大的连续 \(k\)-token 窗口。
  - **Fixed-chunk**：将可复用提示切成等长 span，允许跨文档边界，按平均偏差选。
  - **Random-document**：使用文档 span，但随机排序，忽略偏差。
  - **Document-aligned**：使用指令、单个文档、最终 query 等文档边界定义 span，按平均偏差排序，优先选完整 span；若预算未用完，再从最高排名剩余 span 中选连续窗口，最终恰好重算 \(k\) 个 token。
- **主策略**：文档对齐重计算用于缓存历史敏感性实验和 TTFT 基准；其他三种 span 策略作为消融控制，用于分离“连续性”“文档边界”“偏差排序”三个因素。
