## 摘要
长时间运行的智能体会反复调用 LLM，同时保留其大部分文档窗口，淘汰旧文档并追加新文档。这些滚动更新破坏了精确前缀缓存，并推动了带选择性重计算的非前缀 KV 缓存复用。我们表明，带选择性重计算的持久化 KV 缓存复用可能具有历史依赖性：在我们的滚动智能体工作负载中，同一个未变化的提示会因之前处理过的请求不同而产生不同答案。在匹配的 5% 重计算预算下，按文档对齐的重计算将跨请求顺序的答案变异从 CacheBlend 的 token top-$k$ 策略下的 69.0% 降至 26.1%。当每个提示在不同前置请求序列之后被评估时，相较于 token top-$k$，按文档对齐的重计算将对完整预填充的保真度提高了 34.5–52.5 个百分点，而两种策略均实现了约 5.7 倍的中位 TTFT 加速。我们的消融研究表明，在我们的滚动智能体工作负载中，连续性是与稳健的选择性重计算相关的主要因素。

## Abstract
Long-running agents repeatedly call an LLM while retaining most of their document window, evicting old documents, and appending new ones. These rolling updates break exact prefix caching and motivate non-prefix KV-cache reuse with selective recomputation. We show that persistent KV-cache reuse with selective recomputation can be history-dependent: in our rolling-agent workload, an unchanged prompt can produce different answers depending on the requests processed before it. At a matched 5% recomputation budget, document-aligned recomputation reduces answer variation across request orders from 69.0% with CacheBlend's token top-$k$ policy to 26.1%. When each prompt is evaluated after a different sequence of preceding requests, document-aligned recomputation improves fidelity to full prefill by 34.5-52.5 percentage points over token top-$k$, while both policies achieve approximately 5.7$\times$ median TTFT speedup. Our ablation study shows that, in our rolling-agent workload, contiguity is the main factor associated with robust selective recomputation.

# 论文总结：Request Order Matters: Cache-History Sensitivity in Selective KV-Cache Reuse for Rolling Agents

## 1. 核心问题与整体含义

- **背景**：长时运行的智能体（rolling agents）会反复调用 LLM，每轮保留文档窗口中绝大部分文档、淘汰最旧的文档、追加新文档（如 `[D1..D84] → [D2..D85]`）。这类"滚动更新"使所有保留文档在提示中的位置前移、前置上下文改变，导致**精确前缀缓存失效**——最长共享前缀仅剩固定指令部分。
- **技术动因**：为绕开前缀限制，业界提出**非前缀 KV 缓存复用 + 选择性重计算**（CacheBlend、LMCache 等）：加载各文档块独立计算的 KV 状态，再对少量高偏差 token 重算，以修补跨块注意力不一致。
- **核心问题**：这类复用是否可靠？论文指出一个被忽视的维度——**缓存历史敏感性**。由于 KV 状态在请求间持久存在，同一个**未改动的提示**在不同前置请求序列下可能产生**不同答案**，即"闭环服务问题"：每次 LLM 调用既消费也更新缓存状态，后续请求被先前请求所"条件化"。
- **整体含义**：重试、分支轨迹、并发会话、调度交错都可能让同一提示遇到不同缓存状态。因此 KV 复用方法不应只在"干净缓存 + 孤立请求"上评测，而应在**缓存状态持续累积的真实请求序列**上评测。

## 2. 方法论

- **核心思想**：在**固定重计算预算（5%）**下，比较"选哪些 token 重算"对稳健性的影响，分离出**连续性（contiguity）**这一因素。
- **偏差度量（CacheBlend / LMCache 基础）**：在选定层比较每个可复用 token 的当前 key 与加载 key 的 L2 距离：
  - `d_i = ||K_current_i − K_cached_i||²₂`
  - 偏差越大，越优先重算；重算 token 数 `k = max(1, ⌊rN⌋)`，默认策略取 `d_i` 最大的 k 个 token。该选择仅在选定层做一次，后续各层沿用同一位置集合。
- **span 级重计算**：为候选连续区间 `S_j` 定义平均偏差 `ρ_j = (1/|S_j|) Σ_{i∈S_j} d_i`（按长度归一化，避免长区间仅因 token 多而占优）。
- **四种 span 策略（均重算恰好 k 个 token）**：
  - **Single-window**：选总偏差最大的连续 k-token 窗口。
  - **Fixed-chunk**：将可复用提示切成等长（92 token）区间，跨越文档边界，按 `ρ_j` 排序。
  - **Random-document**：使用文档边界划分，但**忽略偏差分数**，按确定性随机顺序排序。
  - **Document-aligned**：使用文档边界划分（指令段、各文档段、最终查询段），按 `ρ_j` 排序，优先整体选取完整 span 直至预算耗尽；若仍有剩余预算，则从最高排名剩余 span 中取总偏差最大的连续窗口。
- **设计意图**：Document-aligned 作为主对比策略；其余三种 span 策略作为消融对照，分别隔离**连续性**、**文档边界**、**偏差排序**三者的作用。文档边界之所以被采用，是因为它在文档导向提示中天然可用，无需学习式分段器或人工设定 chunk 大小。

## 3. 实验设计

- **模型与系统**：Qwen3-8B，贪心解码（temperature 0），固定随机种子；LMCache 0.5.1；vLLM 0.23.0；**关闭 vLLM 前缀缓存**以隔离 LMCache 的非前缀复用路径。两种策略共享同一模型、提示、可复用 token 接口、偏差度量与 5% 重算规则。
- **数据集 / 场景**：全量事件数据集含 **8,995 条真实记录、15 只美股**——7,515 条 Yahoo Finance 日频价格、792 条 FNSPID 新闻标题、688 条 SEC EDGAR 申报标题；新闻与申报日期映射到各股票的交易日历上以交错三通道并保持通道内顺序。
- **负载构造**：模拟有界文档窗口智能体，每次调用前淘汰 1 篇、保留 83 篇、追加 1 篇，共 **7,735 次滚动更新**，窗口固定 84 篇文档，stride = 1；提示长度约 **7.2K–7.7K token**。最终查询要求模型逐字复制当前窗口中某条观察的指定字段，构成**确定性抽取任务**，便于精确答案比对。
- **评测协议（请求顺序扰动）**：同一批提示以 **5 种顺序**进入服务系统，仅改变进入顺序而不改提示内容，从而改变持久缓存状态：
  - Chronological（源顺序）、Fixed-random（3 个预定打乱顺序）、Reversed（逆序压力测试）。
  - 每种"策略 × 顺序"组合均从空 LMCache 开始、跨请求保留缓存、与其他运行不共享状态。
- **评测指标**：
  - **Answer variation**：5 种顺序两两配对（共 10 对）中答案不一致的百分比。
  - **Fidelity**：与完整预填充（full prefill）答案的精确一致率。
  - **TTFT**：请求级首 token 时延（中位数、P95、相对 full prefill 的加速比）。
- **对比方法**：CacheBlend/LMCache 的 **token top-k**（默认、散点式）vs **document-aligned**；消融中再加入 single-window、fixed-chunk、random-document，共 5 种策略。

## 5. 实验数量与充分性

- **主实验**：5 种请求顺序 × 2 种主对比策略（token top-k、document-aligned），覆盖 7,735 次滚动更新；额外含一次 chronological 独立重复以排除运行间波动。
- **消融实验**：5 种选择策略（token top-k、single-window、fixed-chunk、random-document、document-aligned）在**同一 500 请求队列**上、chronological 与 fixed-random 两种顺序下评测；每策略在各顺序内重算 token 总数严格匹配（chronological 188,562 个；fixed-random 188,721 个；中位每请求 386 / 387 个），确保差异源于"选在哪里"而非"选多少"。
- **缓存重置对照**：500 请求、每请求前重置缓存，token top-k 94.0% vs document-aligned 92.6%（p = 0.23），用于证明差异依赖于累积缓存历史。
- **统计检验**：报告 95% 置信区间、Wilson score 区间与 p 值，对顺序间差异做了显著性检验。
- **充分性与公平性评估**：
  - **优点**：预算严格对齐、缓存隔离、单一变量控制（仅改请求顺序）设计严谨；加入随机顺序与逆序压力测试，覆盖了共享缓存多智能体交错与极端场景。
  - **局限**：数据仅覆盖**美股金融文本**单一领域，且任务为**确定性复制式抽取**；模型仅 Qwen3-8B 一个规模；500 请求消融队列小于主实验规模；TTFT 仅在 L4 单卡测点。因此"充分性"在深度（变量控制）上较强，在广度（领域、模型、硬件、任务类型）上有限。

## 6. 主要结论与发现

- **请求顺序会改变答案**：token top-k 的答案变异率为 **69.0%**，document-aligned 降至 **26.1%**。
- **保真度差异**：
  - Chronological 顺序下二者**无显著差异**（86.8% vs 85.4%，p = 0.12）。
  - 其余四种顺序下，token top-k 保真度 **19.8–41.5%**，document-aligned 为 **54.3–91.7%**（均 p < 0.0001），提升 **34.5–52.5 个百分点**；但在 Reversed 压力测试下 document-aligned 也降至 54.3%，说明它**更稳健但非免疫**。
- **缓存历史是关键**：在每请求重置缓存的 500 请求对照中二者无显著差异，说明优势来自**跨请求累积的缓存状态**，而非方法本身的静态优劣。
- **延迟收益相当**：full prefill 中位 TTFT 2,408 ms；token top-k 426 ms（5.68×）；document-aligned 415 ms（5.74×），二者延迟近似。
- **消融结论——连续性最重要**：
  - Chronological 下五种策略保真度均在 86.2–89.2%，无策略占优。
  - Fixed-random 下 token top-k 跌至 **38.6%**，四种 span 策略达 **89.4–92.8%**（各提升 50.8–54.2 个百分点，p < 0.0001）。
  - Document-aligned 与 single-window（p = 0.076）、fixed-chunk（p = 0.85）、random-document（p = 0.37）均无显著差异；**文档边界与偏差排序未带来统计显著的额外收益**。
- **"捕获更多偏差 ≠ 更高保真"**：fixed-random 下 token top-k 覆盖了 **99.7%** 的偏差分数却仅得 38.6% 保真度，并把预算散落在中位 **180.5** 个不连续区间；而 random-document 完全不看偏差（仅捕获 4.8% 偏差）、只选 6 个整文档 span，却提升 50.8 个百分点。
- **总体结论**：在相同重算成本下，重算**连续区域**比重算**散点式高偏差 token** 更有效；选择性 KV 复用应与**持久缓存生命周期协同设计**，评测须在缓存状态持续累积的真实请求序列上进行。

## 7. 优点

- **问题新颖且切中实际**：首次把"请求顺序 / 缓存历史"作为 KV 复用评测维度提出，揭示了孤立请求评测可能掩盖的闭环服务风险。
- **变量控制严谨**：仅改变请求进入顺序而不改提示内容；所有策略在每种顺序内重算 token 数严格一致；缓存隔离、单请求串行下发以排除批组合效应；独立重复验证可复现性。
- **消融设计精巧**：用四种 span 策略分别剥离"连续性""文档边界""偏差排序"三个因素，得出"连续性为主因"的清晰归因，并给出 segments / captured deviation 两个量化视角支撑。
- **实用性强**：document-aligned 依赖文档提示中天然存在的边界，无需学习式分段器或人工 chunk 尺寸，落地成本低。
- **统计规范**：报告置信区间与 p 值，并包含缓存重置对照这一"阴性对照"，增强结论可信度。
- **成本—收益对齐**：在证明保真度大幅提升的同时报告 TTFT 基本不变，说明改进不靠"多算"换取。

## 8. 不足与局限

- **领域与任务单一**：仅覆盖 15 只美股的金融事件数据，且任务为确定性字段复制抽取；结论能否推广到开放式生成、多跳推理、代码等任务尚不明确。
- **模型与规模单一**：仅 Qwen3-8B，未验证不同架构、更大/更小规模模型下缓存历史敏感性的表现。
- **硬件与延迟结论有限**：TTFT 仅在单块 NVIDIA L4 上测得，未报告 GPU 数量、批大小/并发配置、显存占用等，也未在更高吞吐或分布式场景下验证 5.7× 加速的可移植性。
- **未定位失效机制**：论文观察到"连续性有效"，但**未从注意力机制层面解释原因**（如注意力汇聚点、位置编码、跨块注意力分布），缺少机制性分析。
- **"无显著差异"的证据强度**：多处结论基于"未检出显著差异"（如 document-aligned vs single-window，p = 0.076；缓存重置对照 p = 0.23），在样本量有限时属于**不能证伪**而非证明等价，需谨慎解读。
- **缓存生命周期变量未拆解**：论文在结论中自承未来工作才将"隔离保留缓存条目与重建缓存条目的效应"，当前未区分缓存条目被命中、被淘汰、被重建等不同状态。
- **压力测试下的退化**：Reversed 顺序下 document-aligned 保真度仍跌至 54.3%，说明稳健性有边界，方法在极端缓存历史下仍不可靠。
- **缺少与其他修复机制的比较**：未与 ProphetKV、CacheClip、EPIC/LegoLink、KVLink 等更完整的重计算/位置无关方案做同预算对比，因此"连续性优先"结论的普适性有待扩展验证。
