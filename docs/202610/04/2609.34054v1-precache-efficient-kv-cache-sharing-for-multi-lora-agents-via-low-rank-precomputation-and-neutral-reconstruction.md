## 摘要
多 LoRA 智能体系统通过共享一个公共主干模型来实现高效的角色专业化。然而，每个智能体都会重复处理不断增长的共享轨迹，并构建自己的 KV 缓存，这在长时程任务中引入了大量内存与计算冗余。现有的 KV 缓存共享方法减少了重复预填充，但它们要么需要额外训练或架构约束，要么仍保留大量模型计算。此外，直接复用缓存会使当前智能体依赖前一智能体适配器生成的缓存状态，从而削弱其自身 LoRA 所编码的角色特定行为。我们提出 PReCache，一种免训练的 KV 缓存共享框架，包含两种设计，即 PreLRShared 和 ReBaseShared，它们共享使用预训练权重计算的基础缓存，并预计算紧凑的、智能体特定的低秩（LR）缓存。为消除重复预填充，PreLRShared 在首次处理共享上下文时为每个智能体预计算其 LR 缓存，使当前智能体能够使用自己的 LR 缓存，而无需重新处理之前智能体已处理过的上下文。为提高共享准确性，ReBaseShared 从无适配器的隐藏状态重建共享基础缓存，从而减少由前一智能体适配表示所导致的剩余误差。为最小化其重建成本，我们提出两种推理方案，分别面向单流推理和并发服务，分别在每个智能体轮次结束后或与其执行同时进行相同的重建。在多个模型和智能体基准上，与不使用 KV 缓存共享的推理相比，PreLRShared 实现了最高 3.1 倍的 TTFT 加速，并将每请求吞吐量提升最高 2.3 倍。在所评估的缓存共享方法中，ReBaseShared 总体上最能保持准确率，相较于不使用缓存共享的推理，平均仅下降 1.1 个百分点。

## Abstract
Multi-LoRA agent systems enable efficient role specialization by sharing a common backbone model. However, each agent repeatedly processes the growing shared trajectory and constructs its own KV cache, introducing substantial memory and computation redundancy in long-horizon tasks. Existing KV cache sharing methods reduce this repeated prefill, but they either require additional training or architectural constraints or retain substantial model computation. Moreover, direct cache reuse causes the current agent to rely on cache states generated by the previous agent's adapter, weakening the role-specific behavior encoded by its own LoRA. We present PReCache, a training-free KV cache sharing framework with two designs, namely PreLRShared and ReBaseShared, that share the base cache computed using the pretrained weights and precompute a compact agent-specific low-rank (LR) cache. To remove repeated prefill, PreLRShared precomputes each agent's LR cache when the shared context is first processed, allowing the current agent to use its own LR cache without reprocessing context processed by previous agents. To improve sharing accuracy, ReBaseShared reconstructs the shared base cache from adapter-free hidden states, reducing the remaining error caused by the previous agent's adapted representation. To minimize its reconstruction cost, we propose two inference schemes tailored to single-stream inference and concurrent serving, performing the same reconstruction after each agent's turn or alongside its execution, respectively. Across multiple models and agent benchmarks, PreLRShared achieves up to a 3.1x TTFT speedup and a 2.3x improvement in per-request throughput over inference without KV cache sharing. ReBaseShared best preserves accuracy overall among the evaluated cache-sharing methods, with an average drop of only 1.1 points relative to inference without cache sharing.

# PReCache 论文详细总结

## 1. 核心问题与整体含义

- **研究背景**：多 LoRA 智能体系统通过共享一个预训练主干模型、为每个角色挂载轻量 LoRA 适配器，实现角色专业化并降低模型内存占用，在资源受限场景下尤其有价值。
- **核心痛点**：尽管主干共享，多智能体在长时程任务中会累积"共享轨迹"（用户请求、检索信息、工具观测、前序智能体输出）。每个智能体都要**独立重复预填充（prefill）**这段不断增长的上下文，并为同一上下文构建**独立的 KV 缓存**，造成显著的内存与计算冗余；轨迹越长、智能体与轮次越多，预填充负担越重。
- **直接复用的困难**：由于适配器不同，隐藏状态变为智能体依赖的，即使处理相同上下文，各智能体的 KV 缓存也不同。直接复用前一智能体的缓存（FullShared）会显著降低准确率，因为当前智能体被迫依赖前序适配器生成的状态，削弱了自身 LoRA 所编码的角色行为。
- **现有方法的局限**：
  - **选择性重算**（DroidSpeak / CacheBlend / RelayCaching）：重算关键层或 token，但异构 LoRA 造成多层多 token 的缓存偏差，重算比例小则精度不足，比例大则计算/内存节省被抵消。
  - **偏差校正方法**：面向前缀/位置差异，当前缀与位置匹配时其校正变量不变，对适配器差异无校正作用，退化为 FullShared。
  - **需训练/改架构的方法**（如 BaseLRShared 需共享 LoRA 下投影）：无法直接支持已有适配器。
  - **BaseShared（LRAgent）**：共享基础缓存 + 保留智能体专属 LR 缓存，精度好且内存低，但**仍需当前智能体对累积上下文做全长主干前向以构建自身 LR 缓存**，重复预填充几乎未减少，计算开销甚至不低于 token 级重算。
- **整体含义**：论文提出 **PReCache**，一个**免训练**的 KV 缓存共享框架，目标是在**不重训、不约束已有 LoRA 适配器**的前提下，同时降低 KV 缓存内存占用与重复预填充计算，并尽量保持角色特定行为与准确率。

## 2. 方法论

### 核心思想
- 将适配后的投影分解为**共享基础贡献**与**智能体专属适配器贡献**：
  - `Yi = Xi,adpt(W0 + AiBi) = Xi,adpt·W0 + (Xi,adpt·Ai)·Bi`
  - 前者构成**共享基础缓存（base cache）**，后者为宽度仅 r 的**紧凑 LR 缓存**（r ≪ din, dout）。
- 两个互补设计：**PreLRShared**（消除重复预填充）与 **ReBaseShared**（降低基础缓存对前一智能体的依赖）。

### 关键技术细节
- **PreLRShared（LR 缓存预计算）**：
  - 当某段上下文**首次**被智能体 i 处理时，对其隐藏状态 `Xi,adpt ∈ R^{LP×din}` 同时施加**所有**智能体的下投影 `Ak`（k=1..N），一次性生成 `Xi,adpt·Ak ∈ R^{LP×r}`，即所有智能体的 LR 缓存。
  - 后续智能体 j 直接复用共享基础缓存 + 自己的预计算 LR 缓存，仅对**新增上下文 LC** 做适配主干计算，不再重算累积轨迹 LP。
  - 把"后续全维度主干处理"替换为"轻量 rank-r 下投影"，是该设计效率收益的核心来源。
- **ReBaseShared（中性基础缓存重建）**：
  - 观察：`Xi,adpt` 携带前一智能体适配器逐层传播的影响，使基础缓存 `Xi,adpt·W0` 仍条件化于前一智能体。
  - 做法：以**禁用 LoRA 适配器**的方式处理共享上下文，得到**无适配器隐藏状态 Xneut**，并构建**中性基础缓存** `Xneut·W0`。
  - 该中性重建与 LR 缓存预计算**并存**：新增上下文上，智能体 j 用自身适配隐藏态生成并扩展自己的 LR 缓存，同时用无适配器隐藏态构建中性基础缓存并为其他智能体 k≠j 生成其 LR 缓存。
  - **理论分析**：定义 `Ci = Xi,adpt W0`、`Cj = Xj,adpt W0`、`Cneut = Xneut W0`，偏移 `Δi = Ci − Cneut`、`Δj = Cj − Cneut`，误差比
    `Γerr = Eprev/Eneut = sqrt(1 + ρ² − 2ρcosθ)`，其中 `ρ = ‖Δi‖/‖Δj‖`。
    当 `ρ ≥ 2cosθ`（即 `Γerr ≥ 1`）时，中性基础缓存相对当前智能体自建基础缓存的误差**不高于**沿用前一智能体缓存。作者在两种模型、三种智能体转移上实测该几何条件，各层平均 `Γerr > 1`。
- **两种推理调度（逻辑等价、仅执行时机不同）**：
  - **LP（lazy prefill）**：智能体 j 轮次内只跑适配路径；解码结束后，以适配器关闭状态对 LC 做一次**连续预填充**，扩展中性基础缓存。适合**单流边缘推理**，避免维护第二条解码路径，且可与工具调用重叠。
  - **DB（double batching）**：在预填充与解码全程，把适配路径与无适配路径**同时批处理**（同一 token、同一位置、独立 KV 视图）；适配路径只关注当前智能体 KV 缓存并产出 logits，无适配路径只关注并扩展中性基础缓存。适合**并发服务端**，避免轮次后的单独预填充造成排队延迟。

### 算法流程（文字描述）
1. 智能体 i 处理 LP：构建共享基础缓存，同时为全部 N 个智能体预计算 LR 缓存 → 缓存覆盖 LP。
2. 智能体 j 接收 LP + LCin：复用基础缓存与自身 LR 缓存（ReBaseShared 使用中性基础缓存），仅对新增上下文做适配主干计算并生成。
3. 并行/随后生成无适配隐藏态，扩展中性基础缓存，并为其他智能体生成 LR 缓存。
4. 轮次结束，基础缓存与全部 LR 缓存覆盖 LP + LC，供下一智能体同样复用。

## 6. 主要结论与发现

- **准确率**：ReBaseShared 在四种模型–benchmark 组合中整体最接近 NonShared，**平均仅下降 1.1 个百分点**，与 BaseShared 相当；PreLRShared 平均下降 1.0%–3.3%，但优于或持平于选择性重算基线。FullShared 下降最大（如 Ministral 上 ScienceQA 降 5.68 分）。
- **效率（单流）**：PreLRShared 相对 NonShared 最高 **3.1× TTFT 加速**、**2.3× 每请求吞吐提升**；66.4k token 时 TTFT 仍接近 FullShared（差 17% 以内）。ReBaseShared LP 最高 3.0× TTFT 加速、1.6× 吞吐提升，并在长轨迹上优于所有选择性重算基线。BaseShared 因仍需全长主干处理，效率接近 NonShared/DroidSpeak。
- **效率（并发）**：高负载下 PreLRShared 与 ReBaseShared DB 保持优势；非饱和负载下分别比 NonShared 高 1.6× 与 1.3× 每请求吞吐；p90/p99 差距随排队累积而扩大。
- **显存**：两者在 66.4k token 时峰值显存与 FullShared 相差在 2% 以内，比选择性重算基线低 **17–23%**；智能体数从 N=4 增至 N=8 时峰值显存仅增约 1–2%，而 NonShared 增 26%、选择性重算增 16–20%。
- **调度**：单流场景 LP 优于 DB；并发场景 DB 优于 LP（避免轮次后单独预填充造成的排队延迟），二者缓存状态逻辑等价。
- **理论发现**：在 `ρ ≥ 2cosθ` 条件下，中性基础缓存比前一智能体基础缓存更接近当前智能体自建基础缓存；实测各层平均 `Γerr > 1`，验证了该条件。
- **超参发现**：LoRA rank 从 4 增至 8 精度提升，之后趋于饱和；rank 增大不缩小缓存共享带来的精度差距，说明差距并非适配器容量不足；r=8 是容量与 LR 缓存开销的合理平衡。QV 适配下效率优势明显；QKVO 适配下 PReCache 仍保持长上下文效率趋势（但 key 侧 LR 缓存无法套用 Flash-LoRA-Attention 的基于结合律的重排）。

## 7. 优点

- **免训练、无架构约束**：可直接应用于已有不同下投影权重的 LoRA 适配器，无需重训或修改适配器结构，工程落地门槛低（对比 BaseLRShared 与需训练映射的方法）。
- **同时解决内存与计算两个冗余**：既有 BaseShared 的低内存优势，又通过 LR 缓存预计算消除了其主要瓶颈——重复全长主干前向。
- **设计组合互补且可解释**：PreLRShared 负责效率，ReBaseShared 负责精度；后者有明确的理论条件（`ρ ≥ 2cosθ`）与逐层经验几何验证，而非纯启发式。
- **场景化调度**：LP/DB 分别针对单流边缘与并发服务，且两者缓存状态逻辑等价，便于按部署环境选择；LP 还能与工具调用重叠。
- **实验严谨性**：受控回放轨迹隔离外部延迟、统一基线重算比例、报告运行间标准差、给出完整数值附录，并做了智能体数量与 LoRA 配置的扩展性验证。

## 8. 不足与局限

- **模型与任务覆盖有限**：仅 2 个 8B 级模型、2 个 QA 数据集、单一 plan–action–reflect 三角色 workflow，未验证更大规模模型、更多智能体角色结构或代码/网页等非 QA 任务域；跨域泛化主要靠引用他文证据间接支撑。
- **训练成本未披露**：仅说明沿用 LRAgent 设置，未报告 LoRA 训练所用 GPU 型号、数量与时长，无法评估端到端部署成本。
- **默认配置的适用边界**：主实验采用 QV 适配（r=8），此设置下 key 缓存完全共享；作者自己也指出参数对齐的 QKVO 适配精度更低（引用 LRAgent），说明方法优势在一定程度上依赖于"key 不参与适配"这一前提。
- **ReBaseShared 的额外计算**：虽避免重复预填充，但引入了无适配器重建路径，单流吞吐低于 PreLRShared（66.4k 时约 1068 vs 1685 tok/s），存在精度—吞吐的取舍。
- **精度仍有差距且分布不均**：ReBaseShared 平均下降 1.1 个百分点，作者承认改善在不同难度分组间不一致；Ministral 上 ScienceQA 仍降 2.60 分，弱于 LLaMA 上的表现。
- **理论条件的经验性**：`ρ ≥ 2cosθ` 是逐 token 平均成立的结论，个别 token/层可能不满足，且分析聚焦于共享基础缓存，未刻画 LR 缓存侧的差异。
- **效率评测使用随机 token id 回放**：虽保证方法间可比，但与真实生成内容的缓存分布可能存在差异；自然轨迹实验（表 3）显示缓存共享会改变生成 token 与后续决策，进而改变轨迹长度，带来间接效应。
- **潜在偏差风险**：选择性重算基线统一 30% 重算比例，虽称接近 Pareto 前沿，但若针对各方法单独调参，其表现可能变化；此外论文与 LRAgent 部分作者重叠，基线比较存在同源关系。
