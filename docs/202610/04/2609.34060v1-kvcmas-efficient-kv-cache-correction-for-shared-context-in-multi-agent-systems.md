## 摘要
提示特化型多智能体系统使多个智能体能够共享同一个模型，同时扮演互补角色来解决复杂任务。然而，智能体特定的前缀会改变为同一共享上下文生成的 KV 缓存，导致每个智能体重复预填充不断增长的上下文，并构建单独的缓存，带来高昂的计算和内存开销。选择性重计算可减少这种冗余，但仍保留大量模型执行；而现有的增量校正方法要么仅支持重复出现的上下文关系，要么为动态变化的上下文维护内存密集型的在线校正状态。对于首次出现的共享上下文，这些方法还会在智能体工作流之外构建参考缓存，并且第一个智能体处的近似校正会影响传递给后续智能体的输出。我们提出 KVCMAS，一种在线 KV 缓存校正框架，它使用紧凑的低秩状态表示跨智能体缓存偏差，并沿智能体工作流无缝串联校正，而无需额外的参考预填充。该设计支持动态变化的共享上下文，同时保留精确的首个智能体缓存。在多种语言和视觉语言工作负载中，KVCMAS 在高度并发服务下实现了最低的 TTFT，同时匹配或优于先前 KV 缓存共享方法的准确率。在受控服务轨迹下，相较于不进行 KV 缓存共享的推理，它实现了 2.0 倍的 TTFT 加速，并且相对于先前的 KV 缓存校正方法，将峰值 GPU 内存最多降低 3.7 倍。这些结果确立了 KVCMAS 是一种面向提示特化多智能体服务的准确且可扩展的 KV 缓存共享方法。

## Abstract
Prompt-specialized multi-agent systems enable multiple agents to share a model while performing complementary roles to solve complex tasks. However, agent-specific prefixes change the KV cache generated for the same shared context, causing each agent to repeatedly prefill the growing context and construct a separate cache with high computation and memory overhead. Selective recomputation reduces this redundancy but still retains substantial model execution, while existing delta correction methods either support only recurring context relations or maintain memory-intensive online correction states for dynamically changing context. For first seen shared context, these methods also construct a reference cache outside the agent workflow, and an approximate correction at the first agent affects the outputs passed to subsequent agents. We present KVCMAS, an online KV cache correction framework that represents cross-agent cache deviations using compact low-rank states and seamlessly chains corrections along the agent workflow without an additional reference prefill. This design supports dynamically changing shared context while preserving an exact first-agent cache. Across multiple language and vision-language workloads, KVCMAS matches or improves the accuracy of prior KV cache sharing methods while achieving the lowest TTFT under highly concurrent serving. Under controlled serving traces, it provides a 2.0x TTFT speedup over inference without KV cache sharing and reduces peak GPU memory by up to 3.7x relative to a prior KV cache correction method. These results establish KVCMAS as an accurate and scalable KV cache sharing approach for prompt-specialized multi-agent serving.

## 1. 核心问题与整体含义

- **研究背景**：提示特化型多智能体系统（prompt-specialized MAS）让多个智能体共享同一模型权重，通过不同角色提示完成规划、工具调用、批判、总结等互补任务。
- **核心痛点**：智能体专属前缀会改变同一共享上下文所生成的 KV 缓存。即使共享上下文内容相同，不同智能体生成的 KV 缓存也不同，导致每个智能体重复预填充增长中的上下文，并保存独立缓存，带来高计算与高显存开销。
- **现有方法不足**：
  - **选择性重计算**：只重建部分层或 token，虽降低冗余，但仍需模型执行，且未重建部分的缓存偏差会保留，精度与效率存在权衡。
  - **增量校正**：可避免对校正条目执行模型，但多数方法只支持重复出现的上下文关系，难以应对动态变化的用户请求和智能体输出。
  - **在线校正方法**：如 KVComm 支持动态上下文，但存储全维 base cache 和 agent-specific 校正，内存随共享上下文长度、锚点数和智能体数增长。
  - **首次共享上下文问题**：非链式校正需要额外构建 context-free 参考缓存，且首个智能体的近似校正误差会沿工作流传给后续智能体，放大总体误差。
- **整体含义**：KVCMAS 旨在为提示特化多智能体服务提供一种在线、低内存、高精度的跨智能体 KV 缓存校正与共享方案，兼顾动态共享上下文、首智能体精确缓存和高效并发服务。

## 2. 方法论：核心思想与关键技术

- **总体思想**：
  - 用**紧凑低秩状态**表示跨智能体 KV 缓存偏差。
  - 沿智能体工作流进行**链式校正**：每个已被校正或密集预填充得到的共享上下文缓存，作为下一工作流边的参考缓存。
  - 首个智能体密集预填充，保证精确缓存，避免首智能体误差传播。
  - 在线锚点池支持动态共享上下文，无需额外 context-free 参考预填充。

- **问题形式化**：
  - 对共享段 `seg`，智能体 `i` 的前置上下文为 `c_{i,seg}`，其 KV 缓存为 `C_{i,seg} = KV(seg | c_{i,seg})`。
  - 同一共享段在不同智能体下通常产生不同缓存：`C_{i,seg} != C_{j,seg}`。
  - 精确跨智能体偏差：`Δ_{j←i,seg} = C_{j,seg} - C_{i,seg} = Δ_{j←ref,seg} - Δ_{i←ref,seg}`。
  - KVCMAS 选择源智能体缓存 `C_{i,seg}` 作为参考，而非单独构建 context-free 参考。

- **低秩锚点池**：
  - 对 base cache 或 delta correction 矩阵 `Z ∈ R^{L×D}` 做截断 SVD：`Z ≈ U_{Z,r} Σ_{Z,r} R_{Z,r}^T = A_Z B_Z`，其中 `A_Z ∈ R^{L×r}`，`B_Z ∈ R^{r×D}`。
  - 每个锚点存储低秩 base cache 表示和面向消费智能体的低秩 delta correction。
  - 内存从 `O(VNLD)` 降至 `O(VNr(L+D))`，显著降低在线校正状态开销。
  - 默认 `r = 32`，`V = 10`。

- **在线校正流程**：
  - 对源智能体 `i` 到目标智能体 `j` 的共享段，先对 `C_{i,seg}` 做 key 位置对齐。
  - 将源缓存与在线锚点池中的重建 base 表示比较，计算相似度权重 `w_v`，满足 `Σ w_v = 1`。
  - 估计校正：`\hatΔ_{j←i,seg} = Σ_v w_v A_{Δ,v} B_{Δ,v}`。
  - 将估计校正应用到对齐后的源缓存，物化全维目标缓存 `\hat C_{j,seg}`。
  - 该缓存直接用于注意力，并作为下一工作流边的参考，实现链式校正。

- **可靠性门控与回退**：
  - 使用锚点匹配分数的归一化熵判断可靠性：低熵表示匹配明确，高熵表示无可靠匹配。
  - 当归一化熵 `H(g) ≤ τ` 时接受校正；否则回退到密集预填充，生成精确缓存并重置传播误差。
  - 更高 `τ` 提高复用率 `ρ`，但可能降低精度。
  - 若可用锚点少于 2 个，也触发密集预填充。

- **锚点池管理**：
  - 每个共享上下文槽维护一个最多 `V` 个锚点的进程级池。
  - 锚点存储低秩源缓存表示和对应消费工作流节点的校正。
  - 接受校正后不重新插入；池更新使用通过密集模型执行得到的目标缓存。
  - 池满时，在五个最旧条目中按最少使用策略淘汰。
