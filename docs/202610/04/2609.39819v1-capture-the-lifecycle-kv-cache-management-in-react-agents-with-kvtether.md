## 摘要
长上下文推理与行动（ReAct）智能体的高效服务依赖于 KV Cache 复用，以降低大语言模型（LLM）的预填充延迟和经济成本。然而，智能体框架（agent harnesses）与底层服务栈之间存在语义鸿沟。通过上下文变更、工具执行和子智能体协调，上下文消息可能处于活跃使用、永久丢弃或暂时未使用状态，而服务栈只能观察到对相应 KV Cache 的访问。这种生命周期盲区使得 LRU 等仅基于最近使用时间的策略无法及时回收已死 KV，也无法保留那些将比更新条目更早被复用的较旧 KV。我们提出 KVTether，一种面向 ReAct 智能体的生命周期感知 KV Cache 管理框架。通过追踪嵌入智能体框架中的语义原语，KVTether 能够在高度动态的执行过程中捕获运行时生命周期语义。随后，KVTether 将消息级语义转换为 KV 级生命周期状态，并利用这些状态驱动按状态优先的缓存管理，而无需向智能体框架暴露物理复杂性。在回收已死 KV 后，KVTether 优先保留正在等待复用的存活但空闲 KV，从而减少复用前的过早驱逐。在智能体基准测试和生产工作负载中，KVTether 相对于 LMCache 和 MORI 分别将端到端请求延迟最多降低 26.3% 和 17.4%，并将估计任务成本平均降低 40.0% 和 33.2%。

## Abstract
Efficient serving of long-context reasoning-and-acting (ReAct) agents relies on KV cache reuse to reduce large language model (LLM) prefill latency and monetary cost. However, a semantic gap exists between agent harnesses and the underlying serving stack. Through context mutation, tool execution, and subagent coordination, context messages may become actively engaged, permanently discarded, and temporarily unused, while the serving stack only observes accesses to the corresponding KV cache. This lifecycle blindness prevents recency-only policies such as LRU from reclaiming dead KV promptly and from preserving older KV that will be reused sooner than newer entries.   We present KVTether, a lifecycle-aware KV cache management framework for ReAct agents. By tracing semantic primitives embedded in agent harnesses, KVTether captures runtime lifecycle semantics during highly dynamic execution. KVTether then translates message-level semantics into KV-level lifecycle states and uses these states to drive state-prioritized cache management without exposing physical complexities to agent harnesses. After reclaiming dead KV, KVTether preferentially preserves live-but-idle KV that is waiting for reuse, reducing premature eviction before reuse. Across agent benchmarks and production workloads, KVTether reduces end-to-end request latency by up to 26.3% and 17.4% relative to LMCache and MORI, respectively, and lowers estimated task cost by 40.0% and 33.2% on average.

# KVTether 论文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：LLM 应用正从交互式聊天机器人演进为自主智能体（如 Claude Code、Codex、OpenClaw、Hermes），它们通过 ReAct 循环（推理与行动交替）执行任务，单次请求可累积数十万 token（如 Codex 可达 258K token），KV Cache 复用对降低预填充延迟与成本至关重要。
- **核心问题**：智能体框架（agent harness）与底层服务栈之间存在**语义鸿沟**。
  - 应用层通过消息级操作（append、replace、remove、fork、one-shot 构造）定义消息的逻辑生命周期（长期复用、短期复用、临时使用）。
  - 推理层与存储层只能观察到 token 序列、共享前缀和 cache page 访问事件，无法判断 KV 是逻辑存活、显式保留、暂时等待还是已死。
- **两类缓存管理失败**（基于生产 trace 与 benchmark 分析）：
  - **Liveness failure（僵尸驻留）**：逻辑生命周期结束的 KV 仍物理驻留，LMCache 僵尸页占比峰值达 31.1%/36.3%/15.8%，MORI 峰值达 49.7%/33.1%/27.4%。
  - **Ordering failure（错误方向驱逐）**：LRU 假设最近使用最接近复用，但 ReAct 中新建 KV 常等待工具/子智能体，导致 71.0%–95.0% 的驱逐为错误方向（LMCache），MORI 为 45.7%–75.6%。
- **整体含义**：仅靠下游推断无法弥合鸿沟，生命周期语义必须在运行时从 harness 导出；论文提出生命周期感知的 KV Cache 管理框架 KVTether。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：将消息级生命周期语义从 agent harness 导出，翻译为 KV 级生命周期状态，驱动按状态优先的缓存管理，且不向 harness 暴露物理复杂性。
- **三个设计模块（管道式）**：

### （1）语义原语模型（Semantic Primitive Model）
- 目标：以消息级上下文操作为稳定基底，跨异构 harness 通用。
- **八个原语**分三类：
  - 消息编辑：`append`、`replace`、`remove`；
  - 上下文创建：`fork`（共享父前缀）、`spawn`（独立子上下文）；
  - 生命周期声明：`one_off`（单次推理）、`pin`（长期保留）、`unpin`（释放保护）。
- 开发者通过 SDK 在现有 ContextManager 中调用，捕获空间演化与时间保留需求。

### （2）事件驱动生命周期管理器
- **KV 范围解析**：以 context 为管理单元，维护消息到 token/KV 范围的映射；`remove`/`replace` 因前缀依赖导致后缀失效（suffix invalidation），受影响 KV 进入 Expired；仅在推理边界应用更新，按程序顺序串行处理事件。
- **生命周期状态**（每 context 中每个消息版本维护）：
  - `Pinned`：显式长期/临时保护；
  - `Active`：新追加或参与请求；
  - `Suspended`：LLM 解码开始后挂起；
  - `Expired`：生命周期结束；
  - `Temporary`：一次性推理，其独占 KV 绕过复用存储；
  - `Discarded`：所有映射版本均失效后可回收。
- **共享 KV 管理**：同一 token KV 被多 context 映射时取最高优先级状态，父删除但子仍持 Suspended 引用则共享 KV 保持 Suspended。

### （3）状态引导 KV Cache 引擎
- **按状态优先的准入算法（Algorithm 1）**：先绕过 Temporary KV；再依次按 Expired → Suspended → Active 释放空间；若请求为 Pinned 才与 Pinned KV 竞争。此顺序将语义确定情形从竞争中移除，缩小不确定性至 Suspended 层。
- **Suspended 层的 MRU 排序**：观察到 ReAct 中新建 Suspended KV 常需等待工具/子智能体，复用集中在写回后数秒（Agent-G 43.1% 在 1–3s，Codex 46.6% 在 3–6s，Agent-X 87.5% 在 2–4s）。因此采用 **MRU（最近使用优先驱逐）**，优先驱逐刚挂起的 KV，保留等待较久、更接近复用的 KV。
- **关键设计原则**：不依赖精确的逐项复用预测，而利用 ReAct 执行导致的稳定方向性趋势。

## 6. 主要结论与发现

- **命中率**：KVTether 相对 LMCache 和 MORI 平均绝对命中率提升 **33.3%** 和 **24.5%**，最高提升 47.8% 和 36.4%；在高负载下退化更平缓（如 Agent-X 最高 RPS 时，LMCache 10.2%、MORI 35.7%、KVTether 49.5%）。
- **预填充时间**：平均降低 **29.2%**（vs LMCache）和 **23.3%**（vs MORI），最高 41.2% 和 33.2%。
- **端到端延迟**：平均降低 **16.5%** 和 **12.4%**，最高 **26.3%** 和 **17.4%**（延迟收益小于预填充收益，因解码仍需执行）。
- **任务成本**：平均降低 **40.0%** 和 **33.2%**，最高 53.6% 和 44.1%。
- **消融结论**：
  - 无生命周期追踪时（w/o LT），僵尸页平均占 22.1%–38.5%，而 KVTether 在 Codex 上 <2.5%、其他工作负载为 0；
  - 无 MRU 优化时（w/o RO），错误方向驱逐仍达 65.6%–92.3%，KVTether 降至 25.7%–38.7%；
  - 单独使用 MRU 甚至可能劣于 LMCache 的 LRU，说明生命周期过滤与状态排序缺一不可。
- **集成成本**：六个 harness 集成仅需 26–216 行代码，验证了原语模型的易用性。

## 7. 优点

- **问题洞察深刻**：明确指出 harness 与 serving stack 之间的语义鸿沟，并将缓存问题分解为 liveness failure 与 ordering failure 两类，逻辑清晰。
- **跨层抽象优雅**：以消息级原语作为跨异构 harness 的统一接口，物理细节（token 化、前缀依赖、共享 KV）由生命周期管理器封装，避免将复杂性推回应用层。
- **方法务实**：不依赖精确的逐项复用预测，而是利用 ReAct 执行导致的稳定方向性趋势（MRU），在不确定性下鲁棒性更强。
- **状态优先设计**：先过滤语义确定情形（Temporary 绕过、Expired 回收），将不确定性收敛至 Suspended 层，避免确定情形干扰不确定决策。
- **实验扎实**：结合生产 trace（27,000+ 活跃会话）与 benchmark，覆盖多负载点、多消融维度，指标兼顾性能与成本。
- **低开销与易集成**：运行时开销约占 LLM 调用的 2.0%，六个 harness 集成代码量小，工程可行性高。

## 8. 不足与局限

- **依赖 harness 主动集成**：需要在各 agent harness 中显式使用 8 个原语并正确声明生命周期（如 pin/one_off），若开发者误用或漏用，生命周期语义将不准确；论文未深入讨论错误声明下的鲁棒性。
- **事件重建偏差风险**：Agent-X/Agent-G 的生命周期事件为离线从日志重建，可能丢失部分运行时信息；Codex 虽为在线记录，但两来源不一致，可能影响结论泛化性。
- **工具执行被模拟**：实验中工具调用以固定记录时长等待，消除了真实工具执行时间抖动，可能低估真实部署下复用区间的不确定性。
- **工作负载覆盖有限**：仅三个 ReAct agent 工作负载（两个编码 agent + 一个 Codex 软件工程 agent），未涵盖多模态、深度研究、长链规划等其他 agent 类型；对非 ReAct 或结构化 workflow agent 的适用性未验证。
- **MRU 的边界条件**：MRU 的有效性依赖 ReAct 执行导致的稳定方向性趋势，若部署环境（如队列调度策略）破坏缓存事件的相对顺序，其优势可能减弱；论文仅以 FIFO 为例简单提及。
