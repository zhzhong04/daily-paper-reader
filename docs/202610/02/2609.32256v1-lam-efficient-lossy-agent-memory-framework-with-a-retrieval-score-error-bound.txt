## ABSTRACT 

Agent memory grows as agents read inputs, reason, and call tools. Longer his-tories increase inference cost and eventually exceed the context window. LLM-based summarization reduces this history but adds latency and provides no ex-plicit bound on information loss. We propose LAM, a Lossy Agent Memory sys-tem with three components: a deterministic deduplication rule with a substitution bound on retrieval scores — a bound on score perturbation, not a certificate of un-changed ranking, a memory manager that preserves the cached prefix and overlaps compaction with inference, and a performance model that estimates compaction costs before deployment. On 600 agent trajectories, LAM removes 22.47% of observation tokens while retaining 99.984% of the measured gold-patch evidence. At a fixed deletion set, the performance model predicts a 71.4 ×–91.6 × end-to-end speedup from removing records before prefill instead of deleting them from a prefilled context. That benefit comes from the schedule rather than the rule and applies to any prefix-preserving test. 

## 1 INTRODUCTION 

AI agents retain the files they read, the commands they run, and the resulting outputs. This history supports task completion (Chhikara et al., 2025; Yu et al., 2026), but its growth raises inference cost and latency, and once it exceeds the context window some of it must go. Memory compaction decides what to retain, rewrite, compress, or discard (Chhikara et al., 2025; Fang et al., 2026; Chen et al., 2026); during long tasks it runs repeatedly and can block inference for tens of seconds per event (Cim et al., 2026; Kummer et al., 2026). Existing methods select information for later reuse. LLM summarization and learned compressors process the context with a model (Mu et al., 2023; Ge et al., 2024; Cheng et al., 2024; Pan et al., 2024), adding inference cost; SemDeDup (Abbas et al., 2023) clusters embeddings with k-means, 1arXiv:2609.32256v1 [cs.AI] 26 Sep 2026 Preprint. Under review. whose output can vary with its initialization; observation masking keeps recent tool observations and discards older ones (Lindenbauer et al., 2025). Each exposes a token budget, cluster count, or window size, but none of those parameters bounds the retrieval-score loss that deletion causes. Furthermore their reproducibility depends on the model and execution configuration (§D). Tool outputs often repeat: agents reread files, rerun tests, and list directories more than once. Hash-ing (Quinlan & Dorward, 2002; Zhu et al., 2008) detects exact copies but misses outputs differing in small details. LAM therefore keeps exact hashing as its first layer — the mechanism serving systems already use to reuse identical KV blocks (Kwon et al., 2023) — and adds a second above it that merges near-duplicates whenever unit-normalized embeddings satisfy ∥a − b∥2 ≤ δ, a query-free test equivalent to a merge threshold on cosine. Thus every deleted record keeps a retained representative within δ, and for every unit query the maximum retrieval score decreases by at most 

δ (Theorem 1). The guarantee concerns scores, not ranking or task outcomes, which we evaluate separately (§3). With fixed embeddings and arrival order the rule is reproducible and reports the maximum substitution distance it observed, ˆδ.

Compaction scheduling. The rule tests each record on arrival, before prefill, so the prefilled prefix survives. Deleting from an existing context instead shifts subsequent positions and invalidates their KV entries. Specifically, re-prefilling a 360K context costs ≈538 s in our cost model against ≈12 sfor the turn’s inference: over 600 trajectories removing the same records either way, deletion in place spends 98.6% of the run on compaction and re-prefill against 0.1% for ours (Figure 1). The test can also run on the host CPU while the accelerator serves; encoding is charged when embeddings are not already available. 

Evidence retention. We score evidence retention against each SWE-smith task’s gold patch and count lines accessible only through reference stubs as lost. At a retention floor of 0.999 , none of the evaluated observation-masking settings qualifies; SemDeDup removes 19.60% of tokens, com-pared with LAM’s 22.47%. At a 0.99 floor, SemDeDup removes more (§3). LAM’s removal rate rises from 0.80% at 1K tokens to 25.58% at 33K. On LHTB, which contains 1,459 terminal-agent trajectories from 28 models under a different scaffold, the near-duplicate rule removes 33.39% of observation tokens, compared with 13.81% on SWE-smith. Near-duplicates are rare in the LoCoMo conversational-memory control.

## 2 DESIGN 

LAM combines bounded deduplication (§2.1–2.4), a memory manager that overlaps compaction with inference (§2.5), and a model of deployment cost (§2.6). 2.1 THE PROXIMITY RELATION 

Let records be embedded as unit-normalized vectors in RD . Two records a, b are ε-equivalent when 

∥a − b∥2 ≤ δ. This relation is not transitive, and for unit vectors it is equivalent to a threshold on cosine: 

∥a − b∥22 = 2 − 2 cos( a, b ), so merging at cos ≥ t ⇐⇒ ∥ a − b∥2 ≤ δ = √2 − 2t. (1) We call t the merge threshold and δ the substitution bound ; ε denotes the error budget generically and δ its value under ℓ2. Each fixes the other, and §2.4 shows the same δ bounds the retrieval-score loss: the radius of the query-free test is the size of the guarantee. We use ℓ2 because a coordinatewise tolerance ∥a − b∥∞ ≤ 2ε would yield a bound proportional to √D instead. The quantization step in Qε only proposes candidates and does not enter the bound (Appendix K.1). 2.2 THREE LAYERS 

L0, byte-exact hashing. This layer is carried over from LLM serving: vLLM hashes fixed-size blocks so a repeated prefix reuses one copy of the KV cache instead of recomputing it (Kwon et al., 2023). We apply the same mechanism one level up, to the text an agent accumulates rather than the cache it produces — xxHash3 over individual lines, repeats replaced by stubs — lines being the granularity that removes the most under exact matching (Appendix B). L0 thus inherits the serving cache’s need for an exact match, which L1 removes, and runs after L1 to preserve the blocks near-duplicate matching uses (Figure 4). L1, ε-equivalence candidates. We quantize each coordinate with Qε(x) = round( x/ 2ε), divide the vector into bands, and hash each band; records sharing a band digest are candidates and every candidate pair is checked in full-precision ℓ2. Hashing is O(N )

at fixed dimension and band settings, while verification cost scales with the candidate count. Missed candidates change removal but never invalidate the substitution bound on accepted merges. L2, error-bounded byte compression. We compress retained embeddings with cuSZp (Huang et al., 2023) under a relative codec error bound , separate from the substitution bound. Deduplication and byte compression multiply their storage reductions. Byte compression does not reduce the text in the context (§F.7). 2.3 THE ε ERROR -BOUNDED TEST 

LAM applies the redundancy test before each arriving record is prefilled. The test is the bound: an arrival is dropped only when some retained record lies within ℓ2 distance δ = √2 − 2t of it, the radius that equation 1 assigns to the merge threshold t. Every merge is therefore a δ-substitution (Definition 1), and the error it introduces is at most δ for every query rather than on average (The-orem 1); at cos ≥ 0.95 , δ = 0 .316 . The index contains only retained records, and decisions are never revised. The rule has three proper-ties. Prefix stability: replacing an arriving duplicate with a stub leaves all prefilled tokens in place. Later eviction can invalidate the prefix and is accounted for separately (Appendix E.2). Single en-coding: each chunk is embedded once. Encoding, which accounts for 99.989% of compaction cost, processes only the arriving tokens ∆ rather than the full context C. Measured bound: the max-imum substitution distance ˆδ is updated with each merge and reported for the turn; the maximum across turns gives the run’s bound. Each dropped chunk is replaced by a reference stub identifying its retained representative. The stub supports later lookup and inspection. We report both gross removal and net removal after the 0.69% input-token cost of stubs. 2.4 THE SUBSTITUTION BOUND 

Each merge deletes a record and retains a nearby representative. This can change retrieval scores and rankings (Appendix C). The following bound limits the decrease in the maximum score for any unit query. 

Definition 1 (δ-substitution) . (R, π ) is a δ-substitution of S if R ⊆ S, π : S → R with π|R = id ,and ∥x − π(x)∥2 ≤ δ for every x ∈ S.

Theorem 1 (Score deficit) . Let (R, π ) be a δ-substitution of S. Then for every unit query q, 0 ≤

max x∈S q · x − max z∈R q · z ≤ δ, and both constants are tight. 

The proof uses Cauchy–Schwarz (Appendix C). Both endpoints are attainable. The bound holds for all unit queries in the same embedding space without assumptions about their score distribution. It also implies a distribution-free rate–distortion bound; Appendix C relates admissible removal to the corpus’s covering number. 

Scope of the bound. The theorem does not guarantee unchanged rankings or task outcomes. The rank-invariance test in Appendix K.1 requires a sufficient score margin. On LoCoMo, the bound 

δ = 0 .3162 exceeds the median top-1 margin of 0.0185 by 17 ×; even at cos ≥ 0.99 , only 0.46% of queries pass the test. At the shipped threshold the bound therefore certifies score perturbation, not rank: it is not a retrieval guarantee, and we do not claim one. We therefore measure retrieval quality and evidence retention separately (§3). 

The substitution map. For each deleted x, π(x) is the lowest-indexed retained candidate within 

δ. With fixed embeddings and arrival order, this choice is independent of candidate traversal order. Each substitution therefore satisfies Theorem 1. Direct comparison with a retained representative is necessary because the distance relation is not transitive. At cos ≥ 0.95 , this rule removes 13.81% of observation tokens. 

The measured bound. Each run reports its maximum substitution distance alongside the config-ured bound: 0.268 versus 0.316 at cos ≥ 0.95 . The smaller value bounds the substitutions made in that run. 3.1 EXPERIMENTAL SETUP : BENCHMARKS AND BASELINES 

Benchmarks. The primary corpus contains 6,026 SWE-smith agent trajectories (361,802 records, 136.3M tokens); unless stated otherwise we use a fixed 600-trajectory subset with 15,169 obser-vation records, 27,986 chunks, and 9.07M observation tokens, encoding 512 -token windows with 

bge-base-en-v1.5 (D = 768 ). The determinism study uses 27,986 of those windows. LHTB adds 1,459 trajectories from 28 models and 131,357 steps, with roughly an order of magnitude more steps per trajectory (Appendix F.9); LoCoMo provides a conversational-memory control, in which we find only 2 near-duplicate pairs among 17,296,021. Main measurements use an NVIDIA GB10, serving experiments two nodes with four NVIDIA A100-SXM4-40GB on the serving node. 

Baselines. We report LAM in three cumulative configurations: L0 alone, L0 +L1, and the full pipeline. L0, the exact-hashing layer inherited from serving-side prefix caching (§2.2), is therefore an ablation of our own design rather than a competing system. Evidence retention is measured by searching for gold-patch lines in the residual text, which applies to deletion methods: observation masking, keeping the last k observations (Lindenbauer et al., 2025), and SemDeDup (Abbas et al., 2023). A relaxed variant also covers token dropping (§F.4), admitting LLMLingua-2 (Pan et al., 2024), the intake compressor of LightMem (Fang et al., 2026) and thus that component rather than the full system. Neither variant assesses paraphrases or latent representations, so MemAgent (Yu et al., 2026), Gisting (Mu et al., 2023), ICAE, and xRAG are compared on modeled cost and a Mem0-style deletion prompt separately. 3.2 MAIN RESULTS 

Removal and evidence. ECR@ τ is the maximum token removal a method achieves while retain-ing at least a fraction τ of the 6,276 gold-patch evidence lines across 598 trajectories; lines reachable only through stubs count as lost, SemDeDup is swept finely near perfect retention over five seeds, and L2 compresses stored embeddings rather than context tokens, so it moves neither axis. At the default threshold LAM removes 22.47% of observation tokens and retains 99.984% of evidence, losing 1 line, and with perfect retention it removes 21.49%. At τ = 0 .999 it removes 22.47% against 19.60% for SemDeDup and no qualifying masking setting (Figure 3, Table 17); SemDeDup removes more at lower floors, 22.84% versus 22.47% at 0.99 and 33.74% versus 31.99% at 0.95 .We selected the 0.999 floor after examining 35 settings from four families (Appendix F.5): there every admissible setting retains all evidence in at least 99.3% of trajectories, and among families with a measured conditional resolve-rate ceiling the largest decrease is 0.17 points, about a tenth of a standard error, against 5.5% of tasks losing evidence and 1.83 points at 0.99 . These are static evidence metrics, not task-success measurements. SemDeDup’s cross-trajectory search contributes to its higher removal: restricting it to each trajectory drops removal from 33.74% to 13.69% at 

cos t = 0 .95 . Masking removes 4.42% at τ = 0 .99 , 5.1 × less than LAM; within LAM, L0 alone removes 18.04% with no measured evidence loss and adding L1 raises removal to 22.47%. 

Scheduling dominates. With the compressor, corpus, and deletion set fixed, the cost model pre-dicts 71.4 × speedup at batch 1 and 91.6 × at batch 32 from removing records before prefill instead of deleting them from a prefilled context (Figure 1; Appendix E.2). The benefit comes from the schedule, not the rule: any prefix-preserving test receives it, L0 included. Algorithm ablation. Table 3 sweeps five merge thresholds over 600 trajectories against an un-compacted resolve rate of 75.83%: no substitution exceeds the configured bound, mean realized displacement being 0.350 of it at cos ≥ 0.99 and 0.559 at 0.95 , where recall@10, evidence reten-tion, and the resolve-rate ceiling stand at 0.9846, 99.984%, and 75.67% against 0.9518, 98.709%, and 70.33% at 0.90 ; we therefore ship cos ≥ 0.95 . Layer order matters there because the layers overlap: assuming independent removal overstates their joint rate by 4.0–11.7 points (Table 12), and running L0 first costs 2.45 points at cos ≥ 0.95 and 4.08 at 0.90 , since line deletion fragments the blocks L1 would match. Thus we run L1 first, leave the base layer last, and configure L2 for the bound rather than for peak ratio (Appendix F.7). Candidate generation keeps the test cheap at full pair recall, examining 31.6% of 283,980 within-trajectory pairs against 1.46% at 0.99 , a 3.2 ×

reduction; since a band match needs agreement in all r coordinates, looser thresholds need smaller bands, and r = 32 reaches only 0.314 recall at 0.95 . Furthermore the yield grows with the horizon: scoring at each input size T only the trajectories reaching it, removal rises from 0.80% at T = 1 K to 25.58% at T = 33 K against a whole-trajectory mean of 22.50%, so short contexts understate it. The rule is insensitive to arrival order — online and batch residuals are byte-identical on 600/600 trajec-tories — but not to the encoder, four of which differ in removal by 2.7 × (11.26% to 30.57%, against 13.79% by default) and recover 75.8%–90.9% of its deletion set at matched removal, so thresholds need per-encoder calibration (Appendix B.4). Search is not the bottleneck here: trajectories retain at most 112 chunks and search is 0.46% of test time, matching encoding cost only at 1.2 M synthetic survivors (Appendix F.11). 

System performance breakdown. The cost model is anchored on measured rather than advertised device numbers: 237 GB/s and 90.3 TFLOP/s on GB10 and 1,365 GB/s and 288.5 TFLOP/s on an A100-SXM4-40GB, or 0.87 and 0.88 of specification, so the advertised A100 bandwidth would overstate it by 14%. Bandwidth differs by 5.7 × between the devices but encoder throughput only by 1.4 ×, so encoder cost does not scale with memory bandwidth. Furthermore the re-prefill term the schedule avoids also holds on a server: serving Qwen2.5-7B-Instruct under vLLM on four NVIDIA A100-SXM4-40GB with prefix caching, cold prefill of 30,720 tokens takes 1.12 s against 0.09 s once 99.7% of the prompt is cached, a 12.1 × difference, and the effective rate peaks at 36.9 K tok/s near 4K tokens before falling to 27.3 K tok/s, from which quadratic and linear fits extrapolate to 64 s and 13 s at 360K, beyond the measured range. Placing the compactor on that serving node costs the server almost nothing: with CPU compaction co-located and the load generator on a second node, output throughput stays at 0.9999 × of baseline, median time to first token moves by 9.5 ms, and the compactor keeps up at 4.7 × the GPU’s output-token rate. The node has 64 cores, so past 16 compactor threads both sides lose. That contention invites isolating the compactor, but non-uniform memory access (NUMA) place-ment does not deliver it: confining compaction to the two of four NUMA domains furthest from the GPUs holds server throughput at 0.9966 × but drops compactor throughput to 0.540 of standalone, 8Preprint. Under review. costing it more bandwidth than it saves the server. As a result we ship unrestricted placement (Ap-pendix E.3). 

## 4 RELATED WORK 

Model-based compaction. Gisting learns soft tokens representing a prefix (Mu et al., 2023), ICAE encodes context into memory slots (Ge et al., 2024), xRAG projects a document embedding into a token (Cheng et al., 2024), and LLMLingua-2 selects text with a token-level classifier (Pan et al., 2024). All require model inference, none bounds substitution error, and reproducibility depends on weights and execution settings, whereas our rule records explicit deletions and representatives. 

Model-free deduplication. Min-hash (Broder, 1997), LSH (Indyk & Motwani, 1998), and SimHash (Charikar, 2002) underlie the banded hashing LAM uses for candidate generation. SemD-eDup clusters embeddings offline to remove near-duplicate training examples (Abbas et al., 2023), whereas LAM substitutes under a bound as records arrive: across five seeds only 50.9% of SemD-eDup’s deleted chunks are common to all runs, while LAM’s are identical (Appendix F.8). Error-bounded HPC compression (Huang et al., 2023) motivates such distortion control. 

Agent-memory systems. Mem0 issues LLM ADD /UPDATE /DELETE operations (Chhikara et al., 2025), observation masking retains the last k observations (Lindenbauer et al., 2025), LightMem filters intake and consolidates offline (Fang et al., 2026), MemAgent learns a rewriting policy over fixed-length memory (Yu et al., 2026), and Omri et al. (2026) characterize memory growth in stateful workloads — all without a substitution bound. 

Compaction off the critical path. Slipstream validates candidate compactions in the back-ground (Chen et al., 2026) and Parallel Context Compaction overlaps compaction with serving (Cim et al., 2026), both by LLM summarization. Rewriting a prefix, however, forces re-prefill of the af-fected entries and competes for the GPU, whereas LAM removes before prefill, so the prefix survives and the test runs on the CPU. 

Serving systems and prefix reuse. PagedAttention supports block-level KV reuse (Kwon et al., 2023), CachedAttention preserves caches across turns (Gao et al., 2024), Preble schedules for prefix sharing (Srivatsa et al., 2025), and SMetric balances agent sessions (Wang et al., 2026); LAM com-plements them by preserving prefixes during compaction, and adopts their exact-match hashing as its first layer. 

Performance models and rate–distortion. Vidur simulates inference latency (Agrawal et al., 2024) and KVServe models KV compression under service constraints (Liu et al., 2026); ours adds the error threshold, compaction cost, and re-prefill cost, while Kolmogorov ϵ-entropy (Kolmogorov & Tikhomirov, 1959; Posner & Rodemich, 1971) gives the covering and packing framework for our removal bounds. Prior work studies prompt compression in expectation (Nagle et al., 2024), decision-preserving (Zou et al., 2026) and KV-cache rate–distortion (Colaco & Lahjouji, 2026); our worst-case bound implies one for every source on the record set (Corollary 2), complementing eval-uations of task success (Zheng et al., 2025; Kummer et al., 2026), cost (Johnson & Lee, 2026), and retrieval (Chai et al., 2026). 

Scope of comparison. LAM’s scheduling benefit depends on the cost of rebuilding invalidated cache entries and its removal benefit on observation-stream near-duplicates, so cheap cache repair, low redundancy, or poor retention would limit it; we evaluate each separately.

Consequences for the cost model. At the selected setting the CPU processes context at roughly 4.7 × the GPU’s output-token rate, so this workload overlaps with serving at little throughput cost, and overlap reduces what compaction contributes to elapsed time below what the sequential model charges. Deriving the floor. Pooled retention hides trajectory-level loss: SemDeDup at cos 0 .995 retains 99.092% of lines, yet 5.5% of trajectories lose at least one. Across 35 settings from four families, raising the floor from 0.990 to 0.999 cuts the largest admissible fraction of affected trajectories from 5.5% to 0.7% and the largest RSC decrease from 1.83 to 0.17 percentage points (Table 16); against an uncompacted resolve rate of 75.83% on 455 of 600 trajectories (binomial standard error 1.75 points), those are about one standard error and one-tenth of one. We therefore use τ = 0 .999 ,chosen after examining the data. The transition lies between 99.889%, where the least intact setting (LAM at t = 0 .93 ) retains all evidence in 98.997% of trajectories, and 99.917%, the loosest tested floor meeting the 99% requirement. M.3 PER -ARRIVAL REMOVAL AND CONTEXT GROWTH 

The measured removal rate r is the fraction of arriving tokens duplicating earlier content. A token can be removed once, so context grows as C ← C + ∆(1 − r) per arrival; applying r to the full context on every event would count the same duplicates again. Testing first imposes no steady-state size on its own, so a hard budget also needs eviction (Table 27). The two accountings diverge where it matters. In the growth regime LAM supports 1,727 turns before the KV capacity limit against 1,615 for L0 alone, a modeled 1.07 × speedup. Under a hard budget every method eventually reaches Bctx , so additional removal gives 1.00 × latency benefit; it buys delayed eviction of nonredundant content instead, a quality effect the model does not capture. 35
