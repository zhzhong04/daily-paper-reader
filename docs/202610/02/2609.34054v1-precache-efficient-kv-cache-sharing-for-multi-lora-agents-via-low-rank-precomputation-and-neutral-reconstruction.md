## 摘要
多 LoRA 智能体系统通过共享一个公共主干模型来实现高效的角色特化。然而，每个智能体都会重复处理不断增长的共享轨迹，并构建自己的 KV 缓存，从而在长时程任务中引入大量内存与计算冗余。现有的 KV 缓存共享方法减少了这种重复预填充，但它们要么需要额外训练或架构约束，要么仍保留大量模型计算。此外，直接复用缓存会使当前智能体依赖于前一个智能体的适配器所生成的缓存状态，从而削弱其自身 LoRA 所编码的角色特定行为。我们提出 PReCache，一种免训练的 KV 缓存共享框架，包含两种设计，即 PreLRShared 和 ReBaseShared，它们共享使用预训练权重计算的基础缓存，并预计算紧凑的、智能体特定的低秩 (LR) 缓存。为消除重复预填充，PreLRShared 在共享上下文首次被处理时为每个智能体预计算其 LR 缓存，使当前智能体能够使用自身的 LR 缓存，而无需重新处理先前智能体已处理的上下文。为提升共享准确性，ReBaseShared 从无适配器的隐藏状态中重建共享基础缓存，减少由前一智能体经适配的表示所导致的剩余误差。为最小化其重建开销，我们提出两种分别面向单流推理与并发服务的推理方案，分别在每个智能体轮次结束后或与其执行同时进行相同的重建。在多个模型和智能体基准上，与不进行 KV 缓存共享的推理相比，PreLRShared 实现了最高 3.1 倍的 TTFT 加速，并将每请求吞吐量提升 2.3 倍。在评估的缓存共享方法中，ReBaseShared 整体上最好地保持了准确率，相对于不进行缓存共享的推理，平均仅下降 1.1 个点。

## Abstract
Multi-LoRA agent systems enable efficient role specialization by sharing a common backbone model. However, each agent repeatedly processes the growing shared trajectory and constructs its own KV cache, introducing substantial memory and computation redundancy in long-horizon tasks. Existing KV cache sharing methods reduce this repeated prefill, but they either require additional training or architectural constraints or retain substantial model computation. Moreover, direct cache reuse causes the current agent to rely on cache states generated by the previous agent's adapter, weakening the role-specific behavior encoded by its own LoRA. We present PReCache, a training-free KV cache sharing framework with two designs, namely PreLRShared and ReBaseShared, that share the base cache computed using the pretrained weights and precompute a compact agent-specific low-rank (LR) cache. To remove repeated prefill, PreLRShared precomputes each agent's LR cache when the shared context is first processed, allowing the current agent to use its own LR cache without reprocessing context processed by previous agents. To improve sharing accuracy, ReBaseShared reconstructs the shared base cache from adapter-free hidden states, reducing the remaining error caused by the previous agent's adapted representation. To minimize its reconstruction cost, we propose two inference schemes tailored to single-stream inference and concurrent serving, performing the same reconstruction after each agent's turn or alongside its execution, respectively. Across multiple models and agent benchmarks, PreLRShared achieves up to a 3.1x TTFT speedup and a 2.3x improvement in per-request throughput over inference without KV cache sharing. ReBaseShared best preserves accuracy overall among the evaluated cache-sharing methods, with an average drop of only 1.1 points relative to inference without cache sharing.

# PReCache 论文总结

## 1. 核心问题与整体含义

- **背景**：多 LoRA 智能体系统通过共享一个预训练主干模型（backbone）来实现角色特化（如规划、行动、反思智能体），每个角色仅附加一个小型 LoRA 适配器。这种方式显著降低了模型内存占用，适合资源受限场景。
- **核心问题**：
  - 尽管共享主干，每个智能体仍需独立处理不断增长的共享轨迹（用户请求、检索信息、工具观察、前序智能体输出），重复进行 prefill 并构建各自的 KV 缓存，导致长时程任务中**内存与计算冗余严重**。
  - 直接复用前一智能体的 KV 缓存（FullShared）会因适配器权重不同而引入**精度显著下降**，削弱当前智能体自身 LoRA 编码的角色特定行为。
- **现有方法的不足**：
  - 需要额外训练、校准模型对或特定架构约束（如 Cache-to-Cache、Icarus、PrefillShare 等）。
  - 选择性重计算（DroidSpeak、CacheBlend、RelayCaching）在异构 LoRA 适配器下精度恢复有限，且重计算比例提高会削弱计算与内存节省。
  - LRAgent 的 BaseShared 虽保持精度，但当前智能体仍需对累积上下文做全长度主干处理，重复 prefill 未消除；BaseLRShared 要求共享 LoRA 下投影，不兼容现有适配器。
- **整体含义**：PReCache 提出一种**免训练**的 KV 缓存共享框架，在不重新训练、不限制现有 LoRA 适配器的前提下，同时降低 KV 缓存内存与重复 prefill 计算，并保持角色特定行为。

## 2. 方法论

### 核心思想
- 将适配后的投影输出分解为：
  - **基础贡献**：\( X_{i,\text{adpt}} W_0 \)（共享 base cache）
  - **适配器贡献**：\( (X_{i,\text{adpt}} A_i) B_i \)（紧凑的智能体专属低秩 LR cache，秩 \( r \ll d_{\text{in}}, d_{\text{out}} \)）
- 共享 base cache，同时为每个智能体保留独立的 LR cache，从而在降低内存的同时保留角色特定行为。
- 关键创新：**在共享上下文首次被处理时，就为所有智能体预计算其 LR cache**，而非等到各智能体轮次时重新处理累积轨迹。

### 两种设计

**PreLRShared（低秩预计算）**
- 当智能体 \( i \) 处理上下文段 \( L_P \) 时，对每个智能体 \( k = 1,\dots,N \) 同时应用其下投影 \( A_k \)，构造 \( X_{i,\text{adpt}} A_k \in \mathbb{R}^{L_P \times r} \)。
- 后续智能体 \( j \) 直接复用共享 base cache 和自身的预计算 LR cache，仅对**新增上下文** \( L_C \) 执行适配后的主干计算。
- 消除了对累积轨迹的重复全长度主干处理，将后续开销降为轻量级 rank-\( r \) 下投影。

**ReBaseShared（中性重建）**
- 动机：共享 base cache 仍由前一智能体的适配后隐藏状态构造，存在前序智能体依赖。
- 方法：用**禁用 LoRA 适配器**的隐藏状态 \( X_{\text{neut}} \) 构造“中性 base cache” \( X_{\text{neut}} W_0 \)。
- 理论条件（附录 A.1）：定义 \( \rho = \|\Delta_i\|_2 / \|\Delta_j\|_2 \)，\( \cos\theta = \langle \Delta_i, \Delta_j \rangle / (\|\Delta_i\|_2 \|\Delta_j\|_2) \)，则中性 base cache 相对误差更低当且仅当：
  \[
  \rho \geq 2\cos\theta \quad \text{（等价于 } \Gamma_{\text{err}} > 1 \text{）}
  \]
- 实测（附录 A.2）：在两个主干、三个智能体转换的每一层上，\( \Gamma_{\text{err}} \) 均大于 1，支持中性重建的有效性。
- ReBaseShared 保留 LR cache 预计算，且其他智能体的 LR cache 也由同一无适配器隐藏状态构造。

### 两种推理调度方案
- **LP（Lazy Prefill，惰性预填充）**：智能体轮次内只执行适配路径；解码结束后，以禁用适配器方式对新增上下文 \( L_C \) 做一次连续 prefill，重建中性 base cache。适合**单流边缘推理**。
- **DB（Double Batching，双重批处理）**：适配路径与无适配器路径在 prefill 与 decoding 阶段通过双批处理同时调度，共享同一 token 序列与位置，维护独立 KV cache 视图。适合**并发服务器端服务**，避免单独重建 prefill 造成排队延迟。
- 两种调度产生逻辑等价的缓存状态，仅重建时机不同。

## 6. 主要结论与发现

- **PreLRShared**：
  - 相比 NonShared，单流推理 TTFT 最高加速 **3.1×**，每请求吞吐量最高提升 **2.3×**。
  - 在 66.4k token 时 TTFT 仍接近 FullShared 的 17% 以内。
- **ReBaseShared**：
  - 在评估的缓存共享方法中**整体保精度最好**，相对 NonShared 平均仅下降 **1.1 个百分点**，与 BaseShared 相当。
  - 消除了 BaseShared 保留的大部分重复 prefill 计算。
- **内存效率**：
  - 在 66.4k token 时，两种方法峰值内存均在 FullShared 的 **2% 以内**，比选择性重计算方法低 **17–23%**。
  - 智能体数从 N=4 增至 N=8 时，峰值内存仅增约 1–2%，而选择性重计算增 16–20%，NonShared 增 26%。
- **调度方案**：
  - LP 适合单流边缘推理（TTFT 更低、吞吐量更高）。
  - DB 适合并发服务（高负载下 TTFT 更低、吞吐量更高）。
- **理论验证**：中性 base cache 在每一层上相对误差均低于前序智能体适配后的 base cache（\( \Gamma_{\text{err}} > 1 \)）。

## 7. 优点

- **免训练**：无需额外训练、校准模型对或特定架构约束，直接适用于现有不同下投影权重的 LoRA 适配器。
- **同时解决内存与计算冗余**：既降低 KV 缓存内存（紧凑 LR cache），又消除重复 prefill（首次处理时预计算）。
- **保留角色特定行为**：通过保留智能体专属 LR cache，避免直接复用导致的角色行为弱化。
- **理论支撑**：附录 A.1 给出中性重建降低相对误差的严格条件，A.2 实证验证。
- **场景适配**：针对单流与并发两种推理环境分别设计 LP 与 DB 调度，实用性强。
- **实验全面**：覆盖准确率、TTFT、吞吐量、内存、智能体数量、LoRA rank 与投影配置，并报告 20 次运行标准差。
- **公平对比**：受控轨迹隔离各方法计算开销，确保效率比较的公平性。

## 8. 不足与局限

- **模型与数据集覆盖有限**：仅在两个 8B 级模型（LLaMA-3.1-8B、Ministral-8B）和两个 QA 基准（HotpotQA、ScienceQA）上评估，未验证更大规模模型或其他任务域（如代码、多模态）。
- **BaseLRShared 未对比**：因其需共享下投影训练，被排除在实验外，导致无法全面比较与架构约束类方法的优劣。
- **训练算力未披露**：论文未说明 LoRA 训练所用 GPU 数量、训练时长等，算力可复现性不足。
- **ReBaseShared LP 吞吐量较低**：因额外的无适配器重建计算，单流吞吐量低于 PreLRShared，需在精度与吞吐间权衡。
- **QKVO 配置效率下降**：当 key 投影也被适配时，key-side 适配贡献需在 RoPE 前从 rank-\( r \) 扩展，Flash-LoRA-Attention 的关联重排不直接适用，额外增加 LR cache 计算。
- **偏差风险**：准确率评估依赖外部搜索 API（Serper）与 Wikipedia，外部搜索结果波动可能影响轨迹与准确率；受控效率实验使用随机 token id，可能与真实负载存在差异。
- **应用限制**：方法针对多 LoRA 智能体系统，需预先为每个角色训练 LoRA 适配器；对于非 LoRA 或全参数微调的多模型协作场景不直接适用。
