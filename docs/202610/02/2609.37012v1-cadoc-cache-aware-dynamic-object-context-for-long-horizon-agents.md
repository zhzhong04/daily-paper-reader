## 摘要
对于长时程智能体而言，上下文是瓶颈：历史记录会随每次请求重新发送，窗口限制了任务长度，且随着历史增长，推理能力会下降。用紧凑的检索卡片（Cards）替换结构化对象可缩短提示词，并保持原始内容可精确检索，但编辑历史会破坏前缀缓存复用，而先前的可恢复方法通过预测未来复用或预设时间间隔来决定编辑时机。我们提出 CADOC（缓存感知动态对象上下文），一种在线算法，它用紧凑的 Cards 替换结构化对象，同时保留对其原始内容的精确、按需检索。CADOC 通过权衡累积等待成本与共享缓存重建成本，以批量方式调度替换。其调度规则源自经济订货量（EOQ）权衡，在平稳性假设下可得到最优整数批量。在评估中，CADOC 在比较配置中始终实现最低的总输入成本，平均将输入成本降低约 40%，同时使任务性能接近完整上下文。因此，CADOC 为可压缩上下文管理提供了一种由成本推导的方法，表明高效压缩不仅取决于缩短提示词，还取决于调度编辑以保持缓存复用。

## Abstract
For a long-horizon agent, context is the bottleneck: the history is resent with every request, the window caps task length, and reasoning degrades as the history grows. Replacing structured objects with compact retrieval Cards shortens the prompt and keeps the exact originals retrievable, but editing the history can break prefix-cache reuse, and prior recoverable methods time their edits by forecasts of future reuse or by preset intervals. We propose CADOC (Cache-Aware Dynamic Object Context), an online algorithm that replaces structured objects with compact Cards while preserving exact, on-demand retrieval of their original contents. CADOC schedules replacements in batches by balancing accumulated waiting cost against shared cache-reconstruction cost. Its scheduling rule follows from an economic order quantity trade-off, recovers the optimal integer batch under stationary assumptions. Across evaluation, CADOC consistently achieves the lowest aggregate input cost among the compared configurations, which reduces input cost by approximately 40\% on average while maintaining task performance close to full context. CADOC thus provides a cost-derived approach to compressible context management, demonstrating that efficient compression depends not only on shortening prompts but also on scheduling edits to preserve cache reuse.

- **压缩的两条路线**：
  - **有损方法**（token 剪枝、学习式智能体压缩、子轨迹折叠等）会丢弃后续步骤可能需要的细节。

  - **Token-Pilot**（Xu et al., 2026）：每隔固定、经验选择的轮数运行 LLM 估计器，驱逐其判定为过期的片段。

## 2. 方法论

### 2.1 核心思想

- **可逆的对象外置而非有损压缩**：Working Memory 保存原始字节，Card 在提示词中占位；注册与替换保持对象在交互历史中的原始位置；检索以新的工具结果形式返回其不可变版本。
- **对象与不可变版本**：通过运行时元数据和解析规则识别结构化片段（文件内容、代码、工具结果、日志、表格、生成产物等）；每个存储对象具有不可变版本，历史 Card 即使文件后续被修改也能恢复当时观察到的内容。
- **Card 与精确检索**：Card 记录对象身份、版本、来源、结构元数据，**不含 LLM 生成的摘要**；模型通过普通函数工具 `retrieve_object`（参数为 `object_ref` 与 `reason`）取回精确字节。
- **热尾部与待处理序列**：保留一个受最大块数 `h` 与 token 预算 `Thot` 约束的近期原始后缀；对象离开该保护后缀后进入待处理序列，保持原始状态直到批量提交。

### 2.2 成本模型与 EOQ 对应

- **输入成本定义**（归一化未缓存 token 成本为 1，`wr` 为缓存读取权重）：
  - `C = Σ_t (Nt + wr·Rt)`，主实验取 `wr = 0.1`。
- **首次请求成本差**（对可复用前缀内一次替换，`I` 为从首次编辑到缓存前沿的缓存 token 数，`G` 为移除 token 数）：
  - `ΔCfirst = (1 − wr)(I − G) + F − wr·G`，即"重建溢价"减"缩短收益"。
- **平稳块模型**：每请求周期产生一个固定长度 `x` 的块，含一个可替换对象，替换缩短 `g ∈ (0, x)`；热尾部恰好 `h ≥ 1` 个块；每次提交替换全部 `b` 个待处理块。
- **等待损失**：对象在可编辑后多等待 `b−1, b−2, …, 0` 个请求，`Wb = r·b(b−1)/2`，其中 `r = wr·g`。
- **平均每对象额外成本**：
  - `ℓh(b) = K + Qh/b + r(b−1)/2`
  - 其中 `K = f + (1−wr)(x−g)`（每对象常量项），`Qh = F0 + (1−wr)(h−1)x`（共享重建成本，`F(b) = F0 + b·f`）。
  - 这正是 EOQ 中"固定设置成本 vs. 持有成本"的权衡（Harris, 1913; Erlenkotter, 1990）。

### 2.3 平稳最优与在线规则

- **命题 1（平稳最优批量）**：
  - 连续最优解 `b*cont = max(1, sqrt(2Qh/r))`。
  - 整数最优充要条件：`r·b(b−1)/2 ≤ Qh ≤ r·b(b+1)/2`。
  - 等价形式 `b† = max(1, ⌈(sqrt(1+8Qh/r) − 1)/2⌉)`（取相邻并列中的较小者）。
- **首次跨越规则**：由于 `Wb + wr·Gb = Wb+1`，条件可写为 `Wb ≤ Qh ≤ Wb + wr·Gb`；从空待处理序列出发，取第一个满足 `Wb + wr·Gb ≥ Qh` 的 `b` 即为最优整数批量。
- **在线化（动态历史）**：在边界 `t` 用当前量替换平稳量：
  - `Gt = Lkeep_t − Lcommit_t`（保留 vs 替换全部待处理内容后的下一提示长度差）。
  - `ΔWt = wr·Gt`（多携带一轮的等待损失增量，新可编辑内容以零损失进入）。
  - `Qt = F0,t + (1−wr)·Hshared_t`（`Hshared_t` 为最新待处理块之后、可复用缓存前沿之前的已缓存 token）。
  - **提交条件**：`Pt` 非空且 `Wt + wr·Gt ≥ Qt`。
  - 一旦触发即**整批提交全部待处理替换**，因为最早的待处理编辑已决定重建起点，同一请求内提交后续替换不增加额外缓存破坏。
- **实现细节**：`Gt` 由粗略的 keep/commit 提示长度估计，`Qt` 由提示与缓存估计，`Wt` 由持久化的 per-delta 等待账本维护；提交在模型成功响应确认后清除；硬容量上限可强制提前提交。
- **理论保证**：附录 A.4 对等待–设置目标证明**有限时域竞争比** `J(ALG) ≤ (2Qmax/Qmin)·J(OPT)`，当 `Qt` 为正常数时为 **2-竞争**。
