## 摘要
多智能体系统将大型上下文分布到多个通过通信协作解决任务的智能体上。文本消息紧凑，但需要解码，并且可能遗漏接收智能体所需的证据。最近的潜在通信则改为传输 KV 缓存。这避免了文本生成，并能提高准确率并降低延迟。然而，完整的 KV 缓存会随单个智能体处理的上下文以及协同工作的智能体数量线性增长。这会带来内存和上下文成本，往往远超可用的 GPU 资源和上下文窗口大小。我们的关键观察是，智能体只需发送接收智能体完成其本地任务所需的内容——我们称之为接收方条件化通信。接收方智能体会向发送方传递其信息需求的小型描述，用于过滤和压缩发送方智能体的 KV 缓存。CacheBack 是接收方条件化的一种简单、鲁棒、免训练的实例，基于发送方的注意力权重。在 FanOutQA 上，使用 Qwen 3 的 CacheBack 去除了智能体原本会接收的状态的 75%，相比文本通信，准确率提高 14.7 个百分点，任务完成延迟中位数降低 3.2 倍。我们在涵盖稠密 Transformer、Mamba-注意力混合模型和滑动窗口注意力的模型系列上展示了类似的改进。

## Abstract
Multi-agent systems distribute large contexts across agents that communicate to solve a task. Text messages are compact but require decoding and may omit evidence the receiving agent needs. Recent latent communication instead transfers KV caches. This avoids text generation and can improve accuracy and latency. However, a full KV cache grows linearly with both the context an individual agent processes, and the number of agents that coordinate together. This raises memory and context costs, often far exceeding available GPU resources and context window sizes. Our key observation is that agents need only send what the receiving agent requires for its local task -- which we call receiver-conditioned communication. The receiver agent passes the sender a small description of its information needs, which serves to filter and compress the sender agent's KV cache. CacheBack is a simple, robust, training-free instance of receiver conditioning based on the sender's attention weights. On FanOutQA, CacheBack with Qwen 3 removes 75% of the state the agent would otherwise receive, improving accuracy by 14.7 percentage points and reducing median task-completion latency by 3.2x relative to text communication. We show comparable improvements across model families that span dense Transformers, Mamba-attention hybrids, and sliding-window attention.

# 论文总结：Receiver-Conditioned Latent Communication（CacheBack）

## 1. 核心问题与研究动机

- **背景**：多智能体系统（DAG 拓扑，含 fan-in 并行与 sequential chain 串行）通过智能体间通信分摊长上下文。文本消息紧凑但存在两个问题：(1) 每个 token 都需自回归解码，成本高（FanOutQA 中 Qwen 3 8B 生成三条消息的中位耗时 73.2 秒）；(2) 离散 token 表达力弱于连续隐表示，可能遗漏接收方所需证据。
- **已有方案及其缺陷**：近期潜在通信（如 LatentMAS）直接传输完整 KV cache，省去文本生成，但会带来"上下文再膨胀"（context re-expansion）：
  - 接收方上下文长度变为 `H_R = H_R + Σ T_i`（T_i 为发送方全部序列位置数），随子智能体数量和文档规模线性增长。
  - 传输量、接收方 KV 显存、注意力负担同步线性增长。作者在 FanOutQA + Qwen 3 8B 设置下发现，全量缓存传输**在每个任务上**都导致接收方剩余上下文不足以完成生成。
- **关键观察**：智能体只需发送**接收方本地任务真正需要**的信息。据此提出"接收方条件化通信"（receiver-conditioned communication）——接收方把信息需求（query q）告知发送方，用于筛选与压缩发送方 KV cache。
- **定位**：已有工作关注潜在状态"如何表示与传输"（embedding / hidden state / KV / 层选择），本文关注**消息应包含哪些信息**，并论证该选择应由接收方需求决定。

## 2. 方法论

### 2.1 核心思想与三要素

接收方条件化通信包含三部分：
1. **接收方 query q**：描述接收方需要什么信息。实验中 q 即任务问题，在发送方完成原始 prefill 之后追加，仅用于对发送方位置打分（不改变发送方原任务状态），因此同一份已完成的发送方状态可服务不同接收方的不同 query。
2. **选择**：发送方用 q 从自身序列中挑选 ≤ B_i 个位置。位置分为输入 token 位置（有 token ID）与 latent step 位置（连续向量，无 token ID）。
3. **表示**：被选位置以连续行（continuous-row encoding）或 token ID 形式传输。

### 2.2 选择器：从均值注意力到 CacheBack

- **基础（mean query attention）**：改造 SnapKV——把接收方 query 放在末尾位置，令其只对已有 KV 计算注意力；对 query token 与 query head 求平均，跨层求和，再做宽度 7 的局部最大池化（Pool7），得到每个发送方位置一个分数 `Q_t`。
- **均值化的缺陷**：若某位置仅被 query 的一小部分 token 强烈关注，平均会稀释信号（文中图 3 的 A/B 反例）。
- **CacheBack 的修正**：`S_CB,t = Q_t · C_t²`，其中 `C_t` 比较"先池化后平均"与"先平均后池化"的注意力（`C_{p,t}`，p>1）。在 p=2 且无池化时，该修正退化为 `1 + 归一化方差`——即位置在某部分 query token 上注意力越集中，得分被放大越多。
- 超参 p=α=2（α 控制修正强度，mean query attention 相当于 α=0），在 13 个 FanOutQA 开发问题上选定后固定不变，**全程免训练、无学习模块**。

### 2.3 预算与位置选择规则

- FanOutQA：`B_i = ⌈T_i / r⌉`（r 为压缩比）。
- 串行链：相对预算 `B_i = T_old + ⌈T_new / r⌉`（继承位置也计入预算，可与新位置一起重排，继承位置可被丢弃）；固定预算 `B_i = min(B_max, T_old + T_new)`。
- 统一规则：始终保留第 1 个位置与全部 40 个当前 latent 位置（共 41 个，计入预算），其余按宽度 16 的 span 平均分排序填充；结果按源顺序返回。

### 2.4 传输表示与上下文约束

- 连续行编码对 Qwen3-8B 约比完整 KV 小 18×；token-ID 编码再小 75×（300 Mbit/s Wi-Fi 下 664→9 ms），但在 NVLink（450 GB/s，55→0.7 μs）下可忽略，故全部实验采用连续行。
- 上下文约束：`H_R + Σ B_i + O_R ≤ L_R`，即必须为接收方 prompt 与输出预留空间（式 2）。
- 接收方对选中行做**重新 prefill**，从而在新位置应用位置编码，避免发送方–接收方位置错配问题（该问题本身未评估）。

## 3. 实验设计

- **数据集 / 场景**：
  - **FanOutQA**（并行 fan-in）：3 个发送方各读不同 Wikipedia 页面，1 个接收方汇总作答。每个发送方 ≥40K token，总计 ≥120K；50 道题，从官方 dev split 按 SHA-256 哈希排序取前 50（非手工挑选），并剔除 1 道因截断丢失参考答案的题。指标为 **strict accuracy**（需命中全部参考答案组）。
  - **LongBench v2**（串行链）：将 100K–246K token 文档均分四份，4 个智能体依次阅读并传递消息，最终接收方作答；50 道题。因文本发送方频繁触顶截断，最终面板**仅保留 Easy 子集**（作为降低截断的多项改动之一）。
- **对比方法**：
  - 文本通道：smaller / medium / **same-size text** 三种发送方规模（与 CacheBack 使用同一接收方 query 生成报告，保证对比的是"消息如何构造"而非信息需求）。
  - 潜在通道：**Full rows** 全位置对照（仅 Ministral、Gemma 的 FanOutQA 因上下文可容纳而可行）。
  - 选择器对照（诊断阶段）：StreamingLLM、H₂O、ChunkKV、KVzip（接收方无关）vs. mean query attention vs. CacheBack。
- **模型**：Qwen 3（1.7B/4B/8B/32B 诊断，8B 端到端）、Ministral 3（3B/8B/14B）、Gemma 4（E2B/E4B/12B）、Nemotron Nano 2（9B/12B）与 Nano 3（4B）。FanOutQA 覆盖全部四族，LongBench v2 覆盖 Qwen 与 Nemotron，横跨稠密 Transformer、Mamba+注意力混合、全局+滑窗注意力三种架构。
