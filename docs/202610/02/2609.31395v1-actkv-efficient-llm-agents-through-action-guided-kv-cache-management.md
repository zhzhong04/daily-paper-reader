## 摘要
智能体式 LLM 推理在迭代的观察-推理-动作循环中会累积较长的 KV 缓存，带来显著的内存开销并限制服务吞吐量。现有压缩方法侧重整体输出质量，忽视了动作在推动任务进展中的不对称重要性。我们的核心思想是建立一种压缩准则，根据 KV 条目对动作生成的贡献来评估其价值，并优先保证动作质量。然而，迭代执行、动态内存需求以及分散的动作关键条目，给驱逐策略、预算分配和分页内存集成带来了挑战。为此，我们提出 ActKV，这是首个专为智能体式 LLM 推理设计的 KV 缓存压缩框架。(i) 面向动作的 KV 缓存驱逐利用稳定的动作访问模式，保留对未来动作至关重要的条目，从而在压缩下支持可靠的任务进展。(ii) 置信度驱动的自适应预算分配利用 LLM 的内在置信度，使预算适应不断变化的动作关键内存需求。(iii) 页感知的压缩管理将压缩标准化为三种原语，并配以定制化内核，从而实现实际吞吐量收益。在长轨迹任务上，ActKV 在仅使用 FullKV 峰值 KV 缓存内存的 25.98% 时，平均保留了 FullKV 准确率的 98.53%。其 token 吞吐量和任务吞吐量还分别达到 FullKV 的 3.97 倍和 3.58 倍，实现了最先进的性能。

## Abstract
Agentic LLM inference accumulates long KV caches across iterative observation-reasoning-action loops, imposing substantial memory overhead and limiting serving throughput. Existing compression methods emphasize overall output quality, overlooking the asymmetric importance of actions in driving task progress. Our key idea is to establish a compression criterion that values KV entries by their contribution to action generation and prioritizes action quality. However, iterative execution, dynamic memory demands, and scattered action-critical entries pose challenges to eviction policies, budget allocation, and paged memory integration. To this end, we propose ActKV, the first KV cache compression framework tailored for agentic LLM inference. (i) Action-oriented KV cache eviction exploits stable action access patterns to retain entries critical to future actions, supporting reliable task progress under compression. (ii) Confidence-driven adaptive budget allocation uses LLM's intrinsic confidence to adapt the budget to evolving action-critical memory demands. (iii) Page-aware compression management standardizes compression into three primitives with customized kernels, realizing practical throughput gains. On long-trace tasks, ActKV retains an average of 98.53% of FullKV's accuracy with only 25.98% of its peak KV cache memory. It also achieves 3.97 times and 3.58 times FullKV's token and task throughput, delivering state-of-the-art performance.

# ActKV 论文中文总结

## 1. 核心问题与研究背景

- **背景**：智能体（Agent）将 LLM 从被动问答转变为任务求解系统，其核心执行范式是 ReAct 式的迭代「观察—推理—动作」（Observation-Reasoning-Action, ORA）循环，代表系统如 OpenClaw、Claude Code、Codex。
- **核心问题**：Agentic LLM 推理在每轮循环中不断累积 observation / reasoning / action token 的 KV 缓存，造成巨大显存开销并限制服务并发与吞吐。例如 Qwen3-30B 执行 WebShop 任务需 25 轮、约 35K token，消耗 3.20 GB KV 缓存，其中 observation 与 reasoning 条目占比超过 99%。
- **现有方法的失配**：主流 KV 压缩方法（StreamingLLM、H2O、SnapKV、R-KV 等）面向常规连续文本生成，假设 token 重要性均匀，通过近似「近未来注意力」贪婪驱逐低分条目。但在 agentic 推理中 token 重要性是**高度不对称**的：
  - observation / reasoning token 主要支撑内部状态理解与推理，对用户往往隐藏或无用；
  - 只有 **action token** 真正影响环境、决定任务进展。
- **三个具体挑战**：
  - **保留什么（What to keep）**：迭代执行需要稳定准则识别动作关键 KV 条目，当前重要性未必预示未来效用。
  - **保留多少（How much to keep）**：动作关键条目的内存需求随任务类型、难度、交互轮数动态变化，离线静态预算不适用。
  - **如何高效压缩（How to compress efficiently）**：动作关键条目分散在分页内存的多个 block 中，token 级驱逐与 block 级分配不匹配，现有方案要么引入额外拷贝开销（R-KV），要么依赖策略专用改造（ThinKV）。
- **整体含义**：论文主张把压缩准则从「整体输出质量」转向「动作质量与任务结果」，是首个面向 agentic LLM 推理的 KV 缓存压缩框架。

## 2. 方法论

### 2.1 核心思想
- 建立以 **KV 条目对动作生成的贡献** 为价值标准的压缩准则，优先保证动作质量，从而对齐 agentic 推理的「结果驱动」本质。

### 2.2 模块一：动作导向的 KV 缓存驱逐
- **关键观察**（Fig. 2、Fig. 3）：
  - 动作关键 KV 条目与服务 observation / reasoning 的条目**不同**：observation 关注局部扩展前缀，reasoning 关注全局弥散历史，action 聚焦少量任务关键历史。
  - 动作关键 KV 条目在不同迭代间**稳定**，源于动作在语义（动作类型有限）、上下文（参数反复引用共享任务上下文）、结构（标准化输出模板）上的相似性。
- **动作访问向量（AAV）**：对每个 KV 条目记录其在各动作区域是否贡献（注意力分数进入 top-p 90% 则为 1），丢弃全零 AAV，并分类为：
  - cold-start（前期为 0，后期重要，占比极小）；
  - continuous（连续贡献，最常见，但单次注意力贡献较低）；
  - intermittent（间断贡献，单次注意力贡献高）。
- **Attention-aware LRFU 策略**：以「最近 + 频繁」折中替代静态重要性，keep score 更新公式为
  - `KS_t(i) = λ · KS_{t-1}(i) + AttnScore_t(i) · {hit at t}`，其中 λ=0.5 为衰减因子；
  - λ=0 偏向近期驱逐会误删暂时不活跃但未来重要的 intermittent 条目；λ=1 偏向频率会保留过时 continuous 条目；0<λ<1 可兼顾两者。
- **算法流程（Algorithm 1）**：每轮 ORA 结束后触发 → 由动作区域 query 计算注意力分数 → 为新条目初始化 keep score → 生成 hit/miss 掩码 → 更新 keep score → 取 TopK（k=预算 B）生成 KeepMask → 分页压缩。

### 2.3 模块二：置信度驱动的自适应预算分配
- **关键观察**（Fig. 4、Fig. 7）：预算越紧，动作关键信息越不完整，模型倾向于用「wait」「I guess」「let me check」等低置信标记延长推理以恢复缺失上下文，表现为**置信度下降**；因此置信度可作为预算充足性的在线信号。
- **三层置信度监控**：
  - **Token 级**：`T_i = -(1/k) Σ_{j=1..k} log P_i(j)`，取 top-k（k=20）预测概率的负平均对数概率。
  - **Trace 级**：对 token 置信度序列做窗口 w=64、步长 s=8 的**最小池化**，再保留底部 b%=10% 的值，突出局部置信度退化片段。
  - **趋势检测**：对 trace 级置信度做一阶最小二乘拟合，取斜率 α；α<0 表示置信度下降、预算不足。
- **预算调整（Algorithm 2）**：仅在触发压缩时判断，若 α<0 则 `B' = min(B · scale_up, B_upper)`，scale_up=1.75，B_upper=30K；初始预算 512，置信度恢复时保持当前预算不缩减，避免再次信息损失。监控与 LLM 推理并行，开销可忽略。

### 2.4 模块三：页感知的压缩管理
- **统一三原语**：`AttnScore ← CalAttn(target_q, KCache)`、`KeepMask ← Eviction(AttnScore, Budget)`、`KVCache ← Compaction(KVCache, KeepMask)`，其中驱逐策略与缓存布局无关，系统瓶颈在注意力计算与缓存压缩。
- **恢复式注意力计算内核（Algorithm 3）**：
  - 利用分页注意力后端产生的 softmax log-sum-exp（LSE）恢复注意力分数：`A_{i,j} = exp(s_{i,j} - LSE_i)`，避免重算注意力，也无需把分散 block 物化为连续内存。
  - 仅处理处于动作区域的请求，按「请求 × 逻辑 KV block × KV head」并行；每线程块经 block table 解析物理块并直接加载 key；在 GQA 组内对各 query head 取 max；对动作 query token 增量更新均值，进入新动作区域时重置。Triton 实现。
- **原地压缩内核（Algorithm 4）**：
  - 观察到驱逐后保留条目通常靠近已分配页尾部，因此将所有保留条目压入最后 X = ⌈budget/block_size⌉ 个逻辑块。
  - 目标槽位 = 尾部区域内被驱逐的位置，源槽位 = 尾部区域外被保留的位置，二者不相交，可生成**无冲突拷贝对**，一次并行完成，无需辅助 KV 缓冲。
  - 压缩后释放的空闲 block 归还给服务系统复用，对内存需求波动的 agentic 推理尤其重要。

## 6. 主要结论与发现

- **核心指标**：长轨迹任务（ALFWorld、WebShop）上，ActKV 平均保留 FullKV 准确率的 **98.53%**，仅使用其峰值 KV 内存的 **25.98%**；token 吞吐与任务吞吐分别达 FullKV 的 **3.97×** 和 **3.58×**。
- **对比基线**：R-KV、SnapKV、StreamingLLM 在同等条件下最多仅 74.22% 准确率、约 33.60% 内存；ActKV 在 ALFWorld/WebShop/HotpotQA-Web 上对三者的平均增益分别约为 27–55%、32–71%、29–70%。
- **压缩可反哺准确率**：ActKV
