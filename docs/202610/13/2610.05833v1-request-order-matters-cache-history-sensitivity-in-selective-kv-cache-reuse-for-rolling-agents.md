## 摘要
长时间运行的智能体会反复调用 LLM，同时保留其大部分文档窗口、逐出旧文档并追加新文档。这些滚动更新破坏了精确前缀缓存，并促使采用带选择性重计算的非前缀 KV 缓存复用。我们表明，带选择性重计算的持久化 KV 缓存复用可能具有历史依赖性：在我们的滚动智能体工作负载中，同一个未更改的提示可能因之前处理的请求不同而产生不同答案。在相同的 5% 重计算预算下，文档对齐的重计算将跨请求顺序的答案变化从 CacheBlend 的 token top-$k$ 策略下的 69.0% 降至 26.1%。当每个提示在不同先前请求序列之后进行评估时，与 token top-$k$ 相比，文档对齐的重计算将对完整预填充的保真度提高了 34.5–52.5 个百分点，而两种策略均实现了约 5.7 倍的中位 TTFT 加速。我们的消融研究表明，在我们的滚动智能体工作负载中，连续性是与稳健的选择性重计算相关的主要因素。

## Abstract
Long-running agents repeatedly call an LLM while retaining most of their document window, evicting old documents, and appending new ones. These rolling updates break exact prefix caching and motivate non-prefix KV-cache reuse with selective recomputation. We show that persistent KV-cache reuse with selective recomputation can be history-dependent: in our rolling-agent workload, an unchanged prompt can produce different answers depending on the requests processed before it. At a matched 5% recomputation budget, document-aligned recomputation reduces answer variation across request orders from 69.0% with CacheBlend's token top-$k$ policy to 26.1%. When each prompt is evaluated after a different sequence of preceding requests, document-aligned recomputation improves fidelity to full prefill by 34.5-52.5 percentage points over token top-$k$, while both policies achieve approximately 5.7$\times$ median TTFT speedup. Our ablation study shows that, in our rolling-agent workload, contiguity is the main factor associated with robust selective recomputation.

# 论文总结：Request Order Matters —— 滚动智能体中选择性 KV 缓存复用的缓存历史敏感性

## 一、核心问题与整体含义

- **背景**：长运行智能体（如研究助手、金融监控助手）反复调用 LLM，每次只对文档窗口做小幅滚动更新——逐出最旧文档、保留其余文档、追加新文档。这种"滚动更新"打破了精确前缀缓存（prefix caching）的前提：被保留文档的文本虽未变，但其位置前移、前置上下文改变，因此其先前计算的 KV 状态不再是当前 prompt 下完整预填充所产生的一致状态。
- **动机**：非前缀 KV 缓存复用（如 CacheBlend/LMCache）通过加载分块 KV 状态 + 选择性重计算来修复跨块注意力不一致，从而降低 prefill 开销与 TTFT。但现有方法多在"干净缓存"或孤立请求上评测，忽略了**持久缓存状态跨请求累积**这一现实场景。
- **核心问题**：在缓存状态跨请求持续存在时，同一个未更改的 prompt 是否会因之前处理过的请求序列不同而产生不同答案？即**选择性 KV 缓存复用是否具有缓存历史敏感性**。
- **整体含义**：这是一个"闭环 serving 问题"——每次 LLM 调用既消费也更新缓存状态，后续请求被先前请求所条件化。论文主张，选择性 KV 复用应与缓存生命周期协同设计，而非仅在孤立 prompt 上优化 prefill 成本。

## 二、方法论

### 1. 核心思想
在相同的重计算预算（5% 可复用 token）下，比较两类选择性重计算策略：
- **Token top-k（CacheBlend/LMCache 默认）**：按逐 token KV 偏差排序，选取偏差最大的 k 个**分散** token 重计算。
- **文档对齐（Document-aligned）**：按**连续文档跨度**分配预算，选取平均偏差最高的若干完整文档跨度。

### 2. 关键技术细节与公式
- **逐 token 偏差分数**（选择层计算）：
  $$d_i = \|K_i^{current} - K_i^{cached}\|_2^2$$
  偏差越大表示加载的 KV 状态与当前 prompt 下重新计算的 key 差异越大，优先级越高。
- **重计算 token 数**：$k = \max(1, \lfloor rN \rfloor)$，其中 $N$ 为可复用 token 数，$r=5\%$。
- **跨度平均偏差分数**（归一化防止长跨度占优）：
  $$\rho_j = \frac{1}{|S_j|}\sum_{i \in S_j} d_i$$
- **选择层只运行一次**，同一批位置在后续所有层重计算，不再重新排序。
- **文档对齐策略流程**：将可复用 prompt 划分为指令跨度、各文档跨度、末尾查询跨度 → 按 $\rho_j$ 排序 → 在预算内优先选取完整跨度 → 若仍有剩余 token，从最高排名剩余跨度中选取总偏差最大的连续窗口 → 最终恰好选满 k 个 token。

### 3. 四种跨度策略（用于消融，分离不同因素）
| 策略 | 定义 | 是否连续 | 是否用文档边界 | 是否按偏差排序 |
|---|---|---|---|---|
| Single-window | 总偏差最大的连续 k-token 窗口 | ✅ | ❌ | ✅（总/平均等价） |
| Fixed-chunk | 等长（92 token）、跨文档边界的固定分块 | ✅ | ❌ | ✅ |
| Random-document | 文档跨度，但随机排序 | ✅ | ✅ | ❌ |
| Document-aligned | 文档跨度，按 $\rho_j$ 排序 | ✅ | ✅ | ✅ |
| Token top-k | 分散的高偏差 token | ❌ | ❌ | ✅ |

## 三、实验设计

### 1. 数据集与场景
- **真实事件数据集**：共 8,995 条记录，覆盖 15 只美国股票：
  - Yahoo Finance 日价格记录 7,515 条
  - FNSPID 新闻标题 792 条
  - SEC EDGAR 文件标题 688 条
  - 按各股票价格日历将三类渠道交错排列，保留各自内部顺序。
- **滚动智能体工作负载**：窗口固定 84 篇文档、步长 1，每次逐出 1 篇、保留 83 篇、追加 1 篇，共产生 7,735 次滚动更新；prompt 约 7.2K–7.7K token。
- **任务**：确定性抽取任务——查询指定当前窗口中的一条观测，要求模型逐字复制指定字段，便于精确答案比对。

### 2. Benchmark 与评测协议
- **五种请求顺序**：Chronological（源顺序）、Fixed-random ×3（预定乱序，模拟多智能体共享缓存交错）、Reversed（逆序压力测试）。
- **每个"策略×顺序"组合都从空 LMCache 开始**，请求间保留缓存状态，不同运行间不共享状态。
- **两个缓存历史敏感性指标**：
  - **答案变异（Answer variation）**：五个顺序两两配对共 10 组比较中答案不一致的百分比。
  - **保真度（Fidelity）**：与完整预填充答案的精确一致率。

### 3. 对比方法与系统配置
- 模型：Qwen3-8B，贪心解码（temperature=0），固定随机种子。
- 系统：LMCache 0.5.1 + vLLM 0.23.0，**禁用 vLLM 前缀缓存**以单独测量 LMCache 的非前缀复用路径。
- 对比：Token top-k vs Document-aligned（相同模型、prompt、可复用 token 接口、偏差度量、5% 规则）；另加消融中的 Single-window、Fixed-chunk、Random-document。
- 额外对照：**500 请求缓存重置控制实验**（每请求前清空缓存）；Chronological 顺序独立重复以排除运行间波动。

### 充分性与客观性评估
- **优点**：
  - 严格控制变量——所有策略重计算**完全相同数量**的 token，因此保真度差异只能归因于"选在哪里"，而非"选了多少"。

  - 仅 1 个模型（Qwen3-8B）、1 个领域（金融文档）、1 种任务类型（确定性抽取），泛化性证据有限。
  - 消融主要在 1 个固定随机顺序上进行，3 个随机顺序未全部进入消融。

## 六、主要结论与发现

1. **请求顺序确实改变答案**：答案变异 token top-k 为 **69.0%**，document-aligned 为 **26.1%**。
2. **保真度差异显著**：
   - Chronological 顺序下两者无统计显著差异（86.8% vs 85.4%，p=0.12）。
   - 其余四种顺序下，token top-k 保真度仅 19.8–41.5%，document-aligned 为 54.3–91.7%（全部 p<0.0001）。
   - 相对 token top-k，document-aligned 保真度提升 **34.5–52.5 个百分点**；但 Reversed 压力测试下其保真度也降至 54.3%，说明并非免疫。
3. **延迟收益相当**：两者中位 TTFT 约 **5.7×** 加速（token top-k 426ms / document-aligned 415ms，vs 完整预填充 2,408ms），P95 也接近。
4. **缓存历史是关键**：500 请求缓存重置对照中两者无显著差异（94.0% vs 92.6%，p=0.23），说明优势来自缓存状态累积，**干净缓存的评测会掩盖该问题**。
5. **连续性而非文档边界或偏差排序是主因**：
   - Fixed-random 顺序下，四种跨度策略保真度 89.4–92.8%，token top-k 仅 38.6%。
   - Random-document 完全忽略偏差信号，仅捕获 4.8% 的总偏差，仍比 token top-k 高 50.8 个百分点（p<0.0001）。
   - Token top-k 虽捕获 99.7% 偏差、分散在 180.5 个区域，保真度却最低——**"捕获更多 KV 偏差"不等于"更高保真度"**。
   - Document-aligned 与 Single-window（p=0.076）、Fixed-chunk（p=0.85）、Random-document（p=0.37）均无显著差异。
6. **实践建议**：文档边界本身便于定义连续跨度（无需学习型分割器或人工块大小），但真正的鲁棒性来源是**重计算区域的连续性**。

## 七、优点

- **问题新颖且现实**：首次系统性地将"持久缓存历史"作为选择性 KV 复用的评测维度，揭示了闭环 serving 中被忽视的失效模式。
- **实验控制严谨**：所有策略匹配实际重计算 token 数，排除了"多算多准"的混淆因素；逐请求发送避免 batch 效应；Chronological 重复验证可复现性。
- **缓存重置对照设计巧妙**：直接证明差异源于缓存历史而非方法固有属性，是全文最有说服力的对照之一。
- **消融设计有分析力**：通过 Single-window / Fixed-chunk / Random-document / Document-aligned 四组控制，把"连续性""文档边界""偏差排序"三个因素彼此解耦，得出"连续性主导"的清晰结论。
- **发现反直觉且具指导性**：token top-k 捕获 99.7% 偏差却保真度最低，挑战了"按偏差排序选 token"的直觉，对系统设计有直接启示。
- **实用性强**：document-aligned 不增加延迟成本（TTFT 与 token top-k 相当），且可直接利用 prompt 中已有的文档边界。

## 八、不足与局限

- **模型与领域覆盖窄**：仅 Qwen3-8B、仅金融文档滚动场景、仅确定性抽取任务；对开放式生成、多模态、代码等任务是否成立未知。
- **任务特殊性**：抽取任务可精确比对答案，但真实智能体任务往往是开放式生成，答案变异与保真度的度量方式可能不适用。
- **算力信息不完整**：仅报告单卡型号（NVIDIA L4），未说明 GPU 数量、总机时、实验重复次数以外的资源开销。
- **机制解释不足**：论文指出"连续性"是主因，但未从注意力机制层面解释为何分散重计算会导致严重误差累积（如是否与 attention sink、位置编码漂移或层间误差放大相关）。
- **Document-aligned 并非完全鲁棒**：在 Reversed 顺序下保真度仍降至 54.3%，说明方法本身仍有失效边界，论文未深入分析该情形下的补救手段。
- **消融顺序覆盖有限**：选择模式消融主要在 Chronological + 1 个 Fixed-random 上进行，未覆盖全部 5 种顺序，可能遗漏某些顺序下的行为差异。
- **未评估缓存条目"保留 vs 重建"的细分效应**：作者在 Future Work 中承认这一点，当前实验无法区分不同缓存来源（保留的旧条目 vs 新创建的条目）对结果的贡献。
- **潜在偏差风险**：数据集来自 Yahoo Finance、FNSPID、SEC EDGAR，事件交错方式为人工设计，可能不完全反映真实智能体请求的分布；三种随机顺序虽为预定，但仅 3 个样本，随机性覆盖有限。
