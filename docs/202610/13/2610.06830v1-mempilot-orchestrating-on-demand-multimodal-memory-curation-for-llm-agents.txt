Memory has become integral to the LLM agent ecosystem, supporting information retention and reuse across interactions. However, most existing agent memory systems construct memory in a query-agnostic manner, which can incur unnecessary preprocessing cost and discard details that later prove essential. Recent studies have begun shifting memory processing toward runtime adaptation, but typically specialize in particular operations or fixed processing schemes, leaving flexible control over performance, cost, and latency largely underexplored. To address this challenge, we present MemPilot , a flexible framework that orchestrates on-demand memory curation under different performance–cost–latency preferences. Specifically, we optimize a multi-step LLM policy via reinforcement learning to iteratively choose between retrieving from query-agnostic memory and delegating query-specific curation of raw multimodal history to heterogeneous LLMs and VLMs. The policy jointly controls evidence amount, curation instructions, model selection, and visual access, enabling fine-grained allocation of runtime computation. To optimize this policy under competing objectives, we adapt objective-wise advantage decoupling by separately estimating each objective’s advantage before aggregation. Moreover, we introduce prefix-based marginal utility estimation for fine-grained credit assignment across multi-step rollouts. Experiments on five multimodal agent-memory benchmarks demonstrate favorable performance–cost–latency trade-offs across optimization preferences, with preference sweeps yielding broader frontiers than existing trade-off-aware baselines. 

1. Introduction 

As large language model (LLM) agents evolve toward persistent, long-horizon interaction, memory becomes increasingly central to preserving and reusing past experience (Hu et al., 2025; Huang et al., 2026). However, most existing agent memory systems construct memory from interaction histories in a query-agnostic manner, and relying solely on such pre-query construction can be wasteful and lossy, as it cannot reliably anticipate future query needs (Fang et al., 2025; Liu et al., 2026c; Xu et al., 2025). To mitigate this limitation, a growing line of work moves memory adaptation to runtime through query-time evidence distillation, on-demand memory construction, and adaptive memory strategies (Yan et al., 2025a; Zhang et al., 2026d). Despite this progress, flexible orchestration of runtime memory adaptation remains underexplored, particularly when adapting runtime computation to query needs and multimodal evidence while balancing performance, cost, and latency (Zhang et al., 2026b). This raises a key challenge: how can runtime multimodal memory curation be adaptively orchestrated with controllable performance–cost–latency trade-offs? 

Unfortunately, addressing this challenge is non-trivial due to three key limitations of existing ap-proaches to runtime memory adaptation. 1 Runtime memory control remains structurally rigid : existing methods typically rely on hand-designed operations or fixed processing pipelines, with efficiency

Collectively, these limitations call for a more flexible framework that can orchestrate runtime memory operations and processing backends according to both query needs and optimization preferences. Building on these observations, in this work we introduce MemPilot , a flexible framework for orchestrating on-demand memory curation under different performance–cost–latency preferences. At a high level, MemPilot follows a simple design principle: retain query-agnostic memory, compatible with off-the-shelf agent memory systems, for efficient access, while preserving raw interaction history for query-specific runtime curation. Specifically, at inference time, a multi-step LLM policy constructs a query-adaptive orchestration trajectory by iteratively choosing between retrieving from the query-agnostic memory bank and delegating curation of the raw history to heterogeneous LLMs and vision-language models (VLMs), whose distinct capabilities naturally offer different quality, cost, and latency profiles. Rather than relying on hand-crafted pipelines or discrete budget tiers, the policy adaptively determines how much evidence to process, how it should be curated, which model to invoke, and whether visual evidences are needed, exposing fine-grained controls over runtime computation trade-offs. We optimize this policy with reinforcement learning under different performance, cost, and latency preferences. To better handle the resulting multi-objective optimization, we adapt objective-wise advantage decoupling by estimating each objective’s advantage separately before weighted aggregation. We further introduce prefix-based marginal utility estimation, which estimates the marginal contribution of individual curation steps for fine-grained credit assignment. Experiments on five multimodal agent-memory benchmarks show that MemPilot achieves favorable performance–cost–latency trade-offs across different optimization preferences. Fine-grained prefer-ence sweeps further reveal broader trade-off frontiers than existing trade-off-aware baselines, while behavioral analyses show that MemPilot adaptively reallocates runtime computation as optimization preferences change. Our contributions are summarized as follows: 

• We introduce MemPilot , a systematic framework for preference-aware runtime memory orchestra-tion that jointly controls memory access, query-specific curation, heterogeneous model delegation, and visual evidence usage. By unifying these decisions within a multi-step policy, MemPilot en-ables fine-grained performance–cost–latency control without relying on fixed processing pipelines, predefined budget tiers, or a fixed processing backend. • To optimize the orchestration policy under competing objectives, we adapt objective-wise advan-tage decoupling and introduce prefix-based marginal utility estimation for fine-grained credit assignment in multi-step rollouts, enabling stable and effective optimization. • Experiments on five multimodal agent-memory benchmarks demonstrate favorable performance– cost–latency frontiers across preferences, with analyses revealing shifts in model selection, visual access, and computation allocation as preferences change.

2.1. Agent Memory and Runtime Adaptation 

LLM agents increasingly rely on memory mechanisms to preserve and reuse information from long-term interaction histories (Packer et al., 2023; Zhong et al., 2024). Most existing text-centric systems construct memory before future queries are known, using either hand-designed mechanisms for extraction and organization (Chhikara et al., 2025; Fang et al., 2025; Kang et al., 2025; Liu et al., 2026c; Xu et al., 2025) or learned policies for memory construction, updating, and retrieval (Wang et al., 2025; Yan et al., 2025b; Yu et al., 2026b; Yue et al., 2026; Zhang et al., 2026a). Beyond text-centric memory, recent work has extended agent memory to multimodal interactions, maintaining structured representations over textual, visual, and other sensory experiences (Feng et al., 2026a; Liu et al., 2026b, 2025; Long et al., 2026; Wang and Chen, 2025). Despite increasingly adaptive and multimodal memory designs, they still construct memory in a largely query-agnostic manner. A growing line of work instead shifts memory processing toward runtime adaptation. GAM (Yan et al., 2025a) performs just-in-time research over stored memory and raw history, while BudgetMem (Zhang et al., 2026b) learns query-aware runtime extraction under different computation budgets. Mem-Gen (Zhang et al., 2025a) and AdaMEM (Zhang et al., 2026d) dynamically generate or refresh memory guidance according to evolving reasoning states, whereas MemRL (Zhang et al., 2026c) adapts the utility of stored experiences from interaction feedback. More recent work further explores query-time evidence distillation and deferred memory construction (Yin and Tang, 2026; Yu et al., 2026a). However, these approaches typically specialize in a particular form of runtime adaptation or follow a predefined processing pattern. MemPilot instead learns to orchestrate heterogeneous multimodal memory curation at runtime under controllable performance–cost–latency preferences. 

2.2. LLM Routing 

LLM routing aims to match different queries with suitable models based on their heterogeneous capabilities and costs. Early approaches route queries through model cascades or select models based on estimated query difficulty (Chen et al., 2023; Ding et al., 2024). More recent work improves routing through preference learning (Ong et al., 2025), contrastive objectives (Chen et al., 2024), and graph-based modeling (Feng et al., 2024), while further extending routing to multi-agent settings (Yue et al., 2025) and unified routing frameworks (Feng et al., 2026b). Moving beyond one-shot routing, several methods employ reinforcement learning to enable multi-step model selection and orchestration (Feng et al., 2026c; Qian et al., 2025; Zhang et al., 2025b). These advances highlight the potential of LLM routing as a general paradigm for adaptively allocating heterogeneous model computation according to task demands and resource constraints.

4. Experiment 

4.1. Setups Benchmarks and Metrics. We mainly evaluate MemPilot in multimodal settings involving both textual and visual interaction histories. Specifically, we use five multimodal agent-memory benchmarks: Mem-Gallery (Bei et al., 2026), WorldMemArena (Liu et al., 2026a), H2HMem (Zhu et al., 2026), MemEye (Guo et al., 2026), and MemLens (Ren et al., 2026), with MemEye and MemLens further serving as out-of-distribution evaluation sets. We evaluate answer quality using F1 score and an LLM-judge score (L-J), with GPT-4o-mini as the judge model. Cost measures the total token-based monetary cost incurred by both the orchestrator and delegated external models. Latency measures their total inference latency in seconds. Appendix A.1 and A.4 provide further details. 

Baselines. We organize baselines into two groups according to whether they support explicit trade-off control. The first group contains fixed-configuration methods used for the main comparison. It includes 

(1) text-centric memory systems including A-MEM (Xu et al., 2025) and SimpleMem (Liu et al., 2026c), 

(2) training-based memory methods including GAM (Yan et al., 2025a), AgeMem (Yu et al., 2026b), and Mem-T (Yue et al., 2026), and (3) multimodal memory systems including MIRIX (Wang and Chen, 2025), MemVerse (Liu et al., 2025), and M2A (Feng et al., 2026a). The second group contains 

(4) methods that explicitly expose performance–efficiency trade-offs , including LightMem (Fang et al., 2025), BudgetMem (Zhang et al., 2026b), and OmniSimpleMem (Liu et al., 2026b). Section 4.4 compares these methods separately through frontier analysis. 

4.2. Implementation Details 

MemPilot is implemented based on VeRL 1, with Qwen3-4B-Instruct (Yang et al., 2025) as the default orchestrator policy. To disentangle gains from RL-enhanced answer generation, we additionally report a decoupled-answer evaluation where the curated context is passed to a separate, non-RL-trained answer model, using Qwen3-VL-4B-Instruct and Qwen3.5-9B. External LLMs and VLMs are accessed through OpenRouter 2, with the heterogeneous model pool specified in Appendix A.2. We segment raw interaction histories into 256-token chunks and use Qwen3-Embedding-0.6B (Zhang et al., 2025c) for semantic retrieval. Unless otherwise specified, the query-agnostic memory bank is constructed with LLMLingua-2 (Pan et al., 2024) at a 0.4 compression ratio for policy training and main evaluation. We further examine compatibility with memory banks produced by other agent memory systems in Section 4.6. We retrieve at most five evidence items per step for both MemPilot and applicable baselines. Since memory items from different systems can vary substantially in length, we directly compare monetary cost and latency rather than memory-item counts. Remaining hyperparameters are provided in Appendix A.5.

4.5. How Does MemPilot Allocate Runtime Computation? 

To better understand how MemPilot realizes different trade-offs, we analyze its learned runtime curation behavior in Figure 3. Panels (a) and (b) show that as the optimization preference shifts toward lower cost or lower latency, the policy adjusts multiple control dimensions in a coordinated manner rather than relying on a single knob. Moving from left to right, MemPilot generally reduces the number of policy steps, the frequency of Curate actions, image access, and policy output tokens. At the same time, evidence count also changes adaptively, indicating that the policy does not simply retrieve less information, but learns to reconfigure how memory is accessed and processed under different resource preferences. Panel (c) further shows that model selection is a key mechanism behind this adaptation. Under higher-cost settings, MemPilot relies more heavily on stronger VLMs and LLMs, while lower-cost settings shift computation toward cheaper model groups. Together, these results show that MemPilot learns a coherent allocation strategy over curation depth, modality access, and routed model capacity, which explains its ability to realize controllable performance–cost–latency trade-offs.

5. Conclusion 

We presented MemPilot , a framework for orchestrating on-demand memory curation under control-lable performance–cost–latency preferences. MemPilot formulates runtime memory adaptation as a multi-step decision process, combines query-agnostic memory with raw interaction history, and adap-tively delegates curation to heterogeneous LLMs and VLMs. We further introduced resource-aware policy optimization with objective-wise advantage decoupling and prefix-based marginal utility for fine-grained credit assignment. Experiments across multimodal agent-memory benchmarks demon-strate that MemPilot achieves favorable trade-off frontiers while adapting computation to different optimization preferences. We hope this work encourages agent memory systems to move beyond performance-only optimization toward resource-aware runtime adaptation.

A.4. Evaluation Details Memory preprocessing and indexing. We serialize each multimodal conversation in chronological order and partition it into approximately 256-token text chunks. Dialogue turns are treated as atomic units: a turn is never split across chunks, and its attached images, image identifiers, and captions remain associated with the same chunk. An oversized individual turn is retained as a single chunk. For WorldMemArena (Liu et al., 2026a), the memory available to each question is additionally restricted to the cumulative conversation prefix visible at its corresponding checkpoint. We construct separate dense indexes for the raw and compressed memory corpora. Query-agnostic compression is performed independently for chunk text and image captions using LLMLingua-2 (Pan et al., 2024) with a default compression rate of 0.4, while memory and image identifiers remain unchanged. Document embeddings are computed offline using Qwen3-Embedding-0.6B (Zhang et al., 2025c), normalized, stored in float16 format, and reused throughout evaluation. At runtime, only the policy-generated retrieval query is encoded, after which evidence is ranked by embedding similarity. The compressed-memory and raw-memory indexes are searched independently, with at most five retrieved items per curation operation. Image captions participate in textual retrieval, whereas image pixels are made available only when an image-capable external model is selected. Reference answers are never used during preprocessing, indexing, or retrieval. 

Benchmarks and data splits. Our in-distribution evaluation covers Mem-Gallery (Bei et al., 2026), the lifelong subset of WorldMemArena (Liu et al., 2026a), and both the dyadic and multiparty variants of H2HMem (Zhu et al., 2026). Each dataset is split at the conversation level into 70% training, 10% validation, and 20% test data, ensuring that questions derived from the same conversation never appear in different splits. WorldMemArena is additionally stratified by category and scenario. The

Inference. We evaluate one deterministic trajectory per question using greedy decoding with temper-ature 0. The maximum prompt and response lengths are both 4,096 tokens. Each trajectory permits at most six sequential curation rounds and at most two concurrent independent curation operations. All policy-facing memory-access settings are kept identical to those used during the corresponding training run. 

LLM-as-a-judge evaluation. We additionally evaluate semantic answer correctness using openai/gpt-4o-mini .We preserve each benchmark’s official judge role, correctness rubric, score semantics, and output convention. The only sample-dependent inputs presented to the judge are the predicted answer and the ground-truth reference answer. Minor answer-only adaptations are applied when an official prompt requires information unavailable to common baseline outputs. Specifically, we remove the question field from all judge inputs; remove Key Memory Points from WorldMemArena because they evaluate evidence coverage rather than final-answer correctness; convert H2HMem’s session-batched evaluation into itemwise evaluation; and remove the previous answer from MEMLENS Knowledge Update prompts because correctness is determined by the current reference answer. Mem-Gallery and H2HMem use five-level scores in {0, 0.25 , 0.5, 0.75 , 1}. WorldMemArena classifies each answer as Correct, Hallucination, or Omission, with only Correct receiving score 1. B.1. Per-Benchmark Runtime Computation Allocation 

Figure 5 provides the per-benchmark breakdown of the runtime-allocation analysis in Section 4.5. The overall behavior is consistent across all five benchmarks. As stronger cost or latency preferences

Meanwhile, individual controls such as evidence depth and image access need not change monotonically, show-ing that MemPilot reallocates computation jointly rather than uniformly shrinking every decision dimension. B.3. Memory-Bank Compatibility Across Benchmarks 

We further report per-benchmark results for the memory-bank compatibility analysis in Figure 6. Across all five benchmarks, replacing the default memory bank with SimpleMem (Liu et al., 2026c) or A-MEM (Xu et al., 2025) preserves clear performance–cost frontiers without retraining, confirming that MemPilot is not tightly coupled to a particular query-agnostic memory construction. Different memory banks occupy distinct cost regimes while retaining similar improvements as runtime computation increases. The default bank generally provides more cost-efficient operating points, whereas A-MEM incurs higher overall cost but often reaches a higher performance ceiling, particularly on WorldMemArena, MemEye, and MemLens. SimpleMem typically lies between these regimes and remains competitive on Mem-Gallery and H2HMem. These results suggest that MemPilot preserves its runtime orchestration behavior across diverse memory banks while retaining the distinct performance– cost characteristics of their upstream memory representations.

D. Limitations and Future Work 

While MemPilot provides flexible runtime memory orchestration, several aspects could be further improved: • Privacy-aware delegation. Runtime curation may send retrieved interaction history to external models, which can raise privacy concerns for sensitive memories. Future work could incorporate privacy-aware routing, local processing, or access-control mechanisms while remaining orthogonal to MemPilot’s core orchestration design. • Preference calibration. MemPilot controls trade-offs through predefined optimization preferences. Future work could study more user-friendly ways to map high-level deployment preferences to reward coefficients, making trade-off specification easier across applications. • Deployment-aware latency modeling. We use a proxy latency estimator during training to avoid instability from transient network and serving fluctuations. Future work could instead optimize directly against measured latency in a controlled system-level sandbox with stable networking and serving conditions. 

E. Broader Impact 

MemPilot advocates a broader shift in agent memory from performance-oriented optimization toward explicit and controllable performance–cost–latency trade-offs. In practical deployments, the highest-performing memory configuration is not always the most desirable, as different users and applications may place substantially different values on monetary cost and response latency. This mirrors modern commercial LLM services, which increasingly offer model tiers spanning different capability, cost, and latency profiles (e.g., GPT-5.6-Sol/Terra/Luna), allowing users to choose operating points that best match their needs. We believe agent memory systems should provide similar flexibility rather than committing to a single performance-oriented configuration. This becomes particularly relevant for multimodal agents, where accessing and processing visual evidence can introduce substantially different resource demands. More broadly, treating memory curation as adaptive computation allocation may encourage tighter integration between agent memory, model routing, and resource-aware decision making, enabling future long-horizon agents to become more efficient, responsive, and deployment-aware.

The standard answer is a specific number. • Assign 1 point if the student clearly states the exact number in any equivalent form (e.g., “3”, “three”, “3.0”). • Assign 0 points if the student gives a different number, a range, an approximation, refuses, or does not clearly answer. 

[MSR — Arithmetic] 

This is an arithmetic question. The standard answer is a specific value. • Assign 1 point if the student gives the same value in an equivalent format (e.g., “0.5” and “1/2” and “50%”). • Assign 0 points if the student gives a different value, an unsupported approximation, refuses, or does not clearly answer. 

[TR — Duration Comparison (A/B)] 

This is a binary choice question. The student must select one of two options. • Assign 1 point if the student clearly selects the same option as the standard answer, regardless of phrasing. • Assign 0 points if the student selects the other option, refuses, or does not make a clear selection. 

[TR — Order Ranking] 

This is an ordering question. The standard answer is an exact sequence of items. • Assign 1 point ONLY if the student gives the exact same sequence in the same order. • Assign 0 points if any item is missing, added, duplicated, misplaced, or if the order is unclear. 

[TR — Date Extraction] 

This is a date extraction question. The standard answer is a specific date. • Assign 1 point if the student gives the same date in any unambiguous equivalent format (e.g., “Jan 15, 2024” and “2024-01-15” and “15/01/2024”). • Assign 0 points if the date is different, incomplete when a full date is required, ambiguous, or missing. 

[AR — Answer Refusal] 

• Assign 1 point if the student explicitly refuses, says there is not enough information, or indicates the question is unanswerable from the provided context. • Assign 0 points if the student gives a substantive answer, even if hedged.
