## 摘要
将长上下文推理分解到多个协作智能体上，限制的是每次调用的活跃 KV 缓存，而非总证据量；当 KV 缓存内存成为瓶颈时，这一点很重要。许多这类系统会增加一个持久层，用于存储和召回推理轨迹，通常通过报告准确率提升的消融实验来验证其有效性。我们在一个三层智能体架构上对两者都进行了测量。分解带来了：每次查询的峰值 KV 工作集为 14.3 MiB，而单遍和检索增强基线分别为 35.5 MiB 和 35.3 MiB。持久层则不然：在八个受控数据集对、每组 n=100 的设置下，它使峰值缓存增加 +0.368 MiB [+0.167, +0.590]，并且未产生可检测的准确率变化（+0.015，95% CI [-0.011, +0.046]）。我们认为这一零结果是结构性的：单问题基准为每个条目提供其自身的证据并独立评分，而正确性要求在不同条件之间重置已存储的轨迹，因此召回没有可检索的有信息内容。得出这一结论需要四次测量校正——其中三次夸大了表观收益，第四次则使该量级的效应看起来可分辨——而这些在结果表中均不可见。我们给出了智能体记忆消融必须满足的条件，以及无需知道具体缺陷即可使用的检测流程。

## Abstract
Decomposing long-context inference across cooperating agents bounds the active KV cache per call rather than total evidence, which matters when KV-cache memory binds. Many such systems add a persistent tier storing and recalling reasoning traces, usually validated by an ablation reporting an accuracy gain. We measure both on one three-tier agent architecture. Decomposition delivers: peak KV working set of 14.3 MiB per query against 35.5 and 35.3 MiB for single-pass and retrieval-augmented baselines. The persistent tier does not: across eight controlled dataset pairs at n=100 per arm it costs +0.368 MiB [+0.167, +0.590] of peak cache and produces no detectable accuracy change (+0.015, 95% CI [-0.011, +0.046]). We argue the null is structural: single-question benchmarks supply each item with its own evidence and score it independently, and correctness requires resetting stored traces between conditions, so recall has nothing informative to retrieve. Reaching it took four measurement corrections -- three inflating the apparent benefit, the fourth making an effect that size look resolvable -- none visible in the results table. We give the conditions an agent-memory ablation must satisfy and detection procedures that need no knowledge of the specific defect.

## 1. 核心问题与研究动机

- **背景**：KV 缓存是长上下文推理的内存瓶颈——它随上下文增长、按峰值而非均值配置，并常超出边缘加速器的显存上限，因此缓存管理本身是一个系统问题（Kwon et al., 2023）。
- **一条主流应对路径**：将任务分解到多个协作智能体，每个智能体只处理部分证据并向下游传递蒸馏状态（Zhang et al., 2024）。这样单次调用不持有全部上下文，活跃工作集随总证据增长仍保持有界。
- **被质疑的常见做法**：这类系统往往再加一层"持久记忆"——存储每次查询的推理轨迹并日后召回，理由直观（会记忆的智能体应需要更少上下文），并通常以"关闭该层则准确率下降"的消融实验来佐证。
- **本文的核心问题**：在同一套三层智能体架构上，同时测量分解与持久记忆两件事的**成本（峰值 KV 缓存）**与**收益（准确率）**。
- **关键区分**：检索增强（RAG）改变的是"哪些证据进入一次调用"；分解改变的是"证据被分散到多少次调用"，只有后者能约束峰值 KV。因此两者在"记忆"问题上不可互换。
- **整体含义**：论文主张——分解确实有效；持久记忆层没有可检测的收益，而且这个零结果是**结构性**的，源于单问题基准的评测方式本身；同时给出智能体记忆消融必须满足的四项条件与通用检测流程。

## 2. 方法论

### 2.1 系统架构（COA-PKV）

- **三层记忆**：
  - **L1**：短暂的按调用 KV 缓存（每次调用的活跃上下文窗口）。
  - **L2**：Redis 支撑的键值存储，承载带类型的"通信单元"（Communication Units），使智能体接收蒸馏后的前驱输出而非原始上下文。
  - **L3**：Qdrant 向量库，承担两个**在代码中可分离**的职责：(a) 证据进入缓存前的语义过滤；(b) (q, k, v) 轨迹持久化以实现跨查询召回。**只有 (b) 属于"持久记忆"主张**。
- **六节点控制器**：Decomposer（分解）→ Retriever（检索）→ Reasoner（推理）→ Critic（批评/路由）→ Synthesiser（综合）→ 独立的 answer critic（答案批评）。
  - 细节：`search_reranked` 在 Retriever、Reasoner、Synthesiser 三处各跑一次且均不设门控；`store_qkv` 不是终点步骤，每个 Reasoner 循环写一次、综合阶段再写一次（两次循环的查询会写三条轨迹）；Critic 是路由器而非门控。
- **消融臂**：`COA-NOKV` 仅关闭 `search_outputs`（召回）与 `store_qkv`（写入）两个操作，L1、L2 与证据过滤在两臂中完全一致。

### 2.2 关键测量定义

- **峰值 KV** = 单次查询内**最大单次调用**的 (prompt + generated) 足迹（不是所有调用之和，后者约为其 4 倍），按服务模型的 **10,240 B/token** KV 几何换算（2 × 10 × 2 × 256 × 1 B(fp8)，即 40 层中仅 10 层全注意力）。
- **明确边界**：峰值 KV 不等于设备占用率——不含另 30 层线性注意力的逐序列状态、分页舍入、模型权重与并发序列限制；因此低峰值 KV 是"KV 缓存中的余量"，而非设备并发数的等比增益。

### 2.3 统计与配对方法

- **逐问题配对**：按问题文本匹配（非行位置），消除题目难度带来的方差。
- **区间估计**：单元内用百分位自助法（B = 10⁴）；跨单元用**两阶段聚类自助法**（先重采样单元，再在单元内重采样问题），因为同一单元内的问题共享数据集、提示格式与难度画像。
- **两列 n 不同**：准确率对"两臂都评分的题"配对（失败题记 0，故 n=100）；峰值 KV 只对"两臂都记录到缓存数值的题"配对（失败题无峰值，故 n 略低）。

### 2.4 召回可达性复现（§4 的核心技术细节）

- 严格复现检索器自身的谓词：同一嵌入模型（`all-MiniLM-L6-v2`）、同一余弦阈值 0.6、且只允许触达同一轮次中**更早写入**的轨迹。
- 结果：按原样发送时仅 **24%** 的题可触达（剥离共享指令样板后为 **20%**）；其余题的召回**可证明地返回空**，因此 §3 的数值是**意向性治疗（ITT）估计**。

### 2.5 四项测量校正（C1–C4）

| 条件 | 内容 | 检测手段 |
|---|---|---|
| **C1 组件真的执行了** | 持久层写下的轨迹从未被读取；另有三个组件同样失效（客户端消融开关对服务端智能体无效、重排器 404 被当作"保持原序"、成本累加器偏离基准路径清零了 38 个已发布单元） | 为每个"声称存在"的组件发计数器，并要求运行摘要中非零 |
| **C2 运行相互独立** | 轨迹按问题嵌入为键，固定种子重跑会召回自己先前的答案（测得 100/100 题已携带存储轨迹；48,915 条轨迹 / 2,856 题）；修正后某数据集从 0.2949 **降到** 0.2282 | 运行前用评测问题查询存储，任何超阈命中即污染 |
| **C3 只变命名的那一个轴** | 原消融开关同时改变了执行位置（服务→进程内）、证据来源与依赖集；时间上记忆臂始终先跑，且服务栈在数天跨度内慢约 3.5× | diff 两臂的序列化请求（须只差一个字段），再做顺序平衡（diff 看不见时间） |
| **C4 效应量超过测量噪声下限** | 同配置复现组内合并标准差 0.046 / 0.052，对应 ±0.09–0.10 的 95% 带；此前准备引用的所有差值都小于此 | 用复现组估计带，而非运行内自助法（后者低估不确定性约 2 倍） |
