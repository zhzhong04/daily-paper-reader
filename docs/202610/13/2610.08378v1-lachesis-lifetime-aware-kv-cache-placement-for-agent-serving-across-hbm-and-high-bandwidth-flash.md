## 摘要
大语言模型（LLM）服务正日益由智能体工作负载主导：在这类负载中，智能体及其子智能体跨多个请求将上下文累积为 KV 缓存，消耗大量内存。高带宽闪存（HBF）是一种颇具前景的解决方案，它以 HBM 级别的读带宽提供高出一个数量级的容量，但其有限的写入耐久度是关键的限制因素。我们的核心洞察是：KV 缓存应根据其生命周期在 HBM 与 HBF 之间进行放置。将生命周期较短的数据放在 HBM 中，可让 HBM 吸收一次智能体运行中更多的写入，从而减少写入 HBF 的数据量。由于智能体服务中 KV 缓存的生命周期由 harness（即编排智能体的程序）决定，我们分析了其行为，并识别出生命周期出现差异的三个维度：时间维度、结构维度与工作单元间维度。在这些观察的指导下，我们提出 Lachesis——一个位于智能体 harness 与服务引擎之间的生命周期感知 KV 缓存放置层。在写入时，它根据生命周期将每个段放置到 HBM 或 HBF 中，并在该段不再被读取后释放其数据块。在基于 trace 的仿真中，与 HBM 优先放置相比，Lachesis 将 HBF 寿命延长了 1.19–3.13 倍，达到 3.3–12.2 器件年。即使在严格 SLO 所允许的满负载下 7×24 小时持续运行，在多智能体 trace 上 HBF 的寿命仍超过其五年质保期。

## Abstract
Large language model (LLM) serving is increasingly dominated by agentic workloads, in which agents and their sub-agents accumulate context as KV cache across many requests, consuming substantial memory. High-bandwidth flash (HBF) is a promising solution, providing an order of magnitude greater capacity at HBM-class read bandwidth, but its finite write endurance is the key limiting factor. Our key insight is that KV cache should be placed across HBM and HBF by its lifetime. Placing shorter-lived data in HBM lets HBM absorb more of an agent run's writes and sends less of them to HBF. As the lifetime of KV cache in agentic serving is dictated by the harness, the program that orchestrates the agents, we analyze its behavior and identify three axes along which lifetime diverges, temporal, structural, and inter-worker. Guided by these observations, we present Lachesis, a lifetime-aware KV cache placement layer between the agent harness and the serving engine. At write time, it places each segment in HBM or HBF according to its lifetime, and frees its blocks once the segment is no longer read. In trace-driven simulation, Lachesis extends HBF lifetime by 1.19-3.13x over HBM-first placement, reaching 3.3-12.2 device-years. Even under continuous 24x7 operation at the full load a tight SLO admits, HBF outlasts its five-year warranty on the multi-agent trace.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景转向**：LLM 服务正从无状态请求转向**智能体（agentic）工作负载**。一个 agent 围绕单一用户任务发起多次 LLM 请求，并派生并发运行的子智能体（sub-agent）。
- **容量墙（capacity wall）**：传统请求的上下文只在其自身请求生命周期内存活；而 agent 会话把已累积的上下文以 KV cache 形式长期保留（部分直到会话结束），再加上子智能体的独立上下文，导致同一时刻存活的 KV 体量远超常规服务。实测显示 agentic 负载的峰值上下文长度比聊天机器人负载大 **29×**（约 0.5K–2.8K vs 37K–69K token）。
- **HBF 的机遇**：高带宽闪存（HBF）基于 NAND 堆叠，容量约为 HBM 的 **16×/stack**，并提供 HBM 级**顺序读带宽**，可缓解容量压力、降低单请求硬件成本。论文考察两类集成架构：级联式（H3，HBF 挂在 HBM 之后）与并列式（HBF 与加速器直连）。
- **核心瓶颈**：NAND 的**写入耐久度有限**（有限 P/E 循环）。因此早期 HBF 设计只放只读数据（模型权重、预计算 KV）；后续工作开始放动态生成的 KV，但主要以**读写比（read-to-write ratio）**为选择依据。
- **论文的关键洞察**：不应按读写比、而应按**生命周期（lifetime）**决定 KV 的层级归属。因为写入落在 HBM 就不消耗 HBF 的 P/E 预算；把**短生命周期**的 KV 放进 HBM，HBM 就能在一次运行中吸收更多写入、更少写入到达 flash。在 agentic 服务中，生命周期由 **harness（编排 agent 的程序）**决定，因此是**在写入之前就可判定**的。

## 2. 方法论

### 2.1 核心思想
- 提出 **Lachesis**：位于 **agent harness 与 serving engine 之间**的生命周期感知 KV 放置层。写入时按段（segment）生命周期决定落在 HBM 还是 HBF；段不再被读时立即释放其块。
- 引入 **context segment（上下文段）** 概念：共享同一生命周期的一组 token；段的终结称为 **context boundary（上下文边界）**。
- 放置覆盖范围：**仅 KV cache**；模型权重的只读映射不变，激活值仍在 HBM。

### 2.2 三条生命周期分化轴（§3 分析结论）
- **时间轴（temporal，§3.3）**：turn 结束时 harness 剥离 reasoning 内容。
  - reasoning-laden 段：占一个 turn 写入 token 的 **66–83%**，但只活 1 个 turn；
  - reasoning-stripped 段：寿命长 **7.6–17.2×**（中位），可跨多轮保留；可分性 0.96–0.99。
  - 边界**确定性已知**（turn end）。
- **结构轴（structural，§3.4）**：子智能体返回时其段被丢弃、只保留结果。
  - lead-agent 段寿命比 worker 段长 **4.0–6.1×**、比 reviewer 段长 **4.7–38.3×**；可分性 0.90–1.00；
  - 关键点：lead-agent 段在其生命周期的 **71–88%** 时间内处于"未被读取"（等待子智能体），因此其读写比与 worker 重叠（0.25–0.60）——**复用度不能作为寿命的代理指标**。
  - 边界**确定性已知**（sub-agent return）。
- **工作单元间轴（inter-worker，§3.5）**：同一 worker 类内寿命差异大（p10–p90 相差 **3.7–23.6×**），写量差 2.8–22.5×，二者 Kendall τ = 0.51–0.72；无 context boundary 分隔，**但可在 spawn 时预测排序**。

### 2.3 关键技术细节
- **归一化生命周期指标**（消除批处理/负载/排队影响，以 decode 节点时钟为参考）：
  - `T_norm(s) = G_dec(s)·TPOT_ref + N_obs(s)·TTFT_ref + Λ_tool(s) + Λ_user(s)`
  - 其中 `G_dec(s)` 为该段存活期间的 decode 生成 token 数，`N_obs(s)` 为 observation prefill 次数，`Λ_tool`/`Λ_user` 为工具调用与用户间隔延迟；参考值 `TPOT_ref = 0.2s`、`TTFT_ref = 1.0s`。
- **读写比定义**（附录 B，用于与既有工作对照）：
  - `V_W(s) = N_W(s)·V_KV_token`
  - `V_R(s) = V_KV_token · Σ_{q∈Q(s)} Σ_{i=1..L_out(q)} n_s(q,i)`
  - `ρ_R/W(s) = V_R(s) / V_W(s)`（仅统计 decode 阶段读取）
- **确定性路径（deterministic path）**：覆盖时间轴与结构轴。短生命周期段（reasoning-laden、sub-agent）优先放 HBM；长生命周期段（reasoning-stripped、lead-agent）放 HBF。reviewer 段作为最短命的 sub-agent 角色**无条件**放 HBM。
- **预测路径（predictive path）**：覆盖 inter-worker 轴。在每次 worker spawn 时，用 **spawn signal**（instruction、context、tool list、会话内 spawn 位置、词袋哈希等）打分；模型为 **ridge 回归线性模型**，只消费其**排序**而非寿命数值。按"最短优先"排序，前 k 个准入 HBM，其余进 HBF。**k 由 HBM 空闲容量决定**（非超参），且先为 reviewer 预留 HBM 容量。预测开销为一次线性模型求值，不引入启动延迟。
- **段表（segment table）**：每个存活段一行，记录 segment id、段类别、关闭它的 context boundary、以及引擎分配的 KV block id。
- **引擎接口仅两个调用**：
  - `alloc(tier)`：从指定层（HBM/HBF）的空闲块表取一块；
  - `free([block ids])`：在 context boundary 触发（而非像 LRU 那样等不活跃期），把块归还到各自的空闲表。
  - 引擎只需为异构内存多维护**一张空闲块表**，块所属层级即其被取出的空闲表；HBM 空闲表为空时改由 HBF 表服务。

## 3. 实验设计

- **实现方式**：在**仿真服务引擎 + 两层内存**上实现并回放真实 agent trace。
  - 引擎：**Frontier**（调度器与请求队列、带 block-hash 前缀缓存的 KV 管理器、按 KV-block 预算表达的容量、逐轮增长的上下文）；
  - 硬件：**LLMSimulator** 及其 HBF 扩展（编译算子内核 + roofline 内存定价），KV 分居两层并按所在层带宽计价；发往 HBF 的 KV 跨 decoder 层缓冲、在 decode step 末尾一次性 flush（因此按 HBF 写带宽计价）。
- **数据集 / 场景**：三类回放 trace（附录 A 给出规模统计）
  - **时间轴（单智能体）**：τ³-bench（airline 58 会话 / retail 114 / telecom 114 / banking 97）、BFCLv4（base 200 / long-context 200），harness 为 Harbor；
  - **结构轴（多智能体）**：AppWorld、DeepSearchQA、SWE-bench Verified、TerminalBench、WebArena，harness 为 AOrchestra（继承 Claude Code），五个 benchmark 混合为**一条多智能体 trace**（另采集一份禁用 reviewer 的版本）。
  - 数据规模示例：多智能体侧 token written 达 6.7M–37.2M；τ³-bench banking 达 7.17M。
- **模型与部署**：Llama-4-Maverick 与 Qwen3-235B-A22B，各跨 **8 张 GPU**，attention 用数据并行、专家用专家并行；预填充—解码分离部署的 **decode 节点**。
- **内存配置（5 种）**：把 GPU 的 8 个 stack 槽在 HBM/HBF 间切分为 **1/7、2/6、3/5、4/4**，外加 H3 的级联 **8/8\***（HBM 与 HBF 同槽并存）。
- **SLO**：TTFT 均为 2s；99 分位 TPOT 分**紧（60 ms）**与**松（100 ms）**两档；单智能体 trace 只在紧 SLO 下跑。
- **对比基线**：**HBM-first placement**（HBM 有空闲块就放 HBM，否则放 HBF），即无 Lachesis 时引擎的自然行为。另做**消融**："去掉预测路径的 Lachesis"。
- **评价指标**：**HBF 寿命（device-years）** = P/E 预算 ÷ KV 平均写入速率（排除加载模型权重的那一次写入）。假设 **100,000 P/E（SLC）**、每 stack **512 GB** flash、写放大 **1.02**（沿用先前工作取值），要求超过 **5 年质保**。
