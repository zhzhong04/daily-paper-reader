## 摘要
跨模型 KV 缓存复用仍是现代 LLM 服务中的关键挑战。编码智能体和多模型系统越来越多地将共享上下文路由到不同模型：用户可能在会话中途切换模型，或者级联系统可能将困难查询升级到更大模型。由于 KV 缓存包含模型特定的表示，每次切换通常都会迫使接收模型从头预填充整个上下文。近期工作表明，闭式线性映射可以在同一系列模型之间转换 KV 缓存，但随着模型规模差距扩大，迁移准确率会下降。本文中，我们确认这些迁移失败集中在少量信息密集的 token 上。为弥合这一差距，我们提出 RaReCache，一个使大型目标模型能够通过选择性重计算，从由小得多的源模型预填充的缓存中准确解码的框架。RaReCache 使用一种新颖的秩不一致度量来识别这些关键位置，通过每个 token 的映射 KV 在输出方向上的能量来对其评分，这些输出方向由校准数据提供较弱支持。在两个模型系列和五个基准上，对于 23 倍参数差距（Qwen3-0.6B 到 14B），仅重计算 30% 的位置即可保留目标准确率的 95-99%；而在 8.8 倍差距（Llama3-8B 到 70B）下，重计算 40% 可保留目标准确率的 96.5%。RaReCache 基本消除了对源模型规模的敏感性，并实现了最高 3.04 倍的预填充加速。对于在线服务，在单块 GPU 上，它可处理目标预填充 1.8 倍的请求吞吐量；在目标模型饱和负载下，在 30% 重计算预算下，将首 token 时间（TTFT）的中位数和第 99 百分位数分别降低 5.0 倍和 6.4 倍。RaReCache 建立了一种高效的服务范式：小模型代大规模目标模型进行预填充，使大模型仅重计算关键 token，从而大幅降低预填充延迟。

## Abstract
Cross-model KV-cache reuse remains a key challenge in modern LLM serving. Coding agents and multi-model systems increasingly route a shared context across models: a user may switch models mid-session, or a cascade may escalate a difficult query. Because KV caches contain model-specific representations, each switch typically forces the receiving model to prefill the entire context from scratch. Recent work shows that closed-form linear maps can translate KV caches between models in the same family, but transfer accuracy degrades as the model-size gap widens. In this paper, we establish that these transfer failures are concentrated in a small subset of information-dense tokens. To bridge this gap, we introduce RaReCache, a framework that enables a large target model to decode accurately from a cache prefilled by a much smaller source via selective recomputation. RaReCache identifies these critical positions using a novel rank disagreement metric, scoring each token by the energy of its mapped KV in output directions weakly supported by the calibration data. Across two model families and five benchmarks, on a 23x parameter gap (Qwen3-0.6B to 14B) recomputing just 30% of positions retains 95-99% of the target accuracy, whereas on a 8.8x gap (Llama3-8B to 70B), recomputing 40% retains 96.5% of the target accuracy. RaReCache largely removes sensitivity to source-model size, and achieves up to a 3.04x prefill speedup. For online serving, it handles 1.8x the request throughput of target prefill on a single GPU, and at the target's saturation load, reduces median and 99th-percentile time-to-first-token (TTFT) by 5.0x and 6.4x respectively, with a 30% recompute budget. RaReCache establishes an efficient serving paradigm where small models prefill on behalf of massive targets, enabling large models to recompute only critical tokens, drastically reducing prefill latency.

# RaReCache 论文详细总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：现代 LLM 服务系统中，编码智能体、多模型级联（cost-quality cascade）、动态请求路由等场景频繁在会话中途切换模型，或把困难查询升级到更强模型，导致共享上下文需要跨模型传递。
- **核心痛点**：KV 缓存与模型自身架构强绑定，接收模型无法直接读取源模型的缓存，每次切换都必须**从头 prefill 整个上下文**，带来高昂的 prefill 延迟。
- **现有方案局限**：
  - 前缀缓存（PagedAttention、SGLang）与 DroidSpeak 等仅限于**同架构**模型；
  - 神经融合器 / 潜在适配器（Cache-to-cache、K-V 对齐）旨在提升精度而非节省 prefill 计算；
  - 最接近的 Heo et al. (2026) 提出无梯度的**闭式线性映射**，可在同系列模型间转换缓存，但当**模型规模差距扩大时迁移精度显著退化**（如 0.6B→14B 仅 71.6% vs. 14B 自身 95.1%）。
- **关键洞察**：作者发现迁移失败**并非均匀分布**，而是集中在**少量信息密集 token**（如问题中的实体、数量、关系），模板类 token 即使 ℓ2 误差大也几乎不影响下游精度。因此只需在目标侧**选择性重计算**这些关键位置，即可弥合差距。

## 2. 方法论

### 2.1 核心思想
- 小模型负责 prefill 并把 KV 缓存通过**闭式线性映射**转换给大模型；大模型只对**秩不一致分数最高**的 ⌈ρT⌉ 个位置做前向计算，其余位置直接读取映射缓存，二者合并构成最终目标缓存。

### 2.2 基础线性映射（§3.1）
- 每个目标层 ℓ、每个张量类型 σ∈{key,value} 独立拟合一个线性映射。
- **输入构造**：对目标层用 R² 分数从源模型所有层中选出 top-K 层，将其 KV 头拼接为输入 x；keys 先**去旋转**再拟合、映射后**重新旋转**，从而跨上下文长度迁移。
- **拟合方式**：对 N 个校准 token 堆叠成矩阵 X、Y，中心化后用**岭回归闭式解**：
  - W = (XᵀX + λI)⁻¹XᵀY，b = ȳ − x̄W，ŷ = xW + b
  - λ 用于正则化高度相关源层导致的近奇异矩阵；只需一次离线 pass 累积 XᵀX 和 XᵀY，无需梯度下降。

### 2.3 秩不一致（Rank Disagreement，§3.2）
- **动机**：ℓ2 误差大小会混淆两类错误——校准集覆盖范围内的插值误差（无害）与真正 OOD 表示误差（有害）。注意力分数则被 sink token 与模板 token 主导。
- **构造**：对校准集预测 ŷ 做协方差分解 Σ = VΛVᵀ，取前 r 个方向张成"**良描述子空间**"Vᵣ。
- **分数定义**：全秩预测 ŷ 与受限秩预测 ŷ⁽ʳ⁾ 之间的平方差，跨所有映射层与 KV 侧求和：
  - sᵢ = Σ_{ℓ,σ} ‖ŷᵢ − ŷᵢ⁽ʳ⁾‖²，其中 ŷ⁽ʳ⁾ = xWᵣ + bᵣ，Wᵣ = WVᵣVᵣᵀ
- **高效计算形式**（附录 A 推导）：‖zₜ‖² − ‖zₜVᵣ‖²，其中 zₜ = (xₜ − x̄)W 为中心化预测；偏置项相互抵消，每层每侧只需一次 dₜ×r 投影。
- **关键性质**：模板 / 指令类 token 落在良描述子空间内，即使误差大也得分接近 0；独特内容 token 投影到校准集未覆盖方向，得分高。所有层共用同一套重计算位置（不同层 top-30% 重叠度达 0.87）。

## 6. 主要结论与发现

- **重计算少数位置即可恢复大部分精度**：23× 差距下重算 30% 保留 94.8%（GSM8K）、96.9%（ARC-C）、98.6%（ARC-E）；重算 50% 时 GSM8K 达 95.3%，甚至略超 14B 自身（95.1%）。
- **重计算可替代源模型容量**：纯迁移时精度严格按源模型大小排序（GSM8K 三源间差 18.9pp），重算后该排序基本消失（ρ=0.4 时三源差异 <0.9pp）。
- **Llama 3 上一致**：8B→70B 纯迁移 81%（不优于 8B 单独作答），重算 40% 升至 92%（70B 的 96.5%，比 8B 单独高约 10pp）。
- **秩不一致显著优于所有基线**：ρ=0.3 时关闭 79% 差距（90.3%），优于随机（82.3%）、注意力 oracle、ℓ2 误差 oracle（80.7%）、DroidSpeak 式层前缀（79.0%）。
- **反向（大→小）迁移**：14B→1.7B 提升 +14.4pp，14B→4B 提升 +3.1pp；但 14B→0.6B 反而下降 7.8pp；**反向场景重计算几乎无收益**（≤0.7pp，属噪声），因为 14B 缓存被映射重建得很好（R² 0.90–0.91）。
- **系统性能**：单请求 T=2048 时加速 1.38×（ρ=0.5）、1.95×（ρ=0.3）、2.31×（ρ=0.2）；批处理下最高 3.04×；吞吐从 6256 tok/s 提升到 12378 tok/s（约 2×）；饱和负载下中位 TTFT 降低 5.0×、p99 降低 6.4×，单 GPU 可服务 1.8× 请求吞吐。

## 7. 优点

- **问题定位精准**：通过案例研究揭示"注意力集中在 sink/模板 token、ℓ2 误差无法预测下游损失"这一反直觉现象，为方法设计提供强动机。
- **指标设计新颖且优雅**：秩不一致是**目标模型无关（target-free）** 的闭式度量，无需目标前向，且可化简为 ‖zₜ‖² − ‖zₜVᵣ‖²，每层每侧仅一次小投影，计算开销极低。
- **架构无关性**：不依赖同架构假设（区别于 DroidSpeak），可在同系列不同规模模型间工作。
- **工程优化扎实**：BF16 映射 + 源块复用把映射延迟从 195ms 降到 27ms（7.2×），选择延迟从 70ms 降到 17ms（4.2×）。
- **实验体系完整**：覆盖精度、选择器消融、双向迁移、系统吞吐与在线排队延迟，并给出**解析加速上限公式**与未来稀疏因果核的潜力分析。
- **诚实披露**：附录明确列出局限性（校准分布依赖、同 tokenizer 假设），并附 AI 使用声明与可复现性声明。

## 8. 不足与局限

- **校准数据依赖**：线性映射对标定分布敏感，当前需用与下游评测分布匹配的数据（如具体 benchmark 的训练集）拟合，尚不能任务无关 / 零样本。
- **Tokenizer 限制**：要求源与目标**共享同一 tokenizer 与词表**（同系列内），跨异构模型族的迁移仍是开放问题。
- **反向迁移的失效**：大→小方向重计算无收益，且 23× 极端差距下反向迁移反而损失 7.8pp，说明该分数对"源侧重建良好"的情形不敏感，存在盲区。
- **系统层面**：
  - 使用标准注意力核，重算 query 仍需 attend 全部 T 个 key，理论加速上限受限于约 1/(2ρ)（ρ=0.3 时 1.67×）；
  - 低负载（λ<30 req/s）时因 eager 模式小核调度开销，TTFT 反而慢于基线（0.43–0.67×）；
  - 权重加载（27.5GB HBM 读取）在短 prompt 下主导延迟，导致延迟节省不随 ρ 线性缩放。
- **实验覆盖**：Llama 8B→70B 仅用 300 条 GSM8K 样本；部分 ρ 档位缺失；系统实验仅覆盖单一模型对（0.6B→14B）与单一 GPU 型号；未报告端到端生成（decode）阶段的性能影响。
