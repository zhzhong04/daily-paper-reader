## 摘要
智能体式 LLM 推理在迭代的观察-推理-动作循环中会累积长 KV 缓存，带来显著的内存开销并限制服务吞吐。现有压缩方法侧重于整体输出质量，忽视了动作在推动任务进展中的不对称重要性。我们的核心思想是建立一种压缩准则，根据 KV 条目对动作生成的贡献来衡量其价值，并优先保证动作质量。然而，迭代执行、动态内存需求以及分散的动作关键条目给逐出策略、预算分配和分页内存集成带来了挑战。为此，我们提出 ActKV，首个面向智能体式 LLM 推理量身定制的 KV 缓存压缩框架。(i) 面向动作的 KV 缓存逐出利用稳定的动作访问模式来保留对未来动作至关重要的条目，从而在压缩下支持可靠的任务进展。(ii) 置信度驱动的自适应预算分配利用 LLM 的内在置信度，使预算适应不断变化的动作关键内存需求。(iii) 页感知压缩管理将压缩标准化为三种原语，并配有定制内核，从而实现实际的吞吐收益。在长轨迹任务上，ActKV 仅使用 FullKV 峰值 KV 缓存内存的 25.98%，平均保留了其 98.53% 的准确率。它还实现了 FullKV 令牌吞吐量和任务吞吐量的 3.97 倍和 3.58 倍，达到最先进性能。

## Abstract
Agentic LLM inference accumulates long KV caches across iterative observation-reasoning-action loops, imposing substantial memory overhead and limiting serving throughput. Existing compression methods emphasize overall output quality, overlooking the asymmetric importance of actions in driving task progress. Our key idea is to establish a compression criterion that values KV entries by their contribution to action generation and prioritizes action quality. However, iterative execution, dynamic memory demands, and scattered action-critical entries pose challenges to eviction policies, budget allocation, and paged memory integration. To this end, we propose ActKV, the first KV cache compression framework tailored for agentic LLM inference. (i) Action-oriented KV cache eviction exploits stable action access patterns to retain entries critical to future actions, supporting reliable task progress under compression. (ii) Confidence-driven adaptive budget allocation uses LLM's intrinsic confidence to adapt the budget to evolving action-critical memory demands. (iii) Page-aware compression management standardizes compression into three primitives with customized kernels, realizing practical throughput gains. On long-trace tasks, ActKV retains an average of 98.53% of FullKV's accuracy with only 25.98% of its peak KV cache memory. It also achieves 3.97 times and 3.58 times FullKV's token and task throughput, delivering state-of-the-art performance.

- **背景**：现代 LLM 智能体（如 OpenClaw、Claude Code、Codex）遵循 ReAct 式的"观察-推理-动作"（Observation-Reasoning-Action, ORA）迭代循环。框架反复扩展 prompt、LLM 生成推理与动作 token，轨迹不断累积，形成极长的 KV 缓存。
- **痛点规模**：文中给出具体例子——Qwen3-30B 完成一次 WebShop 任务需约 25 轮迭代、约 35K token，占用 3.20 GB KV 缓存，其中观察与推理条目占 **99% 以上**。批处理服务时内存开销进一步放大，限制并发与吞吐；长序列还会稀释注意力、降低准确率。
- **现有方法的根本错配**：
  - 主流 KV 压缩（H2O、SnapKV、StreamingLLM、R-KV 等）面向常规文本生成，假设 token 重要性均匀，通过近似"近未来注意力"贪心驱逐低分条目。
  - 但智能体推理中 token 重要性**高度不对称**：观察与推理多为内部状态、对用户隐藏甚至无用；只有动作 token 改变环境、决定任务成败。短期保留推理所需条目可能损害后续动作（第 3.1 节）。
- **核心思想**：建立以"对动作生成的贡献"为价值尺度的压缩准则，优先保障动作质量。
- **三大挑战**：
  1. **保留什么**（What to keep）：迭代执行需要稳定准则识别"动作关键"KV 条目；
  2. **保留多少**（How much）：动作关键内存需求动态变化，需要自适应预算；
  3. **如何高效压缩**（How to compress）：动作关键条目分散，与分页/块级内存管理（PagedAttention）不匹配。
- **整体意义**：作者主张高效智能体服务应让内存管理对齐"任务结果"而非"逐 token 保真"，为内存高效的智能体系统提供原则性基础。ActKV 是首个面向智能体 LLM 推理的 KV 缓存压缩框架。

## 2. 方法论

### 2.1 总体框架（Fig. 5）
ActKV 由三个模块协同构成，每个 ORA 轮结束触发压缩，形成"生成行为 ↔ KV 管理"的轻量反馈闭环：
1. 面向动作的 KV 缓存驱逐；
2. 置信度驱动的自适应预算分配；
3. 页感知压缩管理（系统层接口）。

### 2.2 模块一：面向动作的 KV 缓存驱逐（Sec. 5）
- **关键观察**：同一任务内动作具有语义、上下文、结构上的相似性（动作类型有限、参数复用共享上下文、输出遵循标准模板），导致动作关键 KV 条目**跨迭代稳定但间歇性贡献**。
- **动作访问向量（AAV）**：`AAV_kv = [a1, a2, ..., an]`，其中 `a_i = 1` 表示该条目在第 i 个动作区域的注意力分数落入 top-p（90%）。据此分为三类：
  - *cold-start*（起始多个 0）：占比可忽略（0.7%~5.8%）；
  - *continuous*（无中断）：数量最多（58.5%~64.3%），但单次注意力贡献较低；
  - *intermittent*（中间有 0）：数量约 30%~41%，但单次注意力贡献高，容易被"仅看当前动作"的策略误删。
- **注意力感知 LRFU 策略**：从静态重要性转向"时间性 KV 效用"——只有长时间未贡献高注意力才应被驱逐。保留分数更新公式：
  `KS_t(i) = λ · KS_{t-1}(i) + AttnScore_t(i) · {hit at t}`
  - `λ ∈ [0,1]` 为衰减因子；λ=0 偏重近期（会误删间歇条目），λ=1 偏重频率（会保留过时连续条目）；0<λ<1 兼顾两者（实验取 **λ=0.5**）。
- **算法流程（Algorithm 1）**：① 用 `PagedCalAttn` 获取动作区域注意力；② 为新 ORA 条目初始化保留分数并拼接；③ 由 top-p 生成 hit/miss 掩码；④ 按上式更新分数；⑤ `TopK(KS, k=B)` 选出保留条目；⑥ 调用 `PagedCompaction` 压实缓存。

### 2.3 模块二：置信度驱动自适应预算分配（Sec. 6）
- **关键观察**：预算过紧会破坏动作关键信息，模型被迫延长推理以"复述/修复"缺失上下文（出现 "wait"、"I guess"、"let me check" 等低置信标记），表现为**置信度下降**。因此置信度可作预算充分性的在线信号。
- **置信度监控器**（三级）：
  - **Token 级**：`T_i = -(1/k) Σ_{j=1}^{k} log P_i(j)`（取 top-k 概率的负平均对数概率，k=20）；
  - **轨迹级**：滑窗（w=64，步长 s=8）+ 最小池化，再取底部 b%（b=10）保留，突出局部低置信段；
  - **趋势检测**：对轨迹级序列做一阶最小二乘拟合得斜率 α。
- **预算调整（Algorithm 2）**：监控与推理并行（开销可忽略）。触发压缩时，若 α<0（置信度下降）则 `B' = min(B · scale_up, B_upper)`（scale_up=1.75，上限 30K 条目）。初始预算仅 512 条目，随置信度下降才扩张；置信度稳定/恢复时维持当前预算（避免预算缩减造成二次信息损失）。

### 2.4 模块三：页感知压缩管理（Sec. 7）
- **统一三原语**：`AttnScore ← CalAttn(target_q, KCache)`；`KeepMask ← Eviction(AttnScore, Budget)`；`KVCache ← Compaction(KVCache, KeepMask)`。驱逐策略与内存布局无关，系统瓶颈集中在注意力计算与缓存压实。
- **恢复式注意力计算内核（Algorithm 3）**：利用分页注意力产生副产品 LSE（log-sum-exp），由 `A_{i,j} = exp(s_{i,j} - LSE_i)` 恢复注意力分数，避免重新计算或把散页聚合成连续内存。在 GQA 下按请求/逻辑块/KV 头并行，跨 query head 取最大值并在动作 token 上增量更新均值，动作区域入口重置。Triton 实现。
- **原地压实内核（Algorithm 4）**：观察到驱逐后保留条目偏向尾部，故将保留条目压入最后 X 个逻辑块：
  `X = ⌈budget / block_size⌉`，`start = (Y - X)·block_size`，`end = start + budget`。
  目标槽 = 尾区内被驱逐位置，源槽 = 尾区外的保留条目；经 slot map 映射到物理槽，源/目标不相交，故**无读写冲突、单趟原地拷贝、无需辅助 KV 缓冲区**；压缩后释放的空闲块归还服务系统复用。

### 2.5 其他要点
- 作者强调**上下文工程（Context Engineering）与 KV 压缩正交**：前者决定"什么文本进入模型"，后者决定"哪些运行时 KV 状态值得保留"。
- 实现上同时支持 Transformers (v5.3.0) 与 vLLM (v0.19.0)，后者直接集成到分页内存管理。
- 系统 prompt 与用户任务描述对应的 KV 条目始终保留，不参与压缩。
