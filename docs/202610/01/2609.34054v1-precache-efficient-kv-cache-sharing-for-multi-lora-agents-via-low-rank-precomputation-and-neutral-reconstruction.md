## 摘要
多 LoRA 智能体系统通过共享一个通用骨干模型来实现高效的角色专业化。然而，每个智能体都会重复处理不断增长的共享轨迹并构建自己的 KV 缓存，从而在长时程任务中引入大量内存与计算冗余。现有 KV 缓存共享方法减少了这种重复预填充，但它们要么需要额外训练或架构约束，要么仍保留大量模型计算。此外，直接复用缓存会使当前智能体依赖前一个智能体适配器生成的缓存状态，从而削弱其自身 LoRA 所编码的角色特定行为。我们提出 PReCache，一种免训练的 KV 缓存共享框架，包含两种设计，即 PreLRShared 和 ReBaseShared；它们共享使用预训练权重计算的基础缓存，并预计算紧凑的、智能体特定的低秩（LR）缓存。为消除重复预填充，PreLRShared 在首次处理共享上下文时预计算每个智能体的 LR 缓存，使当前智能体无需重新处理先前智能体已处理的上下文即可使用自己的 LR 缓存。为提高共享准确性，ReBaseShared 从无适配器的隐藏状态重建共享基础缓存，减少由前一智能体适配后表示所造成的残余误差。为最小化其重建成本，我们提出两种推理方案，分别面向单流推理与并发服务：在每轮智能体之后执行同样的重建，或与其执行并行进行。在多个模型和智能体基准上，与不使用 KV 缓存共享的推理相比，PreLRShared 实现了最高 3.1 倍的 TTFT 加速和 2.3 倍的每请求吞吐量提升。在评估的缓存共享方法中，ReBaseShared 总体上最能保持准确性，相对于不使用缓存共享的推理，平均仅下降 1.1 个点。

## Abstract
Multi-LoRA agent systems enable efficient role specialization by sharing a common backbone model. However, each agent repeatedly processes the growing shared trajectory and constructs its own KV cache, introducing substantial memory and computation redundancy in long-horizon tasks. Existing KV cache sharing methods reduce this repeated prefill, but they either require additional training or architectural constraints or retain substantial model computation. Moreover, direct cache reuse causes the current agent to rely on cache states generated by the previous agent's adapter, weakening the role-specific behavior encoded by its own LoRA. We present PReCache, a training-free KV cache sharing framework with two designs, namely PreLRShared and ReBaseShared, that share the base cache computed using the pretrained weights and precompute a compact agent-specific low-rank (LR) cache. To remove repeated prefill, PreLRShared precomputes each agent's LR cache when the shared context is first processed, allowing the current agent to use its own LR cache without reprocessing context processed by previous agents. To improve sharing accuracy, ReBaseShared reconstructs the shared base cache from adapter-free hidden states, reducing the remaining error caused by the previous agent's adapted representation. To minimize its reconstruction cost, we propose two inference schemes tailored to single-stream inference and concurrent serving, performing the same reconstruction after each agent's turn or alongside its execution, respectively. Across multiple models and agent benchmarks, PreLRShared achieves up to a 3.1x TTFT speedup and a 2.3x improvement in per-request throughput over inference without KV cache sharing. ReBaseShared best preserves accuracy overall among the evaluated cache-sharing methods, with an average drop of only 1.1 points relative to inference without cache sharing.

## 1. 核心问题与整体含义（研究动机与背景）

- **多 LoRA 智能体系统的结构性冗余**：多智能体系统通过共享同一个预训练骨干模型、为每个角色挂载轻量 LoRA 适配器来实现角色专业化（规划、行动、反思等）。随着轮次增加，共享轨迹（用户请求、检索信息、工具观测、前序智能体输出）不断累积，形成长而"预填充密集"的上下文。
- **双重冗余**：每个智能体都独立地对已被前序智能体处理过的上下文重复预填充，既重复计算，又为同一段上下文各自维护一份 KV 缓存，导致显存浪费。
- **直接复用的代价**：不同适配器权重会产生不同 KV 缓存，直接复用（FullShared）会造成明显精度下降。原因是适配器贡献经逐层传播后使隐藏状态变为智能体相关，连"基座贡献"也随之不同，从而削弱当前智能体自身 LoRA 编码的角色特定行为。
- **现有方案的困境**：
  - 跨模型/智能体的缓存共享方法（学习映射、校准变换、专用结构）需要额外训练、成对校准模型或特定架构，无法直接用于既有 LoRA 适配器。
  - 免训练的偏差校正方法（KVComm、KAMERA 等）针对"前缀/位置差异"，在多智能体前缀与位置匹配的场景下校正变量不变，退化为 FullShared。
  - 选择性重计算（DroidSpeak、CacheBlend、RelayCaching）在异构 LoRA 下仍残留精度损失；提高重算比例又会抵消计算与显存收益。
  - LRAgent 的 BaseShared 通过"共享基缓存 + 智能体特定 LR 缓存"降低显存并保精度，但构建 LR 缓存仍需对累积上下文做全长骨干前向，重复预填充几乎未被消除；BaseLRShared 虽消除重复处理，却要求所有适配器训练时共享 LoRA 下投影，不支持既有适配器。
- **核心挑战与含义**：在不重训练、不限制现有 LoRA 适配器结构的前提下，同时降低 KV 缓存显存占用与重复预填充计算，且不显著损失精度。Table 1 明确给出 PReCache 在"精度保持 / 重复预填充消除 / 既有适配器支持"三项标准上同时为 ✓ 的定位。

## 2. 方法论

### 2.1 基础记号与分解思想

- 冻结骨干投影 $W_0 \in \mathbb{R}^{d_{in}\times d_{out}}$，智能体 $i$ 的 LoRA 权重 $A_i \in \mathbb{R}^{d_{in}\times r}$、$B_i \in \mathbb{R}^{r\times d_{out}}$（$r \ll d_{in}, d_{out}$）。
- 输出分解为 **基座贡献** $X_{i,adpt}W_0$ 与 **适配器贡献** $(X_{i,adpt}A_i)B_i$ 之和；适配器贡献跨智能体不同，并逐层传播，因此隐藏状态与基座贡献都变为智能体相关。
- 由此得到缓存分解：共享基缓存 + 各智能体紧凑的低秩（LR）缓存。

### 2.2 PreLRShared：LR 缓存预计算

- **核心思想**：在每段共享上下文**首次**被处理时，就为**所有**智能体预计算 LR 缓存，而非等各智能体轮到时各自重建。
- **流程**：智能体 $i$ 处理 $L^P$ 时，把产生的隐藏状态 $X_{i,adpt}$ 施加每个智能体 $k$ 的下投影 $A_k$，得到 $X_{i,adpt}A_k \in \mathbb{R}^{L^P\times r}$，为所有 $k=1,\dots,N$ 构建 LR 缓存。智能体 $i$ 轮次结束时，共享基缓存与全部 LR 缓存已覆盖 $L^P$。
- **效果**：后续智能体 $j$ 直接复用共享基缓存与自己的 LR 缓存，只需对**新增上下文** $L^C$ 做适配后的骨干计算，并在处理过程中继续扩展各智能体 LR 缓存。本质上把"后续全长、全维度骨干前向"替换为"轻量 rank-$r$ 下投影"。
- 局限：其共享基缓存仍由**前一个智能体的适配后隐藏状态**构造，存在前序智能体依赖。

### 2.3 ReBaseShared：中性基缓存重建

- **核心思想**：用**关闭适配器**的路径处理共享上下文，得到无适配器隐藏状态 $X_{neut}$，构造"中性基缓存" $X_{neut}W_0$，替代前序智能体适配状态下的基缓存，降低对前序智能体的依赖；同时**保留** LR 缓存预计算（其他智能体的 LR 缓存也用同一批无适配器隐藏状态构建）。
- **理论分析**（附录 A.1）：设 $C_i = X_{i,adpt}W_0$、$C_j = X_{j,adpt}W_0$、$C_{neut} = X_{neut}W_0$；偏移 $\Delta_i = C_i - C_{neut}$、$\Delta_j = C_j - C_{neut}$。则
  - 复用前序基缓存的相对误差 $E_{prev} = \lVert \Delta_i - \Delta_j\rVert_2 / \lVert C_j\rVert_2$；
  - 使用中性基缓存的相对误差 $E_{neut} = \lVert \Delta_j\rVert_2 / \lVert C_j\rVert_2$；
  - 定义范数比 $\rho = \lVert\Delta_i\rVert_2/\lVert\Delta_j\rVert_2$ 与余弦相似度 $\cos\theta$，误差比 $\Gamma_{err} = \sqrt{1+\rho^2-2\rho\cos\theta}$；
  - 结论：$E_{prev} \ge E_{neut} \iff \rho \ge 2\cos\theta$，即当 $\Gamma_{err} > 1$ 时中性基缓存误差更小。
- **两种推理调度（同一重建逻辑，仅时机不同，缓存状态逻辑等价）**：
  - **ReBaseShared DB（Double Batching）**：适配路径与无适配路径在预填充与解码阶段**同时**批处理，处理相同 token、相同位置，各自维护独立 KV 视图；适配路径关注当前智能体 KV 缓存并产出 next-token logits，无适配路径只关注中性基缓存并扩展之，因此不影响当前智能体生成。适合**并发服务端**，避免单独预填充造成的排队延迟。
  - **ReBaseShared LP（Lazy Prefill）**：智能体轮次内只跑适配路径；解码结束后，用关闭适配器的方式对新增上下文 $L^C$ 做**一次连续预填充**，从已有中性基缓存扩展。适合**单流边缘推理**，无需维持第二条解码路径，且可与工具调用重叠。
- 整体上 PReCache 是**免训练**框架，不改变架构、不限制适配器放置（QV/QKVO 均可）。
