## 摘要
长上下文推理与行动（ReAct）智能体的高效服务依赖 KV 缓存复用来降低大语言模型（LLM）预填充延迟和成本。然而，智能体执行框架与底层服务栈之间存在语义鸿沟。通过上下文变更、工具执行和子智能体协同，上下文消息可能处于活跃使用、永久丢弃或暂时未用状态，而服务栈只能观察到对相应 KV 缓存的访问。这种生命周期盲区使得仅依赖新近度的策略（如 LRU）无法及时回收已失效的 KV，也无法保留那些会比更新条目更早被复用的较旧 KV。我们提出 KVTether，一种面向 ReAct 智能体的生命周期感知 KV 缓存管理框架。通过追踪嵌入在智能体执行框架中的语义原语，KVTether 能在高度动态的执行过程中捕获运行时生命周期语义。随后，KVTether 将消息级语义转换为 KV 级生命周期状态，并利用这些状态驱动按状态优先的缓存管理，而无需向智能体执行框架暴露物理复杂性。在回收已失效 KV 后，KVTether 优先保留等待复用的存活但空闲 KV，减少复用前的过早驱逐。在智能体基准和生产负载中，相较于 LMCache 和 MORI，KVTether 将端到端请求延迟分别最多降低 26.3% 和 17.4%，并将估计任务成本平均降低 40.0% 和 33.2%。

## Abstract
Efficient serving of long-context reasoning-and-acting (ReAct) agents relies on KV cache reuse to reduce large language model (LLM) prefill latency and monetary cost. However, a semantic gap exists between agent harnesses and the underlying serving stack. Through context mutation, tool execution, and subagent coordination, context messages may become actively engaged, permanently discarded, and temporarily unused, while the serving stack only observes accesses to the corresponding KV cache. This lifecycle blindness prevents recency-only policies such as LRU from reclaiming dead KV promptly and from preserving older KV that will be reused sooner than newer entries.   We present KVTether, a lifecycle-aware KV cache management framework for ReAct agents. By tracing semantic primitives embedded in agent harnesses, KVTether captures runtime lifecycle semantics during highly dynamic execution. KVTether then translates message-level semantics into KV-level lifecycle states and uses these states to drive state-prioritized cache management without exposing physical complexities to agent harnesses. After reclaiming dead KV, KVTether preferentially preserves live-but-idle KV that is waiting for reuse, reducing premature eviction before reuse. Across agent benchmarks and production workloads, KVTether reduces end-to-end request latency by up to 26.3% and 17.4% relative to LMCache and MORI, respectively, and lowers estimated task cost by 40.0% and 33.2% on average.

# KVTether 论文总结

## 1. 核心问题与整体含义

- **背景**：主流智能体（Claude Code、Codex、OpenClaw、Hermes）以 ReAct 循环执行任务，交替进行 LLM 推理与工具调用。单个请求可跨越数十到上百轮，累积数十万 token（Codex 请求可达 258K token 上下文），对应 GLM-4.7 下约 93GB 的 KV 缓存，因此 KV 复用是降低预填充（prefill）延迟与成本的关键。
- **核心问题：语义鸿沟（semantic gap）**。智能体执行框架（harness）在**消息级**管理上下文（append / replace / remove / fork / one-shot 构造），定义了消息的逻辑生命周期；而底层服务栈（vLLM、SGLang、LMCache、MoonCake）只看到 token 前缀、缓存页和访问事件，**无法判断某段 KV 在逻辑上仍是存活的、被显式保留的、暂时等待的，还是已经死亡**。
- **由此导致两类失效**：
  - **存活失效（liveness failure）**：逻辑生命周期已结束的"僵尸 KV"仍常驻。回放显示僵尸 KV 最高占 LMCache 容量的 36.3%（Agent-X 31.1%、Codex 36.3%、Agent-G 15.8%）；MORI 因依赖请求空闲度，峰值更高（49.7% / 33.1% / 27.4%）。
  - **排序失效（ordering failure）**：即便排除死 KV，LRU 等仅看新近度的策略仍会错序驱逐。按 Belady 准则统计，LMCache 的"错向驱逐"比例达 71.0%–95.0%，MORI 为 45.7%–75.6%。原因是 ReAct 中**新产生的 KV 常要等待工具、子智能体或调度**，反而比更旧的 KV 更晚被复用。
- **量化影响**：三种负载下实际 KV 命中率仅 28.1%（LMC）与 39.8%（MORI），远低于离线逐个回放得到的理论上限 82.8%；prefill 仍占总执行时间 37.6%（LMC）/ 34.6%（MORI）。
- **整体含义**：ReAct 服务的生命周期信息**必须由应用层在运行时导出**，而非由下层推断——因为替换、删除、一次性构造、保留意图等事件只存在于 harness 的消息级上下文管理中，且执行拓扑是运行时涌现的（Agent-X 中子智能体承担的 LLM 轮次占比在 1.6%–86.5% 间波动），无法用预定义工作流结构刻画。

## 2. 方法论

**核心思想**：把生命周期导出放在**消息操作层**（harness 已有的上下文管理代码位置），由事件驱动管理器翻译为 KV 级生命周期状态，再由状态优先的缓存引擎执行准入与驱逐，全程不向 harness 暴露分页、前缀依赖等物理细节。

### 2.1 语义原语模型（§4）
- 提供 8 个消息级原语，构成 harness 与服务栈之间的通用语义契约：
  - **消息编辑**：`append`、`replace`、`remove`
  - **上下文创建**：`fork`（子上下文继承父前缀）、`spawn`（独立子上下文）
  - **生命周期声明**：`one_off`（仅一次推理）、`pin`（长期保留）、`unpin`（释放保护）
- **表达力论证**：空间上，消息列表变更可归结为增、改、删（组合即可表达顺序变化）；时间上，新上下文或独立开始、或继承已有消息，消息可单次使用、跨轮复用或被显式保留。更复杂的功能（如安全审查、压缩、长期记忆）可由这些原语组合表达。
- **集成方式**：通过继承/包装既有 `ContextManager` 并转发原语调用实现，开发者无需接触 token 或 KV 页。

### 2.2 事件驱动生命周期管理器（§5）
- **KV 范围解析**：以"上下文"为管理单元，维护消息→token→KV 范围的映射；沿用与推理引擎一致的 prompt 格式化与 tokenization 路径。
  - `remove` / `replace` 受**前缀依赖有效性**约束：中间消息变更会使后续 KV 后缀失效，统一翻译为**后缀失效**并进入 `Expired`。
  - 物理翻译以 **KV 是否已存在**为门控：只在推理边界更新；两次推理之间按程序序串行处理事件，下次推理时发出最小化的失效与更新动作。
- **生命周期状态**（图 9）：Pinned（显式保护）、Active（新追加或参与请求）、Suspended（prefill 完成后进入空闲）、Expired（生命周期结束）、Temporary（一次性推理的临时消息）。关键转移包括：
  - 请求完成 prefill 时，Active → Suspended；下一请求前再激活；
  - 上下文终止时普通消息 → Expired，Pinned 消息保持保护；
  - `unpin` 后有效消息回到 Suspended，若上下文已终止则回到 Expired；
  - `fork` 后父/子消息状态**独立演进**；`one_off` 使既有及后续追加消息标记为 Temporary。
- **共享 KV 处理**：一条 token 的 KV 可能映射到多个上下文的多个消息版本，KVTether 取**最高优先级的映射状态**参与驱逐决策；仅当所有映射版本都 Discarded 时才真正可回收。

### 2.3 状态引导的 KV 缓存引擎（§6）
- **第一步：分离确定性与不确定性（Algorithm 1，状态优先准入）**
  - 若到达的 KV 状态为 `Temporary` → 直接绕过（bypass），不进入复用存储；
  - 否则计算缺口 Δ = 新 KV 大小 − 空闲容量，依次按状态释放：先 `Expired`（主动回收死 KV），再 `Suspended`，再 `Active`；
  - 仅当新 KV 自身为 `Pinned` 时，才允许与 `Pinned` 常驻 KV 竞争；
  - Δ ≤ 0 时准入。
  - 该顺序把语义上已确定的情形从容量竞争中剔除，避免死 KV 与高优先级存活 KV 扭曲真正不确定的 idle 层的驱逐决策。
- **第二步：Suspended 层内排序（MRU）**
  - 观察（图 10）：writeback 后的复用并不集中在最年轻的条目，而是聚集在数秒之后——Agent-G 43.1% 的复用发生在 1–3 s，Codex 46.6% 在 3–6 s，Agent-X 87.5% 在 2–4 s。
  - 因此在 `Suspended` 层内采用 **MRU（最久未被使用优先驱逐）**：优先驱逐最新挂起的 KV，保留已等待更久、更接近真实复用的旧 KV，从而缓解错向驱逐。
  - 作者强调这是利用 ReAct 执行带来的**稳定方向性偏置**，而非精确的逐条复用预测；部署引入排队会整体拉长复用区间，但只要缓存事件的相对顺序保持（如 FIFO）该趋势仍然可用。

### 2.4 实现（§7）
- 三组件：轻量 in-harness 框架（同步记录原语、异步按序导出，保持在关键路径外）；服务端 Python 生命周期管理器（复现引擎的格式化/分词流水线，在 LLM 调用前传递 call ID 与 context ID）；运行于 GPU HBM / 主机内存 / 远端内存多级缓存上的状态引导策略（区分全局生命周期控制与分层缓存），提供原生 CUDA + MoonCake 传输路径，并兼容代理到 LMCache / MoonCake Store。

## 3. 实验设计

- **负载 / 场景**（3 个）：
  - **Codex**：自部署的软件工程智能体（基于 Codex）运行 **TerminalBench**，LLM 请求由 DeepSeek-V4-Pro 提供。
  - **Agent-X / Agent-G**：某大型云厂商部署的两个生产编码智能体，各采集 **400 条轨迹**，合计峰值超 27,000 个活跃会话。
  - 请求规模：3–127 个 LLM 轮次、9K–374K prefill token、3–134 GB KV；工具类型 1–47 种。
- **回放设置**：在真实集群上按轨迹逐任务回放，使用随机 prompt 但精确匹配每轮的输入 token 数与记录的输出 token 数，并调整 prompt 内容以精确匹配可复用前缀长度；工具调用按记录时长等待以消除工具时延波动。生命周期事件按原执行点与相对 LLM 调用的顺序回放（Codex 在线集成记录；Agent-X/Agent-G 从日志离线重建，仅使用该执行点可得信息）。
- **负载强度**：每个轨迹 5 个 RPS 设置、Poisson 到达，共 15 个设置点；任务样本与到达序列在各方法间完全一致。
- **对比方法**：
  - **LMCache (LMC)**：语义盲、基于页访问新近度的 LRU 驱逐。
  - **MORI**：智能体感知基线，以"相对空闲度"（近期花在工具调用上的时间占比，含进行中调用）排序程序，偏好忙碌程序常驻、更多空闲程序卸载/驱逐，并在两层做准入控制。
- **指标**：KV 缓存命中率、累计 prefill 时间、端到端延迟、平均任务定价（按 DeepSeek-V4-Pro 峰值费率：缓存命中输入 $0.044/M、未命中输入 $1.32/M、输出 $3.96/M）。
- **消融**：`KVTether w/o LT`（去掉生命周期追踪与状态引导、保留 MRU）与 `KVTether w/o RO`（保留生命周期追踪与状态优先级、Suspended 层内用 LRU 替代 MRU）。
- **可用性实验**：在 6 个 harness（Codex、SWE-agent、OpenCode、Hermes、Agent-G、OpenClaw）上统计集成代码量，并以 Codex 为例给出安全审查（one-off）与子智能体 fork 的集成案例。
- **开销实验**：原语记录、LLM 调用拦截、KV 范围解析、资源占用。

## 6. 主要结论与发现

- **生命周期语义是 ReAct 服务中被系统性忽略的一阶信息**。论文的核心论断是：僵尸 KV 与错向驱逐并非容量或算法精度问题，而是"消息级生命周期"与"token 级缓存视图"之间语义鸿沟的直接后果。前者最高占容量 36.3%（MORI 达 49.7%），后者错向比例达 71.0%–95.0%（MORI 45.7%–75.6%），说明即便给定完美的容量与替换策略，缺乏语义仍会持续做错决策。
- **"状态优先"比"新近度优先"更贴合 ReAct 的复用结构**。把 `Expired` / `Temporary` 从容量竞争中剔除，使驱逐决策只在真正不确定的 `Suspended` 层内进行；再在该层内以 MRU 替代 LRU，利用了"新挂起的 KV 往往因等待工具/子智能体而更晚复用"这一稳定偏置。消融显示两处贡献可分离：`w/o LT` 退化到语义盲的页级 LRU，`w/o RO` 保留生命周期但层内仍按 LRU 排序，二者均低于完整方法，印证"先分层、再排序"的联合必要性。
- **命中率与成本的量化收益**。论文将实际命中率从 LMCache 的 28.1%、MORI 的 39.8% 向离线理论上界 82.8% 显著拉近，同时把 prefill 占总执行时间的比例从 37.6%（LMC）/ 34.6%（MORI）进一步压低；在 DeepSeek-V4-Pro 峰值费率下，命中输入与未命中输入存在约 30 倍价差（$0.044/M vs $1.32/M），因此命中率提升直接转化为平均任务定价下降，且该收益随请求规模（最高 374K prefill token、134 GB KV）放大。
- **生命周期导出具有工程可行性**。集成实验在 6 个 harness（Codex、SWE-agent、OpenCode、Hermes、Agent-G、OpenClaw）上完成，说明 8 个原语并非为单一框架定制，而是可复用的最小语义契约；原语记录、LLM 调用拦截、KV 范围解析与资源占用的开销测量表明，追踪逻辑可置于关键路径之外（同步记录、异步按序导出），不显著影响推理时延。
- **对"智能体感知"缓存设计的启示**。MORI 已尝试用"相对空闲度"刻画智能体行为，但仍是从外部行为（工具耗时占比）间接推断生命周期；KVTether 的对比表明，间接推断在僵尸占比与错向驱逐上均劣于显式导出，说明**智能体服务的缓存优化应上移语义边界，而非在下层做更聪明的猜测**。

## 7. 局限与可讨论之处

- **评测方法学**：每个 RPS 配置点未见多次重复与方差/置信区间报告，单次回放对结论稳定性构成一定风险，尤其对"错向驱逐比例"这类依赖访问序列统计的指标。
- **可复现性**：Agent-X、Agent-G 为内部生产轨迹，Codex 亦为自部署，公开数据缺失使外部复现困难；回放中"随机 prompt + 精确匹配 token 数与可复用前缀长度"的构造虽在控制变量上严谨，但与真实语义内容存在偏差，可能影响真实复用模式。
- **基线覆盖**：仅对比 LMCache 与 MORI，未纳入论文相关工作讨论的 KVFlow、TokenCake、Continuum、CacheWise 等方法，横向比较面偏窄，难以判断 KVTether 在"语义感知"这一维度上的相对优势幅度。
- **通用性边界**：MRU 的合理性建立在"复用集中在挂起后数秒"这一观察上（Agent-G 1–3 s、Codex 3–6 s、Agent-X 2–4 s）。论文承认部署排队会拉长该区间，只要相对顺序（如 FIFO）保持则趋势可用；但若负载调度策略、工具并行度或子智能体拓扑发生质变，该方向性偏置是否稳健尚需验证。
- **语义契约的维护成本**：8 个原语需要 harness 开发者在上下文管理代码中正确标注生命周期意图；若标注错误（如漏标 `one_off` 或误用 `pin`），缓存侧将按错误状态执行准入与驱逐。论文未量化标注错误下的鲁棒性。

## 8. 总体评价

KVTether 的价值不在于提出一种新的替换算法，而在于**重新定位了问题**：把 ReAct 服务的 KV 复用从"页级新近度预测"重构为"消息级生命周期导出 + 状态分层管理"。其论证链条完整——先以回放数据量化语义鸿沟造成的两类失效，再给出原语模型、状态机与状态引导缓存引擎，最后以 15 个配置点的端到端回放、两组消融与多 harness 集成支撑可行性。方法的抽象层级选择（在 `ContextManager` 层拦截、对 harness 隐藏物理细节）兼顾了通用性与低侵入性，是较具实践参考价值的设计。

主要保留意见在于评测的可复现性与基线覆盖：内部轨迹、单次回放、窄基线使得"提升幅度"的普适性证据尚不充分。若能补充公开负载、多次运行的统计显著性，以及与方法学相近的语义感知基线对比，结论将更具说服力。总体而言，这是一篇问题定义清晰、工程落地扎实、实验设计在控制变量上较为严谨的智能体推理系统工作。
