## 摘要
多 LoRA 智能体系统通过共享一个公共主干模型，实现高效的角色专门化。然而，每个智能体都会重复处理不断增长的共享轨迹，并构建自己的 KV 缓存，从而在长时程任务中引入大量内存和计算冗余。现有的 KV 缓存共享方法减少了这种重复预填充，但它们要么需要额外训练或架构约束，要么仍保留大量模型计算。此外，直接复用缓存会使当前智能体依赖于前一个智能体的适配器所生成的缓存状态，从而削弱其自身 LoRA 所编码的角色特定行为。我们提出 PReCache，一种无需训练的 KV 缓存共享框架，包含两种设计，即 PreLRShared 和 ReBaseShared，它们共享使用预训练权重计算的基础缓存，并预计算紧凑的、智能体特定的低秩（LR）缓存。为消除重复预填充，PreLRShared 在首次处理共享上下文时为每个智能体预计算其 LR 缓存，使当前智能体能够使用自己的 LR 缓存，而无需重新处理先前智能体已处理的上下文。为提高共享准确性，ReBaseShared 从无适配器的隐藏状态中重建共享基础缓存，减少由前一个智能体的适配后表示所导致的残余误差。为最小化其重建开销，我们提出两种分别面向单流推理与并发服务的推理方案，分别在每个智能体轮次之后执行相同的重建，或在其执行的同时进行重建。在多个模型和智能体基准上，与无 KV 缓存共享的推理相比，PreLRShared 实现了最高 3.1 倍的 TTFT 加速和 2.3 倍的每请求吞吐量提升。在评估的缓存共享方法中，ReBaseShared 总体上最好地保持了准确性，相对于无缓存共享的推理，平均仅下降 1.1 个点。

## Abstract
Multi-LoRA agent systems enable efficient role specialization by sharing a common backbone model. However, each agent repeatedly processes the growing shared trajectory and constructs its own KV cache, introducing substantial memory and computation redundancy in long-horizon tasks. Existing KV cache sharing methods reduce this repeated prefill, but they either require additional training or architectural constraints or retain substantial model computation. Moreover, direct cache reuse causes the current agent to rely on cache states generated by the previous agent's adapter, weakening the role-specific behavior encoded by its own LoRA. We present PReCache, a training-free KV cache sharing framework with two designs, namely PreLRShared and ReBaseShared, that share the base cache computed using the pretrained weights and precompute a compact agent-specific low-rank (LR) cache. To remove repeated prefill, PreLRShared precomputes each agent's LR cache when the shared context is first processed, allowing the current agent to use its own LR cache without reprocessing context processed by previous agents. To improve sharing accuracy, ReBaseShared reconstructs the shared base cache from adapter-free hidden states, reducing the remaining error caused by the previous agent's adapted representation. To minimize its reconstruction cost, we propose two inference schemes tailored to single-stream inference and concurrent serving, performing the same reconstruction after each agent's turn or alongside its execution, respectively. Across multiple models and agent benchmarks, PreLRShared achieves up to a 3.1x TTFT speedup and a 2.3x improvement in per-request throughput over inference without KV cache sharing. ReBaseShared best preserves accuracy overall among the evaluated cache-sharing methods, with an average drop of only 1.1 points relative to inference without cache sharing.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM 智能体常被赋予专门化角色（规划、行动、反思等），多 LoRA 智能体系统通过共享一个预训练主干模型、为每个角色挂载轻量 LoRA 适配器，实现高效的角色专门化，并降低模型显存占用。
- **核心问题**：尽管主干共享，**每个智能体仍独立处理不断增长的共享轨迹**（用户请求、检索信息、工具观测、前序智能体输出），并各自构建 KV 缓存，在长时程任务中造成严重的**内存与计算冗余**（重复 prefill）。
- **现有方法的两难**：
  - 直接复用前一智能体的 KV 缓存（FullShared）会因适配器权重不同导致精度显著下降。
  - 选择性重计算（DroidSpeak、CacheBlend、RelayCaching）在异构 LoRA 适配器下精度恢复有限，且提高重计算比例会牺牲计算/内存收益。
  - BaseShared 通过分解为“共享基座缓存 + 智能体专属 LR 缓存”缓解了精度与内存问题，但**仍需对累积上下文做全长度主干处理来构建 LR 缓存**，重复 prefill 未真正消除。
  - BaseLRShared 虽能消除重复处理，但要求所有适配器在训练时共享同一 down-projection，**不支持现有异构 LoRA 适配器**。
- **核心挑战**：在**不重新训练、不限制现有 LoRA 适配器**的前提下，同时降低 KV 缓存内存与重复 prefill 计算，并保持角色特定行为与精度。

## 2. 方法论

### 2.1 核心思想
- 提出 **PReCache**：免训练的 KV 缓存共享框架，基于“**基座缓存（base cache）+ 智能体专属低秩缓存（LR cache）**”的分解，包含两个互补设计：
  - **PreLRShared**：消除重复 prefill。
  - **ReBaseShared**：提升共享精度。
- 基础公式：对适配器条件隐状态 $X_{i,\text{adpt}}$，投影输出为
  $$Y_i = X_{i,\text{adpt}}W_0 + (X_{i,\text{adpt}}A_i)B_i$$
  即分为**基座贡献**（共享）与**适配器贡献**（智能体专属，低秩）。

### 2.2 PreLRShared：LR 缓存预计算
- **关键观察**：LR 缓存宽度仅为 rank $r$，但构建它需要先计算全维度的 $X_{j,\text{adpt}}$，因此 BaseShared 保留了全长度主干处理。
- **做法**：当某段上下文**首次被处理**时（如智能体 $i$ 处理 $L_P$），对每个智能体 $k$ 施加其 down-projection $A_k$，构造 $X_{i,\text{adpt}}A_k \in \mathbb{R}^{L_P \times r}$，**一次性为所有智能体预计算 LR 缓存**。
- **效果**：后续智能体 $j$ 可直接复用共享基座缓存与自己的预计算 LR 缓存，仅需对新增加上下文 $L_C$ 做适配主干计算，避免重复处理累积轨迹 $L_P$。

### 2.3 ReBaseShared：中性基座缓存重建
- **动机**：即便 $W_0$ 共享，$X_{i,\text{adpt}}$ 仍携带前序智能体适配器的影响并逐层传播，使共享基座缓存仍依赖前一智能体。
- **做法**：**关闭适配器**，用无适配器隐状态 $X_{\text{neut}}$ 构造“**中性基座缓存**” $X_{\text{neut}}W_0$；同时仍保留 LR 缓存预计算，并可用同一批无适配器隐状态为其他智能体投影生成 LR 缓存。
- **理论条件**：设 $\Delta_i = C_i - C_{\text{neut}}$、$\Delta_j = C_j - C_{\text{neut}}$，定义 $\rho = \|\Delta_i\|/\|\Delta_j\|$，$\cos\theta$ 为二者夹角余弦，则相对误差比
  $$\Gamma_{\text{err}} = \frac{E_{\text{prev}}}{E_{\text{neut}}} = \sqrt{1+\rho^2-2\rho\cos\theta}$$
  当 $\rho \ge 2\cos\theta$（即 $\Gamma_{\text{err}} \ge 1$）时，**中性基座缓存比前一智能体基座缓存更接近当前智能体的目标缓存**。

### 2.4 两种推理调度
- **LP（Lazy Prefill，惰性预填充）**：当前智能体仅执行适配路径；解码结束后，用无适配器主干对新增上下文 $L_C$ 做一次**连续 prefill** 重建中性基座缓存。适合**单流边缘推理**。
- **DB（Double Batching，双重批处理）**：在 prefill 与 decoding 阶段**同时**调度适配路径与无适配器路径，二者处理相同 token 位置、维护独立 KV 视图，互不干扰。适合**并发服务端推理**，可减少排队延迟。
- 两种调度产生**逻辑等价的缓存状态**，仅执行时机不同。

## 6. 主要结论与发现

- **精度**：
  - ReBaseShared 在 4 个“模型 × 基准”组合中整体最接近 NonShared，**平均仅下降 1.1 个百分点**，与 BaseShared 相当。
  - PreLRShared 平均下降 1.0–3.3 个百分点，但仍**优于或持平于选择性重计算基线**。
  - ReBaseShared 通过无适配器重建**显著降低了 PreLRShared 的精度退化**。
- **效率**：
  - PreLRShared 相比 NonShared 实现最高 **3.1× TTFT 加速**、**2.3× 每请求吞吐提升**（单流）。
  - ReBaseSharedLP 实现最高 **3.0× TTFT 加速**、**1.6× 吞吐提升**（单流）。
  - 并发服务下，PreLRShared 与 ReBaseSharedDB 分别提供 **1.6× / 1.3×** 吞吐提升，并在高负载下保持更低 TTFT。
- **显存**：在 66.4k token 轨迹下，PreLRShared 与 ReBaseShared 峰值显存**接近 FullShared（差距 < 2%）**，比选择性重计算基线**低 17–23%**。
- **扩展性**：智能体数从 $N=4$ 增至 $N=8$ 时，PreLRShared 与 ReBaseSharedLP 的 TTFT 仅增加 3% / 7%，而基线增加 32–53%；显存仅增加 1–2%，基线增加 16–26%。
- **调度**：LP 更适合单流推理（TTFT 更低、吞吐更高），DB 更适合并发服务（避免额外 prefill 阻塞排队请求）。

## 7. 优点

- **免训练且兼容现有适配器**：不需要额外训练、不需要特定架构，也不要求适配器共享 down-projection，直接适用于现有异构多 LoRA 智能体系统。
- **同时解决内存与计算冗余**：通过“基座缓存共享 + LR 缓存预计算”分解，既减少 KV 缓存显存，又消除大部分重复 prefill。
- **理论支撑**：给出中性基座缓存误差更小的**充分条件（$\rho \ge 2\cos\theta$）**，并用逐层几何测量实证支持。
- **场景化调度设计**：LP 与 DB 分别针对单流边缘推理与并发服务，考虑周全，且二者逻辑等价、可按部署环境选择。
- **实验设计严谨**：使用控制轨迹隔离变量，报告 20 次运行标准差，包含丰富的消融（rank、投影、智能体数、调度）与多维度指标（精度、TTFT、吞吐、显存）。
- **保留角色专属性**：不同于直接缓存复用，PReCache 为每个智能体维护专属 LR 缓存，保留了 LoRA 所编码的角色特定行为。

## 8. 不足与局限

- **模型与数据集覆盖有限**：仅在两个 8B 级模型（LLaMA-3.1-8B、Ministral-8B）与两个 QA 数据集（HotpotQA、ScienceQA）上验证，未涉及更大规模模型、代码/工具使用/多模态等其他智能体任务。
- **训练算力信息缺失**：未报告 LoRA 适配器训练所需的 GPU 型号、数量与时长，难以评估总成本。
- **默认配置依赖**：主实验采用 QV 适配（仅 query/value 挂 LoRA）；QKVO 配置下效率优势减弱，且 key 侧适配需额外 LR 缓存计算，Flash-LoRA-Attention 的关联重排不直接适用。
- **精度仍有下降**：ReBaseShared 平均下降 1.1 个百分点，在 Ministral-8B + ScienceQA 上下降 2.60 个百分点，部分难度组退化更明显；精度提升并不在所有难度组上一致。
- **DB 调度开销**：DB 在单流场景下 TTFT 与吞吐均劣于 LP（66.4k 时 TTFT 49.29s vs. 27.24s），需依赖并发批处理才能体现优势。
- **ReBaseShared 吞吐低于 PreLRShared**：因额外的无适配器重建计算，ReBaseSharedLP 吞吐低于 PreLRShared（如 66.4k 时 1068 vs. 1685 tok/s），存在精度与效率的权衡。
- **BaseLRShared 被排除**：虽理由是“不支持现有适配器”，但缺少该类方法的直接对比，可能削弱结论的完整性。
- **应用限制**：方法假设智能体共享同一主干与 tokenizer；对于异构主干模型间的缓存共享不适用。中性重建的有效性依赖 $\rho \ge 2\cos\theta$ 条件，在某些适配器差异极大的场景下可能不成立。
