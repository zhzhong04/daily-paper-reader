## 摘要
大语言模型（LLM）智能体会反复将可复用内容（如技能、文档和记忆条目）加载到当前上下文中。为每个请求重新编码这些内容会浪费计算。位置无关缓存（PIC）通过独立编码每个内容项并在任意位置复用其键值（KV）状态来缓解这一问题，但相较于全上下文预填充会带来质量损失。现有方法通过恢复全局位置 ID 或重新计算选定 token 来修复这种损失。在本工作中，我们定位了损失的来源，发现位置不匹配的影响较小，且独立缓存的内容项仍保留忠实的表征：读取给定内容项时基本保持准确，只有当模型必须在多个内容项之间进行选择时性能才会下降。此外，将 PIC 的注意力分数替换为全预填充分数，在缓存 KV 不变的情况下即可恢复性能，从而将失败归因于注意力机制而非 KV 重计算。受此启发，我们提出 Attuner，一种查询侧适配方法，学习读取冻结的内容项缓存。Attuner 在查询投影中插入低秩适配器，并通过将全预填充分布蒸馏到学生模型中进行训练。它仅训练不到 0.05% 的模型参数，并且在推理时既不需要重新计算缓存，也不需要全上下文参考。在 Qwen3-4B 和 Qwen3-8B 上，涵盖技能、文档、记忆和代码的七个基准测试中，Attuner 在域内和域外设置下均显著优于先前的 PIC 基线，达到与全上下文预填充相当的质量，同时提供高达 3.73 倍的加速。

## Abstract
Large language model (LLM) agents repeatedly load reusable content, such as skills, documents, and memory entries, into the current context. Re-encoding this content for every request wastes computation. Position-independent caching (PIC) alleviates this by encoding each artifact independently and reusing its key-value (KV) states at arbitrary positions, but it incurs a quality loss relative to full-context prefill. Existing methods repair this loss by restoring global position IDs or recomputing selected tokens. In this work, we isolate the source of the loss, finding that the positional mismatch has minor effect, and independently cached artifacts retain faithful representations: reading a provided artifact stays largely accurate, and performance degrades only when the model must select among multiple artifacts. Moreover, replacing PIC's attention scores with full-prefill scores recovers performance with the cached KV unchanged, localizing the failure to the attention rather than KV recomputation. Motivated by this, we propose \textsc{Attuner}, a query-side adaptation method that learns to read a frozen artifact cache. \textsc{Attuner} inserts low-rank adapters into the query projections and is trained by distilling full-prefill distribution into the student. It trains fewer than 0.05\% of the model parameters and, at inference, requires neither cache recomputation nor a full-context reference. On Qwen3-4B and Qwen3-8B across seven benchmarks covering skills, documents, memory, and code, \textsc{Attuner} substantially outperforms prior PIC baselines in both in-domain and out-of-domain settings, matches full-context prefill quality while providing up to $3.73\times$ speedup.

## 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：LLM 智能体在运行时反复将可复用内容（技能描述、文档、记忆条目等，统称"artifact/内容项"）加载进上下文。为每个请求重新编码这些内容会浪费大量算力，并显著抬高首 token 延迟（TTFT）。
- **现有方案及其瓶颈**：
  - 传统前缀缓存（如 RadixAttention）要求可复用内容在各请求中占据相同前缀位置，而智能体工作负载中 artifact 的选取、顺序和位置由检索、路由、规划动态决定，前缀缓存难以适用。
  - 位置无关缓存（PIC）通过独立编码每个 artifact 并复用其 KV 状态来绕过位置约束，但相比全上下文预填充（Full prefill）存在**质量损失**。
- **损失来源之争**：PIC 引入两种错配——位置错配（artifact 在未知位置前编码）与上下文错配（独立编码的 artifact 未关注到前序 artifact）。既有方法多在推理时修复：恢复全局位置 ID，或重计算选定 token。
- **本文核心问题**：PIC 的质量损失究竟源于"缓存 KV 表征失真"还是"注意力读取方式错误"？能否在不重算缓存的前提下恢复质量？
- **整体含义**：论文通过受控实验将损失定位于**注意力路由**而非 KV 表征，进而提出查询侧适配方案 ATTUNER，实现"学习读取冻结缓存，而非改写缓存"，为高效缓存复用提供了新范式。

## 2. 方法论

### 核心思想
- 缓存保持冻结（不重算、不修改 artifact KV），仅在**在线查询侧**插入可训练的低秩适配器，学习如何有效地将注意力路由到独立缓存的 artifact 上。
- 通过**全上下文教师输出分布蒸馏**训练适配器，使 PIC 学生的输出分布逼近 Full 教师。

### 关键技术细节

- **问题设定**：请求 $X = P \oplus A_1 \oplus \cdots \oplus A_m \oplus U$。Full prefill 中 $Z_j^{Full} = C_\theta(A_j \mid P \oplus A_{<j})$；PIC 中 $Z_j^{PIC} = C_\theta(A_j \mid P_{cache})$，二者产生不同 KV。
- **诊断发现**：
  - 位置错配影响较小（PIC-Pos 仅带来边际变化）。
  - 单 artifact 场景下 PIC 性能损失很小，说明缓存表征忠实；多 artifact 场景损失显著，问题在于"从哪个 artifact 读取"的决策。
  - 路由 oracle 实验：将 PIC 的在线注意力分数替换为 Full 参考分数（保留 PIC 缓存值），任务性能恢复到接近 Full（MuSiQue EM 从 34.84 → 47.91，Full 为 47.79；BigCodeBench pass@1 从 38.98 → 44.53，Full 为 43.63）。
- **查询适配公式**（对每一层 $\ell$ 冻结的查询投影做低秩更新）：

$$\tilde{q}_{\ell,t} = W^Q_\ell h_{\ell,t} + \frac{\alpha}{r} B_\ell A_\ell h_{\ell,t}, \quad \ell = 1,\dots,L$$

  其中 $A_\ell \in \mathbb{R}^{r \times d_{model}}$、$B_\ell \in \mathbb{R}^{d_q \times r}$ 为可训练矩阵，$r$ 为秩，$\alpha$ 控制缩放。更新后仍经过原始 query normalization 与 RoPE。零初始化，仅训练 $A_\ell, B_\ell$，主干全部冻结。
- **训练目标**（全上下文教师 → PIC 学生，输出分布 KL 蒸馏）：

$$\mathcal{L}(\phi) = \mathbb{E}_{(X,Y)\sim D_T}\left[\frac{1}{|Y|}\sum_{t=1}^{|Y|} D_{KL}\left( sg\left[p_\theta^{Full}(\cdot \mid X, Y_{<t})\right] \,\|\, p_{\theta,\phi}^{PIC}(\cdot \mid X, Y_{<t}) \right)\right]$$

  教师梯度停止，仅监督响应位置分布，不直接监督注意力权重。
- **推理流程**：artifact 离线预填充并存储 KV 于 CPU 内存；请求时加载组装 KV，适配器仅在未缓存 prompt token 与生成 token 上启用；部署时低秩更新可合并进查询投影权重 $W^Q_\ell \leftarrow W^Q_\ell + (\alpha/r)B_\ell A_\ell$，无需教师或缓存重算。

## 6. 主要结论与发现

- **损失定位**：PIC 的质量损失主要不在位置错配，也不在缓存 KV 表征失真，而在**注意力读取/路由**；多 artifact 场景下的"证据利用"退化是关键瓶颈。
- **恢复路径**：在缓存 KV 不变的情况下恢复 Full 注意力路由，即可在表征层面与任务层面大幅恢复性能（MuSiQue、BigCodeBench 均接近 Full）。
- **ATTUNER 效果**：
  - 域内平均分较 PIC 提升 5.13（Qwen3-4B）与 7.77（Qwen3-8B）分，与 Full 的差距缩至 1.61 与 0.51 分。
  - 域外任务（TheoremQA、CHAMP）平均提升 3.02 与 3.51 分，显示跨任务迁移性。
  - 训练参数 < 0.05%；TTFT 仅比 PIC 高 1.8%（4B）与 0.5%（8B），保持 1.79× 与 2.45× 的域内几何平均加速，最高加速达 3.73×。
- **分析结论**：
  - 1,024 条训练样本即可显著恢复，8,192 条时 MuSiQue F1 达 61.15，匹配 Full 的 61.01。
  - 适配器使注意力输出 O 与 Full 的余弦相似度提升（MuSiQue 答案位置 0.903→0.927；BigCodeBench 0.932→0.949），但最后一层对齐变差，说明无需逐层复现 Full 计算。
  - 仅适配一半层（L16–33）即可获得 +16.13 F1 的恢复。
  - 同一适配器在 PIC 下的增益（域内平均 +5.13）远大于在 Full 下（+0.17），说明增益主要源于适配独立缓存上下文，而非通用任务能力提升。

## 7. 优点

- **问题诊断清晰**：通过"artifact discovery vs evidence utilization"的分解、位置对齐对照、路由 oracle、组件级干预（K/V/路由/O）等多重受控实验，层层剥离并定位失败根源，论证严谨。
- **方法轻量且部署友好**：仅查询侧低秩适配，训练参数 < 0.05%，推理时可合并进权重，无需教师、无需缓存重算、无需在线 token 选择，保留 PIC 的全部效率优势。
- **缓存保持冻结**：不修改、不重算 artifact KV，避免了对缓存存储与传输管线的侵入，与现有 PIC 基础设施兼容。
- **泛化性验证**：单一适配器跨技能、文档、记忆、代码四类 artifact 与域内外任务均有效，并做了训练数据规模与层范围的系统消融。
- **公平性意识**：明确说明基线实现差异、TTFT 计时边界、mask/边界变体不可互换，避免误导性对比。
- **效率–质量权衡可视化**（图 6）直观展示 ATTUNER 在质量与延迟上优于所有免训练修复基线。

## 8. 不足与局限

- **实验覆盖局限**：
  - 未考察同时混合技能、文档、记忆三类 artifact 的请求。
  - 仅在全注意力架构模型上验证，未探索其他注意力架构（如稀疏/线性注意力）的适用性。
  - 域外任务仅 2 个，且 CHAMP 含单 artifact 请求，泛化结论的强度有限。
  - 部分基准上恢复仍不完整（如 Qwen3-4B 的 TheoremQA、CHAMP）。
- **资源信息缺失**：正文与附录均未披露 GPU 型号、数量与训练时长，可复现性与算力评估受限。
- **训练数据偏差风险**：
  - BigCodeBench 训练样本为合成任务，未用单元测试验证，监督来自各模型自身 Full 教师，可能继承教师缺陷。
  - 部分教师响应为 legacy 固定前缀或达到长度上限（如 PersonaMem-v2 多数轨迹触达 256 token 上限），蒸馏信号质量存疑。
- **应用限制**：
  - 贡献聚焦"缓存读取"而非存储/传输，未优化缓存放置、淘汰与通信。
  - 论文承认不处理底层模型与数据带来的偏差、隐私与有害输出问题；可复用上下文场景需额外访问控制与缓存信息保护。
  - 与 KV 压缩、基于检索的 artifact 选择相结合是未来方向，尚未验证。
- **对比局限**：AgentKVShift 为论文复现（无官方代码），CacheBlend 为 Qwen3 适配变体，与原始系统性能不完全可比；KVLink 在平均质量上高于 ATTUNER，但 TTFT 超过其两倍，二者权衡定位不同。
