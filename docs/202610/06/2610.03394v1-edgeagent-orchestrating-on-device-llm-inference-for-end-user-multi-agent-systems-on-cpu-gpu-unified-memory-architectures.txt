## Abstract 

Emerging multi-agent LLMs demand privacy-preserving edge deployment, yet current inference systems struggle with these collaborative workflows. Specifically, the memory-bound decode phase causes severe bus contention on unified memory architectures (UMA), paralyzing naive CPU-GPU co-execution. Furthermore, speculative decoding in multi-agent workloads faces extreme variance in drafting difficulty, al-ternating between complex reasoning and predictable struc-tured generation. Compounded by frequent tool-induced stalls, this highly fragmented execution severely underuti-lizes hardware and defeats traditional static batching. We present EdgeAgent, a cross-layer inference system explicitly co-designed for edge UMA and multi-agent work-loads. At the micro-architectural level, it bypasses rigid graph-compiler constraints to enable zero-copy UMA-aware tensor parallelism, utilizing asymmetric memory layouts to fully saturate both CPU and GPU compute units. At the sched-uling level, it dynamically allocates draft budgets based on real-time sequence predictability to bound bandwidth waste. Concurrently, an asynchronous suspend-and-yield mech-anism actively evicts stalled agents, ensuring continuous hardware saturation during unpredictable tool invocations.

## 1 Introduction 

The application of large language models [8, 11, 14] (LLMs) is increasingly shifting from monolithic chat interfaces to-ward coordinated multi-agent systems. In recent agent frame-works, such as LangGraph [18] and OpenClaw [29], a com-mon design choice is to decompose complex tasks into spe-cialized roles and coordinate them through explicit orches-tration mechanisms. With the enhanced capability of multi-agent systems, they start to take over more system access privileges, raising growing privacy and security concerns. arXiv:2610.03394v1 [cs.DC] 2 Oct 2026 ASPLOS ’27, April 11–15, 2027, Heraklion, Greece Yuhai Long, Yuanxin Wei, Kai Wu, Jinhui Wei, Dan Huang, and Jiangsu Du 

This trend makes on-device LLM inference deployment in-creasingly important. However, existing LLM inference sys-tems can hardly handle such multi-agent workloads on end-user devices efficiently. Most existing LLM inference systems [17, 30, 41] are pri-marily designed for cloud environments and multi-user work-loads. These systems process hundreds of concurrent re-quests across multiple discrete GPUs, targeting high-through-put batching and multi-tenant isolation. Lacking awareness of fine-grained, intra-node memory contention, their hard-ware and workload assumptions render them highly inef-ficient when ported directly to edge devices. Conversely, existing edge frameworks (e.g., Llama.cpp [14], MLX [4]) pri-marily target single-user, single-request sequential inference. When confronted with collaborative multi-agent workloads which dynamically generate concurrent, highly fragmented requests on a single device, these monolithic edge systems lack the necessary orchestration, leaving available compute resources severely underutilized. The more balanced CPU-GPU computing capability on modern edge devices enables effective use of tensor paral-lelism (TP) to coordinate heterogeneous execution and fully utilize on-chip compute resources [10, 16, 23, 37, 38]. Modern edge systems-on-chip (SoCs) typically integrate powerful mobile GPUs and highly capable CPUs with advanced matrix extensions, such as ARMv9 Scalable Matrix Extension [5] (SME) in the Apple M4 [3], forming a well-proportioned het-erogeneous computing platform. TP [28], as a mainstream model parallelism technique, partitions LLM workloads (e.g., matrix multiplications) across multiple devices, making it suitable for distributing computation between CPUs and GPUs to speed up inference. During the compute-bound prefill phase, heterogeneous TP can fully exploit aggregated floating-point throughput by engaging both processing units simultaneously. However, during the decode phase, such CPU-GPU parallelism brings little performance gain under the shared unified memory architecture (UMA), since the de-coding process is inherently memory-intensive and severely bounded by memory bandwidth. To mitigate the memory bound in the decode phase, recent systems improve arithmetic intensity through speculative de-coding (SD) [9, 21]. SD decouples generation into two stages: a lightweight draft model first proposes multiple candidate tokens, and the target model then verifies them in parallel, accepting the longest matching prefix. By amortizing target-model weight loading across multiple token verifications, SD reduces per-token bandwidth pressure and improves decode throughput. However, integrating these hardware-aware optimizations for multi-agent workflows into existing graph-based edge frameworks, such as MLX, exposes three critical systemic bottlenecks. First, implementing CPU-GPU lock-free TP on shared memory exposes the limitations of modern graph compilers [2, 19]. Standard directed acyclic graph (DAG) executors cannot safely express asynchronous, orthogonal memory mutations to a single shared tensor, forcing run-times into eager synchronization which severely disrupts the graph optimization pipeline and explicit memory copies that negate the zero-copy benefits of UMA. Second, differ-ent agent tasks exhibit extreme variance in the difficulty of drafting (e.g., highly structured code synthesis vs. deliberate reasoning). As this drafting difficulty is related to the real-time context, traditional SD systems allocate a static draft length uniformly across all tasks. This inevitably results in the waste of limited memory bandwidth, which is frequently used to process rejected drafts. Third, agents frequently ex-ecute external tool calls [25, 40] that incur out-of-system stall. When an agent stalls on a tool call, the runtime can-not dynamically redistribute its idle speculative budget to remaining active agents, failing to fully exploit the available compute capacity and degrading overall system performance on edge devices. To address these challenges, we propose EdgeAgent, a co-designed inference system explicitly tailored for edge UMA and concurrent multi-agent workflows. EdgeAgent adopts a cross-layer architecture featuring an agent-aware scheduling layer, which tightly couples real-time agent states and task predictability directly with the underlying UMA-aware execution layer. In summary, this paper makes the following contributions: 

• We design a UMA-aware execution layer with a zero-copy TP graph that adopts symmetric memory layouts to elim-inate compiler overhead, together with optimized SME micro-kernels to jointly saturate heterogeneous edge com-pute units. 

• We design an agent-aware scheduling layer that dynami-cally allocates draft budgets based on real-time drafting dif-ficulty, and employs an in-place suspend-and-yield mech-anism to instantly reclaim computation slots during tool-induced stalls. 

• We implement and evaluate EdgeAgent on modern edge architectures using trace-driven, concurrent multi-agent workflows. Experimental results demonstrate that our sys-tem delivers substantial improvements in both global con-current throughput and end-to-end task makespan com-pared to state-of-the-practice inference frameworks.

2.3 Speculative Decoding 

To mitigate the memory bandwidth bottleneck of autore-gressive generation, speculative decoding (SD) decouples inference into a lightweight drafting phase and a parallel verification phase. In this paradigm, a small draft model predicts candidate token sequences that the massive target model subsequently verifies in a single forward pass. This design effectively amortizes the high memory latency associ-ated with loading target model weights from main memory, as the memory-intensive target model is invoked only once per draft batch rather than sequentially for each token. However, the speedup achieved by SD scales non-linearly with draft length 𝐿 , and this pattern varies significantly across different tasks. 2.4 The Edge UMA Memory Wall 

Modern SoCs (e.g., Apple M4, Snapdragon X [31]) feature unified memory architectures (UMA) and advanced tensor extensions. By abandoning discrete topologies, UMA allows the CPU and GPU to share a single physical memory pool and bus interface. Simultaneously, equipped with extensions like ARMv9 SME, modern CPUs now rival mobile GPUs in dense computation, even outperforming them at small batch sizes. Though this convergence supports zero-copy sharing of model weights across heterogeneous cores, it triggers memory contention. Specifically, during the prefill phase, high arithmetic intensity keeps the system compute-bound, allowing heterogeneous tensor parallelism (TP) to effectively aggregate compute power. However, in the decode phase, extremely small batch sizes shift the bottleneck entirely to memory bandwidth, fundamentally degrading the efficiency of hardware concurrency. As in Table 1, empirical micro-benchmarks on the Apple M4 SoC confirm the severe UMA bandwidth constraint. A strong scaling test shows that for small matrices, CPUs out-perform GPUs and the co-run achieves a speedup of 1 .36 ×

over GPU on the 4096 × 4096 matrix. However, as the matrix size scales, GPUs approach the UMA’s effective bandwidth ceiling (utilizing over 80% of the 120 GB/s peak). Therefore, CPU-GPU co-run suffers from destructive bus arbitration, re-sulting in a speedup of 0 .99 × over GPU on the 4096 × 128256 matrix. This bandwidth wall explains why heterogeneous TP during the decode phase yields negligible end-to-end speedup, necessitating an agent-aware global co-scheduling paradigm to bypass the bottleneck. 

2.5 Graph Compiler Limitations 

Beyond the hardware memory wall, realizing fine-grained device coordination is obstructed by existing software in-frastructure. The modern deep learning ecosystem relies heavily on graph compilation as the foundational software for high-performance inference. This paradigm manifests through distinct paths across frameworks: PyTorch intro-duced ExecuTorch [27] for ahead-of-time (AOT) static graph serialization, whereas Apple’s native MLX defaults to global lazy evaluation to dynamically construct computation graphs at runtime. Despite these divergent implementations, both approaches transparently construct a global directed acyclic graph (DAG) of the program. Leveraging this intermediate representation, backend compilers can execute aggressive operator fusion and in-place memory lifecycle reuse, dras-tically reducing the framework overhead associated with per-operator scheduling. While graph compilation has achieved tremendous suc-cess in optimizing for standalone hardware backends, its underlying DAG abstraction exposes severe system-level lim-itations for fine-grained, heterogeneous TP across the CPU and GPU on edge devices. The core deficiency of modern graph compilers lies in their coarse, tensor-level dependency tracking, which inherently struggles to safely express the lock-free, concurrent mutation of a single shared physical buffer. Within edge UMA architectures, avoiding exorbitant memory copy overheads requires the CPU and GPU to per-form orthogonal writes to different offset regions of a con-tiguous memory block. However, because the DAG tracks data hazards strictly at a tensor-level granularity, it is seman-tically blind to these disjoint sub-tensor boundaries and flags these orthogonal writes as severe data conflicts. Unable to semantically guarantee the safety of such non-overlapping mutations, the state machine of the graph executor resorts to a conservative over-protection strategy. It forcibly inserts coherence hardware fences across device boundaries, com-pelling the local graph execution to fall back into an eager synchronization mode. This semantic gap within the DAG implementation induces severe interleaved blocking among heterogeneous instruction sequences, significantly diminish-ing the parallel speedups gained from underlying operator partitioning.

The architecture is organized into two collaborative layers, i.e. execution layer and scheduling layer. The UMA-aware execution layer (Section 3.1) provides a unified heterogeneous backend to maximize hardware sat-uration via: (1) A zero-copy TP computation graph, which features asymmetric memory layouts for heterogeneous pro-cessors, plus custom DAG barriers that bypass compiler overheads to enable lock-free tensor parallelism (Section 3.1.1). By promptly decoupling stalled agents from the active batch pool and backfilling their execution slots with pending tasks, the scheduler keeps the hardware well utilized (Section 3.2.2).

Model partitioning and weight residency. EdgeAgent partitions each transformer block with two patterns, both fixed at load time. EdgeAgent therefore holds exactly one copy of the model weights (Figure 5). However, realizing this zero-copy, in-place mutation fun-damentally conflicts with the functional semantics of modern lazy computation graphs. In standard ML compilers, graph abstractions inherently conflate logical data dependence with physical memory materialization. Merging CPU and GPU sub-tensors strictly requires a concat operator, which is lowered into explicit memory allocations and copy kernels, thereby wasting the hardware benefits of UMA. Conversely, performing a naive in-place write into a shared buffer vio-lates the DAG’s tensor-level dependency tracking. Without explicit data-flow edges, the instruction scheduler cannot guarantee execution order, leading to severe data hazards (e.g., downstream operators reading stale data) unless penal-ized by conservative, eager synchronization. To safely merge CPU and GPU results without triggering memory copies or breaking data dependencies, we modify the graph execution via two lightweight mechanisms: (1) Log-ical Dependency Barrier: We replace the standard concat 

operator with a custom barrier node. Logically, it acts as a synchronization point in the DAG, ensuring downstream operators wait for both processors to finish. Physically, it allocates zero memory, simply aliasing the output pointer to the underlying shared buffer. (2) Heterogeneous Fast Path: As the logical barrier handles the graph dependencies, we can execute this specific subgraph outside the framework’s generic scheduling loop. This dedicated fast path issues con-current tasks directly to the CPU and GPU without inserting conservative cross-device hardware fences, achieving a truly lock-free, zero-copy concurrent execution. 

Coherence and memory-model assumptions. EdgeAgent does not introduce a new coherence protocol. It relies on the coherence already provided by the UMA SoC: the CPU and GPU share a single physical address space and are kept coherent through the system-level cache, so a write issued by either device to a shared buffer is visible to both devices without explicit cache flushes or host–device copies. This single coherence domain is exactly the property that the concat-based path in stock MLX discards, since concat ma-terializes a new contiguous array and copies both halves into it. Consistency, however, is weak rather than sequen-tial: Metal follows a weak, relaxed memory model, where cross-device visibility is not guaranteed without explicit syn-chronization. Our Heterogeneous Fast Path therefore estab-lishes only the producer–consumer happens-before relation the design actually needs. The MLP projections and the at-tention Q/K/V/O projections are all column-parallel, so the CPU and GPU write disjoint column ranges: no address is ever written by both devices, so there is no data race and no fine-grained per-line coherence is required. The Logical De-pendency Barrier encodes the remaining ordering as a graph dependency, a zero-copy node that aliases the shared buffer, so MLX’s lazy evaluation orders downstream operators after both producers finish, with no explicit hardware fences or eager synchronization. 

3.1.2 SME Micro-kernel Optimization. Maximizing the efficiency of the CPU requires saturating the SME units. The system achieves this saturation through a tightly coupled hierarchy of micro-optimizations. At the single-core instruction level, we partition the matrix workloads into 16 × 64 micro-tiles. This specific dimension is purposefully chosen to simultaneously saturate the memory bandwidth using continuous multi-vector loads ( svld1_x4 )and to keep all four 2D ZA register tiles maximally occupied. By aggressively unrolling loops along the K dimension, the kernel physically overlaps these continuous memory loads with the outer-product accumulation. This software pipelin-ing effectively masks memory access latencies. To ensure these saturated compute pipelines are not abruptly starved by cache thrashing, we systematically tune the macro-tiling parameters. By strictly confining the active memory foot-print within the 8MB effective L2 working set, the system avoids sharp bandwidth degradation and maintains continu-ous data ingestion. However, scaling to full SoC utilization exposes load im-balance. The asymmetric multiprocessing (AMP) topology of modern edge chips, which mixes high-throughput P-cores with slower E-cores, as illustrated in Figure 5, inevitably in-duces straggler effects under traditional static task binding. To mitigate these straggler effects, we deploy a lock-free dy-namic work-stealing mechanism. Built entirely upon relaxed-consistency atomic operations, this decentralized queue al-lows heterogeneous worker threads to autonomously steal compute micro-tiles based on their real-time physical execu-tion rates. This achieves optimal fine-grained load balancing across the asymmetric hardware topology without ever in-curring lock contention overheads.

3.2.1 Dynamic Drafting Budget Allocation. To reliably saturate these 16 hardware slots without forcing a single re-quest to over-expand its speculative tree (which suffers from diminishing returns in acceptance yield), the system pools multiple concurrent agents into a unified physical batch. However, uniformly dividing this fixed 16-token budget fails to account for the extreme variance in the difficulty of draft-ing across streams. Static allocation strategies inherently bottleneck parallel efficiency by over-provisioning execution slots to difficult tasks while under-resourcing highly produc-tive ones. To dynamically allocate draft length based on these runtime characteristics, we propose an agent-aware sched-uler . By introducing the Historical Accepted Length (HAL) as an objective proxy for the underlying drafting difficulty, this scheduler seamlessly captures the real-time generation state of each concurrent stream. The HAL tracks the absolute number of accepted tokens rather than the acceptance rate. Relying on percentages ob-scures an agent’s true throughput contribution, as a shallow draft tree might exhibit a perfect acceptance rate while yield-ing minimal tokens. 3.2.2 Cooperative Suspend-and-Yield Mechanism. Ex-ternal tool invocations inevitably stall individual execution streams. In a strictly hardware-aligned concurrent batch, a stalled agent occupying active token slots will directly degrade global throughput. To explicitly neutralize these latencies, the agent-aware scheduling layer implements an OS-inspired cooperative suspend-and-yield mechanism tied directly to the speculative budgeting system. At the synchronization boundary of each verification step, the scheduler inspects agent execution states. Upon detecting a tool-induced stall, it triggers a cooperative yield, migrating the stalled agent to a suspended queue and instantly relin-quishing its allocated token slots back to the global drafting budget. Relinquishing these slots allows the dynamic alloca-tor (Section 3.2.1) to instantly redistribute the yielded budget across the remaining active agents. By absorbing the vacated budget, active streams dynamically expand their draft trees, broadening their speculative search space without breaking the optimal hardware-aligned 16-token threshold. Crucially, by exploiting the physically shared addressing of the UMA architecture, the system performs an in-place metadata freeze on the suspended agent’s KV cache. Upon resolution of the external tool execution, the scheduler pro-motes the ready agent back to the active queue to request fresh token slots. As the underlying memory pool guarantees in-place KV freezing and hardware-aware offset-remapping compaction, the awakened agent directly resumes specula-tive execution. ## 4 Evaluation 

EdgeAgent builds upon Apple’s native MLX runtime, funda-mentally restructuring its underlying C++ graph executor to enable zero-copy UMA memory management. Furthermore, it introduces lightweight cross-layer APIs to synchronize multi-agent execution states such as variance in drafting difficulty and tool-induced stalls with the underlying sched-uler. We comprehensively evaluate EdgeAgent using trace-driven multi-agent workflows to demonstrate its end-to-end makespan, concurrent throughput, and resilience to tool-induced execution stalls. 

4.1 Experimental Setup Hardware Testbed. Primary experiments are conducted on an Apple M4 SoC equipped with 32 GB of unified memory and a 120 GB/s UMA bus. The SoC integrates a 10-core CPU (4 performance + 6 efficiency) with the ARMv9 SME2 ex-tension, alongside a 10-core GPU. To verify EdgeAgent’s generalization, the key ablations are additionally evaluated on an Apple M4 Pro SoC with 64 GB of unified memory and a 273 GB/s UMA bus, whose 14-core CPU (10 performance + 4 efficiency) and 20-core GPU shift the compute-to-bandwidth balance relative to the base M4. Since both SoCs share the SME2 extension, the M4 Pro isolates the effect of the band-width balance rather than the micro-kernel backend. To-gether they exemplify the stringent memory-bandwidth and computational constraints of modern edge AI environments. 

Models. We evaluate our system using two represen-tative large language models: DeepSeek-R1-Distill-Llama-8B [12], a reasoning-focused model that exhibits severe draft-ing difficulty (yielding low acceptance rates) during its ex-tensive chain-of-thought (CoT) generation, and Llama-3.1-8B-Instruct [26] for standard instruction-following work-loads. For configurations involving speculative decoding, we uniformly adopt EAGLE-3 [21], a state-of-the-art draft gen-eration and verification framework. 4.2 End-to-End Evaluation 

To evaluate the overall makespan and global throughput of EdgeAgent, we construct a spectrum of concurrent work-loads. As illustrated in Figure 7, we progressively inject task heterogeneity and external tool-induced stalls to expose the scheduling bottlenecks of existing frameworks. This evalua-tion isolates the end-to-end efficiency of the system, while the specific micro-architectural mechanisms driving these re-sults are analyzed in the subsequent subsections (§4.3–§4.5). 

Baseline Inference Performance. We first establish the baseline performance using a continuous, pure code-generation workload without tool-induced stalls (Figures 7(a) and 7(e)). At 𝑁 = 4, where 𝑁 denotes the number of actively decoding agents in the system, EdgeAgent achieves a global through-put of 33.6 tok/s (DeepSeek) and 28.0 tok/s (LLaMA). These metrics represent 1 .29 × speedups over the optimized Batch-SD baseline. This gain reflects our UMA-aware execution layer, which combines the optimized SME kernels with zero-copy TP, prior to enabling HAL scheduling and stall-aware context switching. 

Component ablation. To isolate each contribution, we enable EdgeAgent’s optimizations incrementally on top of the Batch-SD baseline: first the optimized SME kernels, then zero-copy TP, and finally HAL scheduling, measuring the end-to-end makespan for 2, 3, and 4 concurrent agents on both the M4 and the M4 Pro (Figure 8). Each step reduces the makespan. Together, the optimized SME kernels and zero-copy TP constitute our UMA-aware execution layer, which achieves up to a 1 .29 × speedup over Batch-SD. Enabling HAL scheduling provides an additional 1 .05–1 .17 × improvement over the corresponding UMA-aware configuration. Offline packing is included in every bar and is small: 13–16 s on the M4 and 6.2 s on the M4 Pro, under 5% of the makespan. 

Adaptability to Mixed Workload. To evaluate sched-uling efficiency under varying sequence predictability, we introduce a mixed workload combining reasoning and cod-ing tasks without tool-induced stalls (Figures 7(b) and 7(f)). While the overall throughput naturally decreases across all systems due to the hard-to-draft reasoning steps, a static draft-length allocation ( 𝐿 = 16) wastes compute resources generating and verifying unaccepted tokens during low-acceptance reasoning phases. By utilizing dynamic budgeting (§4.4), EdgeAgent mitigates this overhead and achieves a 1.33 × speedup over the Batch-SD baseline, demonstrating the efficiency of predictability-aware resource allocation. 

Sensitivity to Workload Composition. To test whether the 1:2:2 default mix flatters our results, we sweep the rea-soning/code/tool ratio from 1:1:1 to 1:4:4 while holding the arrival process and concurrency settings fixed. HAL sched-uling improves on the fixed-budget baseline across the en-tire sweep, and its gain grows monotonically as the mix shifts toward structured code and tool generation (Figure 9). This is the expected direction: structured-output agents are highly predictable and a static 𝐿 = 16 budget caps the tokens they could otherwise accept, whereas extra budget spent on reasoning-heavy agents is largely wasted on rejected drafts. The 1:2:2 default therefore sits at an interior and conservative operating point of this curve, not a favorable peak. 

Adaptability to Tool Stalls. Real-world agent workflows frequently stall during external tool invocations. To simulate this, we inject log-uniform tool-execution stall durations of 

[1, 10 ] seconds and [1, 100 ] seconds into the mixed workload (Figures 7(c)-(d) and 7(g)-(h)). Under the extreme [1, 100 ]sstall configuration at 𝑁 = 4 (Figure 7d), head-of-line blocking in Batch-SD severely delays execution, inflating its makespan to 213.1 seconds (DeepSeek). In contrast, EdgeAgent lever-ages its asynchronous suspend-and-yield mechanism (§4.5) to evict stalled agents and reclaim verification slots. This effectively hides the stall, compressing the total makespan to just 120.6 seconds and delivering a 1.77 × speedup over the optimized Batch-SD baseline. 

Overall Performance Scaling. Across the evaluated con-figurations, our UMA-aware execution layer, which com-bines the optimized SME kernels with zero-copy TP, achieves up to a 1 .29 × speedup over Batch-SD. The primary systemic gains emerge in stall-intensive environments, where the complete EdgeAgent system reaches a 1 .77 × speedup by combining UMA-aware execution, HAL scheduling, and stall-aware context switching. Furthermore, scaling concurrency from 𝑁 = 2 to 𝑁 = 4 consistently widens this margin, indicat-ing that the system effectively utilizes edge UMA resources under highly irregular execution patterns.

4.3.3 Custom SME Kernel efficiency. Unlike stateless BLAS libraries that redun-dantly repack static weights upon invocation, our kernel pre-packs model weights offline during initialization. This eliminates data-layout transformation overheads from the runtime critical path. We evaluate our kernel against BNNS on standard MLP projections, specifically the 4096 × 14336 up-projection and the 14336 × 4096 down-projection. Measuring pure online inference throughput exclusive of offline packing time, the empirical results presented in Figure 12 demonstrate ma-jor architectural advantages across both decoding and pre-fill regimes. 4.5 Stall-Aware Context Switching 

To evaluate system resilience against tool-induced stalls, we benchmark our asynchronous yielding mechanism using three concurrent agents. Under standard synchronous ex-ecution, tool invocations critically block active execution streams. As depicted in the upper timeline of Figure 14, wait-ing for external processes (such as script execution and API responses) forces the hardware into extended idle states, clearly illustrated by Agent B suffering a prolonged 53-second stall. These synchronous execution stalls entirely serialize external latency and tensor computation, severely degrading overall system efficiency. Our stall-aware runtime eliminates this computational waste. Upon initiating an external tool request, the active agent suspends its execution context and yields the hard-ware. As shown via the interleaved scheduling paths in the lower timeline of Figure 14, when Agent B blocks, the global scheduler instantly promotes Agent A or Agent C. Allowing companion agents to steal these idle budgets achieves deep overlap between tensor computation and tool execution. As quantified in the right panels of Figure 14, this dense execu-tion packing reduces the end-to-end wall-clock time from 286 to 238 seconds and elevates global throughput from 9.9 to 11.4 tokens per second, ensuring continuous hardware saturation despite highly irregular tool invocations. 

## 5 Related Work 

LLM Serving for Agentic Workloads. The shift to ReAct-style agents [40] shatters the continuous batching assump-tions of traditional runtimes like vLLM [35]. To support complex control flows, SGLang [33] and AgentInfer [24] co-design runtime memory with application semantics, while Continuum [20] and INFERCEPT [1] mitigate tool-induced stalls via cache retention and KV swapping. However, these mechanisms target discrete GPUs. In edge unified memory architectures (UMA), such heavy-handed state management is obsolete. EdgeAgent exploits UMA for in-place KV meta-data freezing, achieving zero-overhead context switching without moving physical bytes. 

Dynamic Speculative Scheduling. Recent algorithms push acceptance rates via training-time testing (EAGLE-3 [21]) and pipelined SSM voting (Smurfs [36]). System-level designs tailor speculation budgets to specific constraints: AdaServe [22] optimizes for cloud SLOs, EdgeLLM [39] adapts draft-tree width for memory-constrained devices, and Ghidorah [37] partitions verification across edge cores. For agents, Dual-Spec [42] utilizes semantic critics, and AgentInfer [24] lever-ages suffix automata. Unlike these coarse-grained or static allocations, EdgeAgent uses the HAL as an effective indi-cator of drafting difficulty to dynamically allocate budgets across concurrent multi-agent streams.

Generalizability beyond UMA. EdgeAgent’s two lay-ers have different portability. The agent-aware scheduling layer is memory-topology-agnostic: HAL-based budget al-location and suspend-and-yield operate on runtime state (drafting difficulty and tool-stall events), which exists in any speculative-decoding system. They therefore transfer un-changed to discrete-GPU datacenters, where tool-induced stalls cause the same slot-wasting and head-of-line blocking problem. The UMA-aware execution layer, in contrast, de-rives its benefit specifically from the coherent shared address space: on a discrete GPU over PCIe the disjoint-write trick cannot remove the host–device transfer, although the same principle, partitioning by device throughput and synchro-nizing only on completion, maps to multi-GPU tensor paral-lelism over high-bandwidth interconnects or to CPU-offload schemes such as FlexGen [34], where the goal becomes min-imizing PCIe traffic and overlapping compute with transfers. Finally, the ARM SME micro-kernels are a backend accel-erator rather than an architectural dependency: they speed up the CPU shard but are not required for correctness, and equivalent tiled kernels exist for x86 AMX and NVIDIA Ten-sor Cores. 

## 6 Conclusion 

We propose EdgeAgent, a cross-layer inference system that tightly couples agent-aware scheduling with hardware-level execution to meet the demands of concurrent multi-agent LLM workflows on edge UMA devices. By leveraging agent-aware dynamic budgeting, stall-aware suspend-and-yield mechanisms, and zero-copy architecture-aware tensor par-allelism, EdgeAgent largely improves hardware utilization even under highly irregular execution patterns. Our design illustrates the necessity of end-to-end co-design across se-mantic and physical layers for efficient, real-time agentic AI, paving the way for future intelligent edge systems.
