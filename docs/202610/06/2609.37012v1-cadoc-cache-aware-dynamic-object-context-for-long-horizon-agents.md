## 摘要
对于长时程智能体而言，上下文是瓶颈：历史记录会随每次请求重新发送，窗口限制了任务长度，并且随着历史增长，推理能力会退化。用紧凑的检索卡片（Cards）替代结构化对象可以缩短提示词，并保持原始内容可被精确检索，但编辑历史会破坏前缀缓存复用，而此前的可恢复方法依据对未来复用情况的预测或预设间隔来安排编辑时机。我们提出 CADOC（缓存感知动态对象上下文，Cache-Aware Dynamic Object Context），这是一种在线算法，用紧凑的卡片替代结构化对象，同时保留对其原始内容的精确、按需检索。CADOC 通过权衡累积等待成本与共享缓存重建成本，以批处理方式调度替换。其调度规则源自经济订货量权衡，并在平稳假设下恢复最优整数批量。在评估中，CADOC 在对比配置中始终取得最低的总输入成本，平均将输入成本降低约 40%，同时保持任务性能接近完整上下文。因此，CADOC 提供了一种由成本推导的可压缩上下文管理方法，表明高效压缩不仅取决于缩短提示词，还取决于调度编辑以保留缓存复用。

## Abstract
For a long-horizon agent, context is the bottleneck: the history is resent with every request, the window caps task length, and reasoning degrades as the history grows. Replacing structured objects with compact retrieval Cards shortens the prompt and keeps the exact originals retrievable, but editing the history can break prefix-cache reuse, and prior recoverable methods time their edits by forecasts of future reuse or by preset intervals. We propose CADOC (Cache-Aware Dynamic Object Context), an online algorithm that replaces structured objects with compact Cards while preserving exact, on-demand retrieval of their original contents. CADOC schedules replacements in batches by balancing accumulated waiting cost against shared cache-reconstruction cost. Its scheduling rule follows from an economic order quantity trade-off, recovers the optimal integer batch under stationary assumptions. Across evaluation, CADOC consistently achieves the lowest aggregate input cost among the compared configurations, which reduces input cost by approximately 40\% on average while maintaining task performance close to full context. CADOC thus provides a cost-derived approach to compressible context management, demonstrating that efficient compression depends not only on shortening prompts but also on scheduling edits to preserve cache reuse.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：长时程智能体（long-horizon agent）中，上下文是核心瓶颈。历史在每次请求中被重复发送，保留的 token 会反复计费（即使命中缓存也有缓存读取成本）；上下文窗口限制任务长度；历史越长，模型对相关信息的利用能力越差。
- **压缩的两条路线**：
  - 有损压缩（token 剪枝、学习式压缩、子轨迹折叠等）会丢弃后续步骤可能需要的细节；
  - 可恢复压缩把结构化对象（代码、文件内容、日志、工具输出）移到外部存储，用紧凑的检索卡片（Card）占位，原始字节仍可按需精确取回。
- **关键矛盾（论文的核心洞察）**：编辑历史会破坏前缀缓存（prefix cache）复用。替换越早，缓存重建（重新处理未命中前缀）的代价越大。论文用 HCE 历史中的一个实例说明这一反直觉现象：**立即替换减少了 55.93% 的累计输入 token，却使输入成本上升 3.67%**。即"token 变少 ≠ 成本变低"。
- **现有可恢复方法的不足**：
  - Self-GC 依赖规划 LLM 预测未来复用收益来决定提交时机，需要估计未来复用；
  - TokenPilot 以经验设定的固定轮数间隔运行 LLM 估计器；
  - 二者都没有从"当前可观测的"成本量出发决定编辑时机。
- **论文主张**：高效的上下文压缩不仅取决于"替换什么"，还取决于"何时提交替换"（以保住缓存复用）。CADOC 即为此提供一个完全在线、无需 LLM 的提交调度器。

## 2. 方法论

### 2.1 核心思想

- **可逆对象外置（reversible object externalization）**，而非有损压缩：
  - Working Memory 保存对象原始字节（含哈希），Prompt 中保留同槽位的紧凑 Card；
  - Card 只记录对象身份、版本、来源、结构元数据，**不含 LLM 生成的摘要**；
  - 模型通过普通工具 `retrieve_object(object_ref, reason)` 取回**不可变版本**的精确内容（返回为新的工具结果，拥有独立的生命周期）；
  - 保持对象在交互历史中的原始位置。
- **热尾部（hot tail）**：保留最近一段原始（未压缩）后缀，受块数上限 `h` 与 token 预算 `T_hot`（实验中 12,800 token）约束；离开保护后缀的对象进入 pending 序列，等待批量提交。
- **成本模型**：归一化未缓存 token 成本为 1，缓存读取权重 `w_r ∈ [0,1]`（主实验 `w_r = 0.1`）：
  - `C = Σ_t (N_t + w_r R_t)`，其中 `N_t`、`R_t` 分别为未缓存/已缓存输入 token 数。
- **单次提交的首请求成本差**：设 `I` 为从首个编辑点到缓存前沿的已缓存 token 数，`G` 为被移除的 token 数，`F` 为可选辅助提交开销：
  - `ΔC_first = (1 - w_r)(I - G) + F - w_r G`
  - 前项是"重建溢价"，后项是"缩短收益"。
- **批处理的权衡本质**：单独提交会重复支付同一段缓存重建成本，批量提交可共享该成本；但等待会让可移除载荷继续留在每一次中间请求中（等待损失）。这正是经济订货量（EOQ）中"订货准备成本 vs. 持有成本"的对应。

### 2.2 平稳模型与最优批量

- 设定：每请求周期产生一个固定长度 `x` 的新块，内含一个可替换对象，替换缩短 `g ∈ (0, x)`；热尾部恰含 `h ≥ 1` 块；一次提交替换全部 `b` 个 pending 块。
- 提交影响区间：`I_b = bx + (h-1)x`。
- 单对象单请求的等待成本 `r = w_r g`；一批 `b` 个对象的等待损失：
  - `W_b = r·b(b-1)/2`
- 每对象平均超额成本：
  - `ℓ_h(b) = K + Q_h/b + r(b-1)/2`
  - 其中 `K = f + (1-w_r)(x-g)`（每对象常量），`Q_h = F_0 + (1-w_r)(h-1)x`（共享重建成本）。
- **命题 1（平稳最优批量）**：连续最优 `b*_cont = max(1, √(2Q_h/r))`；整数 `b` 最优当且仅当
  - `r·b(b-1)/2 ≤ Q_h ≤ r·b(b+1)/2`
  - 取小者时 `b† = max(1, ⌈(√(1+8Q_h/r)-1)/2⌉)`。
- 直觉：共享重建成本越大 → 批量越大；每请求节省越多 → 越早提交。

### 2.3 从平稳最优到在线规则

- 关键恒等式：`W_b + w_r G_b = r·b(b+1)/2 = W_{b+1}`，因此整数最优条件可改写为"等待损失首次越过阈值"。
- **在线判据**：在边界 `t`，
  - `G_t` = 保留全部 pending 与替换全部 pending 两种下一 prompt 长度之差（潜在缩短量）；
  - `W_t` = 当前 pending 内容自变为 eligible 以来累积的等待损失，每多承载一次缓存请求增加 `ΔW_t = w_r G_t`；
  - `Q_t = F_0,t + (1-w_r)·H_shared_t`（`H_shared_t` 为最新 pending 块之后、缓存前沿之前需随之重建的已缓存 token 数）；
  - **提交条件：`W_t + w_r G_t ≥ Q_t` 则提交全部 pending 替换**，否则继续等待。
- 提交为"整批一起提交"：因为最早的 pending 编辑点决定了重建起点，同一请求内把更晚的替换一并提交不再产生额外缓存断裂。
- 硬容量上限（实验：超过 `2h` 个推理组或 25,600 原始 token）可强制提前提交。
- **命题 2（竞争比）**：在 waiting–setup 目标（固定 eligibility、`Q_min ≤ Q_t ≤ Q_max`）下，该规则满足 `J(ALG) ≤ (2Q_max/Q_min)·J(OPT)`；`Q_t` 恒定时为 2-competitive。

### 2.4 关键工程细节

- 无需未来信息、无需调度用 LLM 调用、无需按设置调 batch size；使用粗略的 prompt/cache 估计与"逐增量持久等待账本"。
- 提交后需等模型成功响应确认，再清除账本条目。
- 检索返回的 occurrence 重新获得初始原始暴露期，之后同样进入热尾部/提交生命周期，可被"检索回执"再替换。

- **成本模型的外部效度**：成本以 `N + w_r R` 的 token 计费单位衡量，`w_r` 被当作可调常数。真实服务商的缓存定价、缓存过期（TTL）、缓存命中粒度（前缀分块 vs. 精确匹配）、以及未命中后的重算计费方式可能与模型有差异。论文用 5 档 `w_r` 做敏感性是对这一点的部分回应，但未做端到端账单核对。
- **统计功效**：续作质量 93 次评测（31 探针 × 3 种子）在 6 种策略上做比较，单格样本量偏小；未报告置信区间或显著性检验，只能看出趋势而非稳健的统计结论。
- **鲁棒性检验覆盖面**：±5% 扰动仅作用于 `W/G/Q` 三个估计量，未扰动热尾部边界、块长度 `x`、缩短量 `g` 等结构性参数，也未测试估计器系统性偏差（如分词不一致）下的表现。

总体上，实验在"调度策略对比"这一目标上是**受控且自洽**的，但在"端到端系统收益"与"跨供应商成本模型"上的外部效度有限；论文对此基本保持克制，没有过度外推。

## 6. 主要结论与发现

- **核心结论**：上下文压缩的提交时机是一个独立的优化维度，且可以在**完全在线、无需 LLM、无需未来信息**的条件下近似最优地求解。CADOC 把"何时替换"归结为一个可观测的阈值判据 `W_t + w_r G_t ≥ Q_t`，其经济含义是"等待损失首次超过共享重建成本"。
- **反直觉现象的验证与解释**：论文用 HCE 实例说明，立即替换虽然把累计输入 token 砍掉 55.93%，却因为反复打断前缀缓存而使成本上升 3.67%。这直接支撑了"token 更少 ≠ 成本更低"的论点，也解释了为什么 Immediate 与 token 阈值类基线在长历史下会系统性劣于批处理策略。
- **调度器表现**：在 HCE 重放中，CADOC 相对 Immediate 取得显著成本下降，并且其表现接近各 `h` 设置下**调优后的最优固定批量**，却不需要为每个设置手工选择 `b`；跨 `h ∈ {2,4,8,16}` 与 `w_r ∈ {0.05,…,1}` 均保持稳定排序，说明判据对这两个关键超参不敏感。
- **理论保证**：命题 2 给出 `2Q_max/Q_min` 的竞争比；当 `Q_t` 恒定时退化为 2-competitive。这为该在线规则提供了最坏情况下的性能边界，而非仅有经验证据。
- **系统级影响**：在三条完整基准链上，CADOC 在保持任务完成率与 session-macro 分数接近 FULL 的前提下降低了输入成本，说明压缩并不必然以能力损失为代价——前提是对象可逆、可精确检索。
- **边界情形的自洽性**：当 `w_r = 1`（缓存读取与未缓存 token 等价计费）时 `Q_t = 0`，判据退化为"立即提交"，CADOC 与 Immediate 打平。论文主动报告这一退化，说明规则在极端参数下行为合理而非人为占优。
- **决策可验证性**：184 个非空 pending 边界上的提交决策全部与判据一致，±5% 扰动下 172/184 不变，表明该规则实现忠实、且对估计噪声有一定容忍度。

## 7. 局限与未来方向

- **模型假设较强**：平稳模型假定每请求周期产生固定长度 `x`、内含恰好一个可替换对象、缩短量恒为 `g`、热尾部恒含 `h` 块。真实智能体轨迹中对象到达是**突发、变长、成簇**的，`g` 也随对象类型（代码文件 vs. 日志）剧烈变化。论文用在线判据绕开了对平稳性的依赖，但竞争比分析仍建立在 waiting–setup 目标与 `Q_t` 有界的前提上。
- **单一编辑点的简化**：分析中"最早 pending 编辑点决定重建起点"是批处理共享成本的关键，但未讨论同一请求内多个不相邻编辑点、或编辑点跨越多个缓存分块时的更细粒度成本结构。
- **未与有损压缩联合优化**：CADOC 只调度提交，不决定压缩谁。如何把"选择替换对象"的收益（载荷大小、未来复用概率）与"提交时机"的缓存成本放进统一目标，是自然的下一步。
- **缓存模型理想化**：未纳入缓存淘汰、TTL、服务端前缀分块对齐等现实因素；若缓存前沿与论文假设的"连续前缀"不符，`H_shared_t` 的估计会偏乐观。
- **评测范围**：`gpt-5.6-terra` 单一模型路由、三个基准、有限的任务子集（LongMemEval-V2 仅前 18 任务），结论向其他模型族与更长任务谱系的迁移性未经检验。
- **可能的扩展**：把提交判据与检索回执生命周期、跨会话持久化、以及多智能体共享缓存场景结合；用真实账单而非 token 计费单位做端到端验证。
