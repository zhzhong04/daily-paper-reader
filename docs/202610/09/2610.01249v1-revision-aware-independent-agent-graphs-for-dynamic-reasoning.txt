ABSTRACT 

Conventional reasoning protocols present a fixed, preselected task, so they cannot test whether an agent propagates relevant updates, preserves unaffected work, or reconstructs a historical task binding. We therefore study dynamic task routing , in which an event stream revises task bindings and a system must select the document version valid at each query time before solving it. To study this problem, we repurpose six widely used benchmarks: MMLU, MMLU-Pro, MedMCQA, MATH, GPQA, and HumanEval into 31,119 dynamic episodes comprising 373,428 tempo-rally categorized queries. This setting exposes a central trade-off: recomputing after every event wastes work, whereas unguarded reuse returns stale conclusions. We introduce the Revision-Aware Independent Agent Graph (RIAG), a bounded multi-agent policy that separates deterministic temporal resolution from task reasoning. RIAG caches solutions by immutable document identity, starts each fresh task with two unexposed attempts, and conditionally invokes audit and repair, using at most four calls per document version. On this collection, homogeneous RIAG achieves 54.24% joint routing-and-answer accuracy at 0.62 calls/query, compared with 32.22% at 18.00 calls/query for the strongest comparison method; heterogeneous RIAG reaches 49.78% at 0.63 calls/query. 

1 INTRODUCTION 

Language-model agents are being developed as persistent systems that remember across conversations, accumulate experience in interactive environments, and act through software interfaces rather than answer a single isolated prompt (Park et al., 2023; Packer et al., 2023; Wang et al., 2024a; Yang et al., 2024b). This shift is practically useful: an agent can carry work across sessions, incorporate environmental or execution feedback, and update a plan as new information arrives. It also makes the agent’s input an evolving event stream. A report can arrive late and describe an earlier state, an instruction can be visible before it takes effect, and a retraction can change what should have been believed about the past. A multi-agent reasoner must therefore decide which task is currently valid before solving it, whether an earlier solution still applies after a revision, and whether matching answers are independent corroboration or merely agreement induced by communication. Getting the first decision wrong means reasoning about a superseded task; recomputing after every event avoids stale reuse but wastes calls and latency on unchanged inputs; and counting an exposed agent’s agreement as a fresh vote overstates the evidence. These coupled choices motivate our central question: when an event stream revises which task is active, what should a multi-agent reasoner recompute, what may it reuse, and whose agreement should count as evidence?

Broader agent benchmarks add multi-turn interaction and partially observable environments (Liu et al., 2024; Ma et al., 2024), but evaluate progress or final success on a supplied task rather than whether the identity of that task remains valid as its governing events are revised. These settings therefore do not isolate whether a system can distinguish an event’s arrival time from its effective time, propagate a genuine routing change, ignore an irrelevant or not-yet-effective event, revise a historical binding after a retraction, or reuse reasoning when a previously solved task becomes active again. We define dynamic task routing 

to expose these capabilities: given only the event prefix received so far, a system must select the document in force at the requested time and solve it. We instantiate the problem by repurposing six widely used benchmarks: MMLU, MMLU-Pro, MedMCQA, MATH, GPQA, and HumanEval, as dynamic task routing datasets while preserving their original questions and evaluators. Figure 1 illustrates the resulting shift in evaluation. Conventional evaluation supplies one fixed task and scores one response. In dynamic task routing, we hold task content fixed as an experimental control while an arrival-ordered event history changes which document is active. This separates temporal binding and reuse from content editing; a content change would instead create a new immutable document version and force recomputation. A delayed report or future-effective instruction should leave the current route unchanged, an expiration can restore an earlier route, and a retraction can revise the document selected for a historical query. The system must therefore resolve the valid version before deciding whether an earlier solution is reusable. We introduce the Revision-Aware Independent Agent Graph (RIAG), a bounded inference policy that composes a dynamic name resolver with a content addressed reasoner (Section 4) and answers the three questions directly. Which task? At every query, a deterministic resolver uses only the visible event prefix to select the task-document version valid at the requested time. Recompute or reuse? 

RIAG caches each solution under a key containing the document version and inference configuration, and reuses the solution only when that key matches exactly, so a cache hit costs no model call. Whose agreement counts? On a cache miss, a solver and a checker answer without seeing each other’s output, so matching proposals provide independent corroboration. Only when they disagree or a check fails does RIAG call a targeted auditor and, if needed, one repairer, which limits a fresh task 2Preprint to four calls. Every invocation records which earlier outputs it received, distinguishing independent agreement from agreement after communication. RIAG requires no training or learned router and uses only a black box model interface. We compare RIAG with Debate (Du et al., 2023), Self-Consistency (Wang et al., 2023), Refine (Madaan et al., 2023), ReConcile (Chen et al., 2024), Mixture-of-Agents (Wang et al., 2024b), Self-MoA (Li et al., 2025), an answer generation adaptation of CIA (Wu et al., 2026), and Graph-of-Agents with max and mean pooling (Yun et al., 2026). Across the full collection of 31,119 episodes and 373,428 scheduled queries per method, RIAG reaches 54.24% joint accuracy, compared with 32.22% for the strongest comparison method, Debate, while using 0.62 rather than 18.00 model calls per query. It selects the correct document on every query and outperforms the strongest conventional baseline on each of the six source datasets. Its joint accuracy also remains between 53.89% and 54.50% across baseline, changed, propagation, preservation, and historical queries, whereas every conventional method loses between 24 and 29 percentage points from baseline to historical queries. On MATH, 76.9% of queries are answered from the cache and require no new model call. Assigning different specialized models across RIAG’s roles makes the initial solver and checker responses more diverse, yet final accuracy falls from 64.13% with one shared model to 54.88% with the specialized model pool. Together, these results indicate that reliable temporal binding and selective reuse can matter more than either repeated deliberation or model diversity alone. Our contributions are as follows: • We introduce dynamic task routing as an evaluation setting for agents operating over revisable event histories. We transform six widely used benchmarks into 31,119 episodes and 373,428 checkpoint queries that test propagation, preservation, historical revision, and reuse, while scoring document selection, answer correctness, and their conjunction separately. • We propose RIAG, which combines deterministic temporal resolution, exact reuse by document version and inference configuration, and an exposure aware invocation graph. Two agents commit independently before any exchange, and audit and repair are invoked only when needed, with at most four calls for a fresh task and no call for a cache hit. • We provide a broad empirical and mechanistic study across homogeneous and specialized model pools and eight comparison families. The analysis connects RIAG’s gains to accurate task binding and temporal reuse, evaluates sensitivity to inference settings, and shows that greater response diversity does not necessarily improve final accuracy. 

2 RELATED WORK 

Graph-structured agent orchestration. Several systems represent language-model workflows as graphs whose nodes are agents or operations and whose edges carry intermediate outputs. GPTSwarm optimizes node prompts and communication edges (Zhuge et al., 2024), while AFlow searches over code-represented workflows using execution feedback (Zhang et al., 2025). Graph-of-Agents develops a graph-based collaboration framework and evaluates it on isolated questions from the six benchmarks that our dynamic task routing episodes are built from (Yun et al., 2026). Our work uses a graph for a different purpose: its vertices are concrete model invocations and its edges record which outputs were exposed to later calls. The graph is therefore an auditable execution trace that shows which evidence each answer depended on. Our work further combines this trace with temporal document resolution, version-keyed caching, and a fixed four-call budget. 

Multi-agent deliberation and specialization. Multi-agent LLM systems improve test-time rea-soning by eliciting multiple candidate solutions and exchanging them through structured interaction. Multi-agent debate iteratively shares arguments among model instances (Du et al., 2023); ReConcile combines heterogeneous agents through round-table discussion and confidence-weighted consensus (Chen et al., 2024); and Mixture-of-Agents aggregates outputs through successive agent layers (Wang et al., 2024b). These systems primarily organize communication for a task that has already been selected. Our work additionally resolves which task is valid under an evolving event history. It preserves two unexposed initial proposals, treats post-exposure agreement as dependent evidence, and opens audit and repair stages only after disagreement or a structural failure. 3Preprint 

Agent memory, reflection, and revision. Long-lived agents require mechanisms for retaining and revising prior state. Generative Agents stores experience, synthesizes reflections, and retrieves memories for later planning (Park et al., 2023). Reflexion places verbal feedback in episodic memory to improve subsequent attempts (Shinn et al., 2023), while MemGPT manages multiple memory tiers to extend effective context across long interactions (Packer et al., 2023). RIAG reuses a result only when its cache key matches exactly: the same task document, model assignment, prompt policy, seed, and decoding configuration within the episode. It first decides which document is in force and only then looks up the cache, so a route that returns to an earlier document reuses its answer, while an answer is never carried over to a different document. 

3 DYNAMIC TASK ROUTING PROTOCOL 

Conventional isolated question and response evaluation presents one task, requests one answer, and resets the interaction. It measures whether a model can solve the supplied task, but not whether the model can identify which task is valid after a sequence of delayed, scheduled, superseded, expired, or retracted instructions. We therefore turn standard benchmark questions into dynamic task routing 

episodes, in which each response names the selected document and its answer. 

Illustrative example. As shown in Figure 1, a fleet operator has three fixed-content task documents: task A requests a routine market brief, task B requests a high-price budget analysis, and task C requests a regional anomaly review. The event stream and its correct interpretation are as follows. 1. At 08:00, a routine report activates task A. A current query at 08:15 must therefore return A and solve the market-brief document. 2. At 09:00, a high-price alert supersedes the routine route with task B. A current query at 09:15 must return B and solve the budget-analysis document. 3. At 09:05, the system receives a delayed report whose effective time is 07:30 and whose route is A. Although this report arrives after the high-price alert, its earlier effective time means that it must not displace B. 4. At 09:10, an anomaly notice assigning task C arrives with an effective time of 12:00. It is known to the system immediately but must not change the active route before noon. Once noon passes, a current query at 12:05 routes to C. 5. At 12:20, the anomaly instruction expires. Because B is again the most recent valid underlying route, a current query at 12:21 returns B without a new copy of task B being issued. 6. At 12:25, the 09:00 high-price alert is retracted. The retraction removes B from trusted history. Consequently, a query issued at 12:30 about the world state at 09:15 now resolves to A, even though the same historical query would have resolved to B before the retraction arrived. At every checkpoint, the system must first reconstruct the valid route from the evidence available at query time and then solve the selected document. The fixed content is an experimental control: events change the route, not the task payload, so routing and reuse can be measured without content-editing errors. A mutable payload would be represented as a new immutable version with its own answer key. The example therefore tests four distinct failure modes: allowing a delayed event to overwrite a newer route and applying a future-effective event too early ( preservation ), failing to restore an underlying route after expiration ( propagation ), and ignoring a later retraction when answering a historical query (historical ).

The reference MATH runs are cache hits on 76.9% of queries. On fresh tasks, homogeneous RIAG stops after two agreeing calls in 66.2% of cases, invokes the auditor in 30.2%, and reaches repair in 3.5%. The corresponding heterogeneous rates are 41.5%, 51.3%, and 7.2%. This deeper expansion costs more without higher accuracy: homogeneous RIAG reaches 64.13% at 0.548 calls/q, versus 54.88% at 0.614 calls/q for heterogeneous RIAG. Reuse follows the event semantics: baseline and changed queries always open a fresh graph, 74.3% of propagation queries reuse a solution, and all preservation and historical queries do so. On fresh tasks, the two-call agreement route is accurate in 82.1% of homogeneous and 85.4% of heterogeneous cases. Audited and repaired cases are harder, but their conditional accuracy does not measure the value of extra calls because disagreement or failed validation triggers those routes. Figure 4 asks whether greater response diversity is useful. A role probe reaches 34.3% balanced accuracy for homogeneous RIAG (25% chance) and 65.7% for heterogeneous RIAG, where role and model are confounded. Heterogeneity increases mean solver–checker cosine distance from 0.111 to 0.190, a paired increase of 0.080 (95% task-bootstrap interval [0 .075 , 0.084] ), and produces the larger distance on 83.8% of matched tasks. That separation does not improve outcomes. Useful diversity rises from 16.4% to 32.0%, but initial answer coverage falls from 73.4% to 68.8% and final unique-task accuracy from 67.6% to 57.5%. From the closest to farthest distance quartile, coverage also falls from 80.7% to 62.8% for homo-geneous RIAG and from 79.8% to 55.9% for heterogeneous RIAG. Among the 478 homogeneous and 830 heterogeneous tasks selected for auditing, rescue rates are 2.5% and 0.6%, damage rates are 19.2% and 19.4%, and final accuracies are 32.8% and 36.5%. These rates are descriptive because difficult cases trigger auditing. Appendix Section D.6.5 provides the full analysis. 9Preprint 

6 CONCLUSION 

We introduce RIAG, a bounded inference policy that separates temporal task resolution from task reasoning, so that solutions are reused across event revisions and agreement is counted only when it precedes communication. Experiments on six dynamic task routing datasets show higher joint accuracy at fewer than one model call per query, and the resolver-controlled GoA study shows that the temporal front end composes with a different reasoning-graph family. We hope this separation helps future work and agents that operate over evolving event streams.

D.4 INTERPRETATION AND LIMITATIONS 

These experiments evaluate RIAG as a complete system, not the isolated effect of its graph policy. RIAG combines deterministic resolution, episode-local reuse, its model configuration, and a repaired answer path; comparison runs also differ in decoding constraints and context length. The full collection uses one seed, checkpoints within an episode are correlated, and MATH uses exact string scoring. Isolating the mechanisms requires matched resolver and cache controls, multiple inference seeds, and randomized post-trigger actions. D.5 DATASET AND QUERY -CATEGORY BREAKDOWNS

Public episode input. At episode_start , every method receives the same instruction block. It states that documents are immutable tasks rather than answer reports; that delivery_request 

reads active_task while archive_request keeps its initial fixed binding; and that selection uses the greatest valid (effective time , arrival time , event ID ) among only the events received so far. It also specifies the effects of supersession, expiry, retraction, delayed reports, future-effective assertions, and historical queries, and explicitly says that no gold feedback is provided. The complete block is stored once per episode in the public instructions field of stream.jsonl ; it is also reproduced byte-for-byte as INSTRUCTIONS in the frozen source_snapshot/adapt_all_ benchmarks_to_des.py . Here immutability is an experimental control, not a claim about all document workflows: source-task content and its answer key remain fixed while events change the active binding. A content edit would require a new version, but the current collection does not evaluate free-form document editing. For completeness, its full text is: 

This is a synthetic task-versioning workflow over real, immutable source tasks. Task documents are not answer reports. Solve the selected document; never infer correctness from selection. The active_task property selects a task document. The delivery request depends on active_task . The archive request permanently selects the document specified by its binding event. Return a JSON object with document_id (A, B, or C) and 

answer . If a method wraps its response in an answer field, put this object inside that field. The answer value is: for multiple choice, its source option letter; for mathematics, its mathematical answer; for programming, complete Python source implementing the selected document’s original entry point. All active_task assertions have the same authority. At each query use only events already received. At the queried world time, select the still-valid assertion with greatest effective time (then arrival time, then ID). Supersession closes only its target at the new effective time. Expiry closes only its target, preserving earlier history. Retraction discredits its target at all historical times once the retraction has arrived and become effective. An explicitly superseded assertion never revives. Other still-valid assertions can resume after a temporary assertion expires or is retracted. Delayed reports do not overwrite later effective assertions. Future-effective assertions do not apply early. Historical queries use the evidence known now, not evidence that will arrive later. No gold feedback is given.

Parsing and evaluation. For multiple choice, only an original displayed option letter is valid; no random answer is substituted after a parse failure. MATH preserves the text inside the final box and compares it by exact string equality to the frozen source answer, without evaluator-side symbolic equivalence. The 373,428 queries are deliberately balanced by role. Each episode has one baseline and one changed query (31,119 of each collection-wide), four preservation queries (124,476), three historical queries (93,357), and three propagation queries (93,357). Preservation tests that irrelevant, delayed, or not-yet-effective events do not cause an incorrect route; propagation tests that relevant changes do; and historical queries require a past binding to be reconstructed using evidence available at the current arrival point. Figure 9 compares protocol structure over the same 31,119 source items. Relative to one isolated prompt and answer per item, Dynamic task routing creates 12 × as many scored checkpoints and 26 ×

as many public input records. The original source prompts contain 2.70 million whitespace-separated tokens, whereas the visible text fields in the dynamic streams contain 30.05 million, an 11.1 × increase. This is a transparent workload descriptor rather than a model-tokenizer count; it also does not imply that accuracy or sample efficiency improves by the same factor. Baseline and changed checkpoints route to different documents in every episode. Nevertheless, 5,904 of the 30,955 exact-answer episodes (19.1%) have the same baseline and changed answer string. The rate is 25.3% for MMLU, 10.0% for MMLU-Pro, 26.2% for MedMCQA, 1.0% for MATH, and 25.8% for GPQA; HumanEval is excluded because its response is executable code evaluated with hidden tests. These collisions show why answer-only scoring is insufficient: a system can return the coincidentally correct option letter while routing to the wrong document. We consequently report document-selection accuracy, answer accuracy, and their conjunction. Figure 10 summarizes the additional checkpoints and collision rates. F METHOD DETAILS 

This section completes the resolver rules of Section 4.3 and the cache key of Section 4.4, and describes the invocation records of Section 4.5. F.1 COST AND GUARANTEES 

Let U be the number of distinct keys in an episode and nj the number that finish after j ∈ { 2, 3, 4}

calls. The episode then costs 

CRIAG = 2 n2 + 3 n3 + 4 n4 ≤ 4U, U = n2 + n3 + n4, (9) model calls, and every other query in the episode is a cache hit that costs none. Running the solver and checker in parallel shortens a miss from two, three, or four sequential steps to one, two, or three, and leaves the calls, seeds, and graph unchanged; we therefore report calls and tokens separately from latency. The implementation enforces five invariants: • prefix isolation : a query sees only public events with a(e) ≤ t;• selection freshness : the resolver runs at every query; • version binding : a cached solution is reused only under an identical key; • exposure accounting : every node records A(v);• budget integrity : failed calls use up budget, and exhausted results are cached. These invariants cover what each call could see and how many calls ran. They do not guarantee answer correctness, independence of model errors, or safe reuse after an unversioned in-place edit. The benchmark excludes such edits as an experimental control; a content change must create a new version and cache key. 29 Preprint 

Route and archive requests. A delivery request is resolved by the active active_task assertion with the lexicographically largest (τ (e), a (e), id( e)) . An archive request instead follows its own fixed-document binding, provided that binding is still active under the same rules. 

Validity check. The selected document must have exactly one active version assertion; that assertion is edt in Equation 2. The resolver also records the assertion that selected the route, for provenance. The memoization key leaves this route-support event out, so a route that leaves a document and later returns to it reuses the earlier solution. 

No stored state. The resolver keeps no current-route pointer between queries; it recomputes the route from Ht every time. A late retraction therefore changes the route of every later query it affects, current or historical, without any update step. 

Cache-key contents. The fields of Equation 4 are serialized in a fixed order before hashing. In homogeneous RIAG, M is the identity of the shared checkpoint. In heterogeneous RIAG, M is the ordered tuple of role, model ID, and declared model revision for all four roles, so replacing any role’s checkpoint changes the key. Serving endpoints are left out: moving the same declared weights to another server keeps the key. 

Invocation records. Each node stores its role, cache key, document event, model and prompt revisions, sampling seed, parsed answer, parse or structural failures, status, and token usage. Each edge stores its purpose, CHALLENGE for the two edges into the auditor and REPAIR -REQUEST for the edges into the repairer, together with a hash of the exact peer text that was sent. When parallel calls are enabled, the solver and checker requests are sent as one concurrent batch; otherwise they run one after the other with the same seeds, and the graph is identical. The unresolved flag on a repaired or fallback answer marks that no accepting condition was met; an answer is still returned in that case. 

Format checks. All checks use the selected public task; evaluator labels are loaded only after replay, for scoring. For multiple-choice datasets, guided decoding is supplied when the server supports it, and the parser accepts only a listed option letter. An option written out in full is mapped to its letter only when it matches one option’s text uniquely, or when the model’s own justification marks the choice; unmarked prose is left unparsed. For MATH, each role must show a derivation and end with a nonempty \boxed{...} expression, which is extracted as written, without symbolic simplification or reference to the gold answer. For HumanEval, the source must parse as Python and define the entry point named in the prompt; hidden tests are never run during inference. These checks test the format of an answer. A wrong fact, a wrong boxed result, or a buggy but well-formed program passes them and is left to agent disagreement and to the external evaluator. 

Model identity. Server discovery checks that each endpoint advertises its configured model ID. Model revisions are declared by the operator, because the OpenAI-compatible discovery interface does not report weight hashes. F.2 A SHARED -EPISODE RESPONSE EXAMPLE
