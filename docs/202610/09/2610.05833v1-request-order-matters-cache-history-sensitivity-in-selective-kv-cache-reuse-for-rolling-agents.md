## 摘要
长时间运行的智能体会反复调用 LLM，同时保留其大部分文档窗口，逐出旧文档并追加新文档。这些滚动更新破坏了精确前缀缓存，并推动了带有选择性重计算的非前缀 KV 缓存复用。我们表明，带有选择性重计算的持久 KV 缓存复用可能具有历史依赖性：在我们的滚动智能体工作负载中，一个未改变的提示可能会根据其之前处理过的请求而产生不同答案。在匹配的 5% 重计算预算下，文档对齐重计算将不同请求顺序间的答案变化从 CacheBlend 的 token top-$k$ 策略下的 69.0% 降至 26.1%。当每个提示在一组不同的先前请求序列之后被评估时，文档对齐重计算相对于 token top-$k$ 将相对于完整预填充的保真度提高了 34.5–52.5 个百分点，而两种策略都实现了约 5.7 倍的中位 TTFT 加速。我们的消融研究表明，在我们的滚动智能体工作负载中，连续性是与稳健选择性重计算相关的主要因素。

## Abstract
Long-running agents repeatedly call an LLM while retaining most of their document window, evicting old documents, and appending new ones. These rolling updates break exact prefix caching and motivate non-prefix KV-cache reuse with selective recomputation. We show that persistent KV-cache reuse with selective recomputation can be history-dependent: in our rolling-agent workload, an unchanged prompt can produce different answers depending on the requests processed before it. At a matched 5% recomputation budget, document-aligned recomputation reduces answer variation across request orders from 69.0% with CacheBlend's token top-$k$ policy to 26.1%. When each prompt is evaluated after a different sequence of preceding requests, document-aligned recomputation improves fidelity to full prefill by 34.5-52.5 percentage points over token top-$k$, while both policies achieve approximately 5.7$\times$ median TTFT speedup. Our ablation study shows that, in our rolling-agent workload, contiguity is the main factor associated with robust selective recomputation.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：长时运行的智能体（研究代理、金融监控代理等）会反复调用 LLM，同时保留大部分文档窗口，逐出旧文档、追加新文档。例如窗口 `[D1,…,D84]` 在下一步变为 `[D2,…,D85]`。
- **痛点**：这种滚动更新破坏了精确前缀缓存（exact prefix caching）的前提。虽然 83/84 份文档文本未变，但它们的位置前移、前置上下文改变，导致其先前计算的 KV 状态不再等于新提示全量预填充所产生的状态。最长共享前缀仅剩固定指令，标准前缀缓存无法复用任何保留文档的 KV。
- **解决方向**：非前缀 KV 缓存复用 + 选择性重计算（如 CacheBlend 加载缓存 KV 后，只重算高偏差 token）。已有系统（CacheBlend、EPIC、KVLink、MiniPIC、LMCache 等）证明了可降低预填充延迟。
- **核心问题**：作者指出一个被忽视的维度——**持久缓存状态会跨请求累积，选择性重计算可能具有历史依赖性**。同一提示在不同前置请求序列下可能产生不同答案，而现有评估大多在"干净缓存"上孤立地跑单条请求，可能完全掩盖这一问题。
- **整体含义**：这是一个闭环服务问题——每次 LLM 调用既消费又更新缓存状态，后续请求被先前请求所条件化。重试、分支轨迹、并发会话、调度交错都会让同一提示遇到不同的缓存状态，因此选择性 KV 复用策略必须与持久缓存生命周期协同设计。

## 2. 方法论

### 核心思想
在**固定 5% 重计算预算**（重算 token 数量完全一致）的前提下，对比"散点式选择高偏差 token"与"连续区域选择"的鲁棒性差异，并区分连续性、文档边界、偏差排序三个因素各自的贡献。

### 关键技术细节

- **偏差度量**：对每个可复用 token，计算当前 key 与加载的缓存 key 的 L2 距离平方：
  `d_i = ||K_current_i − K_cached_i||²₂`
  值越大表示该 token 的缓存 key 与当前提示下计算出的 key 偏离越大，优先级越高。
- **预算规则**：对 N 个可复用 token、重算比例 r，选取 `k = max(1, ⌊rN⌋)` 个 token。选择器只在某一"选择层"运行一次，所选位置在后续所有层复用同一套选择结果。
- **片段评分**：对候选连续片段 `S_j`，用平均偏差评分
  `ρ_j = (1/|S_j|) Σ_{i∈S_j} d_i`
  按长度归一化，避免长片段仅因 token 多而得分高。
- **五种等预算策略**（均重算恰好 k 个 token）：
  1. **Token top-k**（CacheBlend/LMCache 默认）：选偏差最大的 k 个孤立 token，可能散布在数百个不连续区域。
  2. **Single-window**：选总偏差最大的连续 k-token 窗口。
  3. **Fixed-chunk**：将可复用提示切为等长 92-token 片段（对齐文档中位长度），并偏移使其跨越文档边界，按 ρ_j 排序。
  4. **Random-document**：使用文档片段但按确定性随机顺序选取，忽略偏差分数。
  5. **Document-aligned**（主对比策略）：按指令片段、各文档片段、最终查询切分，按 ρ_j 排序，在预算内优先选完整片段；若仍有剩余 token，则从排名最高的剩余片段中选总偏差最大的连续窗口，最终恰好选满 k 个 token。
- **消融逻辑**：仅 Random-document 与 Document-aligned 使用文档边界；Single-window 与 Fixed-chunk 定义连续区域但不依赖文档边界。据此分离"连续性""文档边界""偏差排序"三个因素。

## 3. 实验设计

### 数据集与场景
- **真实事件数据集**：共 8,995 条记录，覆盖 15 只美股：
  - 7,515 条 Yahoo Finance 日价格记录
  - 792 条 FNSPID 新闻标题
  - 688 条 SEC EDGAR 申报标题
- 将新闻/申报日期映射到各股票的价格日历上，交错三通道并保持各通道内部顺序。
- **滚动智能体工作负载**：固定窗口 84 份文档、步长 1，每次调用逐出 1 份旧文档、保留 83 份、追加 1 份新文档，共产生 7,735 次滚动更新。提示长度约 7.2K–7.7K token。
- **任务**：最终查询要求模型从当前窗口中某一观察记录逐字复制指定字段，属确定性抽取任务，便于精确答案比对。

### Benchmark 与请求顺序协议
- 同一批请求以**五种顺序**处理（提示本身不变，仅进入服务系统的顺序变化）：
  - Chronological（源顺序，模拟正常滚动流）
  - Fixed-random（三种预定打乱顺序，模拟共享缓存服务多代理时的交错）
  - Reversed（逆序，确定性压力测试）
- 每种"策略 × 顺序"组合都从空 LMCache 状态开始，跨请求保留缓存，与其他运行不共享状态。
- 每次滚动更新先填充上一窗口的文档 KV 缓存，再评估更新后的窗口。

### 对比方法
- **主对比**：Token top-k（CacheBlend/LMCache 默认）vs. Document-aligned 重计算。
- **消融对比**：上述五种策略。
- **基线**：Full prefill（完整预填充）。

### 评估指标
- **答案变化率（Answer variation）**：对每个请求，比较五种顺序两两配对（共 10 对）的答案是否不同，统计不一致比例。
- **保真度（Fidelity）**：与完整预填充答案的精确一致率。
- **TTFT**：请求级中位与 P95 首 token 时间，及相对完整预填充的加速比。

### 系统配置
- 模型：Qwen3-8B，贪心解码（temperature 0），固定随机种子。
- 框架：LMCache 0.5.1 + vLLM 0.23.0，**禁用 vLLM 前缀缓存**以测量 LMCache 的非前缀复用路径。
- 两种策略共用同一模型、提示、可复用 token 接口、偏差度量与 5% 重算规则。

## 5. 实验数量与充分性

### 实验规模
- **主实验**：2 种策略 × 5 种请求顺序，覆盖全部 7,735 次滚动更新。
- **缓存历史敏感性分析**：每请求 10 对顺序两两比较。
- **缓存重置对照实验**：500 请求，每次请求前重置缓存。
- **选择模式消融**：5 种策略 × 2 种顺序（Chronological + 一种 Fixed-random），在同一 500 请求队列上，严格匹配重算 token 总数（Chronological 为 188,562，Fixed-random 为 188,721；每请求中位 386/387 token）。
- **可复现性控制**：独立重复 Chronological 顺序，所有答案完全复现，排除运行间随机波动；请求逐条发出，排除批组成效应。

### 充分性与公平性评价
- **优点**：等预算设计（匹配实现的重算 token 数）使保真度差异可归因于"选在哪里"而非"选了多少"，这是很强的公平性保障。统计检验（p 值、95% CI、Wilson 区间）齐备。缓存重置对照有力地区分了"策略固有优势"与"历史累积导致的问题"。
- **不足**：消融仅在 500 请求队列上进行，样本规模相对主实验小；仅测试 5% 单一重算比例；仅一种固定随机顺序用于消融；消融对比未做多随机种子的顺序重复。

## 6. 主要结论与发现

- **请求顺序确实改变答案**：答案变化率为 Token top-k **69.0%** vs. Document-aligned **26.1%**。
- **保真度受顺序影响显著**：
  - Chronological 下两者无显著差异：86.8% vs. 85.4%（p = 0.12）。
  - 其余四种顺序下：Token top-k 为 19.8–41.5%，Document-aligned 为 54.3–91.7%（均 p < 0.0001），提升 34.5–52.5 个百分点。
  - Document-aligned 也非免疫：Reversed 顺序下保真度降至 54.3%。
- **TTFT 收益相当**：Full prefill 中位 2,408 ms / P95 2,524 ms；Token top-k 5% 为 426 ms / 459 ms（5.68×）；Document-aligned 5% 为 415 ms / 477 ms（5.74×）。两者延迟相近。
- **缓存重置对照**：500 请求重置缓存后，Token top-k 94.0% vs. Document-aligned 92.6%（p = 0.23），无显著差异。说明 Document-aligned 的优势**依赖于跨请求累积的缓存历史**，干净缓存评估会漏掉该效应。
- **消融揭示"连续性"是主因**：
  - Chronological 下五种策略保真度相近（86.2–89.2%），无策略有明确优势。
  - Fixed-random 下 Token top-k 跌至 38.6%，而四种连续策略达 89.4–92.8%（各提升 50.8–54.2 个百分点，均 p < 0.0001）。
  - **文档边界与偏差排序无额外显著优势**：Single-window 最高（92.8%），Document-aligned 与 Single-window（p = 0.076）、Fixed-chunk（p = 0.85）、Random-document（p = 0.37）均无显著差异。
  - **捕获更多偏差 ≠ 更高保真度**：Token top-k 在 Fixed-random 下覆盖中位 180.5 个区域、捕获 99.7% 偏差，保真度仅 38.6%；Random-document 完全不看偏差信号、仅选 6 个整文档片段、捕获 4.8% 偏差，保真度却高 50.8 个百分点。
- **总体结论**：相同重算成本下，重算连续区域比重算散点高偏差 token 更有效；连续性（contiguity）是稳健性的主要关联因素；高效代理服务需要将重算策略与持久缓存生命周期协同设计。

## 7. 优点

- **问题视角新颖**：首次系统性地指出选择性 KV 缓存复用的"缓存历史敏感性"，把评估从"孤立单请求 + 干净缓存"推进到"持久缓存 + 真实请求序列"，填补了重要评估盲区。
- **等预算对比设计严谨**：所有策略重算完全相同的 token 数，把保真度差异严格归因于选择位置，避免"多算换高保真"的混淆。
- **消融设计干净**：通过 Single-window、Fixed-chunk、Random-document、Document-aligned 四组对照，清晰分离了连续性、文档边界、偏差排序三个因素，得出"连续性为主因"的结论。
- **缓存重置对照实验极具说服力**：直接证明优势来自缓存历史累积，而非策略本身在孤立场景下的优越性，对评估方法论有警示意义。
- **工程可行性强**：Document-aligned 直接利用文档型提示中已有的文档边界，无需学习型分割器或人工设定块大小，落地成本低。
- **统计严谨**：报告 p 值、95% CI、Wilson 区间，并做了重复运行验证与逐条请求发送以排除批效应。
- **指标设计合理**：答案变化率 + 保真度 + TTFT 三视角结合，兼顾输出稳定性、正确性与效率。

## 8. 不足与局限

- **模型与硬件单一**：仅测试 Qwen3-8B 与 NVIDIA L4，未验证其他模型规模/架构、其他 GPU 或分布式服务场景，结论泛化性存疑。
- **任务类型受限**：仅使用确定性字段复制抽取任务，便于精确比对但缺乏对生成式、推理型、开放式任务的验证；不同任务对缓存误差的敏感度可能不同。
- **数据集规模有限**：仅 15 只美股、8,995 条记录，领域单一（金融），未覆盖多语言、多模态或长文档科研场景。
- **重算比例单一**：仅测试 5% 这一档，未考察 1%、10%、20% 等不同预算下的策略排序是否稳定。
- **消融规模较小**：消融仅在 500 请求队列、单一 Fixed-random 顺序上进行，未做多随机顺序或多随机种子重复；部分 p 值（如 Document-aligned vs. Single-window，p = 0.076）处于临界区，结论需更大样本确认。
