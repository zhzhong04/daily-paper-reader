## 摘要
大语言模型（LLM）服务正日益由智能体工作负载主导；在这些负载中，智能体及其子智能体在多次请求间以 KV 缓存的形式累积上下文，消耗大量内存。高带宽闪存（HBF）是一种有前景的解决方案，它能以 HBM 级读取带宽提供高一个数量级的容量，但其有限的写入耐久性是关键限制因素。我们的关键洞察是：KV 缓存应根据其寿命在 HBM 与 HBF 之间进行放置。将较短寿命的数据放在 HBM 中，可使 HBM 吸收一次智能体运行中更多的写入，从而减少发送到 HBF 的写入量。由于智能体服务中 KV 缓存的寿命由 harness（即编排智能体的程序）决定，我们分析了其行为，并识别出寿命差异的三个维度：时间性、结构性和工作进程间。基于这些观察，我们提出 Lachesis，一个位于智能体 harness 与服务引擎之间的寿命感知 KV 缓存放置层。在写入时，它根据每个段的寿命将其放置在 HBM 或 HBF 中，并在该段不再被读取后释放其块。在轨迹驱动的仿真中，Lachesis 将 HBF 寿命相比 HBM 优先放置延长了 1.19–3.13 倍，达到 3.3–12.2 设备年。即使在严格 SLO 所允许的满负载下持续 24x7 运行，在多智能体轨迹上，HBF 仍能超过其五年保修期。

## Abstract
Large language model (LLM) serving is increasingly dominated by agentic workloads, in which agents and their sub-agents accumulate context as KV cache across many requests, consuming substantial memory. High-bandwidth flash (HBF) is a promising solution, providing an order of magnitude greater capacity at HBM-class read bandwidth, but its finite write endurance is the key limiting factor. Our key insight is that KV cache should be placed across HBM and HBF by its lifetime. Placing shorter-lived data in HBM lets HBM absorb more of an agent run's writes and sends less of them to HBF. As the lifetime of KV cache in agentic serving is dictated by the harness, the program that orchestrates the agents, we analyze its behavior and identify three axes along which lifetime diverges, temporal, structural, and inter-worker. Guided by these observations, we present Lachesis, a lifetime-aware KV cache placement layer between the agent harness and the serving engine. At write time, it places each segment in HBM or HBF according to its lifetime, and frees its blocks once the segment is no longer read. In trace-driven simulation, Lachesis extends HBF lifetime by 1.19-3.13x over HBM-first placement, reaching 3.3-12.2 device-years. Even under continuous 24x7 operation at the full load a tight SLO admits, HBF outlasts its five-year warranty on the multi-agent trace.

# Lachesis 论文深度总结

## 1. 核心问题与整体含义（研究动机与背景）

- **工作负载范式转移**：LLM 服务正从无状态请求转向**智能体（agentic）工作负载**——一个 agent 围绕单个用户任务发起多轮 LLM 请求，并派生并发的子智能体（sub-agent）。
- **KV 缓存的生命周期被拉长**：传统请求的上下文只在单次请求内有效；而 agent 会把会话中累积的上下文以 KV 缓存形式长期驻留，某些情况下持续到会话结束。子 agent 的加入进一步放大了同一时刻存活的 KV 体量。
- **容量墙**：智能体工作负载的峰值上下文长度比传统聊天负载大 **29×**；多智能体会话同时持有多个上下文。HBM 容量不足迫使部署方增加加速器或降低并发会话数，二者都会推高单请求硬件成本。
- **HBF 的机会与约束**：高带宽闪存（HBF）可提供约 **16×** 于 HBM 的单栈容量，并具备 HBM 级顺序读带宽。但其**写入耐久性有限**（NAND 的 P/E 周期有限），无法承担类似 DRAM 的写入角色。
- **已有方案的不足**：
  - 早期 HBF 设计（H3、FLINT 等）仅承载**只读数据**（模型权重、预计算/共享前缀 KV），不消耗写入耐久度。
  - 后续工作（Kyung et al.、DASH、FlashAccel 等）开始把动态生成的 KV 放入 HBF，但主要依据**读写比（ρ_R/W）**选择——该准则源于无状态请求：输出越长、KV 复用越多。
  - 但 agent 会话是**有状态**的，上下文不同部分的可读时长不同，读写比无法刻画寿命。
- **核心洞察**：KV 缓存应按**寿命（lifetime）**在 HBM 与 HBF 间放置。HBM 在一段时间内能吸收的写入量 = 其容量 × 每块被回收的次数；把短寿命块放进 HBM，能让 HBM 吸收更多写入、减少送达 HBF 的写入，从而延长 HBF 寿命。

## 2. 方法论

### 2.1 关键观察：寿命分化的三条轴（基于对 agent harness 的行为分析）

| 轴 | 范围 | 分裂来源 | 短寿命段 | 长寿命段 | 信号类型 |
|---|---|---|---|---|---|
| 时间轴 | 会话 ⊃ 轮次 | 推理内容剥离（turn-end） | reasoning-laden | reasoning-stripped | 确定性边界 |
| 结构轴 | 会话 ⊃ 子 agent | 子 agent 返回 | sub-agent 段 | lead-agent 段 | 确定性边界 |
| 工作进程间轴 | 跨 worker 调用 | 返回时间差异 | 早返回 worker | 晚返回 worker | 预测排名 |

- **时间轴**：每轮用户消息开启一个 turn；下一消息到来时 harness 丢弃该轮产生的推理内容。reasoning-laden 段占一轮写入 KV 的 **66–83%**，但仅存活一轮；reasoning-stripped 段寿命长 **7.6–17.2×**（可分性 0.96–0.99）。
- **结构轴**：lead agent 把子任务委派给 sub-agent，后者返回时只有结果被合并。lead-agent 段寿命比 worker 段长 **4.0–6.1×**、比 reviewer 段长 **4.7–38.3×**（可分性 0.90–1.00）。lead-agent 段在其寿命的 **71–88%** 时间内处于未被读取状态，导致 lead agent 与 worker 的 ρ_R/W 区间重叠（0.25–0.60）——**复用率不能作为寿命的代理指标**。
- **工作进程间轴**：所有 worker 段同属一类，无上下文边界分隔；worker 寿命 p10–p90 相差 **3.7–23.6×**，写入量相差 2.8–22.5×，二者 Kendall's τ 为 0.51–0.72。寿命 = 轮数 × 单轮代价 + 工具调用延迟，而延迟不增加 token，故写入量相近的 worker 寿命可能差异巨大。
- **可预测性**：worker 寿命的**相对顺序**可在 spawn 时刻从 spawn record（Instruction、Context、Tools、Model 及会话位置）预测，而无需精确估计 Tnorm。

### 2.2 Lachesis 设计

- **定位**：位于 agent harness（OpenHands SDK、AOrchestra、Claude Code 等）与推理引擎（vLLM、SGLang 等）之间的**寿命感知 KV 缓存放置层**。仅覆盖 KV，模型权重沿用只读映射，激活仍在 HBM。
- **三个组件**：
  1. **确定性路径（deterministic path）**：处理时间轴与结构轴。harness 已固定的段类别直接决定层级——短寿命段（reasoning-laden、sub-agent/reviewer）放 HBM，长寿命段（reasoning-stripped、lead-agent）放 HBF。reviewer 段无条件进 HBM；worker 段由预测路径裁决。
  2. **预测路径（predictive path）**：处理工作进程间轴。在每个 worker spawn 时，用 **spawn signal**（指令、上下文、工具列表的长度/指示变量、会话位置、词袋哈希）经 **岭回归（ridge regression）** 的线性模型打分，**只取排序名次**；按"最短优先"排序，前 k 个准入 HBM，其余放 HBF。k 由 HBM 空闲容量决定而非超参；在计数 k 前先为 reviewer 预留 HBM 容量。
  3. **段表（segment table）**：每个存活段一行，以 segment id 为键，记录段类别、关闭它的上下文边界、以及引擎侧 KV 块 id。段首次写入时建行，边界到达时释放块并删行。
- **与引擎的接口（仅两个调用）**：
  - `alloc(tier)`：从指定层级（HBM/HBF）的空闲块链表取一个 KV 块；HBM 空闲链空时由 HBF 链服务。
  - `free([block ids])`：段关闭时归还其持有的块，各回到来源层级的空闲链。
  - 引擎只需把单一空闲链改为**每层一个空闲链**，块所属层级即为其来源链；引擎本身不表示寿命概念。
- **寿命度量（分析用）**：
  - Tnorm(s) = G_dec(s)·TPOT_ref + N_obs(s)·TTFT_ref + Λ_tool(s) + Λ_user(s)，其中 TPOT_ref = 0.2 s、TTFT_ref = 1.0 s；Λ_tool 与 Λ_user 为建模值（指数分布/对数正态），而非取自 trace。
  - ρ_R/W(s) = V_R(s) / V_W(s)，V_W(s) = N_W(s)·V_token_KV，V_R(s) 按全上下文注意力下逐 decode 步的存活 token 累加（见附录 B）。
- **流程要点**：所有层级决策在写入前完成；短
