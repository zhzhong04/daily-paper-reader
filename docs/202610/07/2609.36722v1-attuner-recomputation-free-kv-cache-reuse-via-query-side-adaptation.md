## 摘要
大型语言模型（LLM）智能体会反复将可复用内容（如技能、文档和记忆条目）加载到当前上下文中。为每个请求重新编码这些内容会浪费计算。位置无关缓存（PIC）通过独立编码每个工件并在任意位置复用其键值（KV）状态来缓解该问题，但相对于全上下文预填充会带来质量损失。现有方法通过恢复全局位置 ID 或重计算选定 token 来修复这一损失。在这项工作中，我们定位了损失的来源，发现位置不匹配的影响较小，而独立缓存的工件仍保留忠实的表示：读取给定工件时基本保持准确，只有当模型必须在多个工件之间进行选择时性能才会下降。此外，用全预填充分数替换 PIC 的注意力分数，在缓存 KV 不变的情况下即可恢复性能，从而将故障定位到注意力而非 KV 重计算。受此启发，我们提出 Attuner，一种学习读取冻结工件缓存的查询侧自适应方法。Attuner 在查询投影中插入低秩适配器，并通过将全预填充分布蒸馏到学生模型中进行训练。它训练的参数少于模型参数的 0.05%，并且在推理时既不需要缓存重计算，也不需要全上下文参考。在 Qwen3-4B 和 Qwen3-8B 上，跨涵盖技能、文档、记忆和代码的七个基准，Attuner 在域内和域外设置中均显著优于先前的 PIC 基线，达到与全上下文预填充相当的质量，同时提供最高 3.73 倍的加速。

## Abstract
Large language model (LLM) agents repeatedly load reusable content, such as skills, documents, and memory entries, into the current context. Re-encoding this content for every request wastes computation. Position-independent caching (PIC) alleviates this by encoding each artifact independently and reusing its key-value (KV) states at arbitrary positions, but it incurs a quality loss relative to full-context prefill. Existing methods repair this loss by restoring global position IDs or recomputing selected tokens. In this work, we isolate the source of the loss, finding that the positional mismatch has minor effect, and independently cached artifacts retain faithful representations: reading a provided artifact stays largely accurate, and performance degrades only when the model must select among multiple artifacts. Moreover, replacing PIC's attention scores with full-prefill scores recovers performance with the cached KV unchanged, localizing the failure to the attention rather than KV recomputation. Motivated by this, we propose \textsc{Attuner}, a query-side adaptation method that learns to read a frozen artifact cache. \textsc{Attuner} inserts low-rank adapters into the query projections and is trained by distilling full-prefill distribution into the student. It trains fewer than 0.05\% of the model parameters and, at inference, requires neither cache recomputation nor a full-context reference. On Qwen3-4B and Qwen3-8B across seven benchmarks covering skills, documents, memory, and code, \textsc{Attuner} substantially outperforms prior PIC baselines in both in-domain and out-of-domain settings, matches full-context prefill quality while providing up to $3.73\times$ speedup.

# ATTUNER：通过查询侧自适应实现无需重计算的 KV 缓存复用 —— 论文深度总结

## 1. 核心问题与研究动机

- **背景**：LLM 智能体（agent）在每次请求时会动态组装上下文，反复加载可复用内容——技能描述（skill）、文档（document）、记忆条目（memory）等。论文将这类可复用片段统一称为 **artifact（工件）**。
- **痛点**：对每个请求重新编码这些工件会浪费大量计算，并显著抬高首 token 延迟（TTFT）。传统前缀缓存（prefix caching）假设可复用内容处于固定前缀位置，但智能体负载中工件种类、顺序和位置都由检索、路由与规划在运行时动态决定，前缀缓存难以适用。
- **现有方案**：位置无关缓存（PIC, Position-Independent Caching）独立编码每个工件，在请求时把缓存块拼接到任意位置，从而复用 KV 状态。但它相比全上下文预填充（Full prefill）存在明显质量损失。
- **已有修复思路**：一类方法恢复全局位置 ID（如 PIC-Pos），另一类重计算选定 token（如 CacheBlend、EPIC、KVLink）。这些方法要么效果不稳定，要么需要额外重算开销。
- **本文核心问题**：PIC 的质量损失究竟来自哪里？是位置不匹配、KV 表示不忠实，还是注意力读取方式出错？只有定位根因，才能找到不重算缓存的有效恢复路径。

## 2. 方法论

### 2.1 核心诊断发现（问题定位）

- **位置不匹配影响小**：PIC-Pos 独立编码时按目标位置编码，在多工件任务上仅带来边际变化，无法稳定恢复性能。
- **缓存表示本身忠实**：在单工件设置下，证据利用（evidence utilization）几乎没有性能损失，说明独立缓存的工件 KV 仍能忠实保留自身内容。
- **失败出现在多工件选择**：性能下降主要集中在多工件设置，模型难以决定"读哪个工件"。
- **注意力路由是根因**：构造"注意力路由 oracle"，保留 PIC 缓存的 artifact values，仅用全预填充的注意力权重替换注意力分布，结果在 MuSiQue 上 EM 从 34.84 升至 47.91（Full 为 47.79），BigCodeBench pass@1 从 38.98 升至 44.53（Full 为 43.63）。**结论：故障在注意力分数计算，而非 KV 需要重算。**

### 2.2 ATTUNER 方法

- **核心思想**：不改缓存、不重算，而是**让在线查询（query）学会读取冻结的工件缓存**。查询是在线计算的，而缓存的 key/value 保持不变，因此查询侧适配天然与缓存复用兼容。
- **关键技术**：在每一层 Transformer 的 query 投影上插入低秩适配器（LoRA 风格）：

  ```
  ẽ_q(ℓ,t) = W_Q(ℓ) h(ℓ,t) + (α/r) B(ℓ) A(ℓ) h(ℓ,t)
  ```

  其中 A、B 为可训练低秩矩阵，r 为秩，α 控制更新幅度；适配后的 query 再经过原有的 query normalization 和 RoPE 进入注意力。
- **训练方式**：冻结全部基座模型参数，仅训练 query 适配器。用全上下文预填充的教师模型监督 PIC 学生模型，最小化响应位置上的输出分布 KL 散度：

  ```
  L(φ) = E[ (1/|Y|) Σ_t D_KL( sg[p_Full(·|X,Y<t)] || p_PIC(·|X,Y<t) ) ]
  ```

  教师梯度被 stop-gradient 截断；提示位置不直接监督，只监督响应分布。
- **推理流程**：工件 KV 离线预填充一次并复用；适配器仅对未缓存提示 token 和生成 token 启用；训练好的更新可合并回 query 投影权重，部署时**无需教师模型、无需缓存重建**。

## 6. 主要结论与发现

- **根因定位**：PIC 质量损失主要来自注意力路由（读法），而非缓存 KV 表示（存储内容）；位置对齐只能改善 key 相似度，无法恢复任务性能。
- **性能恢复**：ATTUNER 在域内三个基准上平均比 PIC 提升 **5.13 分（Qwen3-4B）与 7.77 分（Qwen3-8B）**，与 Full 的差距缩小到 1.61 与 0.51 分。
- **域外泛化**：在未参与训练的 TheoremQA 与 CHAMP 上平均提升 3.02 与 3.51 分（相对 PIC），说明学到的是通用"缓存读取"行为。
- **效率**：域内几何平均 TTFT 仅比 PIC 高 1.8% / 0.5%，保留 **1.79× / 2.45×** 相对 Full 的加速；整体最高可达 **3.73×**。
- **参数高效**：仅训练不到 0.05% 的模型参数。
- **注意力对齐**：训练后答案位置的平均输出余弦相似度从 0.903 提升至 0.927（MuSiQue）、0.932 提升至 0.949（BigCodeBench），但最后一层对齐反而变差，说明无需逐层复现 Full 计算。
- **适配增益特异性**：同一适配器在 PIC 下平均提升 5.13 分，在 Full 下仅 0.17 分，且每个任务上 PIC 的增益都更大，支持"适配独立缓存读取"是增益主因。

## 7. 优点

- **诊断驱动的方法设计**：先用路由 oracle 严格隔离变量（KV 不变、仅换注意力分数），把"缓存表示"与"缓存读取"解耦，问题定位清晰，方法动机自然。
- **缓存零改写**：只在 query 侧加低秩适配器，缓存 KV 完全冻结，天然兼容现有 PIC 服务栈，不引入缓存重建、token 选择或重计算开销。
- **参数与部署效率高**：<0.05% 可训练参数，推理时可合并权重，部署无需教师模型或全上下文参考。
- **评测覆盖较全**：技能、文档、记忆、代码四类工件，域内 + 域外，质量 + 效率双维度，并给出训练数据规模、层范围、组件干预等多角度消融。
- **实验协议严谨**：匹配提示与队列、明确 TTFT 计时边界、配对 bootstrap 区间、训练式基线共享数据与更新预算。
- **可迁移性**：单一共享适配器跨多任务泛化，并在未训练任务上有效，降低了"任务过拟合"的疑虑。

## 8. 不足与局限

- **工件类型组合未验证**：论文承认只分别评估技能、文档、记忆三类场景，未测试三类工件混合出现的请求。
- **架构限制**：仅在全注意力（full attention）模型上验证，对其他注意力架构（如线性注意力、稀疏注意力）的适用性未知。
- **仅关注"读缓存"**：不涉及缓存存储、放置、驱逐与通信优化；TTFT 虽包含 CPU→GPU 传输，但未做缓存调度层面的优化。
- **部分基准恢复不完整**：域外 CHAMP 等任务上仍与 Full 有差距，并非所有任务都能完全恢复。
- **算力信息缺失**：未报告 GPU 型号、数量与训练总时长，复现成本不透明。
- **基线实现偏差风险**：多个基线为作者自行适配 Qwen3 的版本（AgentKVShift 为纯论文复现），与原始系统性能不可直接等同。
- **训练数据含合成成分**：BigCodeBench 训练样本为合成任务，且不经验证单元测试，监督信号完全来自 Full 教师，可能引入教师偏差。
- **性能-效率权衡**：在域内平均质量上仍略逊于 KVLink，只是效率优势明显；适用场景偏向"延迟敏感、质量可接受小幅损失"的部署环境。
