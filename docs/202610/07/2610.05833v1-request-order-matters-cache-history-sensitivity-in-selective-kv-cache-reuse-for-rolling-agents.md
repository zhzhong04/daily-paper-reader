## 摘要
长期运行的智能体会反复调用 LLM，同时保留其大部分文档窗口、逐出旧文档并追加新文档。这些滚动更新破坏了精确前缀缓存，并促使采用带选择性重计算的非前缀 KV 缓存复用。我们表明，带选择性重计算的持久化 KV 缓存复用可能具有历史依赖性：在我们的滚动智能体工作负载中，同一个未改变的提示可能因在其之前处理过的请求不同而产生不同答案。在相同的 5% 重计算预算下，文档对齐的重计算将不同请求顺序间的答案变化率从 CacheBlend 的 token top-$k$ 策略的 69.0% 降至 26.1%。当每个提示都在不同的前置请求序列之后被评估时，与 token top-$k$ 相比，文档对齐的重计算将相对于完整预填充的保真度提高了 34.5-52.5 个百分点，而两种策略均实现了约 5.7 倍的中位 TTFT 加速。我们的消融研究表明，在我们的滚动智能体工作负载中，连续性是与稳健的选择性重计算相关的主要因素。

## Abstract
Long-running agents repeatedly call an LLM while retaining most of their document window, evicting old documents, and appending new ones. These rolling updates break exact prefix caching and motivate non-prefix KV-cache reuse with selective recomputation. We show that persistent KV-cache reuse with selective recomputation can be history-dependent: in our rolling-agent workload, an unchanged prompt can produce different answers depending on the requests processed before it. At a matched 5% recomputation budget, document-aligned recomputation reduces answer variation across request orders from 69.0% with CacheBlend's token top-$k$ policy to 26.1%. When each prompt is evaluated after a different sequence of preceding requests, document-aligned recomputation improves fidelity to full prefill by 34.5-52.5 percentage points over token top-$k$, while both policies achieve approximately 5.7$\times$ median TTFT speedup. Our ablation study shows that, in our rolling-agent workload, contiguity is the main factor associated with robust selective recomputation.

# 论文总结：Request Order Matters: Cache-History Sensitivity in Selective KV-Cache Reuse for Rolling Agents

## 1. 核心问题与整体含义

- **背景**：长期运行的智能体会反复调用 LLM，并在每轮中保留大部分文档窗口、逐出旧文档、追加新文档，形成“滚动更新”负载。
- **问题**：这种滚动更新会破坏精确前缀缓存：虽然大部分文档文本未变，但删除/插入内容后，保留文档的位置和前置上下文发生变化，其先前计算的 KV 状态不再等同于当前完整预填充下的 KV 状态。
- **核心动机**：非前缀 KV 缓存复用结合“选择性重计算”可降低预填充成本，但作者关注一个被忽视的问题：当 KV 缓存状态跨请求持续存在时，同一提示是否会因先前请求顺序不同而得到不同答案。
- **整体含义**：选择性 KV 缓存复用不仅是单请求近似问题，还受到“持久缓存历史”影响；评估缓存复用策略时，应考虑真实请求序列，而非仅从干净缓存评估孤立请求。

## 2. 方法论

- **核心思想**：在固定重计算预算下，比较两类选择性重计算策略：
  - CacheBlend / LMCache 的 **token top-k**：按单个 token 的 KV 偏差选最高者。
  - 作者提出的 **document-aligned recomputation**：按连续文档跨度分配重计算预算。
- **关键偏差度量**：
  - 对每个可复用 token，计算当前 key 与加载的缓存 key 之间的 L2 平方偏差：  
    \(d_i = \|K^{current}_i - K^{cached}_i\|_2^2\)。
  - 偏差越大，表示该 token 的缓存 KV 与当前提示下应计算的 KV 差异越大。
- **重计算预算**：
  - 给定可复用 token 数 \(N\) 和重计算比例 \(r\)，选择 \(k = \max(1, \lfloor rN \rfloor)\) 个 token 重算。
  - 实验固定 \(r=5\%\)。
- **token top-k 流程**：
  - 在选层比较每个可复用 token 的当前 key 与缓存 key。
  - 选择偏差最大的 \(k\) 个 token。
  - 这些位置在后续层中重算，未选位置保留缓存 KV。
  - 缺点：选择结果可能散布在大量不连续区域。
- **span-level 选择性重计算**：
  - 对候选连续跨度 \(S_j\)，定义平均 KV 偏差：  
    \(\rho_j = \frac{1}{|S_j|}\sum_{i \in S_j} d_i\)。
  - 用平均偏差避免长跨度仅因 token 多而占优。
- **五种等预算策略**：
  - **Token top-k**：选散落的最高偏差 token。
  - **Single-window**：选总偏差最大的单个连续 \(k\)-token 窗口。
  - **Fixed-chunk**：将可复用提示划分为等长固定块，块跨文档边界，按平均偏差选块。
  - **Random-document**：使用文档跨度，但随机排序，忽略偏差。
  - **Document-aligned**：将提示划分为指令、单个文档、最终查询等跨度，按平均 KV 偏差排序；优先选完整跨度，剩余预算从最高排名剩余跨度中选总偏差最大的连续窗口，最终恰好选 \(k\) 个 token。
- **核心对比**：所有策略在相同重计算 token 数下比较，因此差异来自“选在哪里”，而非“重算更多”。

## 3. 实验设计

- **模型与系统配置**：
  - 模型：Qwen3-8B。
  - 解码：greedy decoding，temperature=0，固定随机种子。
  - 服务栈：LMCache 0.5.1，vLLM 0.23.0。
  - vLLM 前缀缓存被禁用，以测量 LMCache 的非前缀复用路径。
- **数据集 / 场景**：
  - 事件数据集包含 8,995 条真实记录，覆盖 15 只美国股票：
    - 7,515 条 Yahoo Finance 日价格记录；
    - 792 条 FNSPID 新闻标题；
    - 688 条 SEC EDGAR 文件标题。
  - 新闻和文件日期映射到股票价格日历，按通道内顺序交错。
  - 模拟有界文档窗口的滚动智能体：每次调用前逐出 1 个旧文档，保留 83 个文档，追加 1 个新文档。
  - 事件流产生 7,735 次滚动更新，窗口固定 84 个文档，步长 1。
  - 最终查询要求模型从当前窗口某条观测中逐字复制指定字段，属于确定性抽取任务，便于精确比较答案。
  - 提示长度约 7.2K–7.7K tokens。
- **请求顺序协议**：
  - 同一批请求以五种顺序处理，提示本身不变，仅改变进入服务系统的顺序：
    - Chronological：源顺序。
    - Fixed-random：三个预定随机顺序。
    - Reversed：反向顺序作为压力测试。
  - 每个“策略 × 顺序”组合从空 LMCache 开始，跨请求保留缓存，与其他运行不共享状态。
- **评价指标**：
  - **Answer variation**：对每个请求，比较五种顺序两两之间的答案，统计答案不同比例。
  - **Fidelity**：与完整预填充答案的精确一致率。
  - **TTFT**：请求级首 token 时间，比较 full prefill、token top-k、document-aligned。
- **对比方法**：
  - 主实验：token top-k vs document-aligned，固定 5% 重计算。
  - 消融：token top-k、single-window、fixed-chunk、random-document、document-aligned 五种等预算策略。
  - 控制实验：500 请求，每次请求前重置缓存，比较 token top-k 与 document-aligned。

## 6. 主要结论与发现

- **请求顺序会影响答案**：
  - 在持久缓存历史下，同一未改变提示可能因先前请求不同而产生不同答案。
  - 答案变化率：token top-k 为 **69.0%**，document-aligned 为 **26.1%**。
- **保真度差异明显**：
  - Chronological 顺序下，两者无统计显著差异：token top-k 86.8%，document-aligned 85.4%，\(p=0.12\)。
  - 其他四种顺序下：
    - token top-k 保真度 19.8–41.5%；
    - document-aligned 保真度 54.3–91.7%；
    - 所有 \(p < 0.0001\)。
  - 相对 token top-k，document-aligned 对 full prefill 的保真度提升 **34.5–52.5 个百分点**。
  - document-aligned 并非免疫：reversed 顺序下保真度降至 54.3%。
- **TTFT 收益相近**：
  - Full prefill：median 2,408 ms，P95 2,524 ms。
  - Token top-k 5%：median 426 ms，P95 459 ms，中位加速 5.68×。
  - Document-aligned 5%：median 415 ms，P95 477 ms，中位加速 5.74×。
- **缓存重置控制**：
  - 每次请求重置缓存时，token top-k 与 document-aligned 无统计显著差异：94.0% vs 92.6%，\(p=0.23\)。
  - 说明优势依赖跨请求累积的缓存历史。
- **消融结论**：
  - Chronological 顺序下，五种策略保真度 86.2–89.2%，无清晰优势。
  - Fixed-random 顺序下：
    - token top-k 降至 38.6%；
    - 四种 span 策略为 89.4–92.8%；
    - span 策略比 token top-k 提升 50.8–54.2 个百分点，均 \(p<0.0001\)。
  - Single-window 在 fixed-random 下最高，92.8%；document-aligned 与 single-window、fixed-chunk、random-document 均无显著差异。
  - token top-k 虽捕获 99.7% 的选层 KV 偏差，但保真度仅 38.6%；random-document 仅捕获 4.8% 偏差，仍大幅优于 token top-k。
  - **连续性**是稳健选择性重算的主要相关因素；文档边界和偏差排序未显示统计显著额外优势。

## 7. 优点

- **问题视角新颖**：将 KV 缓存复用视为闭环服务问题，强调每次 LLM 调用既消费也更新缓存状态，后续请求受先前请求影响。
- **实验控制严格**：
  - 所有策略匹配 5% 重计算预算；
  - 消融中匹配实际重算 token 总数；
  - 禁用 vLLM 前缀缓存，隔离 LMCache 非前缀复用路径；
  - 使用 greedy 解码和固定种子，降低随机性。
