## 摘要
对于长时程智能体而言，上下文是瓶颈：历史会在每次请求时被重新发送，窗口限制了任务长度，且随着历史增长，推理能力会下降。用紧凑的检索卡片替换结构化对象可以缩短提示，并保持原始内容可精确检索，但编辑历史会破坏前缀缓存复用，而先前的可恢复方法根据对未来复用的预测或预设间隔来安排编辑时机。我们提出 CADOC（缓存感知动态对象上下文），一种在线算法，它将结构化对象替换为紧凑卡片，同时保留对其原始内容的精确、按需检索。CADOC 通过平衡累积等待成本与共享缓存重建成本，以批处理方式调度替换。其调度规则源自经济订货量权衡，在平稳假设下可得到最优整数批量。在评估中，CADOC 在比较配置中始终实现最低的总输入成本，平均将输入成本降低约 40%，同时保持任务性能接近完整上下文。因此，CADOC 为可压缩上下文管理提供了一种由成本推导的方法，表明高效压缩不仅取决于缩短提示，还取决于调度编辑以保持缓存复用。

## Abstract
For a long-horizon agent, context is the bottleneck: the history is resent with every request, the window caps task length, and reasoning degrades as the history grows. Replacing structured objects with compact retrieval Cards shortens the prompt and keeps the exact originals retrievable, but editing the history can break prefix-cache reuse, and prior recoverable methods time their edits by forecasts of future reuse or by preset intervals. We propose CADOC (Cache-Aware Dynamic Object Context), an online algorithm that replaces structured objects with compact Cards while preserving exact, on-demand retrieval of their original contents. CADOC schedules replacements in batches by balancing accumulated waiting cost against shared cache-reconstruction cost. Its scheduling rule follows from an economic order quantity trade-off, recovers the optimal integer batch under stationary assumptions. Across evaluation, CADOC consistently achieves the lowest aggregate input cost among the compared configurations, which reduces input cost by approximately 40\% on average while maintaining task performance close to full context. CADOC thus provides a cost-derived approach to compressible context management, demonstrating that efficient compression depends not only on shortening prompts but also on scheduling edits to preserve cache reuse.

# CADOC 论文总结

## 1. 核心问题与整体含义

- **背景**：长时程（long-horizon）智能体的核心瓶颈是上下文。历史在每次请求时被重发，因此保留的 token 会反复计费（即使命中缓存也需付费）；上下文窗口限制了任务长度，且历史越长模型对相关信息的利用越差。
- **压缩的两难**：
  - 有损方法（token 剪枝、学习式压缩、子轨迹折叠）会丢弃后续步骤可能需要的细节。
  - 可恢复方法（对象外置 + 紧凑检索 Card）能保留精确原文按需检索，但**编辑历史会破坏前缀缓存复用**。
- **关键观察**：编辑较早的对象会使其后整个缓存后缀（包括最近热尾的原始块）失效，导致重复重建成本。论文给出的 HCE 示例显示，**立即替换虽然减少了 55.93% 的累计输入 token，却使输入成本上升 3.67%**（图 1a）——"token 更少，成本更高"。
- **现有方法不足**：
  - Self-GC：依赖 planner LLM 预测未来复用收益，需估计未来信息。
  - TokenPilot：按经验设定的固定轮数间隔运行 LLM 估计器，需逐场景调参。
  - 二者均未从"当前可观测信息"推导编辑时机。
- **整体含义**：高效压缩不仅在于"替换什么"，还在于"何时提交替换"以保留缓存复用；CADOC 将提交时机与替换资格解耦，用成本推导的方式在线调度。

## 2. 方法论

### 核心思想
- **可逆对象外置**：Working Memory 保存原始字节与哈希，用确定性 Card（记录身份、版本、来源、结构元数据，**无 LLM 生成摘要**）在提示中占位；原文位置保持不变，检索时以新的 tool-result 出现返回不可变版本。
- **热尾保护**：保留最近一段原始后缀（受最大块数 `h` 和 token 预算 `T_hot` 限制），离开保护后缀的对象进入 pending 序列，等待批量提交。
- **批量提交的经济学权衡**：批量提交可让多个替换共享缓存重建成本，但等待会让可移除内容留在每一次中间请求中。

### 关键技术细节与公式

**成本模型**（式 1）：`C = Σ_t (N_t + w_r R_t)`，其中 `w_r` 为缓存读取权重（主实验取 0.1），`N_t`/`R_t` 为未缓存/缓存 token 数。

**单次替换的首次成本差**（式 2）：
```
ΔC_first = (1-w_r)(I-G) + F - w_r·G
```
即"重建溢价"减去"缩短收益"。

**平稳模型**：每个请求周期产生一个长度 `x`、含一个可缩短 `g` token 的块，热尾恰好 `h` 块，每次提交替换全部 `b` 个 pending 块。
- 缓存区间长度 `I_b = b·x + (h-1)·x`
- 等待损失 `W_b = r·b(b-1)/2`，其中 `r = w_r·g`
- 每对象平均超额成本：
```
ℓ_h(b) = K + Q_h/b + r(b-1)/2
Q_h = F_0 + (1-w_r)(h-1)x
```
这构成 **EOQ（经济订货量）式权衡**：`Q_h/b` 为摊销的共享成本，`r(b-1)/2` 为持有（等待）成本。

**命题 1（平稳最优批量）**：
- 连续最优 `b*_cont = max(1, √(2Q_h/r))`
- 整数最优充要条件：`r·b(b-1)/2 ≤ Q_h ≤ r·b(b+1)/2`
- 差分单调非减，最优即为首次跨越点。

**在线规则**（式 11–14）：用当前量替代平稳量
- `G_t`：所有 pending 内容的潜在缩短量（保留 vs. 替换后的下一提示长度差）
- `W_t`：自变为可提交以来累计的等待损失；每多带一次原始内容增加 `ΔW_t = w_r·G_t`
- `Q_t = F_0,t + (1-w_r)·H_shared_t`：共享重建成本（H_shared 为待重建的已缓存后缀）
- **提交条件**：`W_t + w_r·G_t ≥ Q_t`，即一次提交全部 pending 替换；未满足则等待并累积等待账本。
- 提交成功响应后清空账本；硬容量限制可强制提前提交。

**命题 2（竞争界）**：在等待–设置目标下，该在线规则满足 `J(ALG) ≤ 2(Q_max/Q_min)·J(OPT)`，常数 `Q_t` 时为 2-竞争。

## 6. 主要结论与发现

- **成本显著降低**：CADOC 在 HCE 所有 `h` 设置下取得最低总输入成本；相对 Full Context 在 `h=2,4,8,16` 分别节省 30.65%、20.61%、15.14%、11.56%。
- **基准链结果**（表 1）：
  - Terminal-Bench：输入 ↓49.40%，成本 ↓47.13%，解出 36/89（FULL 38/89）
  - LongMemEval-V2：输入 ↓80.60%，成本 ↓42.40%，解出 10/18（持平）
  - SWE-bench：输入 ↓44.72%，成本 ↓34.12%，解出 29/50（FULL 31/50）
  - 任务完成率最多下降 4 个百分点，整体成本降幅 34.12–47.13%。
- **自适应批量**：CADOC 平均批量随 `h` 增大从 1.50→3.25→4.75→5.00 块，提交次数从 20→3，符合式（7）预测（热尾越大越倾向大批量）。

- **检索开销不抵消收益**：LongMemEval-V2 中 146 次模型请求含 40 次检索事件，仍节省 42.40% 成本。
- **权重敏感性**：在全部 15 个基准–权重组合中 CADOC 均为最低成本；`w_r=1` 时退化为 Immediate（因 `Q_t=0` 导致立即提交），与 Immediate 持平。

## 7. 优点

- **理论驱动**：将提交时机建模为 EOQ 式的 setup–holding 权衡，平稳假设下精确恢复最优整数批量，并给出有限时域竞争界（2-竞争 / 2Q_max/Q_min）。
- **完全在线且无 LLM**：不依赖未来复用预测、不需要额外 LLM 调用、不需要逐场景批量调参，仅用当前可观测的缩短量与缓存估计。
- **可逆且精确**：Card 为确定性、无摘要，配合不可变版本实现字节级精确检索（SHA-256 验证），区别于有损压缩。
- **解耦设计**：将"替换资格"与"提交时机"分离，批处理共享缓存重建成本，是该方法的核心洞察。
- **实验公平性较好**：固定历史回放冻结模型输出与 Card，隔离了策略差异；同时对缓存读取权重做了全面敏感性扫描。
- **实现细节透明**：给出了决策账本、守卫阈值、生产配置等可复现细节，并有记录案例佐证。

## 8. 不足与局限

- **平稳假设的偏离**：核心最优性与竞争界建立在平稳流、等对象收益、稳定前缀缓存之上；真实历史中对象收益异构、块长度不一、存在内部间隙与非线性开销时，仅用"当前估计"近似，理论保证不直接适用。
- **估算粗糙**：运行时 `G_t`、`Q_t` 由粗略的提示/缓存长度估计，而非精确 per-object token 求和；`F_0,t = 0` 的假设在多数实验成立。
- **性能有损**：任务完成率最多下降 4 个百分点（Terminal-Bench 38→36，SWE-bench 31→29），在性能敏感场景可能不可接受。
- **对象识别依赖**：依赖运行时元数据与解析规则来识别"可替换对象"，对识别失败或非结构化内容（如普通对话）无收益。
- **对缓存机制的强依赖**：收益完全来自前缀缓存复用；若底层 API 不支持前缀缓存，或 `w_r` 接近 1，则优势消失（退化为 Immediate）。
- **实验覆盖有限**：仅 3 个基准、1 个模型（gpt-5.6-terra）、3 条 HCE 历史；任务性能样本（31 探针 × 3 种子）偏小；缺少组件消融与跨模型泛化验证。
- **未报告算力/延迟开销细节**：

- **未报告算力/延迟开销细节**：调度器本身的 CPU/内存开销、等待账本与提示/缓存长度估计的额外计算、以及提交触发瞬间因缓存后缀失效而造成的**延迟尖峰**均未量化；论文仅以"不引入额外 LLM 调用"作定性说明，缺少与 Immediate、TokenPilot 类方法在端到端 wall-clock、首 token 延迟（TTFT）与调度器自身开销上的对比。
- **基线对比不完整**：实验中的对照主要是 Full Context、Immediate、固定批量与固定 token 阈值这类"无状态启发式"，并未与论文在动机部分点名批评的 Self-GC、TokenPilot 等预测式压缩方法做直接实验对照。因此"优于现有方法"的论断主要建立在机制层面的论证（不依赖未来预测、无需调参）而非实测证据上。
- **评估协议的外部效度受限**：HCE 回放与基准历史回放均为离线冻结协议，虽然保证了公平，却无法反映在线部署中"压缩→模型行为改变→轨迹分叉→错误累积"的闭环效应；而唯一在线（基准链）的部分又恰好是非配对比较，两者各自的优势无法合并。
- **缓存模型过度理想化**：成本模型假设前缀缓存按 token 精确命中、读取成本线性且 `w_r` 为常数；真实服务商的分层缓存、缓存 TTL/逐出、最小可缓存前缀长度、并发请求对缓存的互相干扰、以及 cache write 溢价均未建模，这些都会改变 `Q_t` 的取值乃至提交阈值的符号。
- **超参依赖人工设定**：`h`、`T_hot`、守卫阈值、`F_0,t = 0` 等设定均由人工选择，论文未系统扫描这些超参对成本与性能的敏感性（只有 `w_r` 做了完整扫描），因此"无需逐场景调参"的说法在调度器超参层面只被部分支持。

## 9. 总体评价与启示

- **贡献定位**：CADOC 属于"调度层"工作——它并不发明新的压缩表示，而是把**"何时提交压缩"**从**"压缩什么"**中剥离出来，识别为一个独立、可解析、可优化的决策变量。这一视角转换是本论文最持久的贡献，其思想可迁移到任何依赖前缀缓存的上下文管理系统，而不限于其自身的对象外置机制。
- **方法论强度**：从成本函数出发推导首次替换的盈亏平衡（式 2），再在平稳假设下得到 EOQ 形式的 `ℓ_h(b)` 与闭式最优批量（命题 1），最后用"当前量替代平稳量"构造在线规则（式 11–14）并给出竞争界（命题 2）——这条"建模→最优解→在线化→性能保证"的链条完整且自洽，是同类系统论文中少见的严谨度。
- **工程可行性**：不训练、不额外调用 LLM、不需要未来信息、不依赖逐场景调参，使其相对学习式压缩方案具有更低的接入成本与更好的可解释性；决策账本与记录案例（SHA-256 精确恢复）也增强了可审计性。
- **核心权衡的普适性**：论文揭示的"token 更少 ≠ 成本更低"（图 1a 中 −55.93% token 对应 +3.67% 成本）是一个容易被忽略、但在缓存计费体系下普遍成立的反直觉现象，对实践者具有直接的警示价值。
- **适用边界**：方法收益严格依赖于（a）底层 API 提供前缀缓存且 `w_r` 显著小于 1；（b）历史中存在可被结构化解耦的"对象"（工具结果、文件、检索块等）。对于无缓存、纯对话或高度非结构化的历史，CADOC 收益趋零甚至退化为 Immediate。
- **后续研究方向**：
  1. **异构收益的在线估计**：放松"等对象收益、等块长"假设，用观测到的实际缩短量在线校正 `G_t`、`Q_t`，使理论保证在非平稳流下仍近似成立；
  2. **与学习式压缩的互补**：CADOC 只管提交时机，理论上可与 Self-GC/TokenPilot 的"替换什么"决策正交组合，值得验证叠加收益；
  3. **跨模型与跨服务商泛化**：在多个模型、多种缓存计费策略（含 TTL、分层缓存、cache write 溢价）下验证 `w_r` 敏感性结论；
  4. **严格的在线配对实验**：设计同轨迹分叉控制或多次重复的配对评估，以更小方差测量性能损失是否真的"最多 4 个百分点"；
  5. **端到端系统度量**：补齐调度器开销、TTFT、缓存重建延迟尖峰的量化，并给出组件消融（热尾保护、等待账本、批量共享成本各自的边际贡献）；
  6. **失效场景刻画**：明确给出"何时不该用 CADOC"的判据（如 `w_r` 阈值、对象可识别率下限），对实践部署同样重要。
