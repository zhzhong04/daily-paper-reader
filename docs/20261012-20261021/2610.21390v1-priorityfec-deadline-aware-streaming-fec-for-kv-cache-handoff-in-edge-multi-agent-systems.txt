# PriorityFEC: Deadline-Aware Streaming FEC for KV-Cache Handoff in Edge Multi-Agent Systems 

Han Shen, Qifu Tyler Sun, Member, IEEE, Fanyang Meng, Member, IEEE , Ye Wang and Yongsheng Liang 

Abstract —Multi-agent large language model (LLM) systems are increasingly deployed at the edge to support complex tasks that require collaboration and information exchange among multiple agents. However, when task contexts are passed across agents, shared context that has already been processed by upstream agents often needs to be prefilled again, resulting in substantial redundant computation. Reusing an already prefilled key–value (KV) cache can avoid this recomputation, but requires the reusable KV state to be transferred across the network before the receiving agent can begin generation. Under strict time-to-first-token (TTFT) deadlines and unreliable edge links, delivering the complete KV cache may be infeasible, making it necessary to prioritize and protect the most valuable KV information within a limited transmission budget. This paper proposes PriorityFEC, a utility-aware KV-cache handoff scheme that jointly exploits model-side KV importance and transport-side reliability. Prior-ityFEC first constructs a utility-aware source stream by placing high-utility KV blocks at earlier transmission positions. It then protects the ordered stream using a feedback-adaptive Streaming Forward Erasure Correction (FEC) mechanism, which schedules repair packets according to receiver feedback before the TTFT deadline. We implement PriorityFEC on a distributed edge LLM serving prototype and evaluate it with Qwen2.5-7B-Instruct and Llama-3.1-8B-Instruct across multiple datasets. Results show that PriorityFEC achieves superior task quality over the compared transport schemes, with its advantages becoming particularly pronounced under stringent deadline constraints. These results demonstrate the importance of jointly optimizing KV-cache utility and deadline-aware transport reliability when reusable LLM state must be handed off across unreliable edge networks. 

Index Terms —Large language model serving, KV cache, collab-orative inference, KV-cache handoff, Streaming FEC, deadline-aware transport. 

I. Introduction The growing complexity of LLM-based applications is increasingly driving inference toward distributed and collab-orative architectures, where multiple LLM workers or agents jointly execute tasks while maintaining a shared and contin-uously evolving context [1], [2]. In such systems, different agents may be dynamically activated or assigned to distinct stages of a long-running task, resulting in computation and model states being distributed across multiple edge nodes. To ensure seamless task continuation, the accumulated inference context must therefore be efficiently transferred between agents as execution proceeds, allowing newly activated agents to resume inference without reconstructing the task state from scratch. During agent handoff, a newly activated agent would conventionally need to prefill the entire accumulated context before decoding can proceed. Yet, most of this context has already been processed by the upstream agent, making the repeated prefill computation largely redundant. Instead of reconstructing the same inference state from the original to-kens, the upstream agent can directly transfer the materialized KV cache to the receiving agent for reuse. Such KV cache handoff eliminates redundant prefill computation and enables the receiving agent to resume inference from the existing context with substantially lower handoff latency. KV cache reuse can eliminate redundant context recompu-tation only when the cached state is delivered to the receiving agent within the required time budget [3]. This condition is particularly difficult to satisfy in collaborative edge multi-agent systems, where KV states produced by an upstream agent may reside on a different edge node and must traverse bandwidth-constrained and potentially unreliable links before they can arXiv:2610.21390v1 [cs.NI] 15 Oct 2026 2

be exploited by downstream agents. The challenge is further amplified for long-context inference, which can generate large KV states whose communication delay may dominate the over-all handoff latency under limited network capacity. Moreover, congestion, user mobility, wireless interference, and handovers can induce bursty and temporally correlated packet losses, making timely and reliable KV delivery increasingly difficult to guarantee. Existing KV-cache systems have largely focused on cache storage, reuse, compression, placement, and high-throughput data movement within centralized computing environments, such as data centers and GPU clusters [4], [5]. These tech-niques improve how reusable KV states are represented, man-aged, and accessed, but typically assume that the underlying interconnect can deliver the required state with sufficiently high and stable throughput. Such an assumption becomes frag-ile in collaborative edge inference, where reusable KV states may reside on remote agents connected through bandwidth-constrained and lossy links. In collaborative multi-agent applications, agents are often required to make decisions and respond within stringent la-tency constraints. When a task is handed off to a newly activated agent, the reusable KV cache must be made available in time to support subsequent inference; otherwise, delayed state transfer can directly slow down agent activation and disrupt task coordination. Under a tight TTFT budget, waiting for the complete KV cache to be reliably delivered can be overly restrictive, especially when the cache is large, and the underlying network is lossy or bandwidth-constrained. This motivates a different transport objective: rather than insisting on eventual delivery of the entire KV cache, the transport layer should make the most useful KV state available within the limited TTFT budget. A deadline-aware and loss-tolerant KV-cache transport mechanism can therefore provide a more flexible solution by trading completeness for timely availability of task-relevant model state. Conventional transport mechanisms are poorly matched to this deadline-aware objective. As illustrated in Fig. 1, reliable protocols such as TCP [6] and QUIC [7] ensure eventual deliv-ery through retransmissions, but loss recovery may consume a substantial fraction of the handoff budget. Unreliable transport such as UDP avoids retransmission-induced delay, yet directly exposes the receiving agent to missing KV state. Packet-level forward erasure correction (FEC) offers an attractive alternative by recovering losses without waiting for retransmis-sions [8]. However, under a strict deadline, redundancy itself competes with source transmission for scarce transmission opportunities: sending more repair packets improves robust-ness but leaves fewer opportunities to deliver additional KV state. Moreover, conventional fixed-rate or fixed-schedule FEC treats packets largely uniformly and does not adapt redundancy to either time-varying network conditions or the receiver’s decoding progress. As a result, redundancy may be wasted when delivery proceeds smoothly, while becoming insufficient during burst losses precisely when timely recovery is most critical. The above observations expose two coupled challenges for deadline-constrained KV-cache handoff.  

> •

First, which KV blocks should receive the earliest trans-mission opportunities? When the complete KV cache cannot be delivered before decode startup, different source positions have different opportunities to become available by the deadline. Treating all KV blocks uni-formly can therefore waste favorable source positions on model state with limited downstream utility.  

> •

Second, when should the limited repair budget be con-sumed? A fixed FEC schedule injects redundancy inde-pendently of decoding progress. Such a schedule may waste repair opportunities when transmission proceeds normally, while reacting too slowly when correlated losses cause the unresolved coding window to grow. Motivated by these challenges, we develop PriorityFEC 

around two complementary mechanisms. First, a utility-aware source ordering maps model-derived KV utility to equal-size transport blocks and places high-utility blocks earlier in the transmission stream, while preserving all KV blocks for pos-sible reconstruction. Second, a feedback-adaptive Streaming FEC mechanism protects the resulting stream by adjusting repair transmissions according to decoding progress under a predefined repair budget. These two mechanisms address different aspects of deadline-constrained KV handoff: utility-aware ordering deter-mines which KV states receive earlier delivery opportunities, whereas adaptive Streaming FEC determines when recovery opportunities should be introduced. Together, they improve the utility of the reconstructed KV state before the TTFT deadline without requiring packet-level retransmissions. The main contributions of this work are summarized as follows.  

> •

Deadline-aware KV-cache handoff. We formulate KV-cache handoff over bandwidth-constrained and unreliable edge links as a deadline-constrained transport problem, with the objective of maximizing the utility of the KV state available at decode startup rather than eventual byte completeness. Controlled KV-perturbation experiments show that equal amounts of recovered KV data can preserve substantially different levels of model-relevant information, establishing the need for utility-aware state delivery under tight latency budgets.  

> •

Utility-Aware Source Ordering and Queue Design. We propose PriorityFEC, which maps offline model-derived KV importance scores to equal-sized transport blocks and organizes them into a utility-aware transmission queue, placing higher-utility blocks at earlier and more favorable source positions for stronger pre-deadline protection.  

> •

Deadline-aware source–repair optimization. We for-mulate adaptive KV-cache protection as a finite-horizon source–repair scheduling problem under hard deadline and repair-budget constraints. Unlike fixed FEC sched-ules, the proposed formulation explicitly captures the op-portunity cost between transmitting additional high-utility source packets and consuming transmission opportunities for loss recovery. We formulate the sequential decision process as an MDP and instantiate the scheduler using a lightweight Double DQN that adapts repair decisions to 3

causal transport feedback and KV utility. Experimental results demonstrate that adaptive source–repair alloca-tion is particularly beneficial in the target regime where complete KV-cache delivery is infeasible before decode startup. II. Related Work 

A. KV-Cache Reuse and Movement in Distributed LLM Serv-ing 

Modern LLM serving systems increasingly treat KV-cache management and movement as first-class system operations. Disaggregated serving systems such as DistServe [9] and Split-wise [10] separate prompt prefill from autoregressive decoding and transfer the resulting state between GPU workers. Moon-cake [11] adopts a KV-cache-centric architecture in which serving workers access a shared KV-cache substrate. These systems demonstrate that moving previously materialized KV state across workers can be preferable to recomputing it when computation and serving roles are distributed. A complementary line of work enables KV states to persist beyond a single inference invocation. PagedAttention [12] im-proves GPU memory utilization through efficient KV paging, while LMCache [4] externalizes KV states from the inference engine and supports cache reuse, offloading, and transfer across devices and serving instances. Such mechanisms make it possible for a worker to reuse an already processed context instead of repeatedly executing the same prefill computation. Recent approaches further optimize the cost of moving KV state. KVDirect [3] provides tensor-aware communication for distributed KV transfer. CacheGen [5] encodes KV tensors into compact bitstreams and adapts compression according to avail-able bandwidth, while KVServe [13] introduces service-aware compression profiles under workload and resource constraints. These studies primarily optimize whether , where , or how compactly reusable KV state is stored and transferred. Our work addresses a complementary transport problem. Once a compatible reusable KV state has been identified on another node, we consider how to deliver its most valuable regions over a bandwidth-constrained and lossy edge path when the receiving worker must begin generation before a prescribed deadline. 

B. FEC for Deadline-Constrained and Lossy Transport 

Under strict latency deadlines, distributed inference over unreliable wireless and IoT links has shown that timely partial state delivery can be preferable to delayed complete state recovery [14]–[16]. This observation motivates the use of loss-tolerant transport mechanisms that prioritize deadline completion rather than eventual full recovery. Packet-level FEC provides loss recovery without waiting for per-packet retransmissions and is therefore attractive for delay-sensitive communication. Classical block FEC partitions source packets into disjoint coding blocks and generates a prescribed number of repair packets for each block using fixed-rate or rateless codes [17], [18]. Although effective for bounded data ob-jects, block coding introduces explicit coding boundaries, and losses exceeding the redundancy allocated to one block cannot be compensated by repair packets generated for subsequent blocks. Streaming FEC instead protects a continuously evolv-ing source stream using overlapping sliding or elastic coding windows [19]–[21]. In such schemes, an unresolved source packet can remain in the coding window and benefit from subsequent repair packets, making Streaming FEC particularly suitable for bursty-loss and deadline-constrained transport. In addition to the coding-window design, adaptive FEC schemes dynamically adjust redundancy or repair scheduling according to network feedback. DeepRS [22] predicts near-future packet losses using an LSTM and accordingly selects the FEC redundancy ratio, while RL-AFEC [23] employs reinforcement learning to choose frame-level Reed–Solomon redundancy for real-time video under varying network condi-tions. At the transport layer, QUIC-FEC [8] integrates several erasure codes into QUIC for proactive loss recovery, and AC-RLNC [24] uses delayed acknowledgments to causally adapt coding decisions to the observed erasure process. FlEC [25] further exposes application-aware reliability and repair-scheduling mechanisms within QUIC. These studies demon-strate that both the amount and timing of redundancy can be adapted to network conditions. Our design instead considers a fixed maximum repair budget under a TTFT deadline and uses cumulative decoding stalls and coding-window growth to concentrate catch-up repairs when unresolved source DoFs are likely to accumulate. A related line of work provides unequal error protection (UEP) by embedding source importance into the coding pro-cess. Priority Encoding Transmission assigns different recov-ery guarantees to source components [26], while expanding-window fountain codes [27] protect more important classes through nested coding windows. UEP random linear coding similarly forms non-overlapping or expanding coding windows for packets with different importance levels [28], while prior-itized RLNC jointly adapts coding and scheduling for layered data delivery [29]. In these schemes, importance generally changes the coding window, protection level, or scheduling policy itself. In PriorityFEC , by contrast, model-derived KV utility affects the source ordering, while the repair scheduler operates on transport state augmented with compact utility-aware features.

A. Transport-Oriented KV-Utility Validation 

Prior studies on KV-cache compression and eviction have shown that different KV regions contribute unequally to model inference [30]–[32]. Our objective is therefore not to introduce a new universal KV-importance estimator. Instead, we ask a transport-oriented question: When only part of the KV cache can be made available before decode startup, does the identity of the recovered state materially affect model fidelity? We evaluate Qwen2.5-7B-Instruct [33] and Llama-3.1-8B-Instruct [34] through controlled KV-zeroing experiments. For each profiling prompt, we first record the next-token dis-tribution obtained using the full KV cache. We then zero both key and value tensors associated with one layer group or one relative-position region and measure the resulting distributional change. The perturbation scores are averaged over the profiling set and normalized within each model. They are used only as relative transport utilities. Fig. 2(a) shows substantial layer-wise heterogeneity. Both models contain a sensitive early-layer region, while their remaining profiles differ noticeably. Hence, a fixed shallow-to-deep transmission order is not sufficient across models. Fig. 2(b) shows a similarly non-uniform position profile: the prompt prefix and recent context are more sensitive than most intermediate positions. We further examine whether the resulting profile remains informative on prompts disjoint from the profiling set. For each retention ratio, we retain the highest-ranked layer–position cells and compare them with random retention. As shown in Fig. 2(c), profile-ranked retention consistently preserves higher teacher-forced top-1 agreement with intact-KV execution. At 40% retention, the agreement improves from 44.0% under random retention to 55.2% under profile-ranked retention. These experiments establish the transport-side property re-quired by our design: equal amounts of recovered KV state can preserve substantially different amounts of model-relevant information. Consequently, a deadline-constrained transport mechanism should account for which KV regions become available, rather than only the number of bytes delivered.

Adaptive Streaming FEC The utility-aware source queue determines which KV blocks should be transmitted first, but cannot by itself recover packet losses over unreliable edge links. Under a strict decode-start deadline, source and repair packets share a limited transmis-sion budget, creating a tradeoff between delivering new KV state and recovering lost packets. To address this, we combine the utility-ordered source queue with ACK-sliding Streaming FEC and an adaptive repair scheduler. The queue determines what to transmit first, Stream-ing FEC provides loss recovery, and the scheduler determines 

when repair packets should be transmitted.

Evaluation We evaluate PriorityFEC to answer two questions: (i) whether utility-aware ordering enables more model-relevant KV state to become available before decode startup; (ii) whether this transport-level utility gain translates into higher downstream LLM task quality; We first describe the prototype, workloads, network config-urations, and compared transport schemes. A. Experimental Setup 

Models and workloads. We evaluate two representative open-source LLMs, Qwen2.5-7B-Instruct and Llama-3.1-8B-Instruct. The evaluation uses three question-answering work-loads from LongBench-E: 2WikiMultiHopQA, HotpotQA, and TriviaQA. These workloads require retrieving and inte-grating information from a long input context, making their outputs sensitive to the KV state available when decoding begins. The input context is truncated to 1,536 tokens using the same preprocessing configuration across all compared transport schemes. Task quality is measured using token-level F1. For every model–dataset pair, we evaluate 48 examples under five paired network realizations. Hence, each operating point contains 240 example–network realizations. All transport schemes are evaluated using the same workload inputs and paired loss realizations.

B. Implementation and Training Details 

Prototype. We implement the LLM execution path using PyTorch and Hugging Face Transformers, and the Streaming FEC codec in native C over GF (2 8). The prototype runs on two servers with NVIDIA RTX 4090 GPUs. For batch size one, each layer’s key and value tensors have shape [1 , H KV , T, d h]

and use BF16. The current transport unit groups one layer and 9

16 consecutive tokens. Each 1,400-B application frame carries at most 1,368 B of KV payload, with the remaining bytes used for codec metadata, causal watermarks, and the protected frag-ment identifier. The repeatable evaluation executes the native codec and downstream LLM decoding under paired channel realizations. Controller and codec wall-clock overhead are measured separately from the simulated transmission deadline. A complementary socket prototype transfers real KV bytes over TCP or UDP and performs receiver-side decode-only inference. Its existing validation uses a single-host loopback path. 

Partial-KV reconstruction. The receiver maps recovered fragments to their original layer, token interval, and byte offsets. In the main evaluation, a BF16 element is retained only when both of its serialized bytes are available; otherwise, the complete element is set to zero. The reconstructed cache preserves its original shape and token positions, and the receiving model does not repeat full-prompt prefill. We additionally implement an explicit partial-KV attention mask. A KV head–token row is usable only when all bytes of both its key and value vectors have been recovered. Unavail-able rows are excluded through a per-layer attention mask, repeated over the corresponding query heads for grouped-query attention. Original RoPE positions are retained, and newly generated KV rows remain valid. This receiver can use intact head–token rows within an otherwise incomplete block. The existing main results use zero-fill; mask-based decoding is a separate receiver condition and must be held constant when comparing repair schedulers. 

Offline scheduler training. The scheduler uses a 15 –64 –

64 –4 Double-DQN network with ReLU activations and 5,444 parameters. Its normalized observations summarize remaining budget and time, source pressure, channel estimates, decoder deficit, coding-window size, ACK staleness, block progress and utility, and sparse-repair coverage. Actions select a source burst of at most eight packets or a repair burst of 1, 4, or 16 packets. Hard masks enforce source availability, repair feasibility, remaining budget, and the deadline. Training uses synthetic utility-ranked blocks and random-ized GE channels, without QA examples, reference answers, or task-F1 rewards. The reward is the change in a transport po-tential that rewards completed-block utility and prefix progress while penalizing decoder deficit and coding-window backlog. The training decoder uses a sparse-coverage surrogate; evalu-ation uses the actual GF (2 8) codec. The final scheduler is initialized from a pretraining stage us-ing randomized transport trajectories, after which it is trained for 120 additional episodes. Adam uses a learning rate of 10 −4,discount factor γ = 1 , and gradient-norm clipping at five. Exploration decreases from 0.25 to 0.05 over the first 80% of this phase. Learning occurs every 16 decision transitions, and the target network is synchronized every 500 updates. The retained log records 321,032 decision transitions and 16,550 gradient updates. The final checkpoint is frozen during task evaluation, without QA-based checkpoint selection. 

Scaling and transfer scope. Training covers link rates of 50, 100, and 200 Mbps and nominal RTTs of 14–26 ms; these rates therefore constitute trained conditions. The synthetic training blocks contain more fragments than the current one-layer-by-16-token blocks, so deployment also in-volves a packetization-scale transfer. Although each Q-network inference has fixed dimensionality, total scheduling and coding work grows with the transmitted cache. Furthermore, the current eager profiler constructs full attention tensors before selecting the last 64 query positions. The present task-quality results therefore do not establish 4K/8K-context scalability. The existing 5G trace replay evaluates the frozen policy under a recorded loss process and a 20.48-Mbps offered-rate service assumption. It provides conditional transfer evidence on the selected trace. Dedicated context-length sweeps and held-out tests of burst persistence, RTT, bandwidth, and non-stationary conditions remain necessary to establish broader generalization.

Therefore, Full-KV is used as a reference rather than as a strict mathematical upper bound. We report two complementary metrics. F. Runtime Overhead and Computational Feasibility 

PriorityFEC operates under a prescribed decode-start dead-line and therefore requires its online control and coding operations to keep pace with packet transmission. Unlike reliable transport, the proposed scheme does not wait for complete KV-cache delivery before activating the decoder. Hence, the relevant implementation question is not whether PriorityFEC reduces the prescribed TTFT, but whether its additional computation introduces sufficient processing delay to interfere with the pre-deadline packet stream. We instrument the implementation and separately measure four sources of online computation: state construction and feedback processing, Double-DQN inference, GF (2 8) encod-ing, and GF (2 8) decoding. The measurements are aggregated over the three evaluation workloads, 48 examples per work-load, and five paired network realizations. Table II reports the computation normalized by the number of transmitted packets together with the latency of the online controller critical path. The measured computation remains stable across the two LLMs and deadline settings. The total online processing de-mand ranges from only 30 .34 to 33 .41 ms per 10 3 transmitted packets. 112 ms per 10 3 packets. Its mean latency is approximately 76 –78 μs, while the P99 latency ranges from 94 .35 to 97 .58 μs, remaining below the 112 μs packet slot in all four settings. The measured rate of controller decisions exceeding one packet slot is only 

0.009 –0.019% . Hence, the Double-DQN scheduler can make source–repair decisions at the granularity required by the packet transmission process without introducing systematic transmission stalls. The component breakdown further shows that RL infer-ence itself constitutes only a small fraction of the runtime cost, requiring approximately 3.3–3.4 ms per 10 3 packets. The dominant costs arise from GF (2 8) packet construction and decoding, while state and feedback processing remain comparable across all operating points. This confirms that the lightweight 15 -64 -64 -4 Q-network is not a computational bottleneck and that introducing learned repair scheduling adds only limited overhead beyond the underlying Streaming FEC operations. Finally, the similar runtime observed for Qwen2.5-7B and Llama-3.1-8B indicates that the transport-side computation is largely independent of the LLM architecture. PriorityFEC operates on packetized KV blocks and transport feedback rather than executing additional model inference on the critical transmission path. Therefore, its online computational cost scales primarily with packet processing and coding operations rather than with the parameter count of the underlying LLM.

Conclusion This paper studied deadline-constrained KV-cache handoff for collaborative edge LLM serving over bandwidth-limited and unreliable networks. When reusable KV state resides on another node, transferring the state can avoid redundant prefill computation, but strict decode-start deadlines may prevent the complete cache from arriving in time. Our profiling exper-iments show that the consequence of such partial delivery depends strongly on which KV regions become available: different layer–position regions contribute unequally to down-stream model execution. Motivated by this observation, we proposed PriorityFEC, which changes the transport objective from eventual byte completeness to deadline-available KV utility. PriorityFEC first maps model-derived KV importance to equal-size transport blocks and places high-utility blocks at earlier source positions. The resulting stream is then protected by ACK-sliding Streaming FEC, while a lightweight DDQN controller adaptively decides when the limited repair budget should be consumed. The coding rule remains independent of KV importance, whereas the scheduler combines transport state with compact utility information to evaluate the oppor-tunity cost of repair relative to continued source delivery. 15 

Experiments with Qwen2.5-7B-Instruct and Llama-3.1-8B-Instruct show that the proposed design provides its largest gains when the decode-start deadline is too tight to permit complete KV transfer. In this regime, utility-aware order-ing determines which model state can realistically become available, while adaptive repair scheduling protects that state against burst losses. As the deadline is relaxed and most KV blocks become recoverable regardless of their source positions, the advantage of prioritization naturally decreases. The runtime measurements further show that the lightweight repair controller and sparse finite-field coding can operate within the packet-transmission timescale of the evaluated link. These results suggest a broader design principle for dis-tributed LLM systems: when reusable model state must cross a constrained network before a downstream computation dead-line, the transport layer should optimize the utility of the state available at that deadline , rather than treating every transmitted byte as equally valuable.
