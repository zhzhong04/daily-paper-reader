# Abstract 

LLM-agent memory selection often uses retrieval rankings based on record rel-evance or individual influence. Such rankings cannot identify sufficient subsets under redundant or jointly necessary evidence. We study per-decision memory sufficiency: selecting a small subset that preserves full-memory behavior. To separate search error from model error, we introduce JointCoreBench, a bench-mark with nine interaction families, six workflow domains, natural-language de-cisions, and exact sufficient-set oracles, and JointCore, a relevance/cost-ordered group-deletion baseline that tests blocks before individual records. On 6,912 exact conditions, cost-ordered JointCore recovers a minimum-cost sufficient set in 100.0% of cases, reduces subset evaluations from 30.00 to 11.13 (62.9%), and achieves 87.8% active-memory savings. Across four 12B–70B model fami-lies and 432 tasks per model, its unweighted mean is 10.28 versus 16.00 model queries and 50.6% versus 43.1% minimum-cost recovery relative to cost-aware singleton deletion. Both methods preserve full-memory behavior under the de-terministic primary interface. Tests with physical deletion, UNKNOWN masks, PENDING sentinels, counterfactual values, and alternative labels identify interface-dependent behavior. JointCore is an efficient benchmark baseline; the study does not establish deployment-ready memory compression. Code is available at https://github.com/dr-pandit-69/jointcore-neurips .

# 1 Introduction 

Long-running LLM agents collect observations, tool outputs, constraints, and decisions. Their memory cannot grow without limit. LongMemEval and MemoryAgentBench test retrieval, cross-session updates, and selective forgetting [Wu et al., 2025, Hu et al., 2026]. The benchmarks show agents remain unreliable on these tasks. Existing methods often retrieve, rank, or evaluate records one at a time. Decisions can depend on several records. Suppose two independent authorization channels can each permit an action. Removing one leaves the decision unchanged because the other remains. Other rules may require two approvals, so neither record is useful alone. Single-record checks can miss the first pattern because neither channel appears necessary when removed alone, and they can miss the second when records are scored without their partners. We instead seek a subset that preserves the full-memory decision. We call this behavioral sufficiency . When the task rule is known, logical

sufficiency asks whether the subset contains required evidence. The minimum-cost sufficient set has the lowest registered cost. Sufficient input subsets and removal-based explanations ask whether an output survives input removal [Covert et al., 2021, Carter et al., 2019]. In agent memory, Causal Memory Intervention measures individual-record effects, DeMem compresses memory around a decision, and MemAudit combines counterfactual influence with structural signals [Srivastava, 2026, Zou et al., 2026, Tan et al., 2026]. These studies address related questions, but existing evaluations do not supply controlled interactions with exact sufficient and minimum-cost sets. Without that ground truth, we cannot separate search errors from errors made by the model judging a subset. Exhaustive search can give an exact answer, but the number of subsets grows exponentially. Each model-mediated check also requires a model query. We introduce JointCore to reduce this cost. It tests a block of records at once. If the block can be removed without changing the decision, JointCore deletes it and skips its smaller groups. If the decision changes, JointCore splits the block and continues. It orders records by relevance and registered cost. The search adapts delta debugging and its use in LLM-integrated systems [Zeller and Hildebrandt, 2002, Zhu et al., 2026] to typed memory and decision preservation. Real agent histories do not reveal which subset is sufficient. Two different subsets can produce the same observed decision, so the decision alone is not enough to evaluate a search method. JointCoreBench provides a reference answer for each controlled case. It combines natural-language workflows with redundancy, conjunction, and other interactions. Its evaluator enumerates every sufficient subset and identifies the minimum-cost solutions. These answers come from task logic, not model behavior. Each selection method is compared with this common target. We then measure behavioral and logical sufficiency, active-memory cost, and selection cost, and separate search errors from incorrect model judgments. We first use the exact evaluator, then repeat the selection process with Qwen, Gemma, Mistral and Llama as the decision models. Llama is the largest-capacity stress test in this cohort. The task format and search procedure remain fixed. We also vary the representation of omitted records and decision labels. These tests examine whether the conclusions depend on the memory or label interface. The paper makes three contributions: 1. JointCoreBench, an exact benchmark for behavioral and logical memory sufficiency, controlled interactions, minimum cost, active-memory cost, and selection cost; 2. JointCore, a relevance and cost-ordered group-deletion baseline for finding jointly sufficient memory with fewer selection queries; and 3. a two-stage evaluation with exact oracles and several model families, together with tests of memory representations and decision labels.

# 3 Interaction-aware memory selection 

JointCore search. JointCore initializes S = V and enqueues the full ordered record sequence as the root group of a FIFO queue. At each step, it dequeues a group G and compares F (S \ G) with the full-memory reference F (V ). A match removes G from S; a mismatch bisects and enqueues G

when |G| > 1, or retains G when it is a singleton. The procedure stops when the queue is empty or the selection budget is exhausted. Every evaluation uses the same environment snapshot, and an invalid model response counts as a mismatch. For a deterministic evaluator, F (S) = F (V ) is an invariant: it holds at initialization, and S changes only after a matching evaluation. Thus, the returned set is behaviorally sufficient under the primary memory representation, including when the budget is exhausted. This guarantee does not imply logical sufficiency, minimum cost, or robustness to another memory representation. 

Selection-evaluation complexity. One selection evaluation computes F (S \ G): it is a subset evaluation in the exact stage and one model query in the model stage. Excluding the shared full-memory reference evaluation, bisection defines a binary partition tree with n leaves and at most 

2n − 1 nodes. Since each node is evaluated at most once, the registered budget Q gives 

NJC (n, Q ) ≤ min {Q, 2n − 1}. (2) An accepted group deletion prunes its descendants. The worst case visits all 2n − 1 nodes because every non-singleton deletion changes the decision, nearly doubling the n evaluations used by condi-tional singleton deletion. The registered caps, Q = 256 for exact evaluation and Q = 64 for model evaluation, exceed the corresponding tree bounds of 127 at n = 64 and 31 at n = 16 .

Search order. The fixed development rule sets B = 4 . It places records outside the semantic top-B in a contiguous low-relevance prefix, followed by the top-B records in decreasing payload cost. The prefix exposes low-relevance records to block deletion, while decreasing payload cost fixes the refinement order within the suffix. The ordering is deterministic and has no learned component. Comparators. We compare full memory; random-B and semantic top-B; independent full-set leave-one-out; cost-aware conditional singleton backward selection; legacy and cost-ordered Joint-Core; and an exact minimum-cost oracle. Static methods use no selection evaluations; the oracle 3is an upper bound, not an implementable model selector. Independent leave-one-out tests every deletion against V , whereas conditional singleton updates the retained set after each accepted deletion. Cost-aware singleton is the primary efficiency comparator: each query tests one record, whereas JointCore can test an entire block. Both conditional methods use the same full-memory decision as their reference. 

# 4 Benchmark and evaluation protocol 

4.1 Benchmark construction 

JointCoreBench instantiates nine logical families across six workflow domains: orders, access control, deployment, calendar, database, and file debugging. The families are singleton, redundant OR, synergistic AND, XOR, threshold, multiple minimum sets, proxy-confounded, delayed-state, and stale-policy conjunction. Stale-policy is a controlled conflict pattern, not a safety evaluation. Support sizes are 2 and 4; record values, order, costs, semantic scores, target-action orientation, and seed blocks are deterministic. Appendix A states each logical rule and follows one task from its full memory to the selected core. We evaluate the same task grammar in two stages. The exact stage crosses the nine families and six domains with candidate counts n ∈ { 8, 16 , 32 , 64 }, two support sizes, four horizon labels, and four seed blocks, for 6,912 conditions. Here, the logical oracle evaluates each candidate subset without a model judgment. The model stage fixes n = 16 and uses all nine families, six domains, two support sizes, and four seed/horizon blocks, for 432 tasks per checkpoint. “Horizon” is a workflow-condition label; each trace contains one condition decision and one terminal action. 

4.2 Primary evaluation 

The primary model interface replaces each omitted record value with a typed UNKNOWN token, so every query preserves the original schema. Each selected subset is compared with the same model’s full-memory decision. We report the outcomes defined in Section 2, together with full-memory control accuracy. In the exact stage, selection cost is measured in subset evaluations; in the model stage, each such check is one model query. Active-memory cost sums the registered synthetic payload weights. It excludes the fixed prompt scaffold and is not a token-count or latency measurement. 

4.3 Model cohort and inference 

The displayed cohort comprises Qwen2.5-14B [Yang et al., 2025], Gemma-4-12B-it [Google Deep-Mind, 2026], Mistral-Small-3.1-24B-Instruct [Mistral AI, 2025], and Llama-3.3-70B-Instruct [Meta, 2024]. Llama is an exploratory largest-capacity stress test in this cohort. Because the 12B display cutoff was not preregistered, the cohort is descriptive and supports no scale claim. Qwen and Gemma use BF16 weights. Mistral uses a registered NF4 derivative; Llama uses the official pinned snapshot with runtime NF4. Both NF4 paths use double quantization and BF16 compute [Dettmers et al., 2023], but are not treated as BF16-weight evidence. All models run locally on 40GB A100 GPUs with Transformers 5.15, PyTorch 2.6/CUDA 12.4, a 768-token input cap, greedy mean conditional log-probability scoring, and no sampling. 

4.4 Robustness protocol 

On a fixed 108-task subset, we reevaluate selected memories using physical deletion, UNKNOWN masks, a schema-compatible PENDING value, and counterfactual values. We compare semantic YES/NO decisions with direct-action and counterbalanced A/B interfaces; the primary condition uses UNKNOWN masks and semantic YES/NO. The subset contains every fourth model-stage task and covers every family/domain/support cell, with seed block 0 and horizon label 1. If the direct-action and A/B interfaces reverse the method ordering, the registered fallback restores the full-memory archive and records zero payload saving. 44.5 Development controls and statistical analysis 

Interface choices were made with separate development models. An audit found and corrected an iterator that overrepresented the first two interaction families before the reported experiments; final development uses eight tasks per family. These corrections preceded the reported experiments. We report each model separately and use the unweighted mean across the four displayed models only as a descriptive summary. The registered statistical family contains twelve tests: behavioral retention, active-payload savings, and model-query count for each model. Binary retention uses exact McNemar tests, while continuous outcomes use paired sign-flip tests. Query-count intervals use 2,000 task-cluster bootstrap replicates, and the associated p values are Holm-adjusted across the twelve-test family [Holm, 1979]. Appendix Table 5 reports these query-count tests. Exact-sufficiency and minimum-cost comparisons are descriptive.

# 6 Limitations and broader impact 

Controlled scope. Exact oracles require generated workflows. The six domain renderings share one grammar, and the horizon labels do not represent long autonomous rollouts, so the benchmark cannot estimate interaction prevalence in natural agent histories. Its fixed 108-task stress subset covers every family/domain/support cell but only one seed/horizon block. Behavioral sufficiency can preserve a model error and does not establish truth or causal importance. 

Model and interface scope. The 12B–70B display cohort uses a non-preregistered cutoff and cannot support a scaling claim; Llama remains exploratory. The models also differ in precision: Qwen and Gemma use BF16 weights, whereas Mistral and Llama use distinct NF4 loading paths. Finally, deletion, UNKNOWN masks, PENDING, counterfactual values, and decision labels are not interchangeable. The observed reversals limit generalization beyond the tested interfaces. 

Deployment implications. Registered payload weights are not token counts or latency measure-ments. Although smaller active memories may reduce inference cost and disclosure, removing authorization, consent, or provenance records can enable harmful actions. A deployed selector would require a trusted archive, access controls, human review, and domain-specific conservative rules; its model queries may themselves expose sensitive records. 

# 7 Conclusion 

JointCoreBench evaluates per-decision memory sufficiency under controlled redundancy and synergy. In exact evaluation, cost-ordered JointCore recovers a minimum-cost sufficient set on all 6,912 conditions with 11.13 subset evaluations, compared with 30.00 for cost-aware singleton deletion. Across four models, mean query count decreases from 16.00 to 10.28, and mean minimum-cost recovery increases from 43.1% to 50.6%. Full-memory behavior is retained under the primary interface, but memory and label changes show interface dependence. Evaluation on natural histories and longer trajectories is required to assess prevalence, interface robustness, and deployment risk.
