# Budgeted KV-Cache Repair for Evolving Contexts 

Han Yu ♣, Wenhui Zhu ♣, Jincheng Cao ♣, Rui Cai ♣, Yuanda Xu ♣, Zhengze Zhou ♣, Xiwen Chen ⋄,

Hao Wang ‡, Xuanzhao Dong ‡, Han Shi △, Menglin Zhou ♣, Shayan Mohajer Hamidi ♣, Lin Su ♣,

Mina Razghandi ♣, Sayan Ghosh ♣, Qing Lan ♣, Rohit Jain ♣, Alborz Geramifard ♣♣LinkedIn, ⋄Clemson University, ‡Arizona State University, △Rice University Language-model agents revise their working context as information becomes obsolete, but deleting text does not erase its influence on cached computation. Later key–value (KV) states remain conditioned on the deleted content, while recomputing the entire retained suffix can be costly. We introduce budgeted KV-cache repair: recovering task performance by recomputing a user-chosen fraction of the retained suffix. Comparing repair allocations under identical relevance scores and token budgets, we find that refreshing coherent regions can substantially outperform refreshing isolated tokens. This finding motivates Semantic-Unit Refresh ( SUR ), which allocates the budget to query-relevant text regions using inexpensive embedding scores, without training or an auxiliary transformer forward. To execute these repairs efficiently, a layer-packed executor processes selected states together at each layer while preserving full causal cache access. Across five models, SUR achieves strong recovery in controlled deletion tasks while recomputing only 2–5% of the suffix. On four natural multi-hop QA datasets, it achieves near-full-recompute exact match at a 5% budget with lower post-edit latency. The executor accelerates fragmented refresh by up to 16.1 × over interval-wise execution.

# 1 Introduction 

Language-model agents build their working context from tool outputs, retrieved passages, and intermediate decisions (Yao et al., 2023; Packer et al., 2023). As a task progresses, some of this information becomes obsolete: an observation is superseded, a passage is replaced, or an abandoned branch of reasoning is discarded. Removing such content keeps the context relevant to subsequent decisions, but creates a problem for cache reuse. A key–value (KV) cache stores representations computed from the earlier context, not independent encodings of its tokens. Deleting a passage therefore is not guaranteed to remove its influence from the states that follow it (Li et al., 2026b; Li, 2026). This residual influence makes a small text edit potentially expensive. The prefix before the deletion remains valid, whereas the retained suffix was computed while the deleted content was still visible. Correcting the suffix’s positions repairs its coordinates, but not its computational history (He et al., 2025; Ma et al., 2026). Replaying the entire suffix from the valid prefix repairs both, yet makes the cost depend on how much text follows the edit rather than how much was removed. An agent may thus have to revisit a long history after discarding only a short record. The question is whether answering the next query requires all of that recomputation. Recent work on cache editing and selective reuse suggests that full reconstruction is not always necessary. Learned editors compensate for erased context, while CacheBlend and ProphetKV select states for recomputa-tion using cache deviation or query attention (Li et al., 2026b; Yao et al., 2025; Wang et al., 2026). This raises a practical question for edited contexts: given a fixed amount of recomputation, where should it be spent to recover the next answer? We study this question as budgeted KV-cache repair , letting the user choose the fraction of the retained suffix to refresh. We investigate this allocation problem empirically, comparing relevance signals and ways of grouping the positions to refresh. A central finding is that relevance alone does not determine repair quality: with identical relevance scores and token budgets, refreshing coherent regions can recover substantially more answers than refreshing isolated high-scoring tokens. The useful unit of repair can thus extend beyond the tokens that make a passage appear relevant. This finding motivates Semantic-Unit Refresh ( SUR ), which distributes the repair budget across query-relevant regions (Figure 1). Frozen input embeddings provide inexpensive relevance scores, while text boundaries define regions to refresh together. The resulting policy can cover separated evidence without training or an auxiliary transformer forward. Region allocation also creates an execution challenge: refreshing separated regions one at a time repeatedly traverses the model. We develop a layer-packed executor that processes the selected regions together, reducing fragmented-refresh overhead while preserving access to the full causal cache. Our contributions are: • Grouping changes what the same repair budget can recover. Holding token scores and budgets fixed, region allocation improves exact match by over 80 percentage points over individual token selection on Qwen3-8B and Llama-3.3-70B at a 2% budget. These controls identify support organization as a design choice distinct from relevance scoring. • Low-cost region selection enables small repairs. Across five models, SUR reaches 89.6–100% exact match with only 2% suffix recomputation in controlled deletion tasks. On four natural multi-hop QA datasets, a 5% budget yields near-full-recompute exact match with lower post-edit latency. • Dispersed repairs share one model traversal. Our packed executor accelerates fragmented refresh by up to 16.1 × over interval-wise execution, preserving full causal cache access while amortizing traversal overhead across regions. 

# 2 Related work 

Context management and cache editing. Context-management methods determine what information a model retains. MemGPT organizes memory across storage tiers, while MEMENTO trains models to compress 2reasoning blocks into summaries (Packer et al., 2023; Kontonis et al., 2026). At the cache level, H 2O and SnapKV retain attention-important states to reduce memory and decoding costs (Zhang et al., 2023; Li et al., 2024). Retaining useful information, however, differs from updating computation after that information changes: a surviving state can still encode a removed passage. Our interface takes the deletion as given and budgets fresh computation over the retained suffix; unselected states remain available to attention. Cache-editing work addresses this state-maintenance problem more directly. PIE corrects rotary positions after code edits, and Leyline exposes policy-directed splicing alongside a re-prefill mode for semantic forgetting (He et al., 2025; Ma et al., 2026). Beyond positional correction, KVEraser learns replacement steering states for the erased interval (Li et al., 2026b), while Models Take Notes identifies downstream representations of earlier conclusions and studies selective recomputation and append-only correction (Li, 2026). These approaches establish that an edit’s effects extend beyond its own cache entries. We investigate how to distribute a user-chosen recomputation budget after physical span removal, recovering task quality through selective recomputation without a learned editor or corrective text. 

Selective recomputation and budget allocation. Modular cache reuse avoids rebuilding recurring context: Prompt Cache provides reusable prompt modules, while subsequent systems reconstruct cross-chunk inter-actions selectively (Gim et al., 2024). CacheBlend uses KV deviation, Cache-Craft uses chunk-dependence metadata, and EPIC’s LegoLink recomputes chunk-initial tokens (Yao et al., 2025; Agarwal et al., 2025; Hu et al., 2025). CacheTune derives salience from frequency-domain KV structure; SpecCache combines auxiliary-model features with score-based span completion (Li et al., 2026a; Wen et al., 2026). These mechanisms address contextual mismatch when cached pieces are assembled. Deletion creates a related mismatch within an already contextualized suffix. We compare adapted selection signals under a shared deletion-repair operator and equal suffix budgets, separating allocation decisions from the original systems’ serving implementations (Appendix A). Query-aware reconstruction further directs computation toward the next answer. A3 uses shallow query attention, ProphetKV aggregates query attention across layers, and InfoFlow KV aligns prompt-conditioned selection with inference-time positional geometry (Zhou et al., 2025; Wang et al., 2026; Teng et al., 2026). QCFuse reduces probing overhead through compact chunk anchors and critical-layer profiling (Yan et al., 2026). For budgeted deletion repair, the question is not only which tokens score highly, but which surrounding computation should be refreshed with them. Our matched-score experiments isolate this allocation choice: coherent regions can recover answers that isolated high-scoring tokens miss at the same budget. SUR turns this finding into a training-free policy: frozen embeddings provide inexpensive relevance, and text boundaries organize the budget into coherent refresh regions. 

# 3 Budgeted cache repair 

Budgeted repair separates how much to recompute from where to spend that computation. Given a context deletion, the next query, and a user-specified budget, we first correct cache positions, use SUR to select coherent regions, and refresh their states while reusing the rest of the cache (Figure 1). Packed execution batches the selected regions to avoid repeated model traversals.

Our objective is to recover answer quality for q, rather than reproduce every state of a newly built cache. The user supplies a recomputation budget, expressed as a percentage b of the S suffix tokens. This gives an allowance of B positions; the selection rule chooses the set A of B positions to refresh. No retained text is discarded: the budget changes which states receive new computation, not which tokens attention can access. Appendix A.1 specifies the integer rounding. Given A, we recompute the selected tokens through every transformer layer and replace their cached keys and values. All other entries are reused and remain available under causal attention. Sparse repair is approximate because selected tokens can still read earlier unrefreshed states computed with e present (Appendix H). A zero budget leaves only deletion and position correction; a full budget recomputes the entire suffix. Between these endpoints, the user can trade recomputation for answer recovery while retaining the same context. With the refresh operation fixed, the design problem is to choose A from the retained context and the next query. Appendix A.2 formalizes this objective. We next develop a selection rule that allocates the budget to query-relevant regions. 

## 3.2 Semantic-Unit Refresh 

A relevance score identifies promising locations, but does not determine which surrounding tokens should be refreshed with them. Our matched-score experiments show that coherent regions can recover answers missed by isolated high-scoring tokens at the same budget (Section 5). SUR turns this observation into a low-cost policy: text boundaries supply candidate regions, and query relevance determines which regions receive computation. 

Scoring relevance without a model forward. The selection signal should be inexpensive relative to the computation it saves. We therefore use the model’s frozen input embedding table E, without an auxiliary transformer forward or a trained selector. We group tokens at message, structured-container, paragraph, and sentence boundaries, splitting long units and merging short ones within their container. Each unit receives the mean of its four highest token scores, or all scores if shorter. A few relevant tokens can thus identify a unit for refresh, bringing its lower-scoring neighbors into the same computation. We rank units by this score, with earlier positions breaking ties. To fill the allowance B, we admit whole units in ranked order. If the next unit does not fit, we select a contiguous window within it that uses exactly the remaining allowance. We choose the window with the largest summed forward-decaying relevance envelope, which extends high relevance toward following tokens. Appendix A.3 specifies this scoring rule and the segmentation details. The resulting set A contains exactly B

positions and may cover several separated regions. We sort these positions, merge adjacent ones into execution intervals, and refresh the same selection at every layer (Algorithm 1). 

## 3.3 Packed execution 

Packed execution avoids traversing the model separately for each selected region. The regions chosen by SUR 

can form R disjoint intervals. An interval-major schedule processes the first interval through every layer, then repeats the traversal for the next interval, incurring dispatch and cache-management work R times. A small token budget can therefore still require many model traversals when the selection is fragmented. We instead use a layer-major schedule: all selected positions advance through one layer together before moving to the next (Figure 2). We gather their token embeddings into a compact batch and keep their hidden states together throughout the traversal. At each layer, we compute fresh K/V for these positions, write them into the retained cache, and evaluate attention and the remaining layer operations for the selected tokens. This produces the packed hidden states for the next layer and, after the final layer, a cache refreshed at exactly the selected positions. Only the recomputation is packed; the context available to attention is not. Each selected token keeps its position in the edited context and attends to the full causal history: fresh K/V at selected positions and reused K/V at unselected positions, including gaps between selected regions. Its position determines which entries are visible, so future tokens remain masked. Packing thus changes the order of computation without restricting attention to the packed tokens or changing the selected set. Appendix G gives the implementation and the equivalence argument. Selection and packing therefore reduce different costs. Across L transformer layers, selecting B of S suffix positions reduces token-layer updates from LS to LB : a 2–5% budget removes approximately 95–98% of suffix-position recomputation. Packing executes that same selection in one model traversal rather than R,batching the selected computation and amortizing traversal overhead across regions. Appendix G.1 develops the arithmetic and overhead models. 

# 4 Experiments 

We evaluate three aspects of budgeted repair. Controlled deletion tests answer recovery and the effect of support organization under matched relevance scores and budgets. Natural multi-hop QA tests whether SUR 

offers a useful quality–latency tradeoff on real questions. A matched-work execution benchmark isolates how packing reduces fragmented-refresh overhead. Section 5 connects these results to allocation and budget choice.

## 4.2 Controlled answer recovery on Erasing-NIAH 

We first ask how much of the retained suffix must be refreshed when deletion changes the correct answer. Erasing-NIAH (Li et al., 2026b) embeds two same-key facts in a long context; deleting one changes the required ordered list of values. This construction makes the effect of deletion directly checkable, allowing us to compare allocation rules over a broad budget range. All five models evaluate the same 96 cases spanning 1K–32K contexts. We sweep all fourteen allocators at 2/5/10/20/40/80% suffix budgets, alongside the four reference operators. Exact match (EM) requires the predicted list to match the edited-context answer in both order and multiplicity. Every score includes all 96 cases, including those already correct under Shift. Appendix A.5 gives the construction and answer-scoring details. 

Recovery with small budgets. Figure 3 shows that high answer accuracy can be recovered by refreshing only a small fraction of the stale suffix. At 2% recomputation, SUR reaches 89.6–100% EM across the five systems. Even the largest model, Qwen3-235B, benefits substantially over Shift despite its stronger starting point: model scale alone does not eliminate repair demand. Increasing the budget brings several models to their dense-reference performance without refreshing the entire suffix. This does not imply a universal saturation point: Qwen3-30B stays near Replay but below Re-prefill across the sweep. The budget offers a tunable tradeoff, with the useful operating point depending on the model. 

## 4.3 Quality and latency on natural multi-hop QA 

The controlled task establishes answer recovery; we next ask whether budgeted repair can preserve accuracy on real questions while reducing the cost of answering them. We use 2WikiMultiHopQA, HotpotQA, IIRC, and MuSiQue to test this tradeoff beyond the same-key numeric construction (Ho et al., 2020; Yang et al., 2018; 7Ferguson et al., 2020; Trivedi et al., 2022). We select 100 source questions per dataset before observing model outcomes. For each source, inserting the same non-supporting passage before, between, or after supporting evidence gives three placement cases. Deleting that passage restores the clean document and its target answer, but leaves suffix states computed with the passage present. Each model has 1,200 cases, with 300 per dataset. We compare a mixture-of-experts model, Qwen3-30B-A3B, and a dense model, Llama-3.3-70B. At 2% and 5% budgets, SUR is evaluated against same-unit BM25 and the CacheBlend-, InfoFlow-, and ProphetKV-derived selectors, with Shift, Replay, and Re-prefill as references. This comparison includes both inexpensive lexical selection and forward-based selection signals, whose acquisition cost matters when the repair budget is small. 

Quality and timing. We report normalized answer EM over all cases and mean post-edit latency, including selection, position correction, refresh, and query/answer decoding. Refresh includes prefix copying and cache assembly; initial dirty-context prefill and harness-only clones are excluded, while Re-prefill’s edited-context rebuild is included. Methods share the same worker and harness for each case, with one timed trial per case and no warmup. Quality differences use source-paired 95% bootstrap intervals, keeping each question’s three placements together. Appendices B.2–B.3 give hardware settings, per-dataset results, and the statistical protocol. 

The quality–latency tradeoff. Figure 4 shows that small-budget repair can preserve answering accuracy while reducing post-edit latency on real questions. At a 5% budget, SUR is within 0.1 percentage points of Re-prefill’s observed EM on both models and is 1.16–1.43 × faster. It also has lower latency than Replay. The smaller budget trades some quality for further savings, most visibly on Qwen3-30B. The comparison with other selectors highlights the importance of inexpensive allocation. At the larger budget, 

SUR has both higher EM and substantially lower latency than the attention/deviation-derived baselines on both models. Same-unit BM25 offers similarly low selection overhead; on Llama, it is marginally faster at the smaller budget but less accurate. Thus, acquiring a more expensive selection signal does not necessarily improve the quality–latency tradeoff. Source-paired analysis supports contextual refresh over position correction alone: at 5%, the improvements over Shift have positive confidence intervals on both models. The small differences from Re-prefill have intervals spanning zero (Table 9), consistent with the near-full-recompute observed EM. 

## 4.4 Execution efficiency of packed refresh 

Finally, we isolate fragmentation overhead at a fixed budget. On Qwen3-8B (BF16, batch one, H100 80GB), we fix B = 64 and vary R = 1 , 4, 16 at 2K and 8K context lengths, matching causal query–key pair counts within each length. We compare packed scaled dot-product attention (SDPA) with interval-wise, direct-cache sequential, and existing one-shot sparse execution. These controls separate shared-traversal savings from cache-assembly and adapter overhead. 

Matched-work refresh timing. Refresh time includes all-layer recomputation, cloning, planning, and mask construction, excluding selection, position correction, and answer generation. We report medians over 20 interleaved trials after ten warmups. This repeated benchmark measures the recomputation stage rather than the complete-answer latency reported for Natural QA. Packing keeps refresh time nearly flat as the same recomputation budget becomes more fragmented, yielding up to 16.1 × faster refresh than interval-wise execution. Most of this gain comes from sharing model traversal: the existing one-shot path already captures much of the benefit, with the packed adapter adding a further 1.21 × at 8K with sixteen intervals. For a single interval, direct-cache sequential execution is slightly faster than packing. The useful execution strategy therefore depends on selection geometry, not just token count. Full refresh timings and backend controls appear in Appendix G, with supplementary recovery timings on actual QA-selected regions in Appendix G.4. 85 Discussion 

The Erasing-NIAH allocation controls identify support organization as a design choice distinct from relevance scoring. With identical token scores, budgets, and repair operators, Qwen3-8B’s EM at 2% rises from 7.3% for individual tokens to 75.0% for the best contiguous window and 89.6% for SUR ; Llama exhibits the same progression. The window already maximizes summed relevance over all windows of that width, yet distributing computation across relevant regions improves recovery further. Random unit selection performs poorly, while same-unit BM25 and InfoFlow-Motivated win at some operating points (Appendix C). The resulting principle is query-directed region allocation. SUR implements it with inexpensive text boundaries; whether linguistic boundaries improve on generic multi-window grouping remains open. This dependence on allocation changes how the budget should be interpreted. On Qwen3-8B, SUR reaches near-perfect EM at 5%, while same-score token selection approaches that level at 80% in the measured sweep. A budget therefore specifies how much computation is available, not how much accuracy it will recover. Natural QA complements this controlled finding by testing SUR ’s practical operating points: a 5% budget approaches Re-prefill’s observed EM while reducing post-edit latency. The highlighted budgets are useful choices, not limits on the interface; the allowance can be increased as the task’s quality requirements demand. Turning reduced computation into faster refresh requires an executor suited to the selection. The matched-work results motivate direct execution for a single interval and layer packing for fragmented selections, avoiding repeated traversals of the model. Allocation and execution thus address two parts of the same objective: reducing the suffix computation needed for recovery and reducing the overhead of carrying it out. 

# 6 Conclusion 

Budgeted KV-cache repair makes recomputation after a context edit a task-directed allocation problem. Our controlled experiments show that allocating the same token budget to relevant regions can recover answers missed by isolated-token refresh. SUR translates this finding into a low-cost policy, with strong controlled recovery at 2–5% budgets and a favorable quality–latency tradeoff on natural multi-hop QA. Layer-wise packing separately accelerates fragmented refresh by up to 16.1 × over interval-wise execution. Together, these results make region allocation and execution geometry central considerations in maintaining reusable context caches. 9Limitations 

Execution coverage. The execution study uses one Qwen3-8B checkpoint on one H100, with fixed-budget fragmentation sweeps at two context lengths and four real-QA timing inputs. These stage-specific measurements cannot establish a deployment-wide speedup. Layer packing changes low-precision execution paths: tested next-token argmax agreement is not a substitute for rerunning task-level evaluation. The optional indexed attention kernel passes the 8K full-model numerical control but exceeds its fixed error budget for one 2K value-state statistic. It remains experimental; packed SDPA is the default. Dense Llama/Qwen3 with full attention, fixed default rotary positions, batch size one, and a single device define the implemented packed scope; MoE, offloading, sliding windows, and distributed serving are not covered. Preparation overlap is measured on one text example, without generation. 

Baseline adaptation. Prior-work-derived allocators share our repair operator and budget, which isolates allocation choices but does not reproduce each original system’s optimized implementation or full policy. Conclusions about these adapted signals should not be read as native-system rankings. 

# Ethical Considerations 

The study concerns reuse of model computation after context editing, not deletion of information from model weights or a privacy guarantee. A repaired cache may retain deleted information in unrefreshed states. Applications requiring confidential-data removal must therefore use a separately validated security mechanism rather than infer erasure from answer accuracy. The experiments use existing research benchmarks; their source citations and evaluation transformations are documented in Appendix A.

# A Repair operators, allocation rules, and evaluation 

This section specifies the cache-maintenance interface, selector implementations, and task evaluators. Repair semantics and selected-token count are fixed across allocators; each rule determines which retained positions receive computation. 

## A.1 Operator semantics and exact budgets 

Write the cached pre-query sequence as x = p ⊕ e ⊕ s, with deleted width d = |e| and retained suffix length 

S = |s|. The requested context is x− = p ⊕ s. At layer h, positional correction maps the old suffix key at position i to its compacted position: 

˜Khi−d = Rhi−d(Rhi )−1Khi ,

˜V hi−d = V hi . (2) Here Rhi is the model’s rotary map, including its position-scaling convention. This operation corrects position without removing the deleted span’s influence on the stored representations. 

Four reference paths. Dirty queries the original cache, with the deleted span still present; it is an untreated reference, not a completed deletion. Shift physically removes the span and position-corrects the retained suffix, without contextual forwards. Replay retains the valid prefix and recomputes the entire suffix under the edited history. Re-prefill rebuilds the complete edited prompt from an empty cache. Replay and Re-prefill are operational dense references; their floating-point execution paths need not produce identical outputs (Appendix E). 

Sparse refresh reads mixed fresh and stale history. Every sparse arm starts from the Shift cache. Selected positions are recomputed through all transformer layers in causal order and written back; unselected positions retain their shifted KV states. Consequently, a refreshed position can still read an earlier unselected stale state. Selecting a position does not establish causal closure. Consecutive selected positions form execution intervals. In the task-quality evaluations, the sparse executor uses sequential maximal-interval replay: each maximal contiguous selected interval is forwarded in order against the evolving cache. Any added bridging positions must count against the same allowance. For an interval [ a, b ), the executor copies the current cache prefix [0 , a ) and forwards the edited tokens x−

> a:b

against that prefix. The resulting K/V rows replace only [ a, b ) at every layer; all other rows are retained. Future cached positions are therefore absent from the forward, while earlier refreshed intervals are available to later ones. The cache length remains unchanged after each replacement. This reference implementation uses ordinary model forwards and tensor concatenation, not a specialized sparse kernel; fragmentation incurs repeated prefix-copy and forward overhead. 

The allowance is an exact count of unique suffix positions. For a requested percentage b, every allocator receives 

B(S, b ) = min {S, ⌈Sb/ 100 ⌉} , 0 ≤ b ≤ 100 . (3) Only pre-query suffix positions are selectable. The query may supply a ranking signal but cannot consume the repair budget. We evaluate sparse arms at b ∈ { 2, 5, 10 , 20 , 40 , 80 }%; Shift and Replay supply the separate 0% and 100% endpoints. Curves retain nonmonotone observations and do not interpolate an unmeasured success rate. A percentage is contextual-forward coverage, not a FLOP fraction: sparse arms also rotate/read/write the suffix, and a rotation is not equivalent to an attention–MLP forward. 12 A.2 Task-aware allocation and repair locality

The central question is how to allocate a fixed repair budget around a query-relevance signal. The 96-case comparisons hold cases, exact selected-token allowance, and all-layer refresh operator fixed. We first compare independent tokens, one contiguous window, and SUR using identical token scores, then examine query direction and alternative relevance rules. ## C.2 Inexpensive relevance versus attention and state signals 

Cheap relevance signals support effective region allocation. BM25 retains SUR’s unit partition and allocator, replacing its relevance rule with lexical scoring. Richer signals are evaluated as complete policies. The attention- and state-derived allocators in Table 13 extend the comparison to richer signals. # D Matched evidence-location experiment 

The direct allocation controls in Appendix C test how SUR spends a repair budget. This supplementary experiment asks an earlier question: whether moving task evidence downstream changes repair demand when edit geometry is fixed. On a separately constructed panel, the gap between full suffix Replay and Shift measures the value of contextual recomputation at each evidence placement; it is not an estimate of SUR ’s gain. 

## D.1 Construction and controls 

The candidate pool contains the same 400 natural-QA sources. All annotated support documents form an untruncated evidence bundle. A control bundle contains one to four native non-support documents, rejecting documents with a normalized answer alias or support title. Whole natural text chunks and a fixed neutral padding family extend both bundles to an identical token width. A source is excluded if exact construction is infeasible; eligibility does not depend on a model outcome. The bundles exchange slots immediately before and after a fixed 256-token deletion. Within each tail condition, the exchange holds edit index, deletion width, slot width, retained-suffix length, text multiset, query, and answer target constant. A neutral-tail extension outside the slots crosses this exchange to form four cells: upstream/short, downstream/short, upstream/long, and downstream/long. Thus the side contrast fixes suffix length, while the tail contrast jointly changes filler, stale-state volume, and evidence-to-query distance. The evidence exchange also changes support order and recency; it is not an isolated intervention on a unique semantic mediator. Geometry selection uses only tokenization and searches a fixed list of candidates before model execution. Their (slot width, edit index, short suffix, long suffix) values are (512 , 2048 , 1024 , 4096), then (768 , 3072 , 1536 , 4096), then (1024 , 4096 , 2048 , 4096) tokens. Literal support text is not truncated to force a match. Exact boundary tokenization, absence of protected answer strings in padding, and absence of special-token IDs in inserted content are checked before execution. The common panel contains 275 sources: 79 from 2WikiMultiHopQA, 64 from HotpotQA, 64 from IIRC, and 68 from MuSiQue. Qwen3-8B, Llama-3.1-8B-Instruct, and Qwen3-30B-A3B evaluate all four cells, giving 825 source–model units. The default backend uses native SDPA. The adapter is implemented for Transformers 4.57.6 native dense Llama/Qwen3 in evaluation mode, full attention, default fixed RoPE, batch size one, and a single device. The reference implementation also provides a one-shot sparse path, included as a control for the benefit of packing already available without the new adapter. 

Indexed attention and writes. The optional Triton attention processes 16 packed query rows and 64 K/V positions per tile, with four warps and two stages. Grouped-query heads use the original head mapping. Online softmax and tiled accumulation follow established IO-aware attention techniques (Dao et al., 2022). The kernel keeps probabilities in FP32 and explicitly uses TF32x3 products for P V , rather than rounding probabilities to BF16/FP16. This is not IEEE-exact FP32. The kernel requires NVIDIA SM80+, FP16/BF16 inputs, and head dimension 64 or 128. An optional indexed scatter writes fresh K and V in one launch. Scatter and attention remain separate, ordered launches on the same stream; there is no cross-program global barrier assumption. Torch indexed writes are the default because they are faster in the measured complete-refresh path.

## G.5 Numerical validation 

Packing preserves the mathematical recurrence but not low-precision execution order. On the six refresh configurations, both packed SDPA and custom attention preserve the input and all unselected K/V bits, and match the sequential path’s two-token query argmaxes. For fragmented supports, packed SDPA’s query logit relative L2 differences range from 0.67% to 1.89%. Custom selected-K/V maximum absolute differences range from 0.5 to 0.875; the largest layerwise relative L2 difference is 1.67%. Query-logit relative L2 differences are 0.54–0.97%. These are numerical probes, not task-quality certification. The indexed attention unit tests use an explicit FP64 oracle with fixed BF16 tolerances atol = 0 .002, rtol = 0 .02 (FP16: 0.00025 and 0.003), covering causal gaps, tails, GQA, strides, metadata changes, and non-default streams. With FP32 probabilities retained, the custom kernel passes this local test on operands from all 36 layers of the 2K checkpoint run; the largest error/tolerance ratio is 0.190. The full H100 regression suite passes 830 tests; 81 GPU memory-sanitizer checks report no memory errors. These counts are software tests, not additional task samples. A separate complete-model control promotes identical BF16 weights and buffers, and the shifted starting cache, to FP32 with PyTorch TF32 disabled. Its engineering budget requires each selected-K/V and query-logit max/RMS error to remain within twice the native low-precision packed-SDPA error. An earlier strict pointwise integration check had failed, and this diagnostic budget was fixed before the subsequent checkpoint controls; it is not an accuracy guarantee. At 8K/ R = 16, the custom path passes, with maximum ratio 1.617. At 2K/ R = 16, zero-based layer 18 V maximum error is 0.21346 versus the native path’s 0.09965: a ratio of 2.142 exceeds the fixed budget. RMS and final-logit checks pass, but this failure remains. Layer-local accuracy does not establish identical accumulated trajectories. Accordingly, custom attention remains an explicit experimental option; packed SDPA is the default. The task-quality results elsewhere in this paper were not rerun on either packed backend.
