## 摘要
大语言模型（LLM）智能体能够处理日益复杂的任务，在较长的观察与动作轨迹中导航。随着这些轨迹增长，键值（KV）缓存的 I/O 与存储成为主要成本。轨迹还可能超出 LLM 的最大上下文长度，因此需要控制活跃缓存的增长。已有工作使用上下文工程，通过裁剪或摘要历史来减小缓存大小。然而，修改轨迹前缀会使后续缓存状态失效，并触发对保留上下文的昂贵重新预填充。当为限制重新预填充成本而保留的上下文过少时，任务准确率也可能下降。我们提出缓存工程作为一种新方案。它使智能体能够直接控制其活跃 KV 缓存，而无需修改轨迹或重新预填充保留的上下文。具体而言，智能体可以主动使用 drop 将选定缓存排除在后续注意力之外，并使用 repos 调整保留键的位置编码。我们将这些缓存操作形式化，并将历史依赖性识别为一种服务挑战：相同的 token 序列在不同缓存操作序列下可能产生不同的缓存状态，使得前缀匹配不足以实现正确的缓存复用。因此，我们协同设计了 AKV 服务引擎。它提供与现有服务 API 兼容的无状态接口，同时在内部管理有状态的缓存复用、驱逐和恢复。实验表明，与传统的阈值触发摘要相比，工具响应滚动丢弃缓存策略将平均基准分数提高 1.7 分，并将平均成本降低 27.7%。借助 AKV，其输出吞吐量最高可达 1.2 倍，P95 请求延迟加速 1.5 倍。缓存策略的递归自我改进在专家设计的基础上进一步降低成本 7.1%。我们的代码位于 https://github.com/thu-nics/AKV。

## Abstract
Large Language Model (LLM) agents can handle increasingly complex tasks, navigating long trajectories of observations and actions. As these trajectories grow, key-value (KV) cache I/O and storage become the dominant cost. Trajectories can also exceed the LLM's maximum context length, requiring control over active cache growth. Prior work uses context engineering to reduce cache size by trimming or summarizing history. However, modifying the trajectory prefix invalidates subsequent cached states and triggers costly re-prefilling of retained context. Task accuracy can also suffer when too little context is retained to limit re-prefill costs. We propose cache engineering as a new scheme. It allows agents to directly control their active KV cache without modifying the trajectory or re-prefilling retained context. Specifically, agents can proactively use drop to exclude selected cache from future attention and repos to adjust retained keys' position encodings. We formalize these cache operations and identify history dependence as a serving challenge: identical token sequences can yield different cache states under different cache operation sequences, making prefix matching insufficient for correct cache reuse. Thus, we co-design the AKV serving engine. It provides a stateless interface compatible with existing serving APIs, while internally managing stateful cache reuse, eviction, and restoration. Experiments show that a tool-response rolling-drop cache policy improves average benchmark scores by 1.7 points and reduces average cost by 27.7%, compared with conventional threshold-triggered summarization. With AKV, it achieves up to 1.2x the output throughput and a 1.5x speedup in P95 request latency. Recursive self-improvement of cache policies further reduces cost by 7.1% over expert design. Our code is at https://github.com/thu-nics/AKV.

- **已有方案的困境**：上下文工程（裁剪/摘要）通过改写轨迹前缀来缩小缓存，但会**使后续缓存状态失效**，触发对保留后缀的昂贵重新预填充（re-prefill）；为压低重预填充成本而过度裁剪又会丢失中间轮次的有用信息，形成"重预填充成本 vs. 任务准确率"的两难。
- **整体含义**：作者提出"缓存工程"（cache engineering）作为新范式——不改写轨迹文本，而是让智能体**直接、增量地操控活跃 KV 缓存**，在不重预填充的前提下同时改善准确率与成本。

## 2. 方法论

### 2.1 核心思想

- 保持逻辑 token 序列（轨迹）不变，直接对**活跃缓存 C**（参与后续注意力的 KV 状态集合）施加操作；"活跃"是算法层面的可见性，而非物理驻留。
- 将位置编码索引与逻辑 token 索引、缓存大小**解耦**，从而在缓存缩减后仍能控制位置范围。

### 2.2 三种基本缓存操作

- **append(x)**：标准 KV 追加，新 token 在活跃缓存条件下计算并追加，位置索引自增。
- **drop(P)**：将逻辑索引集合 P 对应的 KV 从后续注意力中移除，保留项的顺序、位置编码与逻辑序列均不变，且**不改变后续 append 的位置索引**。
- **repos**：按逻辑顺序重排保留缓存的位置编码为 0,…,r−1，并重置下一个 append 的位置索引为 r；对 RoPE，键按 K ← R(q)R(p)⁻¹K 旋转，值保持不变。

### 2.3 缓存操作序列与历史依赖性

- 用序列 o₁:ₘ = (o₁,…,oₘ)（oⱼ ∈ {append(x), drop(P), repos}）从空缓存确定性地刻画当前缓存状态。
- **关键洞察**：相同 token 前缀与保留位置，在不同操作顺序下会产生**不同的缓存状态**（如先 append C 再 drop A，与先 drop A 再 append C，C 的 KV 条件不同），因此传统前缀匹配不足以正确复用。

### 2.4 AKV 服务引擎（无状态接口 + 有状态服务）

- **接口**：沿用标准 messages 字段（隐含 append），新增可选 cache 字段，用"operate-after"语法按消息索引指定 drop 与 reposition；同一位置 drop 先于 repos。客户端无需跟踪服务器端物理缓存。
- **扩展基数树**：插入 drop 节点 Δ 与 reposition 节点 R，token 节点表示为 T(x,p)（x 为 token，p 为存储位置），从而同时索引 token 与操作历史。
- **匹配规则**：先做**精确匹配**（token、位置、操作节点及参数全同）；再做**retrigger 匹配**（投影忽略位置索引、保留全部操作记录），对选中源缓存做键旋转复制，避免重算隐藏状态；操作节点保证不会跨越计算历史分歧点复用。
- **驱逐**：drop-aware 驱逐，被 drop 的缓存条目在所有相关请求都不再需要时可提前释放，优先驱逐被 drop 的缓存而非已完成请求的缓存；树节点保留为空占位符。
- **恢复**：segment-batch attention，在 drop/repos 触发点切分 query，各段只对自身 token 与更早段的活跃缓存做因果注意力，被 drop 缓存对更早段仍可见；仅注意力分段，FFN 仍整批处理以节省权重读取；repos 段通过临时 KV 版本（旋转 K、复制 V）在一次前向中完成恢复。

### 2.5 策略层

- **工具响应滚动 drop（主策略）**：保留全部推理缓存与最近 K=12 轮工具响应缓存，丢弃更早的工具响应缓存；repos 阈值与 Standard 的摘要阈值对齐。
- **缓存管理即工具（CAT）**：把缓存操作暴露为工具，由智能体自主决定何时缩减、保留什么。
- **递归自我改进（RSI）**：让智能体搜索、评估并迭代缓存策略。

## 6. 主要结论与发现

- **准确率**：AKV 在三个模型上取得最高平均通过率，较 Standard 提升 1.3–2.1 个百分点、较 Text Engineering 提升 0.9–8.7 个百分点；平均分数 53.7/53.1/45.8（MiniMax/GPT-OSS-120B/MiroThinker）。
- **成本**：平均较 Standard 降低 27.7%、较 Text Engineering 降低 21.9%。
- **准确率来源**：低于 48K 时三者相当；48–96K 区间 Text Engineering 最差，96K 以上 Standard 最差，说明滚动 drop 的**渐进式缩减**优于阈值触发的突变式摘要。
- **服务效率**：各自峰值吞吐设置下，AKV（C=14）相对 Standard（C=12）平均延迟提速 1.36×、P95 提速 1.51×，输入/输出吞吐分别为 1.53×/1.18×；高并发下优势扩大。
- **加速来源**：全注意力时间降低 59.8%，单步解码时间降低 16.0%。
- **消融**：工具响应 drop + repos 在两个基准上通过率最高；repos 将 BCP 通过率从 55% 提升到 62%（突破位置上限）；丢弃推理缓存反而更差。
- **RSI**：第 3、6 轮策略相对 Standard 分别降本 15.6%、17.8%，优于人工设计的 7.1% 改进。
- **CAT**：两模型上取得最高通过率（61.0%/64.0%），但 MiniMax 因执行更多轮次成本略升。
- **兼容性**：与 Pi harness 集成后准确率分别提升 3%（无压缩）与 4%（有压缩）。

## 7. 优点

- **问题形式化清晰**：用缓存操作序列给出确定性、可编程的缓存状态描述，把"历史依赖性"这一服务层挑战显式提出并给出可判定条件（精确匹配 vs. retrigger 匹配）。
- **范式创新**：将 KV 缓存从"系统内部管理"变为"智能体可主动操控的资源"，绕过上下文工程"改前缀即失效"的根本矛盾。
- **系统与算法协同设计**：扩展基数树、drop-aware 驱逐、segment-batch attention 三者分别对应复用、驱逐、恢复三个目标，且"仅分段注意力、FFN 整批"的设计有明确的访存优化动机。
- **接口设计务实**：无状态接口兼容现有 API，内部有状态管理，便于落地与跨请求隔离。
- **实验较扎实**：多模型、多基准、在线端到端 + 服务吞吐 + 消融 + 策略搜索，成本核算保守，结论可信度较高。

## 8. 不足与局限

- **策略探索有限**：主策略（工具响应滚动 drop）是人工启发式，RSI 仅在 20 个 BCP 任务上搜索、100 个留出任务上验证，泛化性与规模仍有限。
- **未涉及训练**：作者自述在该范式下训练智能体、以及扩展到线性注意力模型均为未来工作。
- **缓存状态膨胀风险**：历史依赖性导致同一 token 前缀可对应多个缓存版本（repos 复制、多分支），内存开销与树管理复杂度上升，论文未系统量化其代价。
- **小模型收益有限**：GPT-OSS-20B 上部分指标未超越基线，作者归因于模型利用保留信息的能力较弱，说明方法对模型能力有依赖。
- **评测偏差**：各方法回

- **部署范围有限**：服务实验限于单节点 8 卡、NVLink 内 KV 传输，未验证跨节点、多副本、多租户隔离下的表现；而 drop-aware 驱逐在共享缓存池中的公平性与抖动问题也未讨论。

## 9. 总体评价与启示

- **定位**：这是一篇"范式提出 + 系统实现 + 策略验证"三位一体的工作，其最大贡献不在于某个具体策略的百分点提升，而在于把 **KV 缓存显式提升为智能体可编程的一等资源**，并给出了使其在真实服务系统中可行的接口与数据结构。
- **核心洞察的可迁移性**：论文指出的"相同 token 前缀在不同操作历史下对应不同缓存状态"这一观察，对所有做前缀缓存复用的推理系统都具有普遍意义——它说明缓存键必须包含"如何得到该缓存"的过程信息，而不只是内容信息。
- **工程与算法的耦合设计值得借鉴**：扩展基数树（复用）、drop-aware 驱逐（内存）、segment-batch attention（恢复）三者各自服务于一个明确目标且互不冲突，这种"一个抽象对应一组系统机制"的组织方式，比单纯堆叠优化更有参考价值。
- **方法论的开放性**：把缓存策略交给智能体自主搜索（RSI）虽只做了小规模验证，但指出了"策略本身可学习"的方向，与"缓存即工具"（CAT）共同构成从人工启发式走向自适应策略的路径。
- **实践建议**：对长时程智能体部署方而言，本文最直接可用的结论是——**渐进式、细粒度、按信息类型区分（保留推理、滚动丢弃工具响应）的缓存缩减，优于阈值触发的整体摘要**；同时 `repos` 这类位置重置手段能实质性地突破位置编码上限，值得优先纳入系统设计。
- **尚待回答的问题**：缓存缩减的"最优粒度与最优时机"是否存在可学习的判据；多分支/多智能体共享缓存时的一致性模型如何定义；以及在训练阶段就让模型感知"缓存可被裁剪"是否能进一步提升信息利用效率——这三点构成了该方向最自然的后续研究空间。
