## 摘要
LLM 智能体正从调用工具的单一模型，演化为编排多个专家模型的规划器，而这些专家模型的能力存在于彼此不同的权重中。这一转变打破了当前服务系统的一个隐含假设：模型的工作集能够放入 GPU 内存。在私有化和边缘部署中常见的内存受限 GPU 上，朴素的整模型交换会使权重传输与计算串行化，并且在缺乏主机端支持的 KV 恢复时，在切换时丢弃会话状态。我们提出 JointServe，一种将权重分片和 KV 块视为竞争同一统一内存预算的驻留对象的服务系统。JointServe 利用智能体工作负载的三个结构特性（有向调用、间隔执行和双状态驻留）在模型被调用之前做好准备：从调用者自身输出流中解析出的意图信号会在生成过程中触发预取，部分 k* 驻留将切换缩减为增量层，抢占式传输调度器以有保证的带宽份额保护活动会话的 KV。一个划分控制步骤会随着工作负载需求变化调整权重/KV 分配。评估表明，JointServe 相比最强的整模型交换基线将会话完成时间缩短了 21.7%，并且在所有整模型交换基线都无法完成的崩溃场景中仍保持可用（差距达 46 倍）。在重放的 SWE-bench、tau-bench 和 OSWorld 轨迹上，它将会话完成时间最多缩短 49%，并将 SLO 达成率从 2.8–24.5% 提升到 76.8–100%。

## Abstract
LLM agents are evolving from a single model calling tools to planners that orchestrate multiple expert models whose capabilities live in distinct weights. This shift breaks a hidden assumption of today's serving systems: that the working set of models fits in GPU memory. On the memory-constrained GPUs typical of private and edge deployments, naive whole-model swapping serializes weight transfer with computation and, without host-backed KV restoration, discards session state at a switch. We present JointServe, a serving system that treats weight shards and KV blocks as residency objects competing for one unified memory budget. JointServe exploits three structural properties of agent workloads (directed calls, gapped execution, and dual-state residency) to prepare models before they are called: an intent signal parsed from the caller's own output stream triggers prefetch during generation, partial k* residency reduces switching to incremental layers, and a preemptive transfer scheduler protects live-session KV with a guaranteed bandwidth share. A carve-out control step adjusts the weight/KV allocation as workload demands change. Evaluations show that JointServe reduces session completion time by 21.7% over the strongest whole-model swap baseline and stays usable in a crash regime where every whole-model swap baseline fails to finish (a 46-fold gap). On replayed SWE-bench, tau-bench, and OSWorld traces, it cuts session completion time by up to 49% and lifts SLO attainment from 2.8-24.5% to 76.8-100%.

## 一、核心问题与整体含义

- **背景转变**：LLM 智能体正从“单模型调用工具”演化为“规划器编排多个专家模型”的架构（model-as-tool）。专家能力固化在各自权重中，无法通过 prompt 唤起，因此服务这类负载意味着“按需服务多个异构模型”，而非把单个模型服务好。
- **被打破的隐含假设**：现有服务系统默认“模型工作集能放入 GPU 显存”。但私有化、边缘、共享 GPU 部署通常只有 1–2 张 80GB 级加速卡，而一个 5 专家池（7B–14B，FP16）的权重合计就达 70–140 GB，全驻留是算术上不可能，而非调参问题。
- **两类用户可见代价**：
  - **TTFT（首 token 时延）**：整模型换入时存在“load-all barrier”，最后一层落地前无法 prefill。在 A800 + PCIe 4.0（实测 24.3 GB/s）上换入一个 7B FP16 专家（15.2 GB）至少 0.63 s，GPU 全程空转；引擎默认 reload 路径（NVMe→主机→HBM→重建运行时）高达 67.76 s。
  - **SCT（会话完成时间）**：换出时为腾空间驱逐的 KV 若无主机副本即被销毁，切回时须从头 re-prefill。该代价随上下文长度**二次增长**：τ-bench 中位 2.7K token 时 0.18 s，SWE-bench 中位 27.5K token 时 2.64 s，p95（61.8K）达 8.89 s；而主机 KV 重载仅 0.05 s，存在约 20× 差距。
- **既有路线为何不够**：
  - 更快的整模型加载（ServerlessLLM、Talaria）只消除“去程”权重传输，未触及“回程”KV 重算；且模型粒度切换存在容量天花板（70B FP16 共 140 GB 时直接不可行）。
  - 量化共驻留（INT4）只是**转移**而非消除竞争：32 GB 预算下权重锁定 21.1 GB、KV 仅剩 10.9 GB；16 GB 预算下 5 专家 INT4 池（21.1 GB）放不下，退化为按需换入，makespan 崩至 34,909 s。同时有精度风险，且 adapter/delta 共享方案要求同基座模型，异构专家池不满足。
  - 被动缓存（LRU、前缀复用）只看历史统计，对“下一个调用哪个模型”无感知，丢弃了智能体调用图天然暴露的先验。
- **核心问题**：在单卡紧张预算下，**哪些字节（权重分片还是 KV 块）应驻留、何时移动、依据谁的信号**。目标是同时获得“激进换出的容量余量”和“全驻留的交互性”。

## 二、方法论

### 2.1 核心思想

把权重分片与 KV 块统一建模为**竞争同一 HBM 预算的驻留对象**，用显式恢复代价在单一价值尺度上排序；再利用智能体负载的三个结构特性（有向调用、间隔执行、双状态驻留）把“何时移动”从**预测问题**转化为**读取问题**——从调用者自身输出流中读出目标模型，在请求到达前完成搬运。

### 2.2 统一驻留模型与代价模型

- 候选集 C = W ∪ K：独立管理的权重层组 W 与会话 KV 单元 K，各自保留模型/会话身份（跨模型 KV 不可复用）。预算 B 扣除运行时、激活、传输缓冲；受保护对象 P（在飞会话状态、到达模型的已承诺流式前缀）不可驱逐。
- 对象 i 的保留价值 **u_i = p_i · c_i**（窗口内复用概率 × 最廉价恢复路径代价），密度 d_i = u_i / s_i。目标为在 s(S) ≤ B_f 下最大化 Σu_i（0-1 背包形式）。
- 恢复代价：
  - 权重重载：c_i^W = α_W + s_i / BW_H2D
  - KV 主机重载：c_i^K,load = α_K + s_i / BW_H2D
  - KV 重算：c_i^K,recompute = Δr_m(n_ready, n)，其中整前缀恢复拟合为 r_m(n) = a₀ + a·n + b·n²，部分缺失只计增量；共享启动开销只计一次。
- 由于启动开销与二次 prefill 代价，恢复价值密度对前缀长度**非单调**（附录 A.2 给出拐点 √(a₀/b)），因此同样大小的对象可能排序不同：重算受限的 KV 块可能比可主机重载的 KV 或权重分片更值钱。

### 2.3 联合预算分配（Algorithm 1）

不固定权重/KV 切分，而是每次事件重建：

1. 若保护集 P 不可行 → 返回 `CapacityShortfall`；
2. 丢弃单对象不可行或价值非正的候选；
3. 计算密度序可行前缀价值 G 与最优可行单例 M，取 **L = max(G, M)**，可证 L ≤ OPT ≤ 2L；
4. 以 τ = ε_K·L 把 KV 分为高价值 K_H 与低价值 K_L；
5. 对 K_H 做“按价值分桶、每桶保留 h = ⌈2/ε_K⌉ 个最小对象”的压缩（因最优解中高价值 KV 数量 < 2/ε_K）；
6. 对 W ∪ K′_H 做**按价值取整、记录最小真实字节**的动态规划，得到前沿代表 (R_q, s_q, v_q)；
7. 对 K_L 建密度前缀索引，查询 F_L(r) 返回适配剩余容量的最长前缀；
8. 在所有代表上取 argmax [ Û(R_q) + Û(F_L(B_f − s_q)) ]；
9. 由对象类型导出 b_W、b_K 配额。

**理论保证**：对独立可加、单一容量约束的候选集，算法返回可行解满足 Û(S_A) ≥ (1−ε)·OPT，ε = ε_C + ε_S + ε_K < 1（附录 A.7 证明）。附录 B 进一步把估计误差 E 与真实收益关联：U(S_A) ≥ α·OPT − (1+α)E，α = 1−ε；并讨论计划复用与未来信息（clairvoyant oracle）之间的不可消除差距 I。

### 2.4 系统设计

- **控制/执行分离**：Request Scheduler、Residency Manager、Signal Engine 构成控制层，产出带版本的驻留计划；GPU Worker 与 Transfer Scheduler 执行计划。
- **意图驱动预取（Signal Engine）**：在 GPU Worker 输出流上挂**旁路 tap**（不改变路由），词法匹配器在调用者流式输出 function-call header 时即锁定目标模型；fan-out header 可泛化为候选集。无显式意图时回退到一阶 Markov 转移（Laplace 平滑），再回退到热度/LRU。误预测代价有界（按同一价值模型计价并正常驱逐），最坏退化到被动基线。
- **部分分片流式热切换**：每个模型常驻 k* 层启动前缀，换入只流式传输剩余 L−k* 层；per-group ready event 使 prefill 在首组就绪后即开始，后续层与计算重叠（论文中 0.11 s 开始 prefill，全部层 1.83 s 就绪）。原型用**原地覆盖**，论文明确说明与 shadow-buffer ping-pong 的差异。
- **双状态 KV 分层**：主机 RAM 作为第二驻留层，重载 vs 重算由代价模型在线决定，offload 先于 release，源缓冲在传输完成前不释放。
- **抢占式传输调度器**：三类流量共享 H2D 通道，静态优先级为“目标预取 > 流水线分片流 > 后台 KV”；权重按层组粒度分块，允许在块边界被抢占；**κ-floor（默认 15% 链路带宽）**为在飞会话的 KV 恢复保留最低份额（是下限而非权重上限）。
- **carve-out 自适应控制**：意图、估计、保护集或容量变化时重新派生 b_W/b_K 配额，在换入前向权重倾斜、生成期回补 KV。
- **实现**：基于 SGLang，核心约 1.5K 行 Python；三组 hook（`submit_plan`、`ready_event`、`kv_load`/`kv_offload`）；绕过引擎默认 loader，从 pinned 只读主机权重库直接写 HBM；提交为三步协议（派发 delta → 报告启动就绪 → 原子切换映射），目标集与就绪集分开跟踪，计划不可行则保留旧映射。
