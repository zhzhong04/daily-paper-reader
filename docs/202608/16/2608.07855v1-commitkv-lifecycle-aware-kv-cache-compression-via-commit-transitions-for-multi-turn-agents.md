## 摘要
多轮推理与行动（ReAct）智能体会积累不断增长的推理、工具调用和观察轨迹。它们的键值（KV）缓存相应增长，增加了模型推理期间的内存使用和注意力成本。现有的KV缓存压缩方法通过驱逐低注意力分数的状态来降低这些成本。然而，当前轮次中的低注意力并不意味着未来无关，因为暂时不活跃的信息可能在以后变得重要。因此，基于快照的驱逐方法没有明确区分暂时不活跃的信息和看似已完成其角色的信息。在本文中，我们提出了CommitKV，它通过提交转换来识别KV生命周期。具体来说，CommitKV首先将完成的智能体事件划分为token页面，并在工具调用提交之前和提交返回的观察结果合并之后，比较每个合格页面的删除效果。基于这些配对测量，CommitKV将不活跃页面与从高到低的完成候选区分开来。然后，它应用贪婪联合测试，仅当候选者提交后的合并效果保持有界时才接受其退役。最后，在后续的压缩检查点，排除已接受的页面，保护一组等待提交后测量的有界页面，并使用相同的token索引为键、值和绝对位置保留缓存预算内的其余KV状态。这些机制确保CommitKV能够区分不活跃信息和已完成其观察角色的信息，并可安全移除。在各种基准上的实验表明，CommitKV减少了智能体内存使用，加速了端到端推理，并比现有KV缓存压缩方法实现了更高的准确性。

## Abstract
Multi-turn Reasoning-and-Acting (ReAct) agents accumulate growing trajectories of reasoning, tool calls, and observations. Their key-value (KV) caches grow accordingly, increasing memory use and attention cost during model inference. Existing KV cache compression methods reduce these costs by evicting states with low attention scores. However, low attention in the current turn does not imply future irrelevance, as temporarily inactive information may become important later. Snapshot-based eviction methods therefore do not explicitly distinguish temporarily dormant information from information that appears to have completed its role. In this paper, we present CommitKV, which identifies KV lifecycles through commit transitions. Specifically, CommitKV first divides completed agent events into token pages and compares each eligible page's deletion effect before a tool-call commit and after the commit's returned observation has been incorporated. Based on these paired measurements, CommitKV distinguishes dormant pages from high-to-low completion candidates. It then applies a greedy joint test, accepting candidates for retirement only when their combined post-commit effect remains bounded. Finally, at a later compression checkpoint, accepted pages are excluded, a bounded set of pages awaiting post-commit measurement is protected, and the remaining KV states are retained within the cache budget using the same token indices for keys, values, and absolute positions. These mechanisms ensure that CommitKV can distinguish dormant information from information that has completed its observed role and can be safely removed. Experiments on various benchmarks show that CommitKV reduces agent memory use, accelerates end-to-end inference, and achieves higher accuracy than existing KV cache compression methods.

## 一、核心问题与整体含义

- **研究动机**：多轮 ReAct（Reasoning-and-Acting）智能体在推理过程中会不断产生推理文本、工具调用和返回观察，导致 KV 缓存持续增长，带来内存占用上升和注意力计算开销增大。
- **现有方法的缺陷**：主流 KV 缓存压缩方法（如 SnapKV、R-KV、TriAttention）多基于当前轮次的注意力分数或查询相关性估计 token 重要性，然后驱逐低分 token。这种“快照式”策略存在根本性歧义：**当前轮次低注意力并不等于未来不重要**。
- **关键问题**：一个早期的观察页（例如“节日在巴黎举办”）可能在当前检查点分数很低，但未来最终回答时仍然需要；而一个工具调用页（例如“查询天气”的请求）在其返回观察已被合并后，可能已经完成了历史使命。仅凭当前低分无法区分“暂时休眠”和“已完成角色”的信息，容易导致有用状态被过早驱逐。
- **整体含义**：CommitKV 提出“生命周期感知”的 KV 缓存压缩，利用工具调用提交点前后信息的角色变化来识别 KV 的真实生命周期，从而在压缩缓存时既能安全清除已完成任务的信息，又能保护未来可能重新激活的休眠信息，提升多轮智能体推理的效率与准确率。

## 二、方法论

### 2.1 核心思想
- 将智能体交互历史中的每个**工具调用**和**返回观察**视为“事件”，并将事件划分为连续的**事件页面（event page）**。
- 把工具调用生成结束视为一次**提交（commit）**，并以此作为生命周期边界。
- 在同一页面、跨提交边界的前后两个查询窗口上分别测量“删除效果”，形成**提交转换（commit transition）**，据此判断页面是“休眠”还是“完成候选”。

### 2.2 关键技术细节
- **删除效果（Deletion Effect）**：对某一注意力头，若删除事件页面中的 token 并重新归一化剩余注意力权重，会得到一个新的注意力输出；删除前后输出向量的相对二范数变化即为删除效果。数值越大，说明该页面在当前查询窗口越重要。
- **配对查询窗口**：
  - 提交前窗口：工具调用生成结束前的最后 W 个解码查询位置；
  - 提交后窗口：返回观察合并并进入下一轮后、下一轮解码的前 W 个查询位置。
- **生命周期状态分类**：同时使用绝对删除效果和百分位排名，将页面标记为高影响/低影响，再配对判断状态：
  - 高→低：**完成候选**（可能已完成任务角色）；
  - 低→低：**休眠页**（暂时不活跃，但可能未来有用）；
  - 低→高：新激活；高→高：持续活跃；其他：不确定。
- **贪婪联合验证**：完成候选按“提交后删除效果升序、提交前删除效果降序”排序，逐个加入退休集合，但只有当所有已接受页面与该页面的**联合删除效果**仍低于阈值时才接受，避免多个小影响累积成大的注意力损坏。
- **保护待测页面**：等待提交后测量的页面（即提交前已测量、提交后尚未测量）在压缩检查点被临时保护，保护预算为总预算的固定比例；超出预算时优先保护提交前删除效果较大的页面。
- **固定预算压缩**：在压缩检查点，排除退休页、保护待测页，然后在剩余 token 中按预算选择保留索引；该索引必须同时用于键、值张量和绝对位置，以保证 RoPE 位置编码的正确性。

### 2.3 公式与算法流程（文字说明）
- 删除效果定义为：删除页面输出与原始输出的相对二范数变化，先对每个注意力头取窗口内最大值，再对所有头取最大值。
- 提交前后分别计算 `R-(E)` 和 `R+(E)`，并转化为百分位排名 `P-(E)` 和 `P+(E)`。
- 高影响/低影响由“绝对阈值 + 百分位阈值”双重条件判断，防止单一指标失真。
- 生命周期状态由配对高低状态查找表得到，只有“高→低”进入候选。
- 退休集合构造采用贪婪算法：按序尝试加入候选，只有当联合提交后删除效果满足 `R+(A∪{E}) ≤ τ_joint` 时才接受。
- 最终保留索引集合满足：包含全部受保护待测索引、排除退休页索引、总数量不超过预算 B。
- 算法按轮次执行：先解码生成，再在提交后测量形成生命周期状态、构建退休集合，最后在压缩检查点应用索引压缩。

## 七、局限性与未来工作

- **依赖工具调用作为提交点**：CommitKV 的生命周期划分建立在“工具调用结束即提交”这一假设上。对于纯对话、无工具调用或连续自由文本生成的场景，缺乏天然的提交边界，方法难以直接套用。
- **删除效果计算带来额外开销**：每个提交点前后需对候选页面重新计算删除效果，涉及多次前向计算，虽然整体仍比全缓存方案加速明显，但在压缩频率较高或页面数较多时，这部分开销可能增长。
- **超参数敏感性**：查询窗口 W、页面大小 G、保护预算比例 η、绝对阈值 τ_use、τ_dead、τ_joint 以及百分位阈值均需手工设定。论文未报告这些参数在不同任务上的敏感性分析，不同场景可能需要重新调参。
- **实验评估深度有限**：未报告多次重复运行的标准差或随机种子，主要结论基于固定配置下的单次评测；部分模型（如 GPT-OSS-20B、Phi-4-Reasonig、InternLM3-8B）的结果仅放入附录，未在正文充分讨论。
- **未来方向**：作者可考虑将生命周期思想推广到无明确提交点的通用对话，或引入可学习/自适应的“提交检测器”；也可尝试与 HeadKV、PyramidKV 等更精细的头部级压缩策略结合；此外，将生命周期感知扩展到前缀缓存或多轮智能体长期记忆管理，是值得探索的方向。

## 八、总体评价

CommitKV 是一个针对多轮 ReAct 智能体推理场景设计的 KV 缓存压缩方法，其核心创新在于用“工具调用提交”作为生命周期边界，通过跨提交窗口的删除效果变化来区分“已完成任务的信息”和“暂时休眠但未来可能有用”的信息，从而避免传统压缩方法中“当前低注意力即永久低价值”的误杀问题。该方法在多个开源模型和推理/工具密集基准上表现出色，尤其在极端低预算条件下相比现有基线有显著优势，同时带来了数倍的内存节省和端到端加速。虽然存在依赖工具结构、超参数需调优、评估细节不足等局限，但整体思想新颖、实验扎实，对智能体推理缓存管理的后续研究具有较好的启发价值。
