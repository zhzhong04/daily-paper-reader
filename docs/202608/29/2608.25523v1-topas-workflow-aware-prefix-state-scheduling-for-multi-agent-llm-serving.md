## 摘要
前缀缓存在多智能体大语言模型（LLM）服务中引入了一个基本权衡：为某个智能体保留较长的系统提示词键值（KV）缓存可加速其未来调用，但这会减少可用于批处理并发请求的GPU内存。在多阶段工作流中，现有调度器倾向于优先考虑即时前缀局部性或者整体工作流进度。然而，在共享KV缓存预算下，孤立地优化任一目标都可能通过下游延迟或频繁的前缀替换延长任务级作业完成时间（JCT）。为取得平衡，我们在此提出TOPAS，一种任务导向的前缀感知调度器，它联合决定在缓存中保留哪些智能体前缀以及调度哪些请求执行。TOPAS通过权衡每个任务最长剩余服务路径的预期缩短与下游前缀复用的近期收益，并考虑前缀移动和抢占的成本，来对候选决策后状态进行评分。还引入了任务级老化机制以防止饥饿。我们在SGLang框架中实现了TOPAS，并在三个合成DAG和两个MetaGPT软件开发工作流上评估其性能。与每个工作负载和指标下表现最佳的基线相比，TOPAS在合成工作负载上将平均/第99百分位JCT降低了最多39.8%/49.4%，在MetaGPT-SOP上将平均JCT降低了9.8%，在MetaGPT-TL上将平均/第99百分位JCT降低了22.0%/26.6%。

## Abstract
Prefix caching introduces a fundamental tradeoff in multi-agent large language model (LLM) serving: retaining a long system-prompt key-value (KV) cache for an agent accelerates future calls, yet it reduces the GPU memory available for batching concurrent requests. In multi-stage workflows, existing schedulers tend to prioritize either immediate prefix locality or overall workflow progress. However, under a shared KV cache budget, optimizing either objective in isolation can prolong tasklevel job completion time (JCT) through downstream delays or frequent prefix replacement. To strike a balance, we here propose TOPAS, a Task-Oriented Prefix-Aware Scheduler that jointly decides which agent prefixes to keep in the cache and which requests to schedule for execution. TOPAS scores candidate post-decision states by trading off the expected reduction in each task's longest remaining service path against the near-term benefit of downstream prefix reuse, accounting for the costs of prefix movement and preemption. A task-level aging mechanism is also incorporated to prevent starvation. We implement TOPAS within the SGLang framework and assess its performance on three synthetic DAGs and two MetaGPT software-development workflows. Compared with the best performing baseline for each workload and metric, TOPAS reduces the mean/p99 JCT by up to 39.8%/49.4% on the synthetic workloads, while lowering mean JCT by 9.8% on MetaGPT-SOP and mean/p99 JCT by 22.0%/26.6% on MetaGPT-TL.

## 1. 核心问题与整体含义

多智能体大语言模型（LLM）应用通过多个角色专业化智能体协作完成复杂任务，每个请求都带有智能体特有的静态前缀。在共享 GPU 显存（KV cache 预算）有限的前提下，系统需要在前缀缓存保留与并发请求批处理之间做出权衡：

- **保留长前缀** → 加速同一智能体的后续调用、消除冗余 prefill 计算，但占用大量显存、压缩批处理容量；
- **保留更多批处理容量** → 可容纳更多并发请求，但可能频繁淘汰/重载前缀，造成额外开销。

现有调度器在共享 KV 预算下存在两种极端倾向：
- **局部性优先（如 LPM）**：围绕可复用前缀聚合请求，提高批处理效率，但工作流在入口处停滞，下游阶段被饿死；
- **进度优先（如 SRPT）**：推进任务走向完成，但频繁切换智能体导致前缀反复移动、重算，有效服务容量下降。

两种孤立优化的策略都会延长任务级作业完成时间（JCT）。论文的核心问题表述为：**在受限 GPU 显存预算下，服务系统应如何协调前缀驻留（prefix residency）与请求准入，以最小化任务级 JCT？**

整体含义：论文将前缀驻留提升为**显式的工作流级调度决策**，而非请求排序和缓存淘汰的间接副产品，首次提出联合优化前缀驻留与请求准入的调度框架。

## 2. 方法论

### 2.1 问题形式化：在线前缀状态调度

- 所有任务遵循已知的 DAG G=(V,E)，任务 Ji 在时刻 τi 到达；
- 每个节点 v ∈ V 是由某个智能体执行的阶段，其所有前驱完成后才就绪；
- 在调度时刻 t，系统状态 St = (Rt, Qt）：Rt 为驻留的智能体前缀集合，Qt 为运行中的请求集合；
- 调度动作选择决策后状态 S′ = (R′，Q′)，需满足联合容量约束：

$$\sum_{a∈R'} \ell_a + \sum_{r∈Q'} d_r(t) ≤ B_t$$

### 2.2 基础转移效用

$$U_{base}(S' | S_t) = J_{admit} - J_{move} - J_{redo} - J_{revoke}$$

- **Jadmit（准入收益）**：基于任务最长剩余路径（longest remaining path）的期望缩短量来衡量，而非简单的请求服务时间。残差分布基于经验历史分布（含 ReAct 轮数）而非固定均值，允许关键路径在残差实现中动态变化；
- **Jmove（前缀移动代价）**：将前缀 KV 在 GPU 与 CPU 间转移的时间成本，按受影响任务的个数摊还；
- **Jredo（重算代价）**：被抢占请求需重建已生成 token 的 KV，按解码时间折算；
- **Jrevoke（信用撤销）**：被抢占请求此前获得的准入收益需撤销，防止"反复拿分"。

### 2.3 短期前缀复用

$$V_{reuse} = β \sum_{a∈R'} n_a(t) \cdot \frac{\mu\ell_a}{B_{swap}}$$

统计即将就绪的下游阶段数 na(t)，并用前缀重载时间量化保留该前缀的潜在收益，作为一阶前瞻（one-hop lookahead）。

### 2.4 任务级老化机制

$$g_i(t) = 1 + \rho \cdot \log\left(1 + \frac{t - τ_i}{H_{age}}\right)$$

按任务年龄加权准入收益，防止新到达任务持续抢占资源导致旧任务饥饿。

### 2.5 分层状态搜索

- 将问题拆分为**前缀集生成**与**请求分配**两层；
- 生成前缀集：代理池规模小（≤M）时全枚举；规模大时先贪心加单代理、停滞时试探双代理组合，再执行单删/交换修复（REPAIR）；
- 请求分配（GREEDY PACK）：优先保留运行中请求，按年龄加权边际收益/额外KV成本贪心准入，确保每个候选状态满足容量约束；
- 完整评分函数：

$$Score(S' | S_t) = J^{age}_{admit} - J_{move} - J_{redo} - J_{revoke} + V_{reuse}$$

在每个调度事件选择评分最高的可行状态，形成事件级贪心策略。

## 6. 主要结论与发现

1. **进度—复用矛盾是真实存在的**：交替调度不同前缀会使异构前缀共驻留，动态批容量减半（批量从 9.3 降至 4.7），完成时间扩大约 1.8–1.9 倍；
2. **纯局部性与纯进度策略均非最优**：LPM 和 SRPT 在任何度量上都不如带下游门控的简单干预，说明需要主动协调而非被动反应；
3. **合成 DAG 上**：相比每项指标的最佳基线，TOPAS 平均 JCT 降低最高 39.8%（DAG-4），p99 JCT 降低最高 49.4%（DAG-4）；
4. **MetaGPT-SOP 上**：相对于最强的平均 JCT 基线 SPF，TOPAS 降低平均/p99 JCT 9.8%/4.5%，吞吐量提升 6.7%；
5. **MetaGPT-TL 上**：中央前缀的反复复用创造更多驻留控制空间，平均/p99 JCT 相对最佳基线分别降低 22.0%/26.6%；
6. **消融验证**：完整 TOPAS 相对无复用/无老化的变体，平均 JCT 额外降低 44.9–51.0%，p99 额外降低 44.2–48.5%，说明未来复用预估和老化机制均不可缺失。

## 8. 不足与局限

1. **实验规模有限**：所有实验在单张 A100 上运行，未评估多卡、分布式、跨节点场景下的有效性；
2. **模型单一**：仅测试 Qwen2.5-32B-Instruct，未验证方法在多模型、不同架构、不同量级模型间的泛化性；
3. **工作负载覆盖有限**：合成 DAG 结构相对简单；MetaGPT 虽为真实应用，但仅两个工作流，且到达模式采用泊松过程，缺乏真实生产中的突发性、周期性到达模式验证；
4. **统计严谨性不足**：未报告多次独立运行的方差/置信区间/显著性检验，对结果可靠性有影响；
5. **超参敏感性未充分探索**：β、ρ、Hage、M、K 等关键超参的取值对性能的影响缺乏系统消融；
6. **在线学习与冷启动问题**：进度分布依赖历史经验数据，在冷启动（无历史阶段服务数据）时其准确性可能下降；工具等待与 ReAct 轮数的不确定性虽被纳入就绪时间，但其对残差分布的影响未深入分析；
7. **无显式理论保证**：算法为事件级贪心策略，缺少竞争比或最优性界的理论分析，收敛性和稳定性结论有限。
