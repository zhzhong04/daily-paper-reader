## 摘要
任务完成是评估上下文压缩的标准指标，但它并不完整：压缩可能增加智能体的交互成本，迫使它重新获取被丢弃的状态，而完成度在统计上保持不变。我们引入了一种受控运行时测量协议，用于测量有界时域工具使用智能体的重新获取成本。该智能体在固定的24回合时域内于确定性规划环境中行动。我们改变压缩严重程度，比较丢弃操作符与保留事实的操作符，通过受控oracle干预恢复丢弃的状态，并将工具调用分解为检索和执行。我们在两种任务机制下评估了三个模型。在所有六种模型-机制比较中，检索调用均增加，且几乎占所有新增交互；其中五项在Holm校正后仍显著。在预设的5倍比较点，任何单元格中的完成度变化均不显著。DeepSeek仅在10倍压缩时表现出显著的完成度下降。GPT-5.5是最清晰的案例：完成度从80%变为85%（p=1.0），而检索从21.0次增加到63.9次（p=0.002）。保留干预进一步区分了状态数量、状态类型和内容有效性。随机选择与离线事后oracle相当，而将保留的D状态替换为语义无关内容会使检索增加57%（p<0.001），且完成度无显著变化。在第二个环境ALFWorld中，滑动压缩未产生检索激增，表明重新获取特征依赖于环境，而非缩短上下文的固有属性。总体而言，当与执行相关的状态缺失且必须重新获取时，压缩可能带来隐藏的交互成本，而仅靠完成度可能无法暴露这些成本。

## Abstract
Task completion is the standard metric for evaluating context compression, yet it is incomplete: compression can increase an agent's interaction cost by forcing it to reacquire dropped state while leaving completion statistically unchanged.   We introduce a controlled runtime measurement protocol for reacquisition cost in a bounded-horizon tool-using agent. The agent acts in a deterministic planning environment under a fixed 24-turn horizon. We vary compression severity, compare a dropping operator with a fact-preserving operator, restore dropped state through controlled oracle interventions, and decompose tool calls into retrieval and execution. We evaluate three models across two task regimes.   Retrieval calls increase in all six model-regime comparisons and account for almost all added interaction; five of six remain significant after Holm correction. At the prespecified 5x comparison point, completion changes are not significant in any cell. DeepSeek shows a significant completion drop only at 10x compression. GPT-5.5 is the clearest case: completion changes from 80% to 85% (p = 1.0) while retrieval increases from 21.0 to 63.9 calls (p = .002).   Retention interventions further separate state quantity, state type, and content validity. Random selection is comparable to an offline hindsight oracle, while replacing retained D-state with semantically irrelevant content increases retrieval by 57% (p < .001) without a significant completion change. In a second environment, ALFWorld, sliding compression produces no retrieval surge, showing that the reacquisition signature is environment-dependent rather than intrinsic to shortening context.   Overall, compression can impose hidden interaction costs when execution-relevant state becomes absent and must be reacquired, while completion alone may not expose those costs.

## 1. 论文的核心问题与整体含义

- **研究动机**：长时程智能体（long-horizon agent）的轨迹会迅速超出上下文窗口，现代运行时普遍依赖上下文压缩（如摘要、滑动窗口、检索过滤）来管理上下文。现有评估以**任务完成率**作为压缩成功与否的标准指标，但该指标存在盲区：压缩可能迫使智能体重新获取已被丢弃的执行相关状态，产生**额外交互成本**（interaction cost），而完成率在统计上可能完全不变。
- **核心问题**：论文提出一个被现有文献忽略的第五类问题——**当状态真正丢失时，智能体重新获取该状态需要付出多大代价？标准的任务完成指标能否暴露这一代价？**
- **整体含义**：压缩并非仅仅因为信息丢失而昂贵，而是当被丢弃的执行相关状态必须在有界预算下通过额外交互重新获取时才变得昂贵。任务完成率与交互成本是两个正交的评估维度，仅看完成率可能导致对压缩策略的严重误判。论文不主张压缩普遍有害，而是通过受控实验揭示完成率中心评估（completion-centric evaluation）的**评估盲区**。

## 2. 论文提出的方法论

- **核心思路**：提出一种受控运行时测量协议（controlled runtime measurement protocol），在固定交互预算下隔离压缩导致的**重获取成本**（reacquisition cost），并将工具调用分解为两类：
  - **检索调用（retrieval）**：重新获取外部状态（对应重获取成本）；
  - **执行调用（execution）**：执行任务的实际操作（对应任务工作）。
- **形式化定义**（Proposition 1，非可辨识性）：
  - 评估结果定义为三元组 \(Y(m) = (Q(m), C_R(m), C_E(m))\)，其中 \(Q\) 为完成率，\(C_R\) 为检索调用数，\(C_E\) 为执行调用数。
  - 完成率投影 \(\pi_Q(Y) = Q\) 丢弃了交互成本维度，因此**不同交互成本的状态可以映射到相同完成率**——完成率评估在结构上无法辨识交互成本。
  - 论文用 GPT-5.5 的实证案例实现这一非可辨识性：完成率 80% → 85%（p = 1.0），而检索调用 21.0 → 63.9（p = .002，Cohen's d = 2.07）。
- **上下文条件**：
  - **Full**：完整轨迹基线；
  - **Sliding**：滑动窗口，按 token 预算（压缩比 r = 1.7×/2.5×/5×/10×）贪心保留最近回合，直接丢弃早期回合（真实删除，而非摘要）；
  - **Summary**：相同预算下用确定性事实摘要替换早期回合（提取式，仅保留观测事实、丢弃推理文本）；
  - **Oracle**：在滑动压缩基础上注入被丢弃的具体状态字符串，分为两类可恢复性投影——**D\*（外部可查询状态**：任务图、资源占用，原则上可通过更多工具调用恢复）和 **R\*（历史依赖状态**：已揭示的约束、失败计数、持有资源，无法由任何单一公共查询恢复）。
- **保留干预（retention interventions）作为因果探针**：在固定压缩点（第 10 回合）提取观测状态原子，按不同选择策略生成摘要前缀，预算 \(B \in \{265, 100, 50\}\) tokens。策略包括：RAR-D（仅保留 D 原子）、RAR-R（仅保留 R 原子）、RAR-All（保留全部）、RAR-TypeAware（R 优先）、Random（随机）、Recent（最近观测）、Hindsight（离线事后最优参考）、D-Irrelevant（D 内容替换为语义无关的虚构状态）。
- **统计方法**：每条件 10 个种子（每种子 10 个任务），逐种子配对（Wilcoxon 符号秩检验 + bootstrap 95% CI）；primary 族为六个检索比较（3 模型 × 2 机制），采用 Holm-Bonferroni 校正。

## 3. 实验设计

- **主环境（IRBench）**：自建的确定性项目规划环境，10 个任务 + 少量容量为 1 的资源，任务携带隐藏执行约束（排序规则、资源持有与释放时间、失败直至成功计数）。智能体有 4 个工具：get task info、check dependency、query resource（均为检索类）和 execute（执行类）。固定 24 回合交互时域。
- **两种任务机制**：
  - **High-IR**：约束仅在执行中揭示，丢失后难以重新推导；
  - **Low-IR**：多跳依赖链，但可从公共任务图重新推导。
- **模型**：DeepSeek（deepseek-v4-flash，完整严重度扫描）、Qwen（qwen3.7-plus）和 GPT-5.5（固定 5× 比率），温度 0.3，无扩展思考模式。
- **对比方法（操作符对比）**：同一 5× 预算下对比 Sliding（丢弃）与 Summary（事实保留）两种压缩操作符。
- **外部环境边界（ALFWorld）**：基于 TextWorld 引擎的家居指令跟随环境，18 个任务覆盖全部 6 种任务类型，每任务 5 个配对种子（共 180 次运行），将 look/examine/inventory 计为检索类动作，take/put/clean 等计为执行类动作。
- **保留干预矩阵**：DeepSeek High 机制、20 个配对种子、540 次运行（主矩阵 500 次 + D-Irrelevant 对照 40 次）；GPT-5.5 子集复制（High 机制、B ∈ {265, 100}、10 个配对种子）。

## 6. 论文的主要结论与发现

- **检索成本普遍上升而完成率不变**：在全部六个模型-机制比较中检索调用均增加（约 2–3×），Holm 校正后 5/6 保持显著；执行调用几乎不变（5/6 保持稳定）；完成率变化在任何单元格均不显著（全部 p ≥ 0.125）。
- **GPT-5.5 是最尖锐的案例**：完成率统计不变（80% → 85%，p = 1.0，CI [−6, +21] pp 含零），而检索调用约三倍化（+42.9，p = .002，d = 2.07）。
- **成本信号比完成率信号更早出现**：DeepSeek 的检索成本在 5× 即显著（p = .002），而完成率仅在 10× 才显著下降（−17pp，p = .016）。若只测 5× 点的完成率，会误判压缩无损失。
- **操作符比压缩比更重要**：同一 5× 预算下，保留事实的提取式摘要接近无损（完成率 83% ≈ 80%，工具 39.0 ≈ 37.4），而滑动窗口降低完成率并使检索翻三倍（55.1 vs 19.0）。
- **Oracle 恢复确认因果机制**：注入 D\*（外部可查询状态）移除了约一半检索成本（72.9 → 35.8 工具调用，−51%）并恢复大部分完成率差距（66% → 80%）；注入 R\*（历史依赖状态）改善完成率（+12pp）但检索成本几乎不变——说明 R 丢失引发对 D 的防御性重复查询。
- **保留内容有效性比细粒度选择更重要**：随机选择与离线 hindsight oracle 表现相当（−22.1% vs −22.4%，配对差 +0.10，CI [−2.3, +2.3]）；而将 D 内容替换为语义无关状态使检索增加 57%（p < 0.001）、完成率不变（p = 0.41）——完成率对成本变化及其行为后果双重失明。
- **内容效应具有预算门控**：仅在摘要占据上下文窗口主要份额时（B = 265）可见，紧凑预算下（B = 100）消失。
- **跨模型复制与模型特异性**：内容效应的方向在 GPT-5.5 上可复制（B = 265 时真实 D < 无关 D < Sliding），但幅度和行为表达（GPT-5.5 减少执行调用而非增加检索）是模型特定的。
- **环境决定性边界**：ALFWorld 中相同滑动压缩未产生检索激增（配对 Δ = −0.13，对称分布）——重获取签名不是压缩的固有属性，而是取决于被丢弃的执行相关状态能否通过可用交互动作直接重观测。

## 7. 优点

- **核心度量创新**：将交互成本分解为检索（状态重获取）与执行（任务工作），使压缩成本可直接观测、可机制归因，优于完成率与 token 计数的粗粒度度量。
- **受控因果推理**：通过 oracle 注入设计将被丢弃状态的可用性作为可操纵变量（而非被动观察），将相关性升级为因果验证。
- **操作符对比公平**：Sliding 与 Summary 共享相同 token 预算，隔离"丢弃 vs 保留事实"的因果效应；提取式摘要排除了摘要器质量混杂。
- **保留干预矩阵精细**：区分"保留多少"（预算扫描）、"保留哪些"（8 种选择策略）、"内容是否有效"（D-Irrelevant 对照），建立从数量到质量的完整因果层级。D-Irrelevant 设计精巧——仅替换 D 原子而固定格式、位置、预算和 R 内容。
- **边界刻画严谨**：通过三模型、两机制、两环境确立了成本信号的边界条件（模型依赖、机制依赖、环境依赖），不做超出数据的泛化主张。
- **统计规范**：预注册 primary 比较、Holm-Bonferroni 校正、逐种子配对、CIs 与效应量报告，透明报告 post-hoc 诊断。
- **对实践的指导性**：给出可操作的诊断清单，指出运行时设计者应关注"哪些执行相关状态被丢弃时需要重获取"，而非"哪个压缩比安全"。

## 8. 不足与局限

- **环境覆盖面有限**：核心机制在合成约束规划环境（IRBench）中测量，ALFWorld 探针的完成率受天花板限制（只有最简单任务类型可靠可解）；未在 WebArena、SWE-bench 等部分可观测长时程环境中验证，成本幅度的迁移性不明。
- **模型样本有限**：仅三个模型家族，跨模型比较是描述性而非配对；未验证更广泛模型上的模式。
- **单压缩比矩阵**：三模型矩阵仅在 5× 固定点比较（API 预算限制），只有 DeepSeek 有完整严重度扫描，限制了跨模型在更激进压缩比下的完成率比较精度。
- **24 回合时域是设计选择**：不同时域可能移动成本→失败的转换点；论文报告该转换是机制依赖而非普遍的，但未做时域扫描。
- **工具调用作为成本代理**：不是墙钟延迟或货币成本（这些是 provider 特定的），轮次/调用计数是"预算货币"而非通用成本度量。
- **分解是工具层面的**：按 schema（检索 vs 执行）而非语义意图归因；论文未做逐消息意图分析。由于每轮工具日志未存储，无法进行时间动态分析（检索爆发何时发生）。
- **选择 null 的跨模型验证缺失**：Random ≈ Hindsight 仅在 DeepSeek 上测量，未在 GPT-5.5 上重新运行选择对照，因此选择 null 的普适性未知。
- **D-Irrelevant 的机制区分受限**：虚构的域外实体可能同时触发"语义无关检测"和"内部不一致验证"，两种读取都支持"内容有效负载"的说法，但无法区分；"真实实体上的错误值"对照留待未来工作。
- **统计效力**：10 个种子的完成率侧统计效力有限（GPT-5.5 的完成率 CI [−6, +21] pp 很宽）；完成率侧无显著结果不等价于等价性。种子级相关性分析仅 GPT-5.5 High 达到名义显著（ρ = −0.64, p = .045），应谨慎解读。
- **提取式摘要是设计对照而非通用摘要器**：其在 5× 的近无损是该具体事实保留摘要的属性，不能推广为任意 LLM 摘要器无损。
