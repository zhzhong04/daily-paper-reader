## 摘要
多智能体AI工作流不仅受限于模型质量，还受限于Token成本、延迟和上下文窗口质量。本文提出了一个面向实践者的Token优化与上下文窗口管理框架，该框架基于内部生产仪表盘，该仪表盘利用大语言模型从会议、电子邮件和聊天中提取结构化工作项，并在各工作流之间路由摘要。本文描述了六种模式：上下文分层、一次获取/本地处理架构、模式精简提示、Token感知的回退链、语义缓存以及智能体间通信压缩。在生产环境中，这些模式将实测冷加载延迟从约3.5-10.5分钟的操作基线降至61-116秒（六次计时运行），并估计减少了60-70%的Token。本文还报告了一项受控的上下文组成研究：在11种模型配置下进行了2,420次验证性试验，使用661个匿名工作场所项目进行相关性评分。在提示中保持固定的十个项目，将一些高相关项目替换为同域低相关项目，相比于仅包含高相关项目，提高了模型对目标项目的相关性评分一致性；我们将此称为相关性对比上下文。在全部11种配置的配对分析中，50:50信号/噪声条件相对于100%条件将相关性准确率提高了+0.077（朴素95%置信区间[+0.056, +0.098]，Cohen's d = 0.49，Holm校正p < .001，n = 220）。这些单元并非独立；按九个模型家族计算，效应量为+0.084（95%区间[+0.064, +0.103]），作为语料库内的描述性比较而非总体推断进行报告。一项Fusion-of-N后续研究发现，学习式综合并未胜过项目ID的机械集合并集。本文的贡献在于模型研究与生产级智能体实践之间的一个可度量的工程层：可复现的模式和评估方法，以实现更快、更便宜、更可靠的工作流。

## Abstract
Multi-agent AI workflows are limited not only by model quality but by token cost, latency, and context-window quality. This paper presents a practitioner framework for token optimization and context-window management, grounded in an internal production dashboard that extracts structured work items from meetings, email, and chat with LLMs and routes summaries across workstreams. Six patterns are described: context stratification, fetch-once/process-locally architecture, schema-contracted prompts, token-aware fallback chains, semantic caching, and inter-agent communication compression. In production they cut measured cold-load latency to 61-116 seconds (six timed runs) from an operational baseline of roughly 3.5-10.5 minutes, with an estimated 60-70% token reduction. It also reports a controlled context-composition study: 2,420 confirmatory trials across 11 model configurations, using 661 anonymized workplace items scored for relevance. Holding the prompt at a fixed ten items, replacing some high-relevance items with same-domain low-relevance items improves the model's relevance-score concordance on the target items, versus high-relevance items only; we call this relevance-contrast context. In the all-11 paired analysis, the 50:50 signal/noise condition improved relevance accuracy by +0.077 over the 100% condition (naive 95% CI [+0.056, +0.098], Cohen's d = 0.49, Holm-adjusted p < .001, n = 220). These cells are not independent; by the nine model families the effect is +0.084 (95% interval [+0.064, +0.103]), reported as a within-corpus descriptive comparison, not a population inference. A Fusion-of-N follow-up found that learned synthesis did not beat the mechanical set union of item IDs. The contribution is a measured engineering layer between model research and production agent practice: repeatable patterns and evaluation methods for faster, cheaper, more reliable workflows.

## 2. 论文提出的方法论

### 2.1 六种 Token 优化模式

| 模式 | 解决的问题 | 实施方式 | 观察效果 |
|---|---|---|---|
| **上下文分层** | 模型接收所有类型的上下文 | 按数据类型路由到对应的提取调用 | 每次调用的输入约 30K → 约 3K Token |
| **一次获取、本地处理** | 子智能体重复抓取相同源数据 | 只获取一次会议/邮件/聊天，之后本地匹配 | API 调用从 7-21 次降到 3 次 |
| **模式精简提示** | 模型在散文、废话、格式上浪费输出 Token | 强制紧凑 JSON 契约 + 显式空结果约定 | 输出 Token 降低、解析可靠性提高 |
| **Token 感知回退链** | 速率限制导致整条管线重试 | 只重试提取阶段，使用验证过的回退模型，不重跑数据获取 | 可用性提高，避免代价高昂的重复抓取 |
| **语义缓存** | 重复加载发送相同上下文 | 缓存完整管线结果，验证请求参数匹配 | 重复加载近瞬时完成，零 LLM Token |
| **智能体间通信压缩** | 智能体之间传递冗长的人类可读文本 | 用模式化机器消息替代散文交接 | 包装 Token 估计减少 40-60% |

### 2.2 统一原则与核心发现

- 统一原则：**发送更少的上下文，但确保结构更优、时机更佳**。核心不是向模型隐藏信息，而是保证每次调用只接收完成该步骤所需的信息。
- **上下文窗口管理作为工程纪律**：作者类比过去的内存管理和状态管理，提出六个核心技能——上下文修剪、信息密度、记忆卸载、并行发现、上下文污染检测、上下文校准。
- **相关性对比上下文（Relevance-Contrast Context）**：核心反直觉发现——在固定十项目的提示中，将部分高相关项目替换为同域低相关项目，反而能提高模型对目标项目的相关性评分准确性。低相关项目帮助模型校准“什么才算相关”的阈值。可能的机制是：当所有项目都相关时，模型缺乏“不重要内容”的参照，倾向于高估相关性。需注意，这不是通用结论——不是任意无关内容都有帮助，而是**同域**低相关内容起作用。

## 3. 实验设计

### 3.1 生产管线分析

- **场景**：内部生产仪表盘，跟踪多个并行工程工作流；输入为近期会议、邮件线程和聊天线程，提取结构化工作项并路由到各工作流、生成状态摘要。
- **数据**：2026 年 2 月记录的 25 次管线运行，其中 6 次具有实测耗时。
- **评估指标**：冷加载延迟（实测）、Token 使用量（历史估计，非精确遥测）、数据获取调用次数、解析成功率（定性）。

### 3.2 受控上下文组合实验

- **数据集**：661 条匿名沟通项目：15 份会议记录、627 封邮件线程、19 条聊天线程，来自一位知识工作者单周的全渠道沟通流。全部由作者按 0-3 四级相关度评分：3＝决策/行动项/阻塞项/承诺，2＝相关状态/上下文，1＝边缘提及，0＝与工作无关。评分 2-3 视为信号，0 视为噪声，评分 1 排除以锐化对比（55 信号 / 595 噪声 / 11 排除）。
- **模型配置**：11 种配置（GPT-4o、GPT-5.4、GPT-5.5、DeepSeek-V3.2、Grok-4-20、Kimi-K2.6、Llama-3.3-70B、Gemini-3.1-Pro-Preview、Claude Opus 4.7 三个推理强度档位）。
- **提示结构**：每个提示固定包含 10 个项目。比例条件：100%、80%、50%、30%、10% 信号；位置条件：6 种排列（信号在开头/中间/末尾/三种散布方式），保持 50:50 比例。
- **主指标**：RelAcc（相关性准确率）——模型 0-3 评分与人工标注的一致程度，完美匹配给满分、相邻分数给部分分。辅助指标：事实类型召回率、精确率、JSON 解析成功率。
- **预指定对比（5 个）**：C1 检验 50:50 混合是否优于 100% 信号；C2 检验随噪声增加是否存在正向趋势；C3 检验散布是否优于连续放置；C4 检验中间位置是否更差；C5 检验末尾是否优于开头。使用 Holm 校正控制多重比较。

### 3.3 Fusion-of-N 后续实验

- **设置**：DeepSeek-V3.2 生成 5 次独立提取样本；比较单一采样、best-of-N 评判、LLM 融合与提取项目 ID 的集合并集。
- **范围**：仅使用一个生成/评判模型（DeepSeek-V3.2 默认设置）、一个语料库、自我融合设置（生成器与融合器相同）。

## 6. 论文的主要结论与发现

1. **相关性对比上下文效应（主发现）**：50:50 信号/噪声相对于 100% 信号，RelAcc 提升 +0.077（95% CI [+0.056, +0.098]，Cohen's d = 0.49，Holm 校正 p < .001）。优势区域为 30-50% 信号（即 50-70% 同域噪声），呈现宽平台而非单点最优。所有 11 种配置方向均为正；按 9 个模型家族汇总为 +0.084（95% 区间 [+0.064, +0.103]），按试验块聚类为 [+0.032, +0.122]。效应集中在低信号密度的邮件来源（+0.119），在会议和聊天中近零。
2. **位置效应较小且依赖模型**：提示末尾优于开头 +0.022，但 Holm 校正后不显著（p_adj = .098）；10 项短窗口下未检测到“中间迷失”效应。推测"中间迷失"在更长窗口中会出现，位置操作应scale-dependent。
3. **域过滤是质量控制杠杆**：按内容类型分别处理（会议 vs. 邮件 vs. 聊天）可使 RelAcc 提升约 +0.16（探索性结果）。原因不是语义而是组合性的：会议 73.3% 高信号 vs. 邮件仅 5.1%。
4. **推理预算与校准效应的关系（探索性）**：Claude Opus 4.7 的校准效应随推理预算增加而下降（+0.078 → +0.050 → +0.013），而 GPT-5.5 呈相反方向。两组族内趋势均不显著，作者明确不将其视为真实效应。
5. **Fusion-of-N：学习式融合未胜过机械集合并集**：集合并集达到召回率天花板，而融合器倾向于丢弃仅在单个样本中出现的低支持度真阳性。对面向召回率的提取任务，先测试集合并集，仅在融合器能超越该基线时再付出额外计算。

## 7. 优点

- **实践导向强**：每项优化模式都对应一个生产实现和观察到的成本/延迟/质量效果，不是纸面理论。
- **发现具有反直觉价值**：揭示“同域低相关上下文有助于校准相关性阈值”，与直觉和部分既有研究（如 Distractor 有损推理）形成张力，且区分了“同域噪声”与“任意不相关干扰”。
- **多模型验证**：11 种模型配置覆盖 OpenAI、Anthropic、Google、DeepSeek、Grok、Kimi、Llama 等多个家族的旗舰模型，增强结果广度。
- **统计处理诚实且严谨**：主动指出 220 个单元不独立，报告 9 个模型家族作为分析单位的效应，明确标注描述性对比而非总体推断；附上匹配项敏感性、逐模型方向和备选指标重算。
- **复现验证**：对修正后语料库进行完整两臂复现，且公开报告修正后的效应略小（−0.008），未选择性地隐藏不利方向的数据。
- **边界声明清晰**：指出并非任意噪声都有帮助、推理预算交互只是探索性假设、Fusion-of-N 结论不普遍化到所有聚合任务。
- **提供了可落地的工具**：随论文发布 `context_arranger.py` 参考实现（MIT 许可，纯 Python 标准库，无外部依赖）。

## 8. 不足与局限

- **数据范围狭窄**：单一知识工作者、单一领域、单周沟通流；结论可能无法推广到其他沟通风格、工作者或领域。
- **单标注者偏差风险**：所有人工相关性分数均由作者本人标注；虽通过固定标签跨条件降低了标注变动的影响，但依然存在主观性风险。
- **历史数据缺乏遥测**：生产分析的 Token 计数是字符数估算而非精确测量；优化的延迟对比中，基线（3.5-10.5 分钟）是操作估计，未经过实时测量。
- **嵌套信号子集**：比例条件的设计导致信号项目嵌套（100% 条件包含 50:50 条件的信号项），匹配项敏感性分析缓解但未完全解决此问题。
- **统计推断边界**：9 个模型家族不足以支持跨总体推断，所有效应应理解为有限语料库内的描述性结果。两臂复现的微小负差未经过严格显著性检验，也未预先指定方向。
- **数据污染残留**：聊天来源中存在导出元数据、无表头聊天和重复内容组，虽通过排除分析显示未驱动结果，但未对重建语料库进行完全重新生成式的稳健性验证（仅做了一次修正语料复现）。
- **Fusion-of-N 范围极窄**：单一模型、单一语料、自我融合设置（生成器与判断器相同，反而使“集合并集胜出”的结论更保守）；不适用于所有聚合任务。
- **位置实验统计功效不足**：未能在 10 项规模检测到中间放置的惩罚，低功效意味着可能漏检小效应。
- **主要指标局限性**：RelAcc 是任务特定的、信号项聚焦的指标，不能直接与标准基准准确率或精确率/召回率比较；模型与人类的 Spearman 相关仅为 +0.48。

## 9. 综合评述

总体而言，这是一篇**工程实践导向的、方法论自洽**的研究。其最大贡献不在单个惊人发现，而在于将“上下文窗口管理”提升为一等工程学科地位的系统化尝试，提供了可复用的模式目录、评估指标框架和诚实的结果披露。核心的反直觉发现（同域噪声有助于校准）和 Fusion-of-N 的“保守基线优先”结论都具有实际部署价值。但作为独立研究，其数据广度、标注深度和统计推断边界决定了它更适合被定位为一篇“模型多样、足够可信的语料库内案例研究”，而非普适性定律——作者本人也明确接受这一限定。
