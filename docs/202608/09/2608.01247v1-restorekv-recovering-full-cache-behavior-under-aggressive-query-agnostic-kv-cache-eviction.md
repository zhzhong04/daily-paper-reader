## 摘要
查询无关的KV缓存驱逐会一次性压缩上下文，并将生成的缓存用于任意后续查询，但在预算紧张时性能可能急剧下降。现有方法主要改进保留哪些原始KV对。我们提出了RestoreKV，通过在同一总KV预算下的学习式恢复来补充这种基于选择的方法。我们的关键见解是，虽然驱逐造成的信息丢失是上下文特定的，但生成其紧凑补充的机制可以跨上下文共享。在上下文预填充后，几个恢复令牌在单次LoRA适配过程中关注完整的KV缓存，生成一个紧凑、上下文条件的恢复缓存。基础重要性评分器和驱逐规则保持不变，并且适配器在后续所有查询和解码中均被禁用。RestoreKV通过从冻结的全缓存模型进行参数高效的自蒸馏来训练，仅优化了0.4%的参数，且无需任务特定调优。在四个骨干模型和四个长上下文基准上，RestoreKV显著减少了压缩引起的性能下降。在Qwen3-4B上，它在五种基础驱逐方法中改善了60个配对、预算匹配设置中的59个；在5%预算下，它将RULER-4K上的KVzip从38.2提高到73.2。应用于KVzip+时，RestoreKV在KVPress基准的16×压缩下达到86.4的RULER准确率，同时在32K上下文评估中增加了不到0.5%的一次性缓存构建开销。我们的项目页面可在 https://paper.pnu-cvsp.com/RestoreKV/ 获取。

## Abstract
Query-agnostic KV cache eviction compresses a context once and reuses the resulting cache for arbitrary future queries, but performance can collapse under tight budgets. Existing methods primarily improve which original KV pairs are retained. We introduce RestoreKV, which complements this selection-based formulation with learned restoration under the same total KV budget. Our key insight is that, although the information lost through eviction is context-specific, the mechanism for generating its compact complement can be shared across contexts. After context prefill, a few restore tokens attend to the full KV cache in a single LoRA-adapted pass, generating a compact, context-conditioned restore cache. The base importance scorer and eviction rule remain unchanged, and the adapters are disabled for all subsequent queries and decoding. RestoreKV is trained through parameter-efficient self-distillation from the frozen full-cache model, optimizing only $0.4\%$ of the parameters and requiring no task-specific tuning. Across four backbones and four long-context benchmarks, RestoreKV substantially reduces compression-induced degradation. On Qwen3-4B, it improves 59 of 60 paired, budget-matched settings across five base eviction methods; at a $5\%$ budget, it raises KVzip from $38.2$ to $73.2$ on RULER-4K. Applied to KVzip+, RestoreKV reaches $86.4$ RULER accuracy at $16\times$ compression on the KVPress Benchmark, while adding less than $0.5\%$ one-time cache-construction overhead in a 32K-context evaluation. Our project page is available at https://paper.pnu-cvsp.com/RestoreKV/

# 论文总结：RestoreKV

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：大语言模型依赖长上下文，但 KV 缓存随序列长度线性增长。KV 缓存驱逐通过只保留部分 KV 对来降低推理成本。
- **研究对象**：**查询无关（query-agnostic）驱逐**——上下文在预填充时压缩一次，生成的缓存可被任意后续查询复用。
- **核心问题**：现有查询无关驱逐方法都遵循"选择更好的原始 KV 对子集"这一范式，但**仅靠改进保留哪些 KV 对，无法在激进压缩（如 5% 预算）下避免性能急剧下降**。全缓存模型与压缩模型之间的差距在预算收紧时迅速拉大。
- **论文主张**：虽然被驱逐信息的内容因上下文而异，但**生成"信息丢失的紧凑补充"的机制可以跨上下文共享**。因此，可以在选择之外引入一个互补的"学习式恢复"维度——即生成少量上下文条件的恢复状态，而非仅从原始缓存中挑选。

## 2. 方法论：RestoreKV

**核心思想**：在保持基础重要性评分器与驱逐规则不变、且总 KV 预算不变的前提下，用少量"恢复令牌"从全缓存中蒸馏出上下文条件的紧凑"恢复缓存"，弥补驱逐造成的信息损失。

**关键步骤（推理流程）**：

1. **上下文预填充**：得到完整 KV 缓存 C（T 个位置、L 层、H 个 KV 头）。
2. **恢复缓存生成**：在上下文后追加 n 个可学习的恢复令牌（默认 n=8），在**单次 LoRA 适配前向传播**中因果地关注完整 KV 缓存，生成上下文条件的恢复缓存 C_res，大小 = nLH 个 KV 对。
3. **预算匹配组合**：
   - 总预算 B = ⌊rTLH⌋；
   - 恢复缓存占用 nLH 个槽位；
   - 由基础驱逐器从原始上下文中选出 B − nLH 个 KV 对；
   - 两者拼接构成最终缓存，缓存总量仍为 B，与未加恢复机制的基础方法完全一致。
4. **后续推理**：LoRA 适配器在恢复缓存生成后**立即关闭**，所有后续查询处理与解码均使用原始冻结骨干模型，不增加解码期开销。

**训练方式（离线自蒸馏）**：

- 使用冻结的全缓存模型作为教师，恢复缓存学生模型与其在相同上下文-查询-答案上的输出分布对齐；
- 损失函数为对称 KL 散度（对答案 token 取平均）；
- 仅训练恢复令牌嵌入和 LoRA 适配器，约占 Qwen3-4B 参数的 **0.4%**；
- 训练时从 U(0.025, 0.25) 均匀采样 KV 预算比，使单个恢复机制支持多种预算水平；
- 无需任务特定微调。

**与现有方法的区别**：不像 KV-Distill（改写选中表示）或 Cartridges（每上下文独立优化）那样替换或重写大部分缓存；RestoreKV 保留大多数原始选中的 KV 对，只学习一个小的补充，且无逐上下文优化或无生成期重建。

## 6. 主要结论与发现

1. **一致且显著的性能恢复**：在四个骨干、四个基准、五种驱逐方法上，RestoreKV 均一致缩小与全缓存性能的差距，预算越激进收益越大。例：Qwen3-4B、5% 预算下 RULER-4K 上 KVzip 从 38.2 提升到 73.2（+35.0 点）；KVzip+ 从 51.6 到 70.7。
2. **即插即用兼容性**：对 KVzip、KVzip+、ContrastKV、SnapKV、H₂O 五种不同机制均有效，说明收益不依赖特定选择策略；也适用于学习型评分器 Fast KVzip（16× 压缩下从 46.7 恢复到 79.3）。
3. **恢复来源的归因**：注意力侧 LoRA 适配（q/k/v 投影）是主要贡献者——固定嵌入 + LoRA 即可达到 71.9，而仅学习嵌入只到 42.1；全上下文条件化提供额外 8.8 点收益（64.4 → 73.2）。
4. **帮助机制**：RestoreKV 部分恢复了被驱逐方法压制的上下文注意力（平均注意力质量从 0.56% 恢复到 1.30%，逐层 KL 散度从 0.198 降至 0.167），预测分布也更接近全缓存模型。
5. **开销可忽略**：一次性缓存构建开销 <0.5% 延迟和 0.4% 内存；推理期 KV 内存与解码成本与基础方法完全一致。

**总体评价**：RestoreKV 的价值在于将查询无关 KV 压缩从"如何选"的单一维度，拓展到"选 + 学"的双维度框架。它用一个极其轻量的附加组件（0.4% 参数、单 GPU 两小时训练、推理期几乎零开销），在严格预算匹配的前提下，系统性地缩小了激进压缩下与全缓存模型之间的性能差距。其研究设计尤为值得称道——通过预算匹配、组件消融、RoPE 偏移控制、驱逐器不匹配检验、训练种子敏感性等一系列对照实验，论文逐一排除了"嵌入记忆"、"位置偏移"、"额外上下文访问"等潜在混淆因素，使"恢复缓存确实在补偿驱逐损失"这一结论具有较强的因果可信度。

**适用场景**：在需要以极低 KV 预算（5%–10%）服务长上下文、且允许一次性预填充阶段付出少量额外计算的应用中，RestoreKV 表现出很强的实用性；其即插即用特性也使其易于叠加在已有的成熟驱逐器（如 KVzip、SnapKV）之上，而无需改动既有推理管线。

**注意事项**：对于频繁更换驱逐器的系统，需注意恢复机制与驱逐器的耦合性——每换一个驱逐器就需要重新训练一次恢复组件，跨驱逐器迁移收益有限；对于低于 2.5% 的极端预算或远超 100K 的上下文，其收益边界仍需进一步验证。

**一句话总结**：RestoreKV 以"选择之外的补充恢复"这一简洁而新颖的视角，为查询无关 KV 缓存压缩提供了一条与既有方法正交、工程友好且经得起推敲的改进路径，是该方向上值得关注的工作。
