## 摘要
LLM推理已成为一种全球规模的异构工作负载，涵盖代理、检索、工具使用、代码执行和多模态推理。这些工作负载天然能够从重叠输入中实现上下文复用，从而为存储和复用上下文的KV缓存而非重新计算创造了重大机遇。然而，模型侧缩小KV缓存和系统侧降低计算、存储及传输成本的进展，在传统云边界内独立演变。我们认为，未来的推理基础设施应允许在云和数据中心之间解耦计算与KV缓存存储。网络成为一种主动的分发渠道；带宽、延迟和定价直接决定KV缓存的管理方式。我们提出了一个KV缓存互联网的愿景，将KV缓存管理作为内容分发系统运作。在这一视角下，KV缓存的存储与重计算决策由模型、基础设施和应用指标共同驱动，以实现自适应的、内容驱动的决策，从而最小化延迟和成本。

## Abstract
LLM inference has become a global-scale, heterogeneous workload spanning agents, retrieval, tool-use, code execution and multi-modal reasoning. These workloads naturally enable context reuse from overlapping inputs, creating a major opportunity to store and reuse the contexts' KV Caches instead of recomputing them. However, model-side advances that shrink the KV Cache and system-side advances that reduce compute, storage, and transfer costs are evolve independently within legacy cloud boundaries. We argue that future inference infrastructure should allow decoupling of compute and KV Cache storage across cloud and datacenters. The network becomes an active distribution channel; bandwidth, latency and pricing directly determines how the KV Cache should be managed. We propose a vision for an Internet for the KV Cache, with KV Cache management working as a content-distribution system. In this view, KV Cache storage and recompute decisions are driven by model, infrastructure, and application metrics, to enable adaptive, content-driven decisions for minimizing latency and cost.

## 1. 核心问题与整体含义（研究动机和背景）

- **研究背景**：LLM 推理已经成为一种全球规模的异构工作负载，涵盖多步 agent 工作流、RAG 检索、工具调用、代码执行和多模态推理等场景。这些工作负载天然存在大量重叠输入，从而使得 **KV Cache（键值缓存）复用** 成为一个关键机遇——即直接复用先前计算好的上下文推理状态，而不必重新计算。
- **核心问题**：当前云基础设施基于“存储与计算必须紧耦合”的陈旧假设（如可用区、区域边界和昂贵的网络出口费用），导致 KV Cache 的存储与计算无法在云和数据中心之间自由解耦和流动。这种传统边界严重制约了 KV Cache 跨区域、跨云复用的潜力。
- **整体论点**：论文主张，KV Cache 的管理问题本质上已经从“存储 vs 重计算”的二元权衡，演化为 **互联网规模的内容分发与内容管理问题**。未来的推理基础设施应允许计算与 KV Cache 存储解耦，并将网络视为主动分发通道，构建一个“KV Cache 互联网（Internet for the KV Cache）”。

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心愿景：Store Anywhere, Use Everywhere（随处存储、随处使用）

- 论文提出彻底打破现有云边界，让 KV Cache（"移动的推理状态"）可以跨存储层级、跨区域、跨云提供商自由移动。
- 将 KV Cache 管理类比为 CDN（内容分发网络）：KV Cache 作为“可再生的内容”，按照**预期的未来需求**进行放置、复制、预取和迁移。
- 关键差异点：与传统 CDN 中不可再生的数据不同，**KV Cache 可以在传输过慢或成本过高时重新计算（regenerate）**，因此系统具有额外的回退自由度。

### 2.2 核心量化模型：存储 vs 重计算的成本公式

论文提出了一个成本决策框架，用于判断“存储并传输”还是“重新计算” KV Cache 更划算：

- **关键定义**：
  - *CacheCost* = 存储成本 + 传输成本
  - *PrefillCost* = 重新计算预填充（prefill）的成本
- **核心公式（成本比）**：
  - CacheCost / PrefillCost = (DeviceCost_hr × K × KV_MB + TransferCost × KV_MB) / [GPUCost_hr × (Prefill_TFLOPs / PeakFlopRate)]
  - 其中 K 为 KV Cache 复用频率，KV_MB 为缓存大小，DeviceCost_hr 为单位存储成本，TransferCost 为单位传输成本。
- **代价平衡条件（式 2）** 进一步推导出两个可直接比较的比率：
  - **模型侧比率**：Prefill_TFLOPs / KV_MB（由模型架构决定）
  - **基础设施+应用侧比率**：(DeviceCost_hr × K + TransferCost) / (GPUCost_hr / PeakFlopRate)（由硬件价格、复用频率和网络费用决定）
- **决策规则**：若基础设施侧比率 < 模型侧比率 → 存储更便宜；反之 → 重计算更便宜。该公式表明，**不存在绝对最优的通用策略**，决策高度依赖具体参数组合。

### 2.3 降低 KV Cache 未命中率（Miss-Rate）应成为核心目标

- 当前工业界普遍使用前缀缓存（Prefix Caching）并优化命中率（Hit-Rate），但论文指出 **命中率本身是不完整的指标**——缓存未命中的代价可能极其高昂，因为长上下文 KV Cache 的重计算成本随前缀长度呈**二次方**增长。
- 前缀缓存具有“脆弱性”：即使是单个 token 的差异也会导致完全缓存未命中。因此，论文主张从追求“精确前缀匹配”转向支持**语义级、近似匹配**的非前缀缓存复用（如通过 CacheBlend 对不同 RAG 分块缓存进行融合、不同顺序拼接等），以显著降低未命中率和重计算成本。

### 2.4 技术演进基础

论文梳理了三类现有优化作为该愿景的基础：
- **模型侧**：MoE 架构（如 Mixture of Lookup Experts、KTransformers）、稀疏注意力（如 NSA、DuoAttention）等，持续缩减 KV Cache 体积和计算量。
- **KV Cache 侧**：缓存融合/编辑（CacheBlend、EPIC）、缓存压缩（TurboQuant、RocketKV、ChunkKV）、记忆压缩与编排（MemAgent、A-Mem、Context Folding）。
- **系统侧**：prefill-decode 分离（DistServe、Mooncake）、跨层级 KV Cache 传输（KVDirect、LMCache、TraCT）、感知状态的调度器（SOLA、ThunderServe、Libra）。

## 6. 主要结论与发现

- **核心结论 1**：KV Cache 复用将 LLM 推理的核心挑战从“计算-存储权衡”转变为“互联网规模的内容管理与分发问题”。
- **核心结论 2**：KV Cache 不是普通的数据结构，而是“上下文知识的紧凑、持久、可引导表示”，是一种新的存储、通信和调度原语（first-class citizen）。
- **核心结论 3**：网络带宽、延迟和传输定价应成为推理执行中的一等公民决策变量；在特定条件下，“网络传输 KV Cache 比重计算更便宜、更快”已成立。
- **核心结论 4**：降低 KV Cache 未命中率（而非单纯提高命中率）是释放缓存复用潜力的关键；需要支持语义级/近似级缓存复用（如跨块缓存融合）。
- **核心结论 5**：未来需要构建一个 KV Cache 控制平面（含查找服务、放置规划器、预取调度器），实现跨云、跨区域的动态 KV Cache 放置决策，并支持优雅降级——当传输失败或成本过高时回退到重计算。
