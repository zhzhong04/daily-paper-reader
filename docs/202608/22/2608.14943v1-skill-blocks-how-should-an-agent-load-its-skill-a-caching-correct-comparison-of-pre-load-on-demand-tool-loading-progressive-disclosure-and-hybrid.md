## 摘要
智能体技能通常会在每次请求时完整注入，从而增加令牌成本。我们比较了四种内容保留的加载方法：完整加载、技能块、引用和混合方法。在SearchQA、SpreadsheetBench、ALFWorld、ScienceWorld和SynthProc上，我们使用原始输入测量单轮任务的令牌使用量，并使用缓存校正的有效输入测量多轮任务的令牌使用量。结果显示没有普遍最优的方法。混合方法在SearchQA上减少了27.4%的输入，在SpreadsheetBench上减少了39.8%。对于大型多轮技能，技能块和混合方法实现了显著减少，在ScienceWorld上分别达到62.5%和52.8%，在SynthProc上分别达到73.0%和66.6%。ALFWorld的收益较小，因为其程序较短且需要反复使用。配对结果检验未检测到质量差异，尽管这并未确立等效性。总体而言，当技能的大部分内容并非每轮都需要时，条件加载最为有益。

## Abstract
Agent skills are often injected in full on every request, increasing token cost. We compare four content-preserving loading methods: Full, Skill Block, Reference, and Hybrid. Across SearchQA, SpreadsheetBench, ALFWorld, ScienceWorld, and SynthProc, we measure token usage using raw input for single-turn tasks and cache-correct effective input for multi-turn tasks. Results show no universal winner. Hybrid reduces input by 27.4% on SearchQA and 39.8% on SpreadsheetBench. On large multi-turn skills, Skill Block and Hybrid achieve substantial reductions, reaching 62.5% and 52.8% on ScienceWorld and 73.0% and 66.6% on SynthProc. ALFWorld shows smaller gains because procedures are short and repeatedly needed. Paired outcome tests detect no quality differences, though they do not establish equivalence. Overall, conditional loading is most beneficial when large portions of a skill are not needed on every turn.

## 1. 论文的核心问题与整体含义

**研究动机与背景**：  
- Agent 技能（Agent Skills / SKILL.md 等）是指导 AI Agent 行为的指令文档，常见实现是将其完整放入每个请求中，即使请求只涉及其中一小部分内容。这种“全量加载”会造成大量 token 浪费，尤其对大型技能和多轮任务更为严重。  
- 已有工作（如 SkillOpt、APE、DSPy、TextGrad 等）主要优化技能内容本身，本文则聚焦一个正交的系统性问题：**在一个技能已经写好且内容固定时，如何决定“何时将技能的哪一部分展示给模型”**，即技能加载机制的对比。  
- 核心贡献是提出内容保留（content-preserving）的块化技能基质，并系统比较四种加载包装，同时引入“缓存校正”的输入成本度量方法。

## 2. 论文提出的方法论

**核心思想**：  
- 将技能划分为多个命名块（block），每个块带有描述、默认标志、依赖、优先级和标签；核心块始终可用，可选块可依赖其他块。所有块完整渲染时能还原原始技能（对块化技能逐字节还原；对转换文档仅受空白/标题规范化影响）。  
- 四种加载机制均保留同样的内容可用性，但 prompt 脚手架不同（工具定义、目录、stub 等为机制必需，不属于可剥离的干扰文本）。

**四种机制**：
- **Full**：全部块始终在上下文中，作为预加载基线。
- **Skill Block**：只加载一个小核心，模型通过工具 `load_skill_block(name)` 请求额外块；有函数 schema 和目录，需一次工具往返。
- **Reference**：核心 + 文本目录，模型先选择参考条目，随后注入参考内容；无工具 schema，但通常需要两轮交互。
- **Hybrid**：所有块仅提供紧凑 stub（摘要/指引），模型认为 stub 不足时才获取完整块；获取率低时几乎只需一轮。

**成本模型**：  
给出输入侧近似公式：
- 全量输入：`input_full = F + c + X + Σ_i s_i`
- 按需输入期望：`E[input_on-demand] ≈ r(F + c + T + X) + Σ_i p_i s_i`
- 净节省：`net saving ≈ Σ_i (1 − p_i)s_i − (r − 1)(F + c + X) + rT`

其中 `c` 为核心块 token，`s_i` 为可选块大小，`p_i` 为其加载概率，`F` 为固定系统开销，`X` 为任务上下文 token，`T` 为工具 schema token，`r` 为加载交互轮数。该模型说明：未使用的可选内容必须超过往返开销，否则按需加载不划算。

**缓存校正记账**：
- 多轮任务中，provider 的 `input_tokens` 包含 cache-read token，直接当作新读 token 会高估成本。因此定义：
  - `new input = input_tokens − cache_read`
  - `effective input = new input + 0.1 × cache_read`
- 另外定义 `total_λ = base_input + λ · output_tokens`（λ = 1, 4, 8）来纳入输出 token 成本，作为敏感性而非真实计费。

## 3. 实验设计

**数据集 / 场景**（五个配对基准）：
- **SearchQA**：单轮问答，技能约 1,966 token，n = 1,400。

- **ScienceWorld**：多轮科学模拟，技能约 6,097 token，16 个流程（约 289 token/个），n = 84（主要非中止集合）。
- **SynthProc**：合成多轮过程，技能约 9,728 token，45 个操作库，n = 40。

**对比方法**：
- 四个主要内容保持机制：Full、Skill Block、Reference、Hybrid。

**主指标**：
- 单轮任务：raw input（原始输入 token）。
- 多轮任务：median effective input（中位数有效输入，缓存读按 10% 计）。
- 质量指标：各基准原生指标（SearchQA 匹配率、SpreadsheetBench 工作簿通过率、ALFWorld/SynthProc 完成率、ScienceWorld 完成率和进度）。

## 6. 论文的主要结论与发现

- **没有普适最优的加载方法**，收益取决于技能可压缩性和任务轮次结构。
- **单轮任务**：
  - SearchQA（小技能）：Hybrid 因获取率仅 1.4% 而减少 27.4% 输入；被强制加载的 Skill Block 反而增加 48.4%；Reference增加 10.4%。
  - SpreadsheetBench（大技能）：所有内容保持的按需机制都优于 Full：Hybrid −39.8%，Skill Block −35.6%，Reference −31.7%；静态剪枝 original8 −55.5%。
- **多轮大型可压缩技能**：  
  - ScienceWorld：Skill Block 有效输入降低 62.5%，Hybrid 降低 52.8%，Reference 降低 23.0%。  
  - SynthProc：Skill Block −73.0%，Hybrid −66.6%，Reference −14.8%。  
  - 在 `gpt-5.6` 配置下，大型技能收益依然保留（ScienceWorld 中 Hybrid/Skill Block 约 −68%），但两方法顺序近乎打平。
- **多轮小且频繁使用的技能**（ALFWorld）：Skill Block 仅有 −12.6%，Hybrid −3.2%，Reference +24.2%；纳入输出 token 后差距缩小甚至消失（λ=4 时 Skill Block 仅 −4.5%）。
- **质量影响**：所有主要配对结果检验均未检测到显著质量差异，但作者明确表示这不等同于等价性或无退化风险。
- **总体规律**：条件加载只有在“技能含有大量并非每轮都需要的内容”时才明显节省成本；小技能或每次都用到的技能，加载开销会抵消节省。

## 7. 优点

- **内容保留的公平比较**：将技能无损块化，完整渲染可还原原始技能，确保四种机制的内容可用性一致（脚手架差异不可避免但被显式说明）。
- **缓存校正度量**：区分 raw / new / effective input，揭示了多轮任务中 cache-read 占比高达 74–94% 时的成本误判问题，并给出可复现的敏感性区间。
- **多维度实验设计**：覆盖单轮/多轮、小/大技能、真实/合成任务，并补充配置级模型转移实验和多项敏感性分析（d、λ、n 变体），结论边界清晰。
- **诚实的不确定性表达**：明确区分探索性与确证性、非显著≠等价、静态对照≠内容对等，方法论透明度高。
- **实践启示**：给出成本模型和“regime map”（不同场景下的决策建议），并附部署检查清单，可直接指导工程实践。

## 8. 不足与局限

- **端点与可迁移性**：主要结果来自非公开的生产端点（gpt-5.5），系统提示和解码设置不可控；`gpt-5.6` 转移实验为同提供商配置级验证，且未保留 provider 返回的模型身份，缺乏跨供应商复现。
- **统计推断局限**：非显著结果不能证明等价或非劣效；SearchQA 和 SpreadsheetBench 使用了最终测试集进行开发，整个推断族属探索性；token 区间为逐个比较而非族级同时区间。
- **SynthProc 安全混淆**：`gpt-5.6` 下与密钥相关指令触发拒绝循环，导致该基准无法作为可靠性证据，并影响 token 成本归因。
- **静态对照问题**：`original8` 永久移除六个块，与动态 CORE_BLOCKS 不完全一致，不能作为因果对照，也不能证明在分布外请求中的覆盖性。
- **选择与划分质量未直接测量**：块边界由作者选择，路由正确性没有直接标签；SpreadsheetBench 的执行反馈可掩盖劣质选择，因此任务准确率并不是路由质量的敏感指标。
- **记账假设未经验证**：缓存折扣 d=0.1 是参考值而非真实计费；无法从日志中区分 schema 缓存与对话前缀缓存；未度量推理 token 和延迟。
- **历史数据不完整**：ScienceWorld 主要分析需排除 abort 样本，修复版 n=90 为时间拼接敏感性结果，非同期完整实证。
- **决策门为事后启发式**：大小门限（约 2K token）仅基于该端点的观察，混合方法的低获取率例外使统一门限不成立，需根据本地测量验证。
