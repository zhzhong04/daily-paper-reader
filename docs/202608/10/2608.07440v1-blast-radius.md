## 摘要
智能体编码正面临日益严重的成本负担和令牌浪费问题。我们引入了爆炸半径，一种预测性记忆管理层，通过耦合的上下文和代码通道来估计传入提示的触及范围。NECROPHORESIS 通过逐字存档死上下文实现可逆驱逐，而重复死物质识别并掩埋反复出现的记录。我们在波兰空间上制定了可逆上下文驱逐，为保留、重复和驱逐提供了可测量的基础，同时将上下文熵与复活概率联系起来。在七个 OpenAI 模型上，爆炸半径将令牌消耗降低了17-26%，在测试策略中实现了最低的溢出率，并保持字节级可逆。在450个被掩埋的尸体中，378个是重复死物质，零个被召回。爆炸半径在 HCRC 之下运行，决定掩埋哪些记录以及传入提示能触及代码库多远。这项工作有助于实现 Algosophy 的更广泛目标：使大型语言模型和智能体编码更具可重用性和可持续性。

## Abstract
Agentic coding faces growing problems of affordability and wasted tokens. We introduce Blast Radius, a predictive memory management layer that estimates an incoming prompt's reach through coupled context and code channels. NECROPHORESIS enables reversible eviction by archiving dead context verbatim, while Recurring Dead Matter (RDM) identifies and buries repeatedly occurring transcripts. We formulate reversible context eviction over a Polish context space, providing a measurable foundation for retention, recurrence, and eviction while connecting context entropy to resurrection probability. Across seven OpenAI models, Blast Radius reduced token consumption by 17-26%, achieved the lowest overflow rate among tested policies, and remained byte exact reversible. Of 450 buried bodies, 378 were recurring dead matter and zero were recalled. Blast Radius operates beneath HCRC, determining which records to bury and how far an incoming prompt may reach into the codebase. This work contributes to the broader goal of Algosophy: making large language models and agentic coding more reusable and sustainable.

## 一、论文的核心问题与整体含义（研究动机与背景）

- **核心问题**：Agentic coding（智能体编码）中token消耗极高，且存在大量浪费。LLM驱动代码仓库时，每一轮迭代都会将整个对话历史（系统提示、工具模式、所有之前读过的文件、每次diff、每个堆栈跟踪）重新提交给模型，导致边际成本随轮次增长而增长，形成“集成式”失控成本。
- **关键痛点——“死上下文”**：文件中为修复某个小错误而被完整转储，之后几十轮仍占据数千token，但已不再影响任何正确的下一步行动。这种死上下文是**纯认知熵（epistemic entropy）**——占用带宽却只携带噪声。
- **现有方案的有损性**：
  - 滑动窗口截断（StreamingLLM）：丢弃最旧token，无论其是否为承重信息。
  - 摘要内存（MemGPT）：通过第二个易出错的模型调用压缩上下文，无法撤销，一旦压缩了重要信息则信息永久丢失。
  - 两者都牺牲了不可恢复的信息来换取可恢复的token。
- **整体含义**：论文提出“可逆遗忘”的策略——先估计提示的“爆炸半径”（影响范围），再进行有下限风险（bounded downside）的遗忘操作，使死上下文的管理从“有损赌博”转变为“有界下注”，推动LLM与agentic coding更可持续、更可复用（服务于“Algosophy”更广泛目标）。

## 二、论文提出的方法论：核心思想、关键技术细节与算法流程

### 1. 总体架构

- **Blast Radius（爆炸半径）**：预测性记忆管理层，位于HCRC（Heaviside Continuity of Rolling Coefficients）框架之下。HCRC决定“是否允许遗忘”（门控），Blast Radius决定“遗忘什么、遗忘多少、下一轮提示能触及多远”。
- **双通道信号**：
  - **上下文通道（context channel）**：预测提示对保留工作集的增量，决定驱逐预算。
  - **代码通道（code channel）**：度量编辑通过依赖图触及的结构表面，触发提交压力信号。
  - 两通道回答同一问题——“什么与我的下一步行动因果耦合”。

### 2. 上下文通道（Context Channel）

- **爆炸半径定义**：B(pt, Ct) = E[L_new_{t+1} − Lt | pt, Ct]，即执行该轮后预期新增的保留负荷（token数）。
- **驱逐预算**：Ht = max(0, Lt + B̂ − (1−γ)W)，当窗口快溢出时需回收至少Ht个token。
- **埋葬（Burial）而非删除**：
  - 被选中的身体（body）被替换为“气味骨架”（scent skeleton）——一个紧凑的驻留替代品，列出使命、触及的文件和归档键，固定成本σ≪τ。
  - 原始内容被逐字节归档到可追加的“垃圾堆”M（midden，SQLite存储）。
- **扫描算子的最优选择**：这是一个最小代价背包覆盖问题（min-cost knapsack cover），通过效率排序的贪心近似求解，目标是回收所需token的同时最小化预期后悔（复活概率×发掘代价κ）。
- **Recurring Dead Matter（RDM，循环死物质）**：
  - 识别重复注入上下文的近乎相同的转录（如反复执行同一构建、测试、git状态命令）。
  - 通过标准化映射Σ将转录归入**循环类**（recurrence class），保留最新实例，埋葬所有更旧的实例。
  - 使用**拉普拉斯继承规则**估计复活概率：q̂c = (ec + 1)/(kc + 2)，从未被发掘的类别q̂c随埋藏次数单调递减，快速达到“见即埋”的许可条件。

### 3. 代码通道（Code Channel）

- **影响波及（Impact Reach）**：Rk(S0) = {v ∈ V : dG(S0, v) ≤ k}，即编辑种子集在依赖图中的k-hop可达节点集合。
- **变更压力（Churn）**：每个文件累积的增删行数w(v) = added + removed。
- **雷达可视化**：每个被触及文件作为雷达图上的光点，径向坐标r(v) = min(rmax, a + c√w(v))，使面积正比于churn；角度为文件路径散列。
- **提交压力信号**：Πt = 1[∃v: tier(v) ≥ RISK]，当任何文件累积变更突破风险层级（如500行）时触发，建议操作者检查点。

### 4. Polish空间形式化

### 5. 核心定理

- **定理7.1（可逆扫描的有界下行）**：埋藏一个身体b的净节省 = (τ−σ)·m′ − κ·1[m<∞]。最坏情况超额成本恒为κ，而收益随埋藏时长线性增长。
- **推论7.2（支配阈值）**：当复活概率q(b) ≤ (τ−σ)·m̄/κ时，埋藏具有非负期望token价值；由于τ≫σ、m̄≥1而κ为小的常数，右侧通常超过1，即携带死上下文被支配。

## 六、论文的主要结论与发现

1. **token消耗显著减少**：完整策略（E）相比carry-all减少约20%（43,053→34,518 tokens/任务），分模型降低17%–26%。
2. **持平有损基线**：条件E的token经济性与lossy的truncation（34,662）相当，但E保持字节级可逆。
3. **最低溢出率**：条件E为4.00次溢出/episode，低于carry-all的5.21，也低于truncation（5.07）和summarization（4.07）。
4. **零发掘（zero exhumation）**：450个被埋尸体中，378个为循环死物质，**零个被召回**——极强地验证了支配阈值假设。
5. **RDM贡献显著**：循环死物质（构建日志、测试重跑、GC状态检查）贡献了39%的回收质量，且是D→E改进的全部来源——因为RDM在重复发生时即被立即回收，无需等待普查阈值。
6. **聚合置信**：RDM的节约在所有模型代系中一致，说明例行流量是会话循环的属性而非模型属性。

## 七、优点（亮点）

1. **可逆性驱动的理论创新**：将“遗忘”从有损压缩转变为有界下注，核心定理（7.1和推论7.2）形式清晰且反直觉地证明了“遗忘可以比携带更安全”。
2. **双通道统一建模**：上下文通道和代码通道共享同一个“因果耦合”度量，使用Polish空间提供了严格的数学基础，使保留、重复、驱逐、复活成为可测函数，具备理论完整性。
3. **务实且透明**：理论完整但部署策略却刻意简单（硬性死分数q=0，保守候选集，反应式普查）；明确区分“理论上可以做什么”和“实际上安全做什么”。
4. **将熵与复活概率连接**：将认知熵减少与可逆遗忘关联，而非破坏性遗忘——这是一个有价值的理论视角。
