## Abstract 

Although agentic coding has been widely adopted by the software engineering industry, it has seen a growing number of problems in terms of affordability and wasted tokens. In this research paper, we introduce Blast Radius as a solution to make agentic coding more sustainable. Blast Radius is a predictive memory-management layer that estimates an incoming prompt’s reach through coupled context and code channels, using retention likelihood and churn-weighted depen-dency reach. Alongside Blast Radius, we also introduce N ECROPHORESIS , which makes eviction reversible by archiving dead context verbatim and replacing it with a compact skeleton, while Recurring Dead Matter (RDM) identifies near-identical transcripts repeatedly injected by routine coding loops and buries recurrence classes using Laplace’s rule of succession. We formulate reversible context eviction over a Polish context space, providing a measurable foundation for retention, recurrence, and eviction. This formulation also connects context entropy to the probability of resurrection, allowing epistemic entropy to be reduced through reversible rather than destructive forgetting. Because eviction is reversible, an incorrect eviction incurs only a bounded exhumation cost, while correct eviction compounds token savings across subsequent turns. From the tests we conducted across seven Ope-nAI models, Blast Radius managed to effectively reduce token consumption by 

17 –26% , achieved the lowest overflow rate among tested policies, and remained byte-exact reversible. Moreover, of 450 buried bodies, 378 were recurring dead matter and zero were recalled. Blast Radius operates beneath the HCRC, which allows the gate to determine whether a record may replace context; Blast Radius identifies which records to bury and how far the next prompt will reach in terms of its potential impact on the codebase. This work is largely a work in progress toward the broader goal of Algosophy: making large language models and agentic coding more reusable and sustainable. 

## 1 Introduction 

A large language model driving a repository does not accumulate understanding the way an engineer does; it accumulates tokens . Each turn of an agentic coding loop re-submits the entire conversation, meaning the system prompt, the tool schemas, every prior file read, every diff, and every stack trace, so that the marginal cost of a turn grows with the integral of everything that came before it. Empirically, the majority of that integral is dead : a file that was dumped in full to fix a typo on turn 3 is still occupying two thousand tokens on turn 40, long after the typo, the file, and the sub-task that motivated it have been concluded. The model pays attention-quadratic and dollar-linear costs to re-read context that can no longer change a correct next action. The HCRC gate was designed to eliminate exactly this epistemic entropy [1]; Blast Radius is the scoping layer that makes the elimination operational. The naive responses are lossy. Sliding-window truncation [2] drops the oldest tokens regardless of whether they were load-bearing; summarization memory [9] compresses context through a second, itself-fallible model call and cannot be undone if it compresses something that mattered. Both trade a recoverable cost (tokens) for an unrecoverable one (information). The broader principle of reducing dimensionality to improve computational performance has been studied in supervised learning settings [23], where dimension reduction on high-dimensional data objects yields measurable accuracy gains, an analogous trade-off faces the agentic coding loop, where the dimension is the growing context window. We argue the right move is different. We estimate, before a turn runs, how far it will reach, both how much new context it will retain and how much structural surface its edits will touch, then use that estimate to license a forgetting operation whose downside is bounded by construction because it is exactly reversible. We call this estimate the blast radius of a prompt. The name is literal and two-channelled. In the 

context channel , the blast radius is the predicted increment to the retained working set; it sets the size of the eviction we must perform to keep the window from overflowing, and it selects which dead bodies to sweep. In the code channel , the blast radius is the churn-weighted set of files and symbols the turn’s edits reach through the dependency graph; it is the impact surface that should trigger a checkpoint before it grows unreviewably large. Both channels answer the same question, what is causally coupled to what I am about to do? , one over context tokens (temporal reach) and one over the code graph (structural reach). Blast Radius does not stand alone. It is the context-management substrate of Chalk, an agentic coding environment whose execution is governed by the Heaviside Continuity of Rolling Coefficients (HCRC) framework [1]. HCRC contributes a gate: a Heaviside step over a confidence and verification product that authorizes state transitions, including gate-licensed memory compaction , in which only gate-derived records may replace session context. That prior work established whether a compaction is licensed; it did not specify what to compact or how much . Blast Radius fills exactly that gap. Where HCRC says “you may forget only what verification has settled,” Blast Radius says “here is the settled, dead mass; here is the cheapest reversible sweep that reclaims the headroom the next prompt needs; and here is the bounded price if we are wrong.” 22 Related Work 

There has been substantial research published by scholars across many domains regarding context management and memory context utilization in large language models. We survey the ones we feel strongly pertains to our research work. Large extent of many of scholars have discussed the cost of long contexts at the attention level. StreamingLLM [2] retains attention sinks plus a sliding window; H 2O [3] evicts key–value entries by accumulated attention mass; Scissorhands [4] exploits the persistence of “pivotal” tokens; FastGen [5] adapts eviction to head structure. Mixture-of-attention-spans [6] optimizes inference with hetero-geneous sliding-window lengths; LongRoPE [7] extends the context window beyond two million tokens; ContextWeaver [8] constructs selective, dependency-structured memory for LLM agents. These operate inside a single forward pass and are irreversible: an evicted KV entry is gone. Blast Radius operates one level up, on the message granularity of an agentic loop, and its evictions are reversible by archival. The two are complementary: a cache policy compresses within a turn, while Blast Radius decides what survives between turns. Moreover a large extent of contemporary solutions pertaining to alleviating efficiency involved the strategies around context window management. MemGPT [9–11] treats the context window like paged virtual memory, swapping between an in-context working set and external storage; summarization-based memories [12] compress history through model calls. Blast Radius shares the paging intuition but differs in two ways it treats as load-bearing. First, eviction is lossless : the archived body is byte-exact, not a summary, so exhumation restores the original rather than a lossy reconstruction. Second, eviction is predicated , licensed by the HCRC gate [1] rather than triggered by a length heuristic alone. Retrieval-Augmented Generation (RAG) has also been adopted by many researchers as a tool and strategy to mitigate poor context window management especially in most applications which rely on context on demand. RAG [13–18] injects retrieved passages into context on demand. Necrophoretic burial is the dual operation: rather than pulling external knowledge in , it pushes transient session knowledge out to a store keyed by a scent skeleton, then pulls it back only if a later prompt’s blast radius indicates it is needed. The scent is precisely a retrieval key that remains resident in-context. The code channel is a probabilistic descendant of change-impact analysis [19, 20] from software maintenance, which estimates the set of program elements affected by a modification through static dependencies or co-change history. We adopt its reachability formulation but weight it by realized churn and render it as an operator-facing pressure signal rather than an offline report. Blast Radius is deployed under HCRC [1], which gates LLM state transitions behind a Heaviside predicate over independent verification signals. We do not re-derive the gate here; we consume it. The relationship is strict layering: verification licenses compaction; Blast Radius scopes it.

4.4 Recurring dead matter 

Production telemetry from Chalk exposed a failure mode the sweep above does not address. An agentic session is not a stream of unique missions; it is a loop. The agent greps the same symbols, reruns the same test suite, rebuilds the project from the first line to the newest (compilation has no memory of the previous build), and checks the same version control status, turn after turn. Each of these routine calls injects a transcript into context that is near-identical to the one before it, and each such transcript dies the moment the next one arrives. Treating every arrival as fresh matter is doubly wrong: the census re-counts it toward the burial threshold, and the radar re-blips it as if it were new impact. The right treatment is to recognize the class , not the instance. Pattern-based recognition of near-identical content has precedent in self-similarity matrix methods for recommendation systems [22], where visual patterns of repetition are compared to identify structural similarity; the recurrence class mechanism here applies the same intuition to transient tool transcripts. 

Definition 4.6 (Recurrence class) . Let Σ be a normalization map that strips volatile content (counters, timings, hashes) from a transcript and retains its generator and stable head. Two tool bodies b, b ′ are 

recurrences of one another iff Σ( b) = Σ( b′); the equivalence class c = [ b ]Σ is a recurrence class .The ledger records, per class, the number of burials kc and exhumations ec of its members. 

Definition 4.7 (Recurring dead matter) . A body b is recurring dead matter (RDM) at turn t if its class contains a strictly newer member. The newest member of each class is presumed live (it carries the current state of the routine: the latest build outcome, the latest test count); every older member is RDM. The resurrection probability of RDM is not guessed; it is estimated from the class ledger by Laplace’s rule of succession, which is the posterior mean of a Beta–Bernoulli model with a uniform prior over the class’s exhumation behavior.

## 5 The Code Channel 

The second face of blast radius measures structural rather than temporal reach. It does not build new machinery: it reads the abstract syntax tree the editor already parses and the dependency DAG the executor already walks (the Coefficient DAG of [1]), and scores reach over them. ## 6 Polish-Space Formulation of Reversible Context Eviction 

The context channel (Sec. 4) and the code channel (Sec. 5) have so far been developed as separate operational mechanisms: one predicts retained tokens, the other predicts structural churn. We now unify them under a single mathematical substrate, a Polish space of context objects, in which prompts, code fragments, dependencies, and archived conversational states are represented as points in a separable, completely metrizable space. This structure provides a stable notion of similarity and convergence for heterogeneous context objects, allowing retention likelihood, churn, and dependency reach to be treated as measurable functions. The unification is not merely cosmetic: it shows that the two channels are two measurable projections of the same object, and that N ECROPHORESIS and Recurring Dead Matter are well-defined operators on the resulting measurable space.

6.5 Domination threshold in the Polish setting Corollary 6.7 (Domination threshold) . Let κ > 0 be the exhumation cost in tokens. Carrying a body

6.6 Deployed specialization 

The shipped system instantiates the Polish-space framework with a conservative discrete specializa-tion. The metric d is replaced by the hard normalization map Σ: two bodies are in the same recurrence class iff Σ( b) = Σ( b′), i.e., d(b, b ′) = 0 on the quotient. The retention likelihood r(x) is replaced by a hard classifier: r(x) = 0 for bodies in old, large, settled missions (the protected window K = 3 

and candidacy floor of 800 characters). The weighting function w(x, y ) is replaced by co-occurrence counts on the dependency DAG. The Polish-space generality is preserved as the target for a learned estimator ˆr, which would replace the hard rules with a model trained on exhumation telemetry. This is the zero-estimated-regret corner of the general policy: the hard classifier is the boundary case where the domination threshold is satisfied by construction for every candidate, because the candidates are chosen precisely from the set where q(x) ≈ 0.

## 7 Theory: Why Reversibility Dominates 

We now state the paper’s central claim. The value of Blast Radius is not that it forgets well, since any truncation forgets, but that reversible forgetting has an asymmetric payoff that makes carrying dead context dominated. 

Theorem 7.1 (Bounded downside of reversible sweep) . Let b be a body buried at turn t by ΦS

under Assumption 4.4. Suppose b is next required at turn t′ = t + m for some m ≥ 1 (set m = ∞

if it is never required within the horizon). Relative to the never-sweep policy that keeps b resident throughout, the token ledger of the sweep policy is: net saving (b) =  τ (b) − σ · m′ − κ · 1[m < ∞], m′ = min( m, turns remaining ).

In particular, the worst-case excess cost of burying b is exactly κ tokens, independent of m, whereas the saving grows linearly in the burial duration m′.

Lossy forgetting (truncation, summarization) has an unbounded

Remark 7.3 (The threshold is measured, not assumed) . Corollary 7.2 is actionable because q(b) is not left as an unknown. A session in which this rate is small is empirical confirmation that the sweep policy’s implicit ˆq was well-calibrated; a session in which it is large is a signal to shrink the candidate set. The framework thus closes its own loop: the quantity the theory needs is the quantity the instrument reports. 

7.1 An information-theoretic reading 

We record a modeling assumption that makes the “dead” in dead context precise, and a bound that follows from it. Let A⋆t+1 denote a correct next action and, for a resident set C, let I(C; A⋆t+1 ) be the mutual information between the context and the correct action. The conditional entropy H(A⋆t+1 | C)

## 8 The Deployed System 

We now describe what actually ships, with its real constants, and locate it inside the framework above. We consider it important that the deployed policy is simpler than the general estimator; the framework’s job is to explain why the simple policy is safe, not to claim the complex one is running. 

The census (context channel). Each idle cycle, Chalk runs a census over the resident assistant bodies. A body is a candidate for burial iff it satisfies all of: (i) it is an assistant mission, not a user turn; (ii) it lies outside the protected window of the last K = 3 missions, which are presumed live (d = 0 ); (iii) it is not already buried or marked immune; and (iv) its content exceeds a candidacy floor of 800 characters, below which a tombstone would not repay its own scent cost. Locating deployment in the framework. The shipped policy is Definition 4.5 with three spe-cializations. First, the death score is hard : qt(b) = 0 for every candidate (equivalently d = 1 ), so estimated regret is zero and the knapsack objective collapses: any covering sweep is optimal, and the policy buries the whole candidate set at once. Second, the eviction budget is reactive rather than predictive: instead of estimating ˆB for the incoming prompt, it triggers on the measured backlog 

Dt crossing θ, which is the conservative choice of acting on realized dead mass rather than forecast demand. Third, the candidate set Kt is deliberately narrow (old, large, settled missions only), which is what makes the hard q = 0 assumption defensible: these are precisely the bodies for which Corollary 7.2’s threshold is easiest to satisfy. The exhumation-rate telemetry (Remark 7.3) is the check that this assumption holds in practice. 

The midden. Bodies are archived to an on-device SQLite store under ~/.chalk . Two tables realize the axioms: a bodies table holds the verbatim content, token count, scent, and exhumation counter (A2); a ledger table appends every bury /exhume with a marker and timestamp (A5). Redaction (A7) runs a fixed battery of secret patterns (provider keys, cloud credentials, token /password 

assignments) and truncates any match to a short prefix before archival, so the midden never persists a plaintext secret. Burial is transactional: either all bodies in a sweep are archived and ledgered or none are, so the resident skeletons are never swapped in against a failed write. 12 The radar (code channel). The Blast Radar renders every file the session wrote or edited as a blip via the radar encoding, sorts the top offenders by churn, and raises the commit-pressure flag 

Πt when any file breaches the RISK tier at 500 churned lines. The rendering pipeline inherits the principle that parallel pattern decomposition on multicore architectures yields scalable performance for compute-intensive feature extraction [24]; the radar’s tiered annuli and per-file blip computation are designed for the same kind of embarrassingly parallel throughput. It is an ambient signal, not a gate: it advises the operator to checkpoint, and never blocks an edit.

Agentic coding continues to incur recurring token costs for context that remains in the model’s working window. Blast Radius estimates how far a prompt reaches into the context it will retain and the code it will touch, while N ECROPHORESIS acts on that estimate as a reversible operator, reclaiming dead token mass without destroying the information carried. In this paper, we postulate that reversibility turns forgetting from a lossy gamble into a bounded downside bet, making provably dead context dominated whenever its resurrection probability falls below an explicit threshold that the system already measures. Blast Radius is the scoping layer beneath HCRC’s gate licensed compaction, which dictates that verification decides what may be forgotten, while Blast Radius decides how much to forget, what to bury, and how far the next prompt can reach, while remaining ready to remember it again. We have formalized the framework, shipped the operator, and validated the mechanism across seven models: 450 bodies buried, 378 recurring dead matter, zero exhumations. While this is still a work in progress, the preliminary results of this effort show a promising future.
