## 摘要
大型语言模型（LLMs）具有受限的上下文窗口。上下文窗口是LLM在单次推理中可消耗的最大输入规模。AI代理依靠一种称为上下文压缩的过程，在调用LLM时将其状态适应于上下文窗口之内。尽管其无处不在，但上下文压缩基本上没有受到正式分析。在本文中，我们开启了对上下文压缩的正式研究。我们首先引入一个框架，包含两个博弈，它们捕捉了当代AI代理在实践中使用的两种上下文压缩算法策略。上下文选择博弈建模了从代理积累的状态中选择子集保留的上下文压缩算法。上下文生成博弈建模了通过任意有界长度的消息来总结代理状态的上下文压缩算法。然后我们证明了上下文生成博弈与单向通信复杂性之间的等价性。在目标误差内回答一组查询所需的最小上下文压缩预算，等于在相同误差下所诱导的通信问题的单向通信复杂性。因此，通信复杂性的已知界限直接转移到上下文压缩。我们还表明，上下文选择博弈对应于单向通信协议的一个受限类。因此，选择与生成之间的任何差距都是两类通信协议之间的差距。我们证明了存在一组查询，使得生成严格需要比选择更少的预算。上下文生成博弈与单向通信之间的等价性也使我们能够衡量部署的上下文压缩算法相对于最优策略在查询上的表现。作为示例，我们提供了一个案例研究，评估了Anthropic的上下文压缩端点在集合成员查询上的表现。

## Abstract
Large Language Models (LLMs) have a bounded context window. The context window is the maximum input size an LLM can consume for a single inference. AI agents rely on a process called context compaction to fit their state within the context window when calling an LLM. Despite its ubiquity, context compaction has received essentially no formal analysis. In this paper, we initiate a formal study of context compaction. We first introduce a framework consisting of two games that capture the two algorithmic strategies for context compaction used by contemporary AI agents in practice. The Context Selection Game models context compaction algorithms that select a subset of an agent's accumulated state to retain. The Context Generation Game models context compaction algorithms that summarize an agent's state by an arbitrary message of bounded length. We then prove an equivalence between the Context Generation Game and one-way communication complexity. The minimum context compaction budget for answering a set of queries within a target error is equal to the one-way communication complexity of the induced communication problem at the same error. Known bounds from communication complexity therefore transfer directly to context compaction. We also show that the Context Selection Game corresponds to a restricted class of one-way communication protocols. Any gap between selection and generation is therefore a gap between two classes of communication protocols. We prove that there exists a set of queries for which generation needs strictly less budget than selection. The equivalence between the Context Generation Game and one-way communication also lets us measure how well a deployed context compaction algorithm performs on a query relative to the optimal strategy. As an example, we present a case study that evaluates Anthropic's context compaction endpoint on set membership queries.

- **核心困境**：上下文压缩会丢失信息，且压缩后代理仅携带压缩结果进入后续会话步骤，丢失的信息将永久性地影响 LLM 未来的决策。然而，尽管这一操作在 Claude Code、Cursor、Codex 等生产级代理系统中无处不在，却缺乏形式化的理论分析。
- **论文意义**：本文首次为上下文压缩建立严格的形式化理论框架，将压缩预算与通信复杂度的经典界连接起来，为理解"压缩需要保留多少信息"提供了理论基准，也为评估实际部署算法提供了量化工具。

## 2. 方法论

### 2.1 两种博弈框架

论文将上下文压缩抽象为两个博弈，均发生在"压缩算法"与"代表未来信息需求的对手"之间：

- **上下文选择博弈（Context Selection Game）**：建模基于子集选择的压缩算法。选择者（selector）只能保留原状态中的一部分条目，需满足预算约束 B；对手随后提出查询 q，选择者以保留子集 S 回答查询，并根据值函数 vq 计算误差。该游戏覆盖 SELECT 类算法（输出为原条目的无序子集）。
- **上下文生成博弈（Context Generation Game）**：建模基于生成的压缩算法。生成器（generator）可将状态压缩为任意有界长度的消息，不要求输出是原始条目的子集，允许重排、重新编码乃至 LLM 摘要。形式化为"冷凝器–解释器"（Condenser–Interpreter）对：冷凝器将状态映射为长度 ≤ B 的摘要，解释器根据摘要和查询产生答案。该类算法统属 GEN 类。

### 2.2 核心定理：生成博弈 ≡ 单向通信复杂度

- **定理 1（生成 ≡ 单向通信）**：将冷凝器视为 Alice、解释器视为 Bob，上下文生成博弈直接对应于一个单向通信问题 ΠG。具体地：
  - 随机查询制度下，达到期望误差 ≤ ε 的最小压缩预算 = R→μ,ε(ΠG)（μ-分布单向随机通信复杂度）；
  - 不知情对手制度下，达到最坏输欧误差 ≤ ε 的最小预算 = R→ε(ΠG)（标准单向随机通信复杂度）。
  - 证明的关键：GEN 算法（Cond, Int）与单向协议本质上是由同一对函数描述的，二者逐输入误差相同。
- **推论 2（选择作为受限协议）**：SELECT 类算法恰好对应一类受限单向协议——Alice 的消息必须标识一个预算限制下的子集，Bob 的输出仅依赖该子集、查询和公共硬币。
- **定理 3（选择 ⊊ 生成）**：存在 n 个条目的集合和单一查询，使得生成算法可用 n 比特零误差回答，而任何选择算法至少需要 n log₂n 比特，产生 Θ(log n) 的预算差距。

### 2.3 查询制度

论文定义了两种查询制度：随机查询制度（输入按分布 μ 抽取，目标是期望误差）和不知情对手制度（对手在不知道选择结果的情况下选定输入，目标是最大误差）。自适应对手（能观察到压缩输出后再提问）不在定理 1 覆盖范围内，作为开放问题留给未来。

## 3. 实验设计

- **案例场景**：集合成员查询（set membership），即判断某项是否在记录的集合中。这是通信复杂度已知的自然基准。
- **数据集**：Malicious URLs 数据集（Kaggle），包含具有结构特征的 URL 记录。选择该数据集是因为 URL 具有共享的域和路径结构，便于压缩算法利用结构进行压缩，属于有利于压缩端点的场景。
- **实验流程**（附录 A）：
  - 从数据集中均匀采样 15,000 个 URL，放入 LLM 上下文（约 500k tokens）。
  - 调用 Anthropic 的上下文压缩端点（Claude Opus 4.8），压缩为约 14 Kbits 的自然语言摘要。压缩提示词明确告知端点其后只做成员查询。
  - 压缩后，提出 200 个成员查询（100 个正样本——集合内抽取；100 个负样本——集合外抽取），每次查询单独请求，仅携带压缩上下文。
  - 重复 3 个随机种子。
- **对比方法与基准**：
  - **Bloom 过滤器**（同预算）：误差率为 ½e−(ln 2)²B/N，是集合成员查询的近最优压缩算法（在最坏情形下达到最优的 1.44 倍因子内）。
  - **信息论下界**：误差率 ≥ ½·2^(−B/N)。
  - **随机猜测**：误差率 0.5。
  - **控制实验**：不压缩、完整保留 15,000 个 URL 的情况下回答相同查询（误差率 0.02）。

## 6. 论文的主要结论与发现

- **理论结论**：
  1. 上下文生成博弈与单向通信复杂度完全等价：最小压缩预算 = 诱导通信问题的单向复杂度（分别对应随机/不知情对手制度）。
  2. 上下文选择博弈对应受限的单向协议（子集编码协议）。
  3. 存在查询集合上生成严格优于选择，差距为 Θ(log n)。
- **应用实例**（set disjointness）：对于依赖集合与 CVE 包集合的相交查询，压缩上下文需携带 Ω(Nm) 比特才能正确回答，等价于不压缩存储依赖列表；即便用 Bloom 过滤器做近似，当查询可覆盖全集时仍回到同样的下界。
- **案例研究发现**：Anthropic 的压缩端点在集合成员查询上以约 50%–55% 的误差率运行，接近随机猜测；同预算的 Bloom 过滤器误差仅约 1/3。控制实验排除了解释误差的其他原因，确认信息在压缩过程中丢失。

## 8. 不足与局限

- **信息论而非计算论**：定理 1 证明的是"至少需要多少比特"，并不保证现实中的 LLM 摘要器能算到这个界限；一个可利用的最优预算可能在实际算法中不可达到。
- **单次压缩模型**：真实代理在会话中反复压缩，每次压缩作用于先前压缩的产物，信息随次数累积丢失。论文仅建模单次调用，重复压缩的行为特征作为开放问题留下。
- **查询制度受限**：自适应对手（观察到压缩结果后选择查询）未覆盖，而真实用户的问题往往受当前上下文影响，可能接近自适应情形。
- **案例实验覆盖窄**：仅一个端点、一个数据集、一类查询、3 个种子；未测试不同模型版本、不同提示词或不同压缩 API 的差异。
- **选择博弈的粒度问题**：条目划分依赖于建模决策，不同粒度（token、消息、工具结果）可能得出不同的复杂度界，论文对此保持"模型无关"但对实际应用者可能缺乏指导。
