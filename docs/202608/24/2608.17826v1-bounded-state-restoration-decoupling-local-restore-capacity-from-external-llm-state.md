## 摘要
分层KV缓存系统可以在GPU内存之外保留长上下文LLM执行状态，但保留容量并不决定使该状态再次可执行所需的本地内存。我们将这第二种资源隔离为恢复工作集（RWS）：在恢复期间生命周期重叠的峰值本地暂存状态。在固定的上游LMCache全路径中，1.956、7.823和15.646 GiB/秩状态的实测完全重用点分别首次在2、8和16 GiB L1层级成功，成功的L1峰值分别为1.956、7.824和15.648 GiB/秩。我们引入了有界状态恢复（BSR），它将完全发现与本地驻留分离。BSR在不将整个命中物化到L1的情况下探测完全可重用前缀，然后通过一个至多包含$W$个块的可重用窗口安装已确认状态。在有界辅助状态下，峰值恢复容量为$O(W)$，而总传输和安装工作量保持$Θ(|S|)$。由于可重用状态跨越异构分配器组和张量并行秩，BSR使用请求级提交规则：部分安装永远不会作为有效的可重用前缀暴露；故障会使通告的前缀失效，并回退到较低的有效层级或确定性重计算。在跨两个DGX Spark节点的TP=2的DeepSeek-V4-Flash上，一次干净的无恢复扫描将外部状态从1.956增加到31.277 GiB/秩，而实测L1 RWS在$W=32$时恰好保持500.75 MiB/秩，最大状态外部与活动暂存之比为63.959倍。第二次全新的524K令牌运行重复了最大状态接受结果。评估的层级和秩不对称故障在回退前暴露完全重用或零外部重用。一项匹配的SSD优化将512K恢复TTFT从43.1秒降低到17.6秒，而RWS不变。

## Abstract
Hierarchical KV-cache systems can retain long-context LLM execution state beyond GPU memory, but retention capacity does not determine the local memory required to make that state executable again. We isolate this second resource as the restoration working set (RWS): the peak local staging state whose lifetimes overlap during restoration. In the pinned upstream LMCache whole-plan path, measured full-reuse points for 1.956, 7.823, and 15.646 GiB/rank states first succeed at 2, 8, and 16 GiB L1 rungs, with successful L1 peaks of 1.956, 7.824, and 15.648 GiB/rank.   We introduce Bounded-State Restoration (BSR), which separates complete discovery from local residency. BSR probes the complete reusable prefix without materializing the whole hit in L1, then installs confirmed state through a reusable window of at most $W$ chunks. Under bounded auxiliary state, peak restoration capacity is $O(W)$ while total transfer and installation work remains $Θ(|S|)$. Because reusable state spans heterogeneous allocator groups and tensor-parallel ranks, BSR uses a request-level commit rule: partial installation is never exposed as a valid reusable prefix; failures invalidate the advertised prefix and fall back to a lower valid tier or deterministic recomputation.   On DeepSeek-V4-Flash with TP=2 across two DGX Spark nodes, a clean no-resume sweep grows external state from 1.956 to 31.277 GiB/rank while measured L1 RWS remains exactly 500.75 MiB/rank at $W=32$, a 63.959x largest-state external-to-live-staging ratio. A second fresh 524K-token run repeats the largest-state acceptance result. Evaluated tier and rank-asymmetric failures expose either complete reuse or zero external reuse before fallback. A matched SSD optimization reduces 512K restore TTFT from 43.1 to 17.6 seconds without changing RWS.

## 1. 核心问题与整体含义

**研究动机与背景：**
- 长上下文 LLM 服务越来越倾向于将先前的计算视为可复用的执行状态。分层 / 解聚式 KV 缓存系统（如 Mooncake、LMCache）可将这些状态保存在主机内存、SSD 或远端内存中，从而显著扩大**外部保留容量（retention capacity）**。
- 然而，保留容量并不决定恢复该状态所需的**本地内存**。论文指出这是一个独立的资源维度——恢复工作集（Restoration Working Set, RWS），即恢复过程中生命周期重叠的峰值本地暂存状态。
- 上游 LMCache 基线路径中，恢复时需要将完整的选中状态物化到本地 L1，导致本地恢复容量与外部状态大小成正比耦合（RWS 随状态规模线性增长），例如 1.956 GiB、7.823 GiB、15.646 GiB 的状态分别需要 2 GiB、8 GiB、16 GiB 的 L1 层级才能完成全量复用。
- **核心问题**：运行时能否在知晓完整可复用外部状态的前提下，仅通过一个有界本地工作集恢复状态，同时保持请求级正确性和对异构张量并行状态的故障闭合恢复？

**整体含义：**
- 论文提出**有界状态恢复（Bounded-State Restoration, BSR）**，将"完全发现（complete discovery）"与"本地驻留（local residency）"分离，使峰值本地恢复容量可从外部状态规模中解耦，变成可由参数 $W$ 显式控制的资源。外部状态增长仅增加迭代次数而非同时驻留的本地暂存量。

## 2. 方法论

**核心思想**：发现完整可复用前缀所需的"知识"不需要同时物化全部字节；BSR 通过分离三个阶段——探测（Probe）、安装（Install）、提交（Commit），实现"完整知识 + 有界驻留"。

**关键技术细节与算法流程：**

- **恢复工作集定义**：
  $$
  \text{RWS}(\rho) = \max_t \sum_{u_i \in L_\rho(t)} c_i
  $$
  其中 $L_\rho(t)$ 是时刻 $t$ 在本地暂存层中同时存活的恢复单元集合，$c_i$ 为单元暂存占用。该定义排除外部保留副本和正常模型执行所需的目标内存。

- **三阶段协议**：
  - **Probe（探测）**：存储层只返回完整候选命中位图（hit bitmap），释放查找侧 L1/L2 锁，不将全部命中的 L2 结果保留在 L1。调度器在分配目标块之前即可得知完整外部命中集。
  - **Install（安装）**：在分配目标块之后，将确认的前缀按至多 $W$ 块一个窗口的方式迭代安装；每窗口执行"获取→验证→映射→传输→同步→释放"，只有释放后才能重用暂存空间。当前原型用专用锁串行化有界恢复。
  - **Commit（提交）**：请求级语义提交。只有所有 TP 秩和语义分组的校验都通过（$Q(S) = \bigwedge_r \bigwedge_g q_{r,g} = 1$）才暴露完整前缀复用；任何窗口失败、超时或传输异常都会使目的地块无效，并将通告前缀整体降级（fallback 到较低有效层级或确定性重计算）。失败后设置 force-local 标记，防止重复触发相同外部故障。

- **容量界**：
  $$
  \text{RWS}_{\text{BSR}}(S, W) \le W c_{\max} + M_{\text{aux}}(W)
  $$
  在固定模型注册和固定 $W$ 下，峰值恢复池容量为 $O(W)$ 且与 $N$ 无关（Proposition 1）——状态增长转化为窗口迭代次数 $K = \lceil N/W \rceil$ 的增长，总工作量仍为 $\Theta(|S|)$。

- **内存实证法则**：对于 MTP-off 的 DeepSeek-V4-Flash 注册，源端核算给出
  $$
  M_{L1}(W) = W \times 16{,}408{,}576 \text{ bytes/rank}
  $$
  实测零残差匹配。

- **实现落点**：扩展现有 LMCache 和 vLLM，新增机制包括：probe-only 查找、恢复窗口配置、窗口化检索、有界检索锁、失败块失效、HMA 感知的全前缀失效、force-local 恢复、FS 加载并发度旋钮。模型内核与外部状态表示不变。

## 3. 实验设计

**模型与系统拓扑：**
- DeepSeek-V4-Flash，TP=2，分布于两个 DGX Spark 节点；每秩通过 100 Gb/s RDMA 连接到外部 Mooncake 存储（128 GiB 段，严格租户隔离），另有本地 SSD/NVMe 作为低一级可复用层。
- MTP-off 注册含 167 个张量（MTP-on 为 170 个），LMCache 块大小 256 令牌。

**实验类型（5 类）：**

1. **上游全规划容量阶梯**（Whole-plan Ladder）：$W=0$，逐步增加 L1 容量直至全前缀复用成功，测量 32K/128K/256K 三个前缀。目的是量化基线路径的容量耦合。
2. **同纪元干净 BSR 缩放扫描**：$W=32$、MTP-off、L1 配置 1 GiB、直接 RDMA；同一批引擎上一次无恢复扫描中评估 32768~524032 六个上下文长度（br-e1-0c12f749f250）。另以新 salt 重复 524K 运行（br-e1-e956c433d35d）验证可重复性。
3. **$W$ 容量控制法则**：在 256K 下测量 $W \in \{8, 16, 32, 64\}$ 的 RWS，验证 $M_{L1}(W)$ 关系。
4. **异构状态与故障闭合**：524K MTP-on（170 张量）；故障矩阵包括远端存储不可用、远端+SSD 均缺失、单秩远端恢复故障。
5. **吞吐量与容量分离 A/B**：512K SSD 恢复中 FS 加载并发度从 1 提高到 4，测量恢复 TTFT 与 RWS 变化。

**成功接受标准**（每个恢复必须满足）：模型与状态注册匹配；报告预期全量缓存令牌；按计数器验证使用预期分层；规范输出哈希与冷执行一致；双 TP 秩健康。故障案例额外检查缓存令牌账目是否符合降级目标（完整低层级复用或零外部复用后重算）。

**对比基线**：上游固定 LMCache 全规划路径（$W=0$）。

## 6. 主要结论与发现

- **容量解耦生效**：在干净的同一纪元扫描中，外部状态从 1.956 增长至 31.277 GiB/秩（增长 15.99 倍），而 $W=32$ 的实测 L1 RWS 恒定在 500.75 MiB/秩，最大外部状态与活动暂存比为 **63.959 倍**。
- **$W$ 是精确容量控制器**：$W \in \{8,16,32,64\}$ 下 RWS 严格等于 $W \times 16{,}408{,}576$ 字节/秩，零残差。
- **异构与故障保持闭合**：524K MTP-on（170 张量）满足同样接受标准；三种故障场景均表现为"完整前缀复用或零外部复用"后回退，没有观测到部分前缀暴露。
- **吞吐与容量可分离**：FS 加载并发从 1 提高到 4，512K SSD 恢复 TTFT 从 43.1 秒降至 17.6 秒（2.45 倍提速），而 RWS 不变（仍为 500.75 MiB/秩）。
- **三个资源维度相互独立**：外部保留容量、本地恢复容量（RWS）、执行余量和恢复吞吐量分别由外部层级、恢复算法和存储调度控制，不应混淆。

## 7. 优点

- **问题定义清晰且有独立价值**：明确将 RWS 从外部状态足迹、目标执行内存中分离，提出新资源维度。
- **抽象与实现之间的措辞严谨**："知识 vs 驻留"的分离是一干净的概念突破；$O(W)$ 容量界与 $\Theta(|S|)$ 工作量明确区分。
- **实验干净、可复现**：同一无恢复扫描完整覆盖 6 种状态规模，实测 RWS 范围为零，极具说服力；证据锚定到提交仓库和原始数据。
- **强接受标准**：输出哈希一致 + 缓存 token 账目 + 分层计数 + 秩健康检测，比仅检查对象计数或字节数强得多。
- **故障语义显式**：请求级提交规则、HMA 感知失效、force-local 恢复共同形成 fail-closed 闭环。
- **正交优化演示**：SSD 并发 A/B 展示吞吐优化不触碰空间契约。

## 8. 不足与局限

- **不是进程总内存的恒定保证**：RWS 只约束 LMCache L1 恢复池；模型权重、目标 KV 状态、分配器元数据、通信缓冲等仍可变。
- **系数非通用**：16,408,576 字节/W 只对特定模型注册与块几何成立；其他模型/状态表示有不同 $c_i$。
- **当前并发性保守**：全局串行化有界恢复便于审计但限制多请求重叠；论文提出"全局预算 B"作为自然扩展但未实现。
- **512K 上游点缺失**：未完成 512K/32 GiB 的上游全规划测量，基线对比到 256K 为止，结论未覆盖更长上下文的整路径对比。
- **正确性为操作性而非形式化**：接受标准虽然强，但不是对任意提示/未来模型生成都等价的形式证明；Proposition 2 依赖实现规则成立。
- **性能非最优**：远程路径中查找、物化、安装、同步开销仍存在；$W$ 变化对延迟的影响未做严格统计比较。
- **单模型、单配置**：实验集中在一种模型和一个 TP=2 系统，推广性依赖抽象而非广泛经验验证。
