## 摘要
共享前缀缓存将图形处理器（GPU）内存转化为跨大语言模型（LLM）租户共享的持久状态。一个组实例化新的键值（KV）块可能迫使另一个组丢失可复用状态，然而请求时调度器仅考虑瞬态服务，替换策略主要对对象价值进行排序，静态分区则会闲置容量。我们将这种不匹配称为准入责任鸿沟。为弥合这一鸿沟，我们提出PrefixShield，它对新实例化的完整KV块进行计量，跨请求传递责任，在债务未清时门控复用提升，并利用预测债务来选择提供逐出候选的组。我们在vLLM中实现了PrefixShield。在一次性污染下的配对运行中，PrefixShield相比最近最少使用（LRU）策略将受害者缓存命中率提高了9.39个百分点，相比S3-FIFO提高了8.64个百分点，在4096块规模下将受害者命中率从4.92%恢复至84.87%，并在两次回放中比S3-FIFO提升2.00个百分点。它保持了良性的ShareGPT行为和保工作（work-conserving）地对闲置容量的访问。延迟回放在债务未清时产生35.16个百分点的优势。这些结果表明，对象价值信号决定保留哪些内容，而持久责任则决定哪个组承受回收压力。

## Abstract
Shared prefix caching turns Graphics Processing Unit (GPU) memory into persistent state shared across Large Language Model (LLM) tenants. A group that materializes new Key-Value (KV) blocks can force another to lose reusable state, yet request-time schedulers account for transient service, replacement policies primarily rank object value, and static partitioning strands idle capacity. We call this mismatch the admission-responsibility gap. To close it, we propose PrefixShield, which meters newly materialized full KV blocks, carries responsibility across requests, gates reuse promotion while debt remains, and uses projected debt to select the group supplying eviction candidates. We implement PrefixShield in vLLM. In paired runs under one-touch pollution, PrefixShield improves victim cache hit ratio by 9.39 percentage points over the Least Recently Used (LRU) policy and 8.64 points over S3-FIFO, restoring the victim from 4.92% to 84.87% at 4096-block scale, and gains 2.00 points over S3-FIFO under two-pass replay. It preserves benign ShareGPT behavior and work-conserving access to idle capacity. Delayed replay yields a 35.16-point advantage while debt remains. These results show that object-value signals rank what to retain, while persistent responsibility determines which group bears reclamation pressure.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：多租户大语言模型（LLM）服务中，前缀缓存（Prefix Caching）将 GPU 内存转化为跨租户共享的持久状态。当请求复用系统提示词、模板、对话历史等公共前缀时，保留其 KV 状态可避免重复预填充计算，降低服务成本和延迟。vLLM、SGLang 等系统已广泛采用该技术。
- **核心问题**：论文提出并形式化了一个此前未被明确识别的问题——**准入责任鸿沟（Admission-Responsibility Gap）**：在共享缓存中，一个会计组（accounting group）不断实例化新的 KV 块，会迫使另一个组丢失可复用状态；但创建缓存压力的组并不一定是承受状态被逐出后果的组。请求时调度器只处理瞬态服务，替换策略（如 LRU、S3-FIFO）主要按对象价值排序，静态分区则闲置容量——三者都无法弥合这一鸿沟。
- **整体含义**：这是一个不同于请求时服务公平性的问题。缓存 KV 状态在创建请求完成后仍然存在，并持续影响后续替换决策。需要一个机制在保持全局共享和工作守恒（work-conserving）的同时，将"谁创造了压力"与"谁承担回收代价"重新关联起来。

### 2. 论文提出的方法论：PrefixShield

**核心思想**：引入新持久缓存压力的会计组，应持续对该压力负责，直至其准入债务（admission debt）得到清偿。责任机制只在共享容量**发生竞争时**生效，不构成准入拒绝或静态容量上限。

**三大关键技术机制**：

1. **完全计量的准入责任（Fully Metered Admission Responsibility）**
   - 计量对象是实际新物化的完整 KV 块数（`n_r`），而非请求活动量；纯缓存命中（`n_r = 0`）不产生任何新增费用。
   - 每个会计组 `g` 和服务合同 `c` 维护块计数的余额 `B_{g,c}`：有效值随时间以速率 `ρ_c` 懒惰式补充（refill），上限为突发容量 `β_c`；新块物化时余额减去 `n_r`。
   - 负余额不代表拒绝准入，而是代表未清偿的准入责任；债务随时间自然恢复——组停止创建新状态后，按 `τ = max(d_{g,c}/ρ_c)` 的时间清零（Proposition 1）。
   - 新块初始分配保留等级（retention class）：首次准入或组处于债务状态时进入 `PROBATIONARY`；资金充足时的后续准入可进入 `NORMAL`。

2. **债务门控的复用提升（Debt-Gated Reuse Promotion）**
   - 防止"复用洗钱"（reuse laundering）：攻击组可通过回放自造的污染前缀来制造虚假复用证据，从而将低价值状态提升为高保留等级。
   - 提升条件：复用证据成立 + 同一组/合同/逻辑前缀匹配 + 组的有效原始债务已清偿（`D_g(t) ≤ ε`）。债务未清时仍记录复用和访问元数据，但不提升等级。
   - 同一组的合同切换不能绕过门控，因为债务按组聚合。

3. **责任感知的复用分段逐出（Responsibility-Aware Reuse-Segmented Eviction）**
   - 将逐出决策拆分为两个问题：**哪个组承担回收**（由归一化债务 `\tilde{D}_g(t)` 决定，按合同权重 `w_c = ρ_c/ρ_min` 归一化，衡量压力相对于合同额度的超额程度）和 **该组的哪个块被逐出**（由保留等级决定：`PROBATIONARY ≺ NORMAL ≺ REUSE`）。
   - 批量逐出时使用临时"投影责任分"（projected responsibility score）`P_g`，每组选出一个受害者后按其最小归一化递减量（`1/W_g`）保守扣减，以在批次内平衡。
   - 无组处于债务状态时，全局按保留等级逐出，退化为复用感知策略。

**工作守恒性**：PrefixShield 不设固定占用上限，不拒绝债务组的准入；真正空闲的块（true-free）总是优先分配。责任机制仅在容量争议时激活。

### 6. 论文的主要结论与发现

- **一次性污染（One-touch）**：PrefixShield 将受害者命中率从 LRU 的 5.54% 提升至 14.93%（配对提升 9.39 pp，95% CI 7.94–10.96），比 S3-FIFO 高 8.64 pp（95% CI 7.23–9.43）；在 4096 块规模下，受害者命中率从 LRU 的 4.92% 恢复至 84.87%（提升 79.95 pp）。
- **低慢旋转（Low-and-slow）**：PrefixShield 恢复受害者至 98.90%，恢复 LRU 攻击损失的 95.5%；S3-FIFO 为 98.64%，PrefixShield 保持 0.25 pp 的统计显著优势。
- **两遍回放（Two-pass replay）**：PrefixShield 达到 95.97%，优于 S3-FIFO 2.00 pp（95% CI 0.93–3.23），P95 TTFT 比 S3-FIFO 低 36.5 ms。
- **良性负载**：与 S3-FIFO 无统计差异（ShareGPT 38.92% vs 38.85%；bursty 38.10% vs 38.72%）——责任保护不牺牲良性命中率。
- **工作守恒**：PrefixShield 与 S3-FIFO 均占用 509–510/511 个可用块，与 LRU 命中率持平（99.33%）；StaticQuota 被限制在 254–255 块。
- **机制归因**：复用分段贡献 1.84–3.38 pp 增益；债务门控在债务未清时阻止全部 193 个回放块提升，产生 35.16 pp 的受害者命中率差异，债务清偿后两组收敛——门控只延迟而非永久惩罚。
- **核心结论**：**对象价值信号决定保留哪些内容；持久责任信号决定哪个组承受回收压力**。二者互补，不可相互替代。

### 7. 优点

- **问题定义精准且新颖**：清晰识别出"准入责任鸿沟"这一此前未被系统研究的机制，区分了请求活动与缓存创建、对象价值与组责任的差异。
- **设计优雅**：三大机制（计量创建、债务门控、责任分段逐出）结构清晰，两条不变量（I1 完整压力归因；I2 债务不可通过复用洗钱）简洁有力。
- **工作守恒与非侵入性**：不拒绝准入、不设容量上限，只在容量竞争时激活；实现不修改模型计算或 KV 内容，可部署性较强。
- **债务自恢复机制**：token bucket + 懒惰式 refill 的设计允许临时突发被吸收，债务随时间自动清偿，避免永久惩罚。
- **实验设计严谨**：配对运行 + bootstrap CI；与 S3-FIFO 的直接对比隔离了"价值信号"与"责任信号"；两个消融实验分别精准定位两个机制的贡献；容量 8 倍范围扫掠和压力比扫掠验证了鲁棒性。
- **机理隔离清晰**：延迟回放实验精确测定了债务门控的效力边界（债务清偿前 35.16 pp，清偿后归零），说明机制是时间性而非永久性的。
