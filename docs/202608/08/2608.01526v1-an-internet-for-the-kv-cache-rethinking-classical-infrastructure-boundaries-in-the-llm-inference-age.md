## 摘要
LLM推理已成为一种全球规模的异构工作负载，涵盖代理、检索、工具使用、代码执行和多模态推理。这些工作负载自然地从重叠输入中实现上下文复用，创造了存储和复用上下文的KV缓存而非重新计算它们的重大机会。然而，模型端缩小KV缓存的技术进步和系统端降低计算、存储和传输成本的进步，在传统云边界内独立演进。我们认为，未来的推理基础设施应该允许在云和数据中心之间解耦计算和KV缓存存储。网络成为主动分发渠道；带宽、延迟和定价直接决定KV缓存应如何管理。我们提出了一个KV缓存互联网的愿景，将KV缓存管理作为内容分发系统运作。在此视角下，KV缓存的存储和重新计算决策由模型、基础设施和应用指标驱动，以实现自适应的、内容驱动的决策，从而最小化延迟和成本。

## Abstract
LLM inference has become a global-scale, heterogeneous workload spanning agents, retrieval, tool-use, code execution and multi-modal reasoning. These workloads naturally enable context reuse from overlapping inputs, creating a major opportunity to store and reuse the contexts' KV Caches instead of recomputing them. However, model-side advances that shrink the KV Cache and system-side advances that reduce compute, storage, and transfer costs are evolve independently within legacy cloud boundaries. We argue that future inference infrastructure should allow decoupling of compute and KV Cache storage across cloud and datacenters. The network becomes an active distribution channel; bandwidth, latency and pricing directly determines how the KV Cache should be managed. We propose a vision for an Internet for the KV Cache, with KV Cache management working as a content-distribution system. In this view, KV Cache storage and recompute decisions are driven by model, infrastructure, and application metrics, to enable adaptive, content-driven decisions for minimizing latency and cost.

## 2. 方法论：核心思想、关键技术细节与公式

- **核心思想**：KV Cache 不应被视为绑定在 GPU 或存储上的本地数据结构，而应视为**可移动的推理状态**，在时间维度上具有不同的复用周期（秒、分钟、小时），因此可以根据预期复用率和传输成本选择放在热、温、冷存储层，甚至跨云移动。
- **内容分发模式**：借鉴 CDN 思想，将 KV Cache 向靠近未来需求的位置预取、复制、迁移；当传输代价过高时，可以选择部分或完全重新计算（recompute），并将重新计算的 KV Cache 按更新后的放置策略传播。
- **决策框架（量化公式）**：
  - 定义 `CacheCost` 为存储 + 传输 KV Cache 的成本，`PrefillCost` 为重新计算 prefill 的成本。
  - 核心公式：

    \[
    \frac{CacheCost}{PrefillCost} = \frac{(DeviceCost_{hr} \cdot K + TransferCost) \cdot KV_{MB}}{GPUCost_{hr} \cdot (PrefillTFLOPs / PeakFlopRate)}
    \]

  - 其中 `DeviceCost_hr` 为单位存储设备每小时成本，`K` 为复用频率，`TransferCost` 为每 MB 传输成本，`GPUCost_hr` 为 GPU 每小时成本，`PrefillTFLOPs` 为 prefill 所需算力，`PeakFlopRate` 为 GPU 峰值吞吐。
  - 由此推导出**模型侧比率**（Prefill TFLOPs / KV MB）和**基础设施-应用侧比率**（(DeviceCost_hr·K + TransferCost)/(GPUCost_hr/PeakFlopRate)）。当二者比较关系变化时，存储或重算的决策可能反转。
  - 论文还强调：相比提高 KV Cache **命中率**，降低 **miss-rate** 更重要，因为缓存未命中时可能需要重算长上下文，代价极高。建议通过非前缀匹配的 KV Cache 混合（如 CacheBlend、Cache-Craft 的层级缓存融合）来提升复用的鲁棒性。
- **架构设想**：
  - 构建**全局 KV Cache 控制平面**，包含 KV Cache 目录、查找服务、放置规划器和预取调度器。
  - 支持根据复用周期分层存储（hot/warm/cold），并做带宽感知的 KV Cache 移动。
  - 决策动作包括：store / load / prefetch / partial fetch / recompute / evict。
  - 需要跨监管者和提供商协调协议，类似 IETF 的标准化组织来定义传输、安全、互操作及故障处理规则。

## 6. 主要结论与发现

- KV Cache 复用已将 LLM 推理从“计算-存储权衡”转变为“互联网规模内容管理问题”。
- 现有云边界（区域、可用区、供应商间）导致 KV Cache 无法自由流动，阻碍了潜在的成本和延迟优化。
- 存储还是重算的决策**不是普适的**，取决于模型侧比率与基础设施-应用侧比率的比较；同一模型在不同基础设施或复用频率下会有不同的最优选择。
- 为了解锁 KV Cache 跨请求复用的潜力，应将降低 **miss-rate** 作为核心目标，并支持非前缀匹配的 KV Cache 融合。
- 网络和存储应被视为**一等推理资源**，推理系统的调度应基于带宽、传输成本、延迟和复用预测进行动态决策。
- 需要新的控制平面、协议、抽象和跨组织协调机制来支持全球范围的 KV Cache 分发。
