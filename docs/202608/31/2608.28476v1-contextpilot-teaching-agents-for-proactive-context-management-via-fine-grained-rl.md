## 摘要
长期智能体任务要求大型语言模型（LLMs）在多轮交互中迭代地检索、整合并维护分散的信息，但保留所有交互历史会导致工作上下文不断增长。近期的主动上下文管理方法允许模型使用专门工具编辑自身的工作上下文，然而它们仍面临三个关键限制：（1）工具集有限，仅限于搜索、删除和摘要，不支持全局规划、长期记忆和自适应压缩；（2）探索效率低下，将上下文管理动作视为统一处理，尽管它们对最终结果具有异质影响；（3）粗粒度的信用分配，在强化学习中将最终的轨迹级奖励分配给所有中间的上下文编辑动作。为解决这些不足，我们提出了ContextPilot，一个面向长期智能体推理的主动上下文管理框架。我们的方法系统地扩展了工具集，加入了规划、长期记忆和软上下文卸载工具。我们进一步提出了一种针对上下文管理定制的强化学习方法，利用上下文和熵变化来识别关键编辑决策以进行分支采样，并从所有通过相应上下文编辑动作的分支轨迹中估计动作级优势。在长上下文问答和深度搜索任务上的实验表明，ContextPilot在更紧凑的工作上下文下实现了更强的性能，在各种基础模型和基准测试上始终优于现有基线。代码可在https://github.com/Tencent/ContextPilot获取。

## Abstract
Long-horizon agentic tasks require large language models (LLMs) to iteratively retrieve, integrate, and maintain dispersed information across multi-turn interactions, but preserving all interaction histories leads to a continuously growing working context. Recent proactive context management methods allow models to edit their own working context with specialized tools, yet they still face three key limitations: (1) a limited toolset restricted to search, deletion, and summarization, with no support for global planning, long-term memory, and adaptive compression; (2) inefficient exploration that treats context management actions uniformly despite their heterogeneous impacts on final outcomes; and (3) coarse-grained credit assignment that assigns the final trajectory-level reward to all intermediate context editing actions during RL. To bridge these gaps, we introduce ContextPilot, a proactive context management framework for long-horizon agentic reasoning. Our approach systematically augments the toolset with planning, long-term memory, and soft context offloading tools. We further propose an RL method tailored for context management, which uses context and entropy variation to identify critical editing decisions for branch sampling and estimates action-level advantages from all branched trajectories that pass through the corresponding context editing action. Experiments on long-context QA and deep search tasks show that ContextPilot achieves stronger performance with a more compact working context, consistently outperforming existing baselines across various base models and benchmarks. Code is available at https://github.com/Tencent/ContextPilot.

### 一、论文的核心问题与整体含义（研究动机与背景）

- **核心问题**：在长程（long-horizon）智能体任务中，LLM 需要在多轮交互中反复检索、整合和维护分散的信息。然而，以 ReAct 为代表的传统智能体范式将全部推理过程、工具调用和工具响应无差别地追加到上下文中，导致工作上下文随交互轮次持续膨胀，最终超出上下文窗口限制并损害推理性能。
- **现有解决方案的不足**：已有研究通过人为设计的规则（截断、摘要）或主动上下文管理工具来缓解上下文膨胀，但现有方法存在三大关键缺陷：
  1. **工具集受限**：仅有搜索、删除、摘要等基础工具，缺乏全局规划、长期记忆和自适应压缩能力；
  2. **探索低效**：将所有上下文管理动作视作等价处理，忽略了不同编辑操作对最终结果影响力的巨大差异（论文通过实验发现不同工具的轨迹分支成功率标准差差异显著，从 0.74 到 2.79 不等）；
  3. **信用分配粗糙**：直接以最终轨迹级奖励回传给所有中间上下文编辑动作，未能区分各编辑决策的实际贡献；且最终正确性与上下文管理质量之间存在错位（正确轨迹可能依赖低效的重复检索，错误轨迹反而可能包含合理管理），导致奖励信号失真。
- **整体含义**：本文主张将智能体从被动接受规则管理的上下文转变为**主动的自上下文管理者**，通过更全面的工具集和专门设计的细粒度强化学习算法，让模型自主决定何时、以何种方式编辑自己的工作上下文，以更紧凑的上下文实现更强的任务性能。

### 二、论文提出的方法论

#### 2.1 核心思想

ContextPilot 的核心理念是"**主动上下文管理**"——让 LLM 像操作系统管理内存一样管理自己的工作上下文。具体通过两条路径实现：（1）**扩展工具集**，赋予模型规划、长期记忆和软卸载能力；（2）**定制化 RL 训练**，针对上下文管理动作的特殊性（对后续轨迹影响大且异质），设计精细化的探索与信用分配机制。

#### 2.2 工具集设计

在 StateLM 基础工具之上新增三类工具：

| 类别 | 新增工具 | 功能 |
|------|----------|------|
| 规划 | `plan` | 提出简洁的后续行动计划 |
| 长期记忆 | `memorize` / `updateMemory` / `readMemory` | 提取实体、时间戳和事件片段的**结构化记忆**，构建跨片段关联边，支持邻居检索 |
| 软上下文卸载 | `summarizeContext` / `compressContext` / `foldHistory` | 分别以摘要、轻量压缩模型（LLMLingua-2）、关键字+摘要折叠方式将历史"软删除"，可通过搜索恢复 |

完整工具集共 16 个（含感知、检索、短期记忆、删除等原有工具）。其中，上下文卸载、记忆写入和记忆更新被归类为**上下文编辑动作**，用于轨迹快照切分。

#### 2.3 两阶段训练流程

**第一阶段：SFT（监督微调）**
- 以 Qwen3.5-397B-A17B 为教师模型，通过精心设计的**上下文管理 harness**（动态展示满足前置条件的工具、失败重试提示等）生成示范轨迹；
- 采用三阶段过滤：基于结果精确匹配的过滤（允许两次重试）、基于 GPT-OSS-120B 的过程质量过滤、峰值上下文长度不超过 32K 的过滤；
- 轨迹在上下文编辑动作处切分为快照，训练时应用 token 级 loss masking 防止重复优化。

**第二阶段：RL（强化学习）——两项核心创新**

**(1) 上下文感知的部分展开（Context-Aware Partial Rollout）**

借鉴 ARPO 思想，将更多探索预算分配给"关键"的上下文管理决策。关键性通过**敏感性得分**衡量：

\[
S(a^{cm}_t) = \alpha \cdot \Delta C^{cm}_t + \beta \cdot \Delta H^{cm}_t
\]

其中：
- **上下文变化量** \(\Delta C^{cm}_t = \frac{len(c^{cm}_{t+1}) - len(c^{cm}_t)}{len(c^{cm}_t)}\)：衡量编辑前后的长度变化比例；
- **熵变化量** \(\Delta H^{cm}_t = H^{cm}_t - H_{initial}\)：衡量动作后模型生成 token 的平均熵（不确定性）相对轨迹初始状态的变化，而非与上一步的局部波动比较。

算法流程：每个查询分配 N=128 个快照预算 → 先执行 8 条完整轨迹级 rollout（产生至多 M=64 个快照）→ 按敏感性得分降序选取剩余 N−M 个分支点 → 从父节点处额外采样子轨迹，扩充快照池。

**(2) 细粒度信用分配（Fine-Grained Credit Assignment）**

- 最终快照 \(S_M\) 的奖励包含三部分：
  \[
  R(S_M) = R_{out} + R_{fmt} + R_{pen}
  \]
  其中 \(R_{out}\) 为答案正确性奖励，\(R_{fmt}\) 为输出格式可解析性奖励，\(R_{pen}\) 为无效工具调用和上下文长度超限的惩罚。
- **中间快照 \(S_i\) 的奖励**为其所有后续终端轨迹奖励的平均值：
  \[
  R(S_i) = \frac{1}{|\mathcal{T}(S_i)|} \sum_{T \in \mathcal{T}(S_i)} R(T)
  \]
- 同一查询下所有快照构成一个优势计算组，按组均值/标准差归一化得到优势估计 \(\hat{A}^{(j)}_t\)，最后用 **GRPO 目标**优化策略。

**理论保证**：附录 A 证明了该细粒度估计器相对于轨迹级信用分配是**同方差更低的无偏估计器**（方差从 \(\sigma^2(S)\) 降至 \(\sigma^2(S)/n_S\)），且部分展开机制通过增加关键动作的 \(n_S\) 进一步放大这一优势。

### 六、论文的主要结论与发现

1. **性能优势**：ContextPilot 在相同上下文窗口（32K）下超越 128K 窗口的基座模型；ContextPilot-8B-RL 比 StateLM-8B-RL 平均高 3.55 分，在深度搜索任务上比 SUPO 平均高 1.51 分（跨两个基座）。

2. **RL 增益随任务复杂度递增**：RL 在 BrowseComp+ 上带来 5.34 分的提升（平均输入 552K token vs. NovelQA 的 119K token），说明任务越长越复杂，细粒度 RL 的价值越大。

3. **紧凑上下文**：ContextPilot 将每轮输入 token 数稳定在 8K–10K 左右，而基线呈线性增长至 30K，证明主动管理能实现 token 效率的大幅提升。

4. **RL 重塑工具使用策略**：训练过程中信息检索占比从约 50% 逐渐下降，规划与感知、长期记忆、上下文卸载工具占比上升——模型从"单纯搜索更多"转向"更协调地管理上下文"。

5. **工具使用正确性协同提升**：记忆和上下文卸载工具的失败率在 RL 早期显著较高（SFT 模型"会用但不懂"），RL 训练显著降低失败率并同步推高任务成功率。

6. **各组件均有效**：工具消融显示规划→软卸载→长期记忆逐级累加带来持续提升（BrowseComp+ 从 63.49% 到 80.96%）；RL 消融证明上下文感知部分展开优于纯熵基线，细粒度信用分配在四基准上均带来进一步增益。

- **算法创新具有针对性**：敏感性得分结合上下文变化量和熵变化量，兼顾了编辑操作的"物理影响"（长度变化）与"语义影响"（不确定性变化）；部分展开机制将探索预算集中到关键决策，避免均匀探索的资源浪费。
- **理论支撑扎实**：附录 A 从方差分析角度严格证明了细粒度信用分配估计器的优越性（无偏且方差降为 1/nS），并将部分展开与方差缩小联系起来，形成完整的理论闭环。
- **训练细节严谨**：SFT 阶段的 harness 动态条件控制、失败重试过滤、三阶段轨迹筛选（结果+过程+长度），以及 token 级 loss masking，显示出工程实现上的成熟度。
- **评估维度丰富**：不止报告准确率，还从 token 效率、工具调用分布、工具失败率等多个维度剖析模型行为，提供了更深入的理解。
- **跨模型泛化验证强**：5 个不同来源和规模的基座模型 + 2 种任务范式的一致性收益，说明方法的通用性。

### 八、不足与局限

- **工具集仍未完备**：作者自认工具集可能无法覆盖所有上下文编辑需求，如面向智能体编程（agentic coding）和 GUI 智能体的特殊上下文操作尚未考虑。
- **算力信息披露不足**：未说明 GPU 型号、数量、训练总耗时，影响可复现性和成本评估；作者也承认未对部分 RL 超参数（如 α/β 权重、快照预算）进行系统搜索。
- **消融覆盖有缺口**：RL 算法消融未包含 14B 规模模型；深度搜索场景缺少工具设计和 RL 组件的独立消融（如仅用部分展开或仅用细粒度信用分配的深度搜索结果）。
- **数据处理成本较高**：SFT 依赖最高 3,196 题→过滤后仅 3,068 条轨迹，且需要 GPT-OSS-120B 进行过程过滤，流程较繁重，对低资源场景的可迁移性存疑。
- **行为分析为描述性证据**：工具失败率与任务成功率的协同变化（图 6）属于相关关系，未进行因果性验证；RL 微调工具失败率下降究竟是奖励函数直接驱动还是任务成功提升的副产品，尚不明确。
- **基准覆盖面局限**：未涉及智能体编程、GUI 操作等更丰富的智能体范式；GAIA 仅使用文本子集（103 例），样本量较小。
- **潜在偏差风险**：LLM-as-a-Judge 评判的 reliability 依赖 GPT-OSS-120B 的判断质量；BrowseComp+ 的固定语料设置与实际开放互联网搜索存在差异；多数基线与本文同属腾讯/上海AI Lab系（WebSailor、OpenSeeker），独立第三方复现尚待进行。
