## 摘要
分层KV缓存系统可以将长上下文LLM执行状态保留在GPU内存之外，但保留容量并不决定使该状态再次可执行所需的局部内存。我们将这第二种资源隔离为恢复工作集（RWS）：在恢复期间生命周期重叠的峰值局部暂存状态。在固定的上游LMCache全计划路径中，1.956、7.823和15.646 GiB/秩状态的实测完全重用点首先在2、8和16 GiB L1梯级成功，成功时的L1峰值分别为1.956、7.824和15.648 GiB/秩。我们引入了有界状态恢复（BSR），它将完整发现与局部驻留分开。BSR在不将整个命中物化到L1的情况下探查完整的可重用前缀，然后通过最多$W$个块的可重用窗口安装已确认状态。在有界辅助状态下，峰值恢复容量为$O(W)$，而总传输和安装工作保持$Θ(|S|)$。由于可重用状态跨越异构分配器组和张量并行秩，BSR使用请求级提交规则：部分安装永远不会暴露为有效的可重用前缀；失败会使公告的前缀失效，并回退到较低的有效层级或确定性重新计算。在TP=2的两个DGX Spark节点上的DeepSeek-V4-Flash中，一次干净的无恢复扫描将外部状态从1.956增加到31.277 GiB/秩，而实测L1 RWS在$W=32$时恰好保持500.75 MiB/秩，最大状态外部与实时暂存之比为63.959倍。第二次全新的524K-token运行重复了最大状态接受结果。评估的层级和秩不对称失败在回退前暴露完全重用或零外部重用。匹配的SSD优化将512K恢复TTFT从43.1秒降低到17.6秒，且不改变RWS。

## Abstract
Hierarchical KV-cache systems can retain long-context LLM execution state beyond GPU memory, but retention capacity does not determine the local memory required to make that state executable again. We isolate this second resource as the restoration working set (RWS): the peak local staging state whose lifetimes overlap during restoration. In the pinned upstream LMCache whole-plan path, measured full-reuse points for 1.956, 7.823, and 15.646 GiB/rank states first succeed at 2, 8, and 16 GiB L1 rungs, with successful L1 peaks of 1.956, 7.824, and 15.648 GiB/rank.   We introduce Bounded-State Restoration (BSR), which separates complete discovery from local residency. BSR probes the complete reusable prefix without materializing the whole hit in L1, then installs confirmed state through a reusable window of at most $W$ chunks. Under bounded auxiliary state, peak restoration capacity is $O(W)$ while total transfer and installation work remains $Θ(|S|)$. Because reusable state spans heterogeneous allocator groups and tensor-parallel ranks, BSR uses a request-level commit rule: partial installation is never exposed as a valid reusable prefix; failures invalidate the advertised prefix and fall back to a lower valid tier or deterministic recomputation.   On DeepSeek-V4-Flash with TP=2 across two DGX Spark nodes, a clean no-resume sweep grows external state from 1.956 to 31.277 GiB/rank while measured L1 RWS remains exactly 500.75 MiB/rank at $W=32$, a 63.959x largest-state external-to-live-staging ratio. A second fresh 524K-token run repeats the largest-state acceptance result. Evaluated tier and rank-asymmetric failures expose either complete reuse or zero external reuse before fallback. A matched SSD optimization reduces 512K restore TTFT from 43.1 to 17.6 seconds without changing RWS.

# 论文深度解析：有界状态恢复（Bounded-State Restoration）

## 一、核心问题与整体含义（研究动机与背景）

- **核心问题**：长上下文 LLM 服务中，分层/分离式 KV 缓存系统虽然能保留远超 GPU 内存的可复用执行状态，但保留容量 ≠ 恢复执行所需本地容量——后者被论文定义为**恢复工作集**（RWS，Restoration Working Set），即恢复过程中生命周期重叠的峰值本地暂存状态。论文要回答：能否在已知完整可复用状态的情况下，通过显式有界的本地工作集完成恢复，同时保证请求级正确性和失败闭环？
- **整体含义**：论文将"外部状态可以存多少"与"本地需要多少暂存才能使其可执行"这两个资源维度解耦。上游全计划路径中，32K/128K/256K 前缀分别保留 1.956/7.823/15.646 GiB/rank 状态，首次成功恢复分别需要 2/8/16 GiB L1 梯级——**外部存储扩容不降低本地恢复容量要求**，这正是论文要打破的耦合。
- **研究意义**：为分层 KV 缓存系统提供了一种新的资源抽象——恢复容量（restoration capacity），使系统设计能够在外部状态规模增长时保持本地恢复容量恒定，同时不牺牲请求级语义正确性。

## 二、方法论：核心思想、关键技术细节与公式

### 核心思想
- **完全知识不需要完全本地驻留**：BSR 将"发现完整可重用前缀"（决策契约）与"本地有界驻留"（资源契约）分离，以窗口迭代取代整计划物化。

### 协议三阶段（Probe / Install / Commit）
1. **Probe（探测）**：仅查找（probe-only lookup）获取完整候选命中集（hit bitmap），不保留整个 L2 结果到 L1，释放查找侧读锁；调度器据此公告前缀并分配目标块。
2. **Install（安装）**：将确认的前缀划分为至多 $W$ 个 chunk 的有序窗口，逐窗口获取、验证、映射到目标块、传输、同步、释放，再复用暂存给下一窗口；当前原型以专用锁串行化有界恢复。
3. **Commit（提交）**：仅当所有 TP rank $r$ 和语义组 $g$ 的有效性均满足 $Q(S)=\bigwedge_{r=1}^{R}\bigwedge_{g=1}^{G} q_{r,g}=1$ 时，才暴露完整前缀重用；任何窗口不完整、超时或传输失败，均使公告前缀失效。HMA（异构内存分配）感知的失效规则：任何无效组都使完整前缀坍缩为零外部 token。失败后设置 force-local 标记，跳过重复外部查找，回退到较低有效层级（如 SSD）或确定性本地预填充重算。

### 关键公式与命题
- **RWS 定义**：$\text{RWS}(\rho)=\max_{t}\sum_{u_i\in L_\rho(t)} c_i$——恢复期间同时存活的暂存单元字节数峰值（不含外部副本与正常执行目标状态）。
- **全计划物化**：$\text{RWS}_{\text{whole}}(S) \ge \sum_{i=1}^{N}c_i \Rightarrow \Theta(|S|)$。
- **有界安装**：$\text{RWS}_{\text{BSR}}(S,W) \le W \cdot c_{\max} + M_{\text{aux}}(W)$，其中辅助状态 $M_{\text{aux}}(W)$ 不随 $N$ 增长。
- **命题1（容量解耦）**：固定注册与 $W$ 下，峰值恢复容量 $O(W)$，与 $N$ 无关；状态增长转化为迭代次数 $K=\lceil N/W\rceil$，总工作量保持 $\Theta(|S|)$。
- **实例化容量律**（评估配置下）：$M_{L1}(W)=W \times 16{,}408{,}576$ bytes/rank。

## 六、主要结论与发现

1. **上游路径的容量耦合**：32K/128K/256K 外部状态分别需要 2/8/16 GiB L1 梯级才能全量恢复，成功峰值分别为 1.956/7.824/15.648 GiB/rank——本地恢复容量跟随选择状态规模。
2. **BSR 容量解耦**：在 E1 干净 sweep 中，外部状态从 1.956 GiB/rank 增长 15.99 倍至 31.277 GiB/rank，实测 L1 RWS 恒为 500.75 MiB/rank（$W=32$），最大外部状态与实时暂存比 63.959:1；全新 524K 重复运行同样通过。
3. **W 是精确容量控制**：$W=8/16/32/64$ 时实测 RWS 分别为 125.1875/250.3750/500.7500/1001.5000 MiB/rank，与公式零残差匹配。
4. **异构与失败安全**：524K MTP-on（170 张量）恢复满足同一验收契约；三类失败均表现为"完整前缀重用"或"零外部重用后回退"，未观察到部分重用的暴露。
5. **吞吐可独立于 RWS 提升**：SSD 加载并发 1→4 使 512K 恢复 TTFT 从 43.1→17.6 秒（2.45×），RWS 完全不变。

## 七、优点

- **概念贡献明确**：将"保留容量/恢复容量/执行余量/恢复吞吐"定义为四个独立资源维度，为分层缓存系统提供了新的设计透视图。

- **理论有界性可证明**：给出 RWS 的严格定义与命题，明确 $O(W)$ 容量与 $\Theta(|S|)$ 工作量属于不同复杂度维度；抽象不依赖具体模型。
- **实验纪律性强**：统一验收契约、干净同 epoch 主实验、公开证据链（仓库/branch/evidence ref）、诚实报告缺失测量（512K 上游）与描述性数据（W TTFT）；对 RWS 的测量与源记账零残差，可信度高。
- **实现侵入性小**：仅扩展 LMCache/vLLM 控制面（probe-only 查找、窗口化取回、失效/恢复标记），不改 kernel 与外部状态格式，工程可行性较好。

## 八、不足与局限

- **硬件与系统拓扑覆盖窄**：仅单一模型（DeepSeek-V4-Flash）、TP=2、双节点 + 单 Mooncake store 配置；未验证更大 TP 规模、更多节点、不同模型注册、GPU 直连内存（如 GH200/GB200）等场景。
- **RWS 并非进程总内存**：论文不声明恒定整体进程 UMA；模型权重、目标 KV 状态、元数据、通信缓冲等仍可变动，RWS 只是其中一个可控制的瞬态容量切片。
- **并发模型保守**：原型以全局锁串行化有界恢复，虽便于审计容量契约，但限制多请求重叠；论文提出全局预算 $B$ 扩展方向但未实现/评估。
- **缺乏统计严谨性**：TTFT 与失败/窗口实验均为非随机小样本；未见多次运行的标准差、置信区间或压力测试；对延迟与真实并发负载未做系统评估。
- **正确性仅操作性验证**：验收契约虽强但非形式化证明；Proposition 2（fail-closed）依赖实现正确执行，论文明确承认这一点。
- **512K 上游缺失**：无 32 GiB 全计划实测点，基线对比缺少最大状态的直接对照；论文也明确不将未完成的运行视为测量。
- **容量系数非通用**：16,408,576 bytes/chunk 仅适用于该模型注册与 chunk 几何；其他模型的 $c_i$ 可能不同，通适性需重新校准。
- **训练/领域数据无关**：属推理系统工作，未涉及训练成本、模型微调或数据分布；对真实业务请求模式（混合前缀、多租户、突发并发）的恢复行为未见实验。
