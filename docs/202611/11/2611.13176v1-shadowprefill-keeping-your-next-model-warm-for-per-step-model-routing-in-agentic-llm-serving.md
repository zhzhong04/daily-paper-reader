## 摘要
逐步骤模型路由器会在每个会话内动态地将智能体的每次 LLM 调用发送给成本最优的模型。然而，每次模型切换都会丢弃前缀缓存复用：KV 缓存是按模型隔离的，因此新模型在生成首个 token 之前必须预填充相关上下文。在具有代表性的智能体工作负载中（包括平均上下文长度为 63K tokens 的生产级编码智能体轨迹），前缀命中率从同一模型调用时的 80–89% 降至切换后的 44–65%，并且切换调用的耗时是原来的 1.5–3.2 倍。我们提出 SHADOWPREFILL，它在路由器未选择的模型上预填充会话上下文，利用服务正常流量的实例所闲置的容量，使下一次切换时其前缀已被缓存。SHADOWPREFILL 利用在途请求每次迭代的 SLO 余量，保护已路由调用，将影子 KV 溢写到主机内存，并在影子不完整时回退到冷切换。在 LLMRouter 于五个智能体基准套件上路由 24 个模型对的情况下，SHADOWPREFILL 将切换调用延迟降低 8.5–21.4%，将 LLM 调用延迟降低 3.7–17.7%，并将路由 token 成本降低 22.5–46.1%，同时正常流量仍满足其 SLO，且每请求能耗仅上升 0.4%。

## Abstract
Per-step model routers send each LLM call of an agent to the cost-optimal model dynamically within each session. However, every model switch discards prefix-cache reuse: KV caches are per model, so the new model must prefill the relevant context before it emits a token. Across representative agentic workloads, including a production coding-agent trace with a mean context of 63K tokens, the prefix hit rate falls from 80-89% on same model calls to 44-65% after a switch, and a switch call takes 1.5-3.2x as long. We present SHADOWPREFILL, which prefills the session's context on the model the router has not chosen, in capacity that instances serving normal traffic leave idle, so the next switch finds its prefix cached. SHADOWPREFILL harvests the per-iteration SLO slack of requests in flight, protects routed calls, spills shadow KV to host memory, and falls back to a cold switch whenever the shadow is incomplete. With LLMRouter routing 24 model pairs over five agentic benchmark suites, SHADOWPREFILL cuts switch-call latency by 8.5-21.4%, LLM-call latency by 3.7-17.7%, and routed token cost by 22.5-46.1%, while normal traffic keeps its SLO and energy per request rises by 0.4%.

# SHADOWPREFILL 论文结构化总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：智能体（agent）通过一系列 LLM 调用完成任务（规划→工具调用→读结果→编辑→测试→循环），不同步骤难度差异大。**逐步骤模型路由**（per-step model router，如 LLMRouter）会为每次调用动态选择成本最优的模型，从而在准确率与成本间取得平衡（相比“总用大模型”，路由可提升 6.6–13.6 个百分点准确率且更省 token）。
- **核心痛点——“模型切换税”（model switch tax）**：服务引擎通过**前缀缓存**（prefix caching）复用 KV，使同一会话的连续调用只需预填充新增 token。但 **KV 缓存按模型隔离**，一旦路由切换模型，目标模型要么没有该会话的 KV，要么只保留上次服务到某一步为止的旧 KV，必须重新预填充缺失上下文才能出首 token。
- **量化表现**：
  - 同模型调用前缀命中率 **80–89%**，切换调用骤降至 **44–65%**；
  - 切换调用耗时是同模型调用的 **1.5–3.2 倍**（主要差异在 TTFT）；
  - 生产级编码轨迹（GHCP）平均上下文 **63K tokens**，切换调用携带 27K–63K tokens；
  - 会话切换频繁：19–33% 的调用发生切换，每会话平均切换 2.0–4.1 次（SWE-bench 达 13 次）。
- **可利用的资源**：部署通常按峰值配置，但（1）非峰值时段整机空闲（代码流量中位数小时 72% 空闲）；（2）即便峰值，decode 迭代是内存受限且远快于 TPOT SLO，**69–79% 的每迭代延迟预算未被使用**——这部分“SLO 松弛”正是可被收割的容量。
- **整体含义**：论文主张把“切换开销”从关键路径转移到**闲置容量**上，通过主动预热“未被选中模型”的前缀缓存，让路由在保持准确率的同时显著降低延迟与成本，且**不增加 GPU、不损害正常流量 SLO**。

## 2. 方法论

### 2.1 核心思想
- 在路由器选中模型 A 服务第 k 次调用时，**在另一个模型 B 的实例上以最低优先级预填充（shadow prefill）该会话的上下文**，利用 B 实例服务正常流量时留下的 SLO 松弛与空闲间隙；当路由器在第 k+1 次切换到 B 时，B 的前缀缓存已基本就绪，只需预填充“未覆盖的尾部”。
- 若影子不完整/被驱逐，则**回退到冷切换**，行为与无 SHADOWPREFILL 完全一致。

### 2.2 关键技术细节（对应五大挑战 C1–C5）

- **影子作业（Shadow Jobs，对应 C4：大量影子工作可能浪费）**
  - **增量式**：记录 B 已持有的前缀与缺失 token，新输入到达时立即追加，A 的输出 token 生成后流式追加（output streaming），因此来回切换只补增量。
  - **粘性放置（sticky placement）**：每个会话在每个模型上绑定一个粘性实例，影子作业跑在“另一模型”的粘性实例上；路由选择预填充完成时间最短的实例，从而让切换调用命中自己的影子。
  - **按切换概率排序**：引擎按“预测的切换概率”优先执行影子作业；`Predictive` 变体额外设置概率阈值（≥0.25）门控以减少浪费。

- **容量收割（Harvesting，对应 C1：峰值无空闲 GPU；C2：影子工作拖慢本应加速的调用）**
  - 影子块作为连续批处理迭代中**最后调度**的工作，仅当等待队列为空且无因显存受阻的准入时才加入。
  - **空闲实例**：跑纯影子迭代，每次迭代上限为 β×TPOT SLO（β=0.5），限制新到请求的排队时延。
  - **SLO 松弛控制器（C1）**：利用生产调度器可观测的量（到达时间、首 token 时间、迭代数）估计每个在途请求的松弛。对已出首 token 的 decode 请求 r，其松弛为  
    **σr = (1−m)·Tr·(kr+1) − (t − fr)**  
    （Tr 为 TPOT SLO，kr 已完成迭代数，fr 首 token 时刻，m 为安全裕度）；prefill 请求的松弛为 (1−m)Fr − (t−ar) − p̂r。迭代预算取批内最小松弛（上限 βT），控制器在延迟模型预测不超预算的前提下追加影子 token。
  - **路由步保护（C2）**：路由调用本身没有可借出的松弛，故改用“信用”机制——信用以 δ×（纯 decode 内存受限迭代时长）累积（δ=0.025），从而把路由调用的长期拖慢限制在 δ 以内；只有纯正常流量的迭代才可借出全部松弛。

- **影子 KV 管理（对应 C3：长上下文超出 KV 预算）**
  - **独立、限额、优先驱逐的缓存类**：影子条目占 KV 池上限 **25%**，只使用空闲块或空闲 >5s 的冷条目；驱逐时先删影子、类内 LRU。
  - **主机内存溢写层（Host Tier）**：被驱逐的会话条目（影子与普通）溢写到主机 DRAM，命中时经 PCIe 重载；对 100K token 编码上下文（Gemma-7B 每 token 458KB KV）尤为必要。

- **安全与回退（对应 C5：不得有 SLO 回退）**
  - 影子工作从不阻塞路由调用或正常请求；按迭代粒度可抢占，新到请求最多等待一个受限迭代；切换调用永不等待影子；影子缺失时走原路径。错误预测的代价仅为消耗的收割容量与该计算的能耗。

- **PD 分离扩展**
  - 影子作业跑在另一模型的粘性 prefill（P）实例上（队列空、后台请求有 TTFT 松弛时，单迭代 ≤0.1s）；粘性 decode（D）实例在入站链路空闲时以 4K token 为单位拉取影子 KV 到可优先回收的空闲显存。切换时 P 只算尾部、D 只收缺失 token。

### 2.3 实现
- **仿真器**：基于 Vidur（高保真 LLM 推理仿真器）+ **约 2,700 行 Python**，逐层算子延迟用 H100 实测剖面拟合。
- **vLLM 原型**：每模型一个 vLLM 实例（开启前缀缓存、chunked prefill、优先级调度），路由侧管理器实现请求级 Harvest；**约 840 行 Python，无需改 vLLM 源码**（原型不含每迭代信用、SLO 松弛控制器、影子 KV 优先驱逐与主机层）。

## 6. 主要结论与发现

- **延迟**：Harvest-SLO+Host 使切换调用延迟降低 **8.5–21.4%**（基准均值 10.4%，GHCP 14.3%），切换调用 **TTFT 降低 44.1%/47.0%**；全部 LLM 调用延迟降低 **3.7–17.7%**（基准 5.0%，GHCP 9.7%）；每任务 LLM 时间降低 4.9%/10.0%。
- **成本**：路由 token 成本降低 **22.5–46.1%**（基准 28.5%，GHCP 32.0%）；在同等准确率下把路由自身账单削减 22–34%。
- **缓存**：全调用 token 加权命中率从 75.0%→82.1%（基准）、55.4%→76.3%（GHCP），接近 Oracle+Host（84.4%/81.3%）。
- **开销可控**：总 prefill 吞吐 +3.8%（含影子 token），路由与正常请求的 prefill 吞吐 −2.4%（因切换命中缓存）；**每达标请求能耗仅 +0.4%**（Dedicated 为 +11.7%）；正常流量 SLO 达标率不降反升 0.1–0.4 个百分点。
- **收益边界**：
  - 目标模型越大收益越小（<15B 降 12%，>50B 仅 3%，因 decode 主导）；DeepSeek-R1（671B）仅 0.2 个百分点（长推理输出挤压松弛）。
  - 上下文越长收益越大（<2K 仅 0.7%，>64K 达 20.5%）。
  - SLO 越紧、负载越高，纯收割收益越小（ρ=0.9 时 Harvest-SLO 仅 0.7%），此时主机层更重要（Harvest-SLO+Host 升至 15.2%）。
- **PD 分离**：prefill 实例常空闲，收割容量更多，切换延迟降 14.0%（同置 7.7%），但能耗 +11.5%（唤醒空闲 GPU）。
- **路由含义**：SHADOWPREFILL 不改变路由决策，只降低切换代价；更频繁切换时收益更大（最多 5.8%），可让“切换感知路由器”更自由地切换以换取准确率。

- **结论有清晰边界**：作者主动给出收益随目标模型规模、上下文长度、SLO 严格度、负载变化的衰减曲线，避免过度宣称。

## 8. 局限与不足

- **主结果以仿真为主**：22 个仿真模型对 vs 仅 2 个模型对（4 个测试台配置）的真实 vLLM 验证；且原型未实现每迭代信用、SLO 松弛控制器、影子 KV 优先驱逐与主机层，即**完整设计未在真实系统端到端验证**，仿真中理想化的调度粒度、PCIe/DRAM 行为可能与实际有偏差。
- **收益边界较窄**：大模型（>50B，decode 主导）仅约 3%、DeepSeek-R1（671B）仅 0.2 个百分点；短上下文（<2K）仅 0.7%；高负载（ρ=0.9）纯收割仅 0.7%；SLO 越紧收益越小。这意味着方法在“最难、最贵”的场景（大模型、紧 SLO、高负载）恰恰收益最弱，需依赖主机层兜底。
- **额外能耗与资源占用**：虽然每达标请求能耗仅 +0.4%，但 PD 分离下能耗 +11.5%（唤醒空闲 GPU），在能耗敏感场景需权衡；影子 KV 占用 25% 池上限、主机层依赖 DRAM 容量（16–256GB/GPU）与 PCIe 带宽，资源紧张时收益会被压缩。
- **依赖若干前提假设**：需要路由器切换概率可预测（Predictive 阈值 0.25）、会话可粘性放置、服务引擎暴露迭代级调度与松弛可观测量；对不支持优先级/可抢占调度的引擎，落地难度上升。
- **不改变路由决策**：方法只降低切换代价，不参与“是否切换”的优化，因此其收益上限受既有路由器策略约束；与“切换感知路由器”的联合优化仅作为展望，未做联合实验。
- **准确率评估规模有限**：SWE-bench 仅用 Verified 的 50 任务固定样本，路由器重训为 50 任务/3 折，统计功效有限；未报告训练/重训的 GPU 小时成本。
- **硬件与模型覆盖**：全部基于 H100（80GB）与特定模型族（Qwen/Llama/Mistral/Gemma/GPT-OSS/Granite），未涉及其他加速器、更低带宽互联或非 NVIDIA 栈；跨族异构 KV 布局差异的影响讨论有限。
- **多会话/多租户干扰**：实验以单会话增长型轨迹与回放流量为主，多会话并发下影子作业的公平性、跨租户资源归属与计费（谁为影子付费）未展开。

## 9. 启发与展望

- **“把非关键路径工作放进 SLO 松弛”是可复用的系统范式**：不仅适用于跨模型 KV 预热，也可推广到跨引擎/跨副本的缓存预热、RAG 索引预取、工具调用结果预取、投机解码草稿模型预热等。
- **路由与系统需协同设计**：现有路由器多为“成本-准确率”静态权衡，忽略切换代价；若把“切换税”纳入路由奖励（切换感知路由），可能在同等成本下进一步提升准确率，这提示 LLM 路由研究应从“模型选择问题”扩展为“模型选择+缓存状态联合优化问题”。
- **缓存层级的重新思考**：跨模型 KV 的“部分覆盖+增量补齐”表明，KV 缓存可被视为一种**可迁移、可分片、可降级**的状态，而非模型私有；这为统一 KV 池、跨模型 KV 变换/投影等方向提供动机。
- **对推理引擎的诉求**：需要更细粒度的可抢占调度、松弛可观测接口、影子/普通缓存的差异化驱逐策略与计费口径，这些可作为 vLLM/SGLang 等引擎的功能演进方向。
- **评估方法论上的启示**：以 Oracle 为上界、以“捕获率”而非绝对提升衡量、并强制报告开销指标，值得在系统类论文中推广。

## 10. 一句话总结

SHADOWPREFILL 首次量化并系统性地消解了逐步骤模型路由的“模型切换税”：通过在空闲/SLO 松弛容量上为未被选中的模型增量式影子预填充前缀 KV，在不增加 GPU、不损害正常流量 SLO 的前提下，将切换调用延迟降低约 8.5–21.4%、路由 token 成本降低约 22.5–46.1%、缓存命中率显著提升，且能耗几乎不变；其收益在短上下文、小模型、低负载场景最显著，在超大模型与紧 SLO 高负载下需依赖主机内存层兜底，完整设计仍有待真实系统端到端验证。
