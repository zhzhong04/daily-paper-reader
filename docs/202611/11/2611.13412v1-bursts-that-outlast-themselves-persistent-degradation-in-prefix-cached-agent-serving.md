## 摘要
LLM 智能体以闭环会话驱动推理引擎，其上下文每一轮都会增长；要经济地服务这些会话，就依赖前缀缓存：命中时只需增量预填充约一千个 token，未命中则需重新计算 10–40K token 的上下文。我们表明，这会使前缀缓存式智能体服务处于亚稳态。在相同的基础负载下，仅几分钟的额外请求到达就会使 vLLM 服务器进入退化状态——命中率约 10%、吞吐约为原来的一半，且积压在其后 70 分钟内持续增长——而无突发流量的对照则保持健康（12 对中有 9 对如此；反向情况未出现）。该状态会出现在缓存已热服务器本可承受的负载下，在没有前缀缓存时不出现，也会在使用 Qwen3-32B、SWE-bench 智能体轨迹形态以及 SGLang 上出现，后者可容忍更大的触发条件。服务变慢会使系统中保留更多会话，其工作集超出 KV 池容量，于是每一轮都变成重新计算；一个独立校准的一阶负载均衡条件界定了该状态何时能够排空。摆脱该状态是更难的问题：限制新请求准入仅恢复了 7 次匹配的崩溃运行中的 1 次，而按基于容量的限制暂停已准入会话，则在数分钟内恢复了全部。CPU 卸载层会延迟崩溃，但不能阻止崩溃。一种预算器将活动会话的常驻 KV 需求限制在池容量内，且其阈值无需针对每个工作负载调参，在我们测试的每次运行中都防止了该故障。

## Abstract
LLM agents drive inference engines with closed-loop sessions whose context grows every turn, and serving them economically depends on prefix caching: a hit costs an incremental prefill of about a thousand tokens, a miss recomputes a 10--40K-token context. We show that this makes prefix-cached agent serving metastable. With an identical base workload, a few minutes of extra arrivals leaves a vLLM server in a degraded regime--a ~10% hit ratio, about half the throughput, and a backlog that grows for the remaining 70 minutes--while its no-burst twin stays healthy (9 of 12 pairs; none in the reverse direction). The regime appears at loads the cache-warm server sustains, is absent without prefix caching, and also appears with Qwen3-32B on SWE-bench agent trace shapes and on SGLang, which tolerates larger triggers. Slower service keeps more sessions in the system, their working set outgrows the KV pool, and every turn becomes a recomputation; a first-order workload-balance condition, calibrated independently, brackets when the regime can drain. Getting out is the harder problem: throttling new admissions recovered 1 of 7 matched collapsed runs, while suspending admitted sessions against a capacity-based limit recovered all of them within minutes. A CPU offload tier delays the collapse but does not prevent it. A budgeter that bounds the resident KV demand of active sessions to the pool, with thresholds that need no per-workload tuning, prevented the failure in every run we tested.

# 《Bursts That Outlast Themselves》论文结构化总结

## 1. 核心问题与研究动机

- **背景**：编码助手、浏览器智能体等工具调用型 LLM 智能体已成为推理流量的重要组成部分。这类会话是**闭环**的：模型输出工具调用 → 工具执行 → 结果追加到上下文 → 上下文增长后再次送入模型，一个任务往往循环几十到上百轮。
- **经济性依赖前缀缓存**：若上一轮的 KV 缓存仍在池中，本轮只需增量预填充约几百到几千 token；若已被逐出，则需重算 10–40K token 的完整上下文，代价相差 10–40 倍。生产编码智能体轨迹的缓存命中率平均可达 90%。
- **核心问题**：当命中率因短时突发流量而下降后，系统能否自行恢复？论文发现**不能**——这是一种**亚稳态失败（metastable failure）**：触发器消失后，维持效应（sustaining effect）仍将系统锁定在退化状态。
- **整体含义**：前缀缓存把 KV 池变成了一个由积压量决定大小的“工作集”。闭环会话使响应时间与并发会话数相互耦合，形成正反馈：服务变慢 → 在系统会话增多 → 工作集超出 KV 池 → 每轮都未命中 → 服务更慢。该退化可在服务器本可承受的负载下被触发，且不会自行退出。

## 2. 方法论

### 2.1 核心思想
- 用**配对实验**（paired runs）隔离历史依赖性：一对运行共享完全相同的基础到达流（同一时刻、同一身份、同一形态），其中一组额外注入短时突发；突发结束后两组的基础负载完全一致，任何差异只能归因于历史。
- 用**无前缀缓存对照**分离出“缓存”这一必要成分。
- 用**一阶工作集–KV 池平衡条件**解释退化为何无法排空。
- 用**网关级控制器**（不修改引擎）比较不同负载控制动作的恢复/预防效果。

### 2.2 关键机制分析
- **闭环放大**：由 Little 定律，稳态下系统内会话数 `N = λ·T·(Z+R)`，其中 λ 为会话到达率、T 为每会话轮数、Z 为思考/工具时间、R 为每轮响应时间。R 增大直接放大必须常驻的前缀集合。
- **未命中代价随会话年龄增长**：未命中需重算整个上下文，而上下文每轮都在增长。
- **运行请求与缓存共享同一 KV 池**：运行请求越多，空闲会话前缀可用的空间越少。
- **三个闭环属性**共同构成维持效应：积压即工作集、未命中惩罚随会话变老而增大、运行请求与缓存争用同一池。

### 2.3 排空条件（公式化描述）
- 若每轮都未命中，服务一个会话的引擎时间为 `S = Σ_{k=0}^{T-1} c(L_k)`，其中 `c(L)` 为上下文长度 L 的冷启动轮代价。
- 退化状态可排空的必要条件为 `λ < 1/S`。
- 在禁用前缀缓存的运行上独立回归得到 `c(L) = −0.06 s + 0.146 ms × L`，得 `S ≈ 78 s`、`1/S ≈ 0.013 sessions/s`；在退化运行的全体未命中窗口上拟合得 `c(L) = −0.71 s + 0.187 ms × L`、`1/S ≈ 0.012`。
- 实验降低到达率后估计剩余冷启动工作量的变化，得到盈亏平衡点在 **0.010–0.014** 之间，恰好包住模型预测的 0.013。

### 2.4 网关控制器（同一执行器，仅限值设置不同）
- **统一执行器**：在每个会话的**轮边界**决定是否放行；超限会话被“停放（park）”到 FIFO 队列，不中断在途请求；重新准入时停放会话优先于新会话，通常需付一次未命中。
- **budgeter**：以已准入会话的常驻 KV 需求 `D = Σ_{s∈A}(L_s + o_s)`（上下文 + 输出预算）为对象，采用滞回带：`D ≤ 0.75C` 时准入，`D > 0.95C` 时停放；C 为引擎启动时报告的 KV 池大小，阈值**不随工作负载调参**。
- **session cap + park**：按测得的每会话需求设固定上限 K（如 K=14，K_hi=17）。
- **adaptive cap + park**：`K = ⌊0.75C/d̂⌋`，`d̂` 为轮边界观测需求的 EWMA（α=0.02）。
- **latency AIMD + park**：每 10 s 调整 K，中位轮延迟超过 15 s 时减半（初始 K=32），作为 CONCUR 类延迟驱动并发控制的简化代理。
- **admission-only cap**：仅限制新会话，不暂停已准入会话。
- **设计理由**：会话数上限等价于“token 上限 ÷ 假设的每会话需求”，而智能体会话上下文可差一个数量级且混合比例会漂移，故按 token（KV 需求）而非按会话计数更稳健。

## 6. 主要结论与发现

- **持久退化可被短突发触发**：λ=0.035（约为缓存热态容量的 70%）下，5 分钟 +1.5λ 的突发使命中率从 0.94–0.95 跌至 **0.10–0.12**、吞吐从约 1.27 降至 **0.35–0.46 turns/s**、积压涨至 100+ 会话，并在其后 70 分钟持续恶化；12 对中 **9 对仅突发臂退化，0 对反向**，2 对双臂均退化，1 对均未退化。
- **这是亚稳态而非普通过载**：无突发对照中也有 2/12 在 25–30 分钟时自发滑入退化且不再退出；禁用前缀缓存后同样的绝对突发只会造成可排空的积压（后 30 分钟积压收缩，2/4 回到对照水平）；有会话上限时 0/10 退化。
- **退化态的本质是“全未命中”**：99.6–100% 的完成轮命中不足一半 prompt，0.10–0.12 的命中率仅来自共享系统提示；引擎在忙（16–32 并发、KV 占用 83–100%），抢占很少（90 分钟 23–37 次），损失来自重算而非抢占抖动；吞吐与禁用缓存时相当。
- **工作集越界是维持机制**：退化对中常驻需求从池的 0.6 倍被推至 1.4 倍并持续升至 4.8 倍，对照峰值仅 0.83 倍；重算 prompt token 从约 1.1K/s 升至 6.4K/s。
- **排空条件被实验包住**：模型预测 1/S ≈ 0.013，实测盈亏平衡在 0.010–0.014；低于此值积压才可能下降。
- **“出去”比“不进”更难**：admission-only cap 仅恢复 2/8

- **“出去”比“不进”更难**：admission-only cap 仅恢复 2/8；budgeter 与 session cap 在 16 个 seed 中分别恢复 15/16 与 14/16，中位恢复时间约 10–20 分钟，而 admission-only 的失败原因正是它只挡住新会话、却无法让已在系统内的会话工作集收缩——停放必须作用于**已准入**会话，才能把常驻 KV 需求压回池内。
- **恢复的时序特征**：budgeter 一旦启用，命中率在数个轮周期内即开始回升，因为停放会话不再参与轮转，运行请求的 KV 占用下降，剩余会话的前缀得以驻留；吞吐先降后升，呈现“先牺牲并发、再换回命中”的典型取舍。AIMD 类延迟驱动控制在恢复上明显弱于按 token 计量的方案，说明**用延迟信号间接推断 KV 压力**存在滞后与误判。
- **32B 轨迹形态同样退化且可被预防**：在 ≈365K 池、λ=0.025、2× 突发 4 分钟下，无控制组退化，budgeter 与 session cap 组均未进入持续退化；但作者指出 32B 的每组样本量（4 次）使其证据强度弱于 8B。
- **第二引擎可复现**：SGLang + RadixAttention 在相同名义负载参数下出现同类的“突发后不恢复”现象，配对实验方向一致，说明该失败不依赖 vLLM 的具体调度实现，而源于闭环 + 前缀缓存的共同结构。
- **无需突发的触发路径**：会话混合漂移实验（短交互 → 长自治，λ 不变、无突发）同样使系统滑入退化，表明**负载形态的阶跃**与短时突发在机制上等价——两者都使常驻工作集越过池容量，而系统缺乏自动回退的力量。
- **扩容不是解药**：CPU KV 卸载把可用池扩大约 2.25 倍（128 GiB ≈ 0.9M token），延迟与命中率短期改善，但配对运行中仍有相当比例最终退化；因为积压会持续把工作集推高，扩容只是**推迟**越界时刻，而非消除正反馈。
- **阈值稳健性**：将滞回带从 0.75/0.95 改为 0.65/0.85 或 0.85/0.98，恢复结论不变，仅吞吐与恢复速度有差异；作者注明这些对比并非严格匹配比较，但足以说明结论不依赖单一阈值点。

## 7. 讨论、启示与局限

### 7.1 机制层面的启示
- 前缀缓存不是一个“免费的加速器”，而是把 KV 池变成了**由闭环积压量决定大小的工作集**。任何提升并发的调度决策，都会通过延长响应时间反向推高工作集，形成负向的外部性。
- 传统过载控制假设“减少输入 → 积压排空”，但在本场景中，**减少新输入不足以排空**，因为已准入会话每轮都在制造未命中重算。有效控制必须直接作用于“常驻 KV 需求”这一状态量。
- 该失败是**亚稳态**而非不稳定平衡：系统在退化态附近有很强的自锁倾向，只有施加足够强的外力（停放相当比例的会话）才能穿越回热态。

### 7.2 工程建议
- 在网关层以**轮边界**为控制点，按会话的上下文 + 输出预算估计常驻需求，用滞回带准入；避免在请求中途打断。
- 控制器应**按 token 而非按会话数**计量，因为智能体会话上下文可差一个数量级，且混合比例会随时间漂移。
- 监控上应把“token 加权前缀命中率”和“常驻 KV 需求 / 池容量”作为一等指标，命中率跌破阈值即为早期预警，而非等到延迟或错误率恶化。
- 扩容、卸载、增加副本可作为缓冲，但不应替代准入控制。

### 7.3 局限
- 实验以**单卡单引擎**为主，未覆盖多副本路由、多租户隔离、跨节点缓存复用等生产形态；结论向集群级推广需谨慎。
- 负载以合成会话与 SWE-bench 轨迹回放为主，真实流量的多样性与相关性可能改变定量结论（如盈亏平衡点位置）。
- 部分实验每组仅 2–4 个 seed，32B 与 SGLang 的证据被作者自认为弱于 8B 主结果。
- 控制器的开销、误判代价（停放导致的任务完成时间延长）未系统量化；停放策略对用户公平性的影响也未展开。
- 未讨论与路由、批处理、投机解码等其他优化手段的交互。

## 8. 总体评价

- **问题价值高**：论文识别并命名了一类此前被忽视的生产故障模式——短突发触发的、由前缀缓存与闭环会话共同维持的持续退化，并给出可操作的判据（排空条件 `λ < 1/S`）与控制手段。
- **方法论扎实**：配对运行 + 无缓存对照 + 统一执行器的多臂比较，构成了较强的因果识别策略；把“历史依赖性”作为实验变量而非噪声来处理，是本文最值得借鉴的设计。
- **结论有边界感**：作者明确区分了“预防”与“恢复”、区分了不同控制器的适用场景，并主动标注了样本量与非严格匹配比较等弱点，态度客观。
- **可改进之处**：算力与运行规模报告不完整；多引擎、多模型的一致性证据仍偏薄；控制器在真实多租户环境下的公平性与开销有待补足；对“为何 AIMD 类延迟信号失效”的机理分析可以更深入。
- **实践意义**：对提供工具调用型智能体服务的团队而言，本文提示应将准入控制前移到网关、以 KV 需求为控制变量，并把命中率纳入核心 SLO；单纯扩容无法根治该问题。
