## 摘要
Agentic LLM 工作流在运行时决定其执行路径。下游计算可能是可预测的，或者之前已经运行过，但在模型或用户解决分支之前，它无法开始。我们将这种串行化称为分支解析屏障。仅靠缓存无法将其隐藏：用于标识可复用结果的键在此时之前并不已知。在本文中，我们提出 DynBranch，它使未解析的分支在解析之前就可被寻址。其稳定坐标允许候选子图在解析期间运行，并使已完成的子图结果可在后续请求间复用。一个两级控制器在预期收益超过负载代价时允许这类工作。DynBranch 位于模型-API 边界，无需更改智能体框架或模型执行引擎。在 4 块 H200 GPU 上使用 Qwen3-32B 的四个智能体工作负载中，DynBranch 将平均延迟较各工作负载最强的先前系统最多降低 32%，较无复用下限降低 46-66%，同时保持工作流结果不变。该收益在不同骨干模型系列上以及商品级 Qwen3-8B/RTX 4090 部署中持续存在。

## Abstract
Agentic LLM workflows decide their execution paths at runtime. Downstream computation may be predictable, or may have run before, yet it cannot begin until the model or the user resolves the branch. We call this serialization the branch-resolution barrier. Caching alone does not hide it: the key that identifies a reusable result is not known until then. In this paper, we propose DynBranch, which makes an unresolved branch addressable before it resolves. Its stable coordinate lets candidate subgraphs run during resolution and completed subgraph results be reused across later requests. A two-level controller admits this work when its expected benefit exceeds the load price. DynBranch sits at the model-API boundary and requires no changes to agent harnesses or model execution engines. Across four agentic workloads with Qwen3-32B on 4x H200 GPUs, DynBranch reduces mean latency by up to 32% over each workload's strongest prior system and by 46-66% against a no-reuse floor, while preserving workflow results. The benefit persists across backbone families and on a commodity Qwen3-8B/RTX 4090 deployment.

## 1. 核心问题与整体含义（研究动机与背景）

- **核心问题：分支解析屏障（branch-resolution barrier）**
  - Agentic LLM 工作流在**运行时**才决定执行路径：下一步调用哪个工具/子任务由模型解码决定，或在交互点由用户从候选动作中选择。
  - 下游计算往往**可预测**或**此前已经算过**，但在分支解析（模型输出或用户点击）之前**无法开始**，形成串行化等待。
  - 论文量化：在编码、科研、科学智能体中，**45–57% 的端到端延迟**是排在模型输出之后的串行下游时间；智能体任务含 82–318 个模型步骤，一次运行会打开数十到数百个解析窗口。

- **为什么现有机制不够（三个挑战）**
  - **C1 共享子图复用**：递归单位是**子 DAG**而非整个请求；请求级缓存（GPTCache、Agentic Plan Caching）与前缀 KV 复用（SGLang、KVFlow、Pythia、PBKV）都锚定在请求边界或首个 token，无法命名请求内部递归的子图；且外部读依赖需要失效机制，仅精确匹配不够。
  - **C2 解析期提前填充**：授权复用的“名字”（键）在分支解析前并不存在，但工作必须提前启动。已有推测智能体（Speculative Actions、SPAgent、DSP、PASTE 等）只能**在产生它的请求内**使用推测结果，请求结束即丢弃，即使预测正确也无法跨请求存活。
  - **C3 按负载定价的准入**：填充与被加速的请求争抢同一批 GPU 槽位与 KV。实测固定形状 32B 请求：1–3 个共驻填充使其 p50 延迟上升 4–6%，48 个上升 53%；上下文增长会进一步放大到 145%。而现有系统（PASTE、SPAgent、TurboSpec、Nightjar）只在运行前一次性打分，无法应对数秒后才知道结果、且随负载变化的成本。

- **整体含义**：把“未解析的分支”本身当作一种可寻址的服务状态（稳定坐标 + 可执行候选子图 + 可复用已完成结果），在模型 API 边界同时解决**提前执行、跨请求复用、负载定价准入**三件事，且不改变工作流结果。

## 2. 方法论：核心思想与关键技术

### 2.1 总体架构
- DynBranch 位于**智能体 harness 与未修改的 SGLang/vLLM 引擎之间的模型-API 边界**，由三部分组成：
  1. **候选接口**：输入分支坐标，返回排序后的候选列表（背后可换任意预测器）。
  2. **两级门控**：对“是否开分支”和“填充哪些候选”分别按当前负载定价。
  3. **Completed-Subgraph Library（CSL）**：存放已完成子图结果，并由**反向索引**（外部记录 → 缓存条目）负责失效；每条分支有独立记录，跟踪成本与节省。
- 生命周期（图 6）：请求 → 提议候选 → 定价 → 填充（与解析解码并发）→ **不可见影子** → 分支解析淘汰败者 → **规范需求授权晋升** → 后续精确命中复用 → 依赖写入失效。

### 2.2 C1：共享子图复用
- **复用名（reuse name）** = 子图指纹（代码、模型、执行参数） + 已实现输入的哈希（哈希假设无碰撞）。
- 记录条目包含：已实现输入、输出、**外部读集合**、一次执行的溯源（provenance）。
- **新鲜度**：反向索引使外部记录写入能失效直接依赖者及失去有效生产者的下游状态；读与失效同步，并发/不确定情形保守地退化为 miss。
- 收益公式：
  $$\mathbb{E}[\Delta T_{\text{reuse}}] = \sum_j P^{\text{hit}}_j \, T^{\text{sub}}_j$$
- 图 7 对比：一次已实现变更下，整响应键、前缀区域键、子图拼接键分别服务 6 个已取节点中的 **0、2、4** 个。

### 2.3 C2：解析期提前填充
- **分支坐标**：工作流模板中决策点的稳定身份（如 routing 工作流的路由阶段），在目标负载中**在分支解析前即可知**。
- 填充在解析窗口内运行，完成后成为**不可见影子**（服务路径不可读）。
- **晋升需两步**：① 选择淘汰败者（排他分支中止败者 in-flight 填充并释放槽位/KV）；② 授权要求规范复用名与影子匹配且读集合仍新鲜，才原子晋升并消费。
- 安全性论证：可推测阶段须**可安全运行两次**（无外部副作用、同输入同依赖版本同结果，如批不变核 + 贪心推理、只读版本化检索）。晋升要求 $(q_s,\theta_s)=(q_c,\theta_c)$ 且 $D_s=D_c$，由确定性得 $y_s=y_c$，从而保证 **值等价** 与 **非干扰**。
- 收益上界：
  $$\mathbb{E}[\Delta T_{\text{gross}}] \le \sum_k P^{\text{cov}}_k \min(T^{\text{gen}}_k, T^{\text{exec}}_k)$$
  对用户等待窗口，用思考时间替代生成时间，衡量点击后延迟的降低。

### 2.4 C3：负载定价准入（算法 1）
- **因果负载价格**：观测填充占用、KV 预留占用、规范需求压力，用因果包络
  $$\bar\rho_H(t)=\max\left\{\rho_t,\ \frac{1}{H}\int_{t-H}^{t}\rho_\tau d\tau\right\}$$
  负载上升立即生效、下降在一个执行窗口内缓慢放松；填充脚印 $\hat{R}_s$（槽位 + KV）经单调价格曲线 $\beta(V_H)$ 转为延迟成本 $C_s(V_H)=\beta(V_H)^\top \hat{R}_s$。
- **Action 0（生成门）**：每条分支只学一个**整路径回报**
  $$\hat{y}_b=\sum_{s\in\text{consume}(b)}\hat{G}^\Delta_s - T_{\text{setup},b} - \hat{K}_b - \hat{W}_b$$
  按坐标分组为 branch class，用上下文岭回归 + 线性 UCB：$\hat{U}_0(c,x)=x^\top A_c^{-1}q_c+\hat\sigma_c\sqrt{x^\top A_c^{-1}x}>0$ 才开门；允许每类 $n_0$ 次冷启动试验，并注册试验记录以防延迟反馈丢失。
- **Action 1（填充门）**：乐观可用概率 $\tilde{p}_s=\tilde\pi^{\text{sel}}_s\bar\pi^{\text{use}}_s$，规则
  $$U_s(V_H)=\tilde{p}_s\hat{G}^\Delta_s-(1-\tilde{p}_s)C_s(V_H)>0 \iff \tilde{p}_s>p^*(s,V_H)=\frac{C_s(V_H)}{\hat{G}^\Delta_s+C_s(V_H)}$$
  每次接纳后重定价剩余候选，直至无正效用；硬可行性（填充数上限、原子 KV 预留）为强约束。
- **延迟反馈**：分支解析后更新选择/可用性；被消费条目必须指向准入时记录的推测生产者才记功；过期或未覆盖的等待计入 $\hat{W}_b$。
- **实现细节**：HTTP 拦截器为每个模型请求打上 `workflow_type_id`、`workflow_id`、`agent_id` 标签；三种生命周期钩子（阶段到达、未解析分支打开、携带解析选择的规范请求）复用现有队列/槽位/KV 账务；关闭 DynBranch 即绕过钩子并保持原语义。

### 2.5 附录中的理论保证
- κ* 是**一致可靠（uniformly sound）**且**最粗的可靠输入型键**（Lemma A.1、A.2、Cor A.3），因而最大化命中率与复用收益。
- **晋升完备性**（Cor A.4）：在 C1/C2 守卫下的候选影子集合中，没有可靠规则能授权而被 κ* 拒绝的配对。
- **最小图基写入级联**（Prop A.5）：时间复杂度 $O(|W|+|A|+|E_A|+|R_A|)$，且无不一致规则能失效其真子集。
- **紧致重叠界**（Lemma A.6）、**Action 0 条件符号保证**（Prop A.7）、**Action 1 逐步最优与终端极大性**（Prop A.8）；并指出含足迹预算的全局序列优化即使零价格也含 0/1 背包，属 NP-hard。
