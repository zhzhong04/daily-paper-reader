## 摘要
智能体式 LLM 推理在迭代的观察-推理-动作循环中累积长 KV 缓存，带来巨大的内存开销并限制服务吞吐量。现有压缩方法强调整体输出质量，却忽视了动作在推动任务进展中的不对称重要性。我们的核心思想是建立一种压缩准则，依据 KV 条目对动作生成的贡献来评估其价值，并优先保障动作质量。然而，迭代执行、动态内存需求以及分散的动作关键条目，对淘汰策略、预算分配和分页内存集成构成了挑战。为此，我们提出 ActKV，这是首个为智能体式 LLM 推理量身定制的 KV 缓存压缩框架。（i）面向动作的 KV 缓存淘汰利用稳定的动作访问模式，保留对未来动作至关重要的条目，从而在压缩下支持可靠的任务进展。（ii）置信度驱动的自适应预算分配利用 LLM 的内在置信度，使预算适应不断变化的动作关键内存需求。（iii）页面感知的压缩管理将压缩标准化为三个原语，并配以定制内核，实现实际的吞吐量增益。在长轨迹任务上，ActKV 仅使用 FullKV 峰值 KV 缓存内存的 25.98%，平均保留了 FullKV 98.53% 的准确率。其 token 吞吐量和任务吞吐量还分别达到 FullKV 的 3.97 倍和 3.58 倍，实现了最先进的性能。

## Abstract
Agentic LLM inference accumulates long KV caches across iterative observation-reasoning-action loops, imposing substantial memory overhead and limiting serving throughput. Existing compression methods emphasize overall output quality, overlooking the asymmetric importance of actions in driving task progress. Our key idea is to establish a compression criterion that values KV entries by their contribution to action generation and prioritizes action quality. However, iterative execution, dynamic memory demands, and scattered action-critical entries pose challenges to eviction policies, budget allocation, and paged memory integration. To this end, we propose ActKV, the first KV cache compression framework tailored for agentic LLM inference. (i) Action-oriented KV cache eviction exploits stable action access patterns to retain entries critical to future actions, supporting reliable task progress under compression. (ii) Confidence-driven adaptive budget allocation uses LLM's intrinsic confidence to adapt the budget to evolving action-critical memory demands. (iii) Page-aware compression management standardizes compression into three primitives with customized kernels, realizing practical throughput gains. On long-trace tasks, ActKV retains an average of 98.53% of FullKV's accuracy with only 25.98% of its peak KV cache memory. It also achieves 3.97 times and 3.58 times FullKV's token and task throughput, delivering state-of-the-art performance.

# ActKV 论文中文总结

## 一、核心问题与研究动机

- **背景**：现代 LLM 智能体（OpenClaw、Claude Code、Codex 等）遵循 ReAct 式的"观察—推理—动作"（Observation-Reasoning-Action, ORA）迭代循环。每一轮都会向 KV 缓存追加新的观察、推理与动作 token，导致缓存随交互轮次线性膨胀。
- **问题**：以 Qwen3-30B 完成一次 WebShop 购物任务为例，需约 25 轮、约 35K token，占用 3.20 GB KV 缓存，其中观察与推理条目占比超过 99%。这带来巨大的显存开销，限制并发与服务吞吐，同时长序列还会稀释注意力、降低精度。
- **核心错配**：现有 KV 压缩方法（H2O、SnapKV、StreamingLLM、R-KV 等）面向通用文本生成，假设 token 重要性均一，用"近未来注意力"贪婪淘汰。但智能体推理中 token 重要性是**高度不对称**的：观察/推理 token 多为内部状态、对用户隐藏；**只有动作 token 真正改变环境、决定任务成败**。因此均匀对待 token 与"以动作为导向"的目标本质错配，且短视保留可能损害后续动作。
- **三大挑战**：
  - **保留什么？** 迭代执行需要稳定准则识别"动作关键"条目，但演化上下文使当前重要性难以预示未来效用。
  - **保留多少？** 动作关键条目数量随任务类型、难度、交互轮数动态变化，离线画像的静态预算不适用。
  - **如何高效压缩？** 动作关键条目分散在各页中，token 级淘汰与块级分页内存管理（vLLM/SGLang）不对齐；现有方案或引入额外拷贝开销，或依赖特定策略缺乏通用性。

## 二、方法论

### 2.1 核心思想
- 建立**以"对动作生成的贡献"为准则**的压缩标准，优先保障动作质量，使淘汰策略与智能体推理的"结果导向"本质对齐。
- 提出 ActKV：首个面向智能体 LLM 推理的 KV 缓存压缩框架，由三个协同模块组成：动作导向淘汰、置信度驱动自适应预算、页感知压缩管理。

### 2.2 动作导向 KV 缓存淘汰
- **关键观察（Sec. 3.1）**：
  - 动作关键 KV 条目与观察/推理所需条目**显著不同**（观察关注局部扩展前缀，推理弥散关注全历史，动作聚焦少量任务关键历史）。
  - 动作关键条目在迭代间**稳定**：动作在语义（有限动作类型集）、上下文（共享任务约束/实体/证据）、结构（标准化输出模板）上具有相似性。
- **动作访问向量（AAV）量化**：对每个 KV 条目记录其在各动作区域是否落入 top-p（p=90%）注意力集合，得到 0/1 序列。分类为冷启动、连续、间歇三类。实验表明冷启动可忽略，连续条目最多但单次注意力贡献较低，**间歇条目单次贡献强**——因此仅按当前动作偏好淘汰会误删未来重新重要的条目。
- **注意力感知 LRFU 策略**：从静态重要性转向**时序效用**，淘汰准则为"某条目长时间未获高注意力才应被淘汰"。保留分数更新：
  - `KS_t(i) = λ · KS_{t-1}(i) + AttnScore_t(i)·{hit at t}`
  - λ∈[0,1] 为衰减因子（实验取 λ=0.5）。λ=0 偏重近因会误删间歇条目；λ=1 偏重频率会滞留过期连续条目；0<λ<1 兼顾两者。
- **算法流程（Alg.1）**：每个 ORA 轮结束触发 → 用动作区域 query 计算注意力分（PagedCalAttn）→ 为新条目初始化 KS → 生成 hit/miss 掩码 → 更新 KS → 按 TopK 选保留条目 → 分页压缩。
- 动作区域通过匹配 LLM 标准化输出模板自动识别起止。

### 2.3 置信度驱动的自适应预算分配
- **关键观察（Sec. 3.2）**：预算越紧 → 动作关键信息受损 → 模型出现 "wait"、"I guess"、"let me check" 等低置信标记并延长推理以复述缺失上下文 → 置信度下降 → 进一步挤压预算，形成恶性循环。故**置信度可作预算充足性的在线信号**。
- **三层置信度监控（Alg.2）**：
  - **Token 级**：`T_i = -(1/k)·Σ_{j=1..k} log P_i(j)`（top-k token 负平均对数概率，k=20），分布越尖峰越自信。
  - **Trace 级**：滑动窗口最小池化（w=64, s=8）后取最低 b%（b=10），强化对局部置信度崩塌的敏感性。
  - **趋势检测**：对序列做一阶最小二乘拟合得斜率 α。
- **预算调整**：仅在压缩触发时判断，若 α<0（置信度下降）则 `B' = min(B·scale_up, B_upper)`（scale_up=1.75，B_upper=30K），初始预算 512。置信度稳定或回升则维持当前预算（避免反复收缩导致信息再损失）。监控与推理并行，开销可忽略。

### 2.4 页感知压缩管理
- **统一三原语抽象**：`AttnScore ← CalAttn(target_q, KCache)`；`KeepMask ← Eviction(AttnScore, Budget)`；`KVCache ← Compaction(KVCache, KeepMask)`。多数方法（H2O/StreamingLLM/SnapKV/R-KV/RaaS/ActKV）均可归入此流程；淘汰策略与布局无关，系统瓶颈在注意力计算与缓存整理。
- **基于 LSE 恢复的注意力计算内核（Alg.3）**：
  - 分页注意力后端不暴露完整注意力矩阵，传统内核需先把散页物化为连续内存（昂贵拷贝）。
  - 利用分页注意力已产出的 softmax log-sum-exp（LSE）副产品，仅重算块内局部 query-key 点积并归一化：`A_{i,j} = exp(s_{i,j} - LSE_i)`。
  - 支持 GQA：同一 KV head 组内多个 query head 取最大值，跨动作 query token 增量更新均值，无需缓存历史 query；Triton 实现，直接在分页布局上计算。
- **原地压缩内核（Alg.4）**：
  - 观察：淘汰后保留条目通常靠近已分配页的尾部，故将所有保留条目压缩至**最后 X 个逻辑块**（X=⌈budget/block_size⌉）。
  - 目标槽位为尾部区域内被淘汰的逻辑槽，源槽位为区域外的保留槽，二者天然不相交。
  - 先做**无冲突槽位规划**，再经 slot map 映射到物理地址，用定制拷贝内核一趟完成原地复制，**无需额外 KV 缓冲区**；释放的块归还调度器复用。

## 六、主要实验结果

### 6.1 精度（Fig.8）
- 在 4 个模型 × 3 个 benchmark 上，ActKV 在同等预算下**一致优于** R-KV、SnapKV、StreamingLLM，并在中高预算档位**接近 FullKV**；预算越紧，动作导向淘汰的相对优势越明显，说明"保动作"的准则在信息稀缺时收益最大。
- 通用方法（SnapKV/StreamingLLM）在智能体场景退化更严重，印证了"以近未来注意力贪婪淘汰"与"动作关键条目间歇性复现"之间的错配。

### 6.2 自适应预算（Fig.9）
- 固定预算存在"两难"：5% 过紧导致低置信—复述—再压缩的恶性循环，25%–30% 则浪费显存且相对 FullKV 无额外精度收益。
- ActKV 的在线自适应在多数模型-任务组合上取得**优于或持平于最佳固定预算**的表现，且无需预先知道轨迹长度，验证了"置信度作为预算充足性信号"的有效性。

### 6.3 系统效率（Fig.10）
- **峰值内存**：ActKV 受限于 `max(Budget + ORA-Len)`，随轮次增长近似**有界**；FullKV 为 `Σ ORA-Len`，随交互线性膨胀，长任务（WebShop、ALFWorld）上差距最显著。
- **端到端吞吐**：在单卡一次性提交 1500 任务的高并发设定下，得益于显存占用下降带来的更大批处理空间，ActKV 相比 FullKV 取得明显吞吐提升。

### 6.4 内核微基准（Table 1）
- 在 r=1/4/16/64 四档并发、三组压缩规模下，**基于 LSE 恢复的注意力内核**避免了散页物化拷贝，相比"先物化再计算"的实现有稳定加速，且并发度越高、压缩规模越大，优势越突出。
- **原地压缩内核**通过尾部区域无冲突槽位规划，实现零额外 KV 缓冲的一趟拷贝，压缩后释放的块可直接归还调度器复用。

## 七、结论与核心贡献

1. **问题界定**：首次系统指出智能体 LLM 推理中 KV 缓存存在"token 重要性高度不对称"的结构性错配，并以 AAV 访问模式统计给出实证支撑（冷启动可忽略、连续条目多但贡献弱、间歇条目单次贡献强）。
2. **方法创新**：提出 ActKV——动作导向淘汰（注意力感知 LRFU）+ 置信度驱动自适应预算 + 页感知压缩管理，三者协同且**免训练**。
3. **系统落地**：给出可直接在分页注意力后端（vLLM/SGLang 式内存管理）上运行的两个 Triton 内核，兼容 GQA，无需额外缓冲区，具备工程可用性。
4. **实验验证**：跨 4 模型、3 类智能体任务验证了精度、内存与吞吐的联合收益。

## 八、局限与未来方向（基于论文内容的推断）

- **超参依赖**：λ=0.5、scale_up=1.75、B_upper=30K、初始预算 512、k=20、w/s/b 等均来自经验设定，跨模型与跨任务的鲁棒性需进一步检验。
- **动作区域识别的脆弱性**：依赖标准化输出模板匹配起止，若智能体框架或提示模板改变，需重新校准。
- **评估范围**：目前集中于文本型 ReAct 智能体，未覆盖多模态、多智能体与超长轨迹场景。
- **理论刻画不足**：LRFU 的衰减—频率权衡、置信度与预算的因果链条目前以实验观察为主，缺乏收敛性或最优性分析。
