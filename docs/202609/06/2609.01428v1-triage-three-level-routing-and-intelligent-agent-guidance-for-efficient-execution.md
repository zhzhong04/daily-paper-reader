## 摘要
基于ReAct范式的大型语言模型（LLM）智能体在工具使用和任务执行中展示了显著能力。然而，ReAct存在一个根本性的效率问题：每个查询都会从头触发完整的推理循环，相似的查询会重复相同的步骤，而不利用历史经验。我们提出TRIAGE，一种三级路由框架，通过重用历史执行轨迹来减少token消耗。其核心创新是TaaS（Trajectory-as-a-Skill），将历史执行轨迹抽象为可重用技能，实现“经验即服务”。TRIAGE将查询分为三级：（1）直接重用——相同查询，0 token；（2）技能替换——相似查询，通过确定性参数替换实现0 token；（3）完整ReAct——新查询，自动存储以供未来重用。在1,007个安全监控查询的大规模实验中，TRIAGE节省了62.3%的token，其中56.0%的查询处于第2级，5.5%处于第1级，均以零成本执行。在ToolBench（15个领域，345个查询）上的跨域验证实现了76.3%的token减少，确认了语义路由的泛化性。在线学习实验展示了从冷启动到成熟的演化：L2命中率在前100个查询中从0%上升到57%，平均token成本从198降至74.7。我们还提出了一种自动技能提取机制，将高频轨迹模式提炼为确定性技能，形成“越用越高效”的正反馈循环。

## Abstract
Large Language Model (LLM) agents based on the ReAct paradigm have demonstrated remarkable capabilities in tool use and task execution. However, ReAct suffers from a fundamental efficiency problem: every query triggers a complete reasoning loop from scratch, and similar queries repeat identical steps without leveraging historical experience. We propose TRIAGE,a three-level routing framework that reduces token consumption by reusing historical execution trajectories. Its core innovation is TaaS (Trajectory-as-a-Skill), which abstracts historical execution trajectories into reusable skills, realizing 'experience as a service'. TRIAGE classifies queries into three levels: (1) Direct Reuse-identical queries, 0 tokens; (2) Skill Substitution-similar queries, 0 tokens via deterministic parameter substitution; (3) Full ReAct-novel queries, automatically stored for future reuse. In large-scale experiments on 1,007 security monitoring queries, TRIAGE achieves 62.3% token savings, with 56.0% of queries at Level 2 and 5.5% at Level 1, both executing at zero cost. Cross-domain validation on ToolBench (15 domains, 345 queries) achieves 76.3% token reduction, confirming the generalizability of semantic routing. An online learning experiment demonstrates cold-start-to-mature evolution: the L2 hit rate rises from 0% to 57% within the first 100 queries, and the average token cost drops from 198 to 74.7. We also propose an automatic Skill extraction mechanism that distills high-frequency trajectory patterns into deterministic Skills, creating a positive feedback loop of 'the more you use it, the more efficient it becomes'.

## 2. 论文提出的方法论

### 2.1 核心思想：TaaS（Trajectory-as-a-Skill）

- 核心创新是把历史上**成功执行过的完整轨迹**（用户查询 + 工具调用序列 + 最终结果）持久化并抽象成可复用“技能”，形成正反馈循环：使用 → 轨迹 → 技能 → 节约 → 更多使用。
- TaaS 的生命周期分为四个阶段：
  1. **Store（存储）**：每条成功执行的查询自动编码后存入轨迹数据库，无需标注，零成本；
  2. **Retrieve（检索）**：新查询经语义编码后检索最相似的既有轨迹；
  3. **Reuse（复用）**：根据相似度等级，选择直接返回结果或进行 Skill 参数替换；
  4. **Distill（蒸馏）**：高频轨迹自动提炼为带类型参数的确定性 Skill 模板，注册进全局 Skill 注册表。

### 2.2 系统架构与三个模块

- 语义编码器：使用 sentence-transformers 的 all-MiniLM-L6-v2，将查询编码为 384 维向量，基于余弦相似度检索；
- 相似度阈值路由器：成本为零、纯确定性机制，负责三级分流；
- 轨迹检索器：在轨迹库中进行余弦相似度检索，设置 L1 ≥ 0.98、L2 ≥ 0.90 两个阈值；
- Skill 提取器：对高频率轨迹模式执行自动提炼和确定性注册。

### 2.3 三级路由算法逻辑（用文字描述）

- **Level 1 —— Direct Reuse（直接复用，0 token）**：当相似度 = 1.0 时属完全相同的查询，直接返回历史 SQL 结果。当相似度 ≥ 0.98 但 < 1.0 时，系统先做一个“轻量归一化 + 参数过滤”步骤，尝试把差异解释为参数值变化（转 L2）或语法性转述差异（留 L1），只有无法解决时才调用 LLM 做二次判断；
- **Level 2 —— Skill Substitution（技能替换，0 token）**：当相似度 ≥ 0.90 时，先在 Skill 注册表中匹配已有技能；若匹配成功，则从查询中抽取参数值执行确定性替换，无任何 LLM 推理。若没有匹配技能则回退 L3；
- **Level 3 —— Full ReAct（完整推理）**：相似度 < 0.90，判定为结构性新查询，执行完整 ReAct 流程；执行后的轨迹自动存储，并即刻进入 Skill 提炼流水线（最小频率阈值为 1，意味着单次出现也可成为可提炼模式）。

### 2.4 自动 Skill 提取的四阶段框架

1. **Pattern Normalization（模式归一化）**：将工具调用中的具体值替换为类型化通配符，生成“结构指纹”，得到规范化模板键；
2. **Frequency Accumulation（频率累积）**：对全部轨迹中的模板键做计数聚合，达到配置阈值后升级为提取候选；
3. **Parameter Induction（参数归纳）**：对候选模板的实例做两两差分，发现可变槽位，并结合查询中的词汇上下文和归一化类型标签，为参数分配合法的语义名称；
4. **Deterministic Registration（确定性注册）**：将含参数 Schema 的模板封装为标准对象，注册为 token 预估成本为零的确定性执行器。

### 2.5 在线学习与查询到达过程

- 论文模拟 30 个“工作日”的查询序列，混合三类分布：
  - 每日重复查询（6.1%）：6 个固定模板按 Zipf 分布重复出现，模拟固定报表类需求；
  - 参数变化查询（57.2%）：15 个 SQL 模板 + 随机参数组合，模拟同一类分析问题针对不同实体的提问；
  - 新查询（36.7%）：无历史先例的结构性新问题，穿插到达。
- 论文指出系统会经历冷启动（1–50 条）→ 预热（50–300 条）→ 成熟（300–1,000 条）三个阶段，L3 比例从 100% 逐步降到 10% 以下并趋于稳定。

## 6. 论文的主要结论与发现

1. **主实验效果显著**：在 1,007 条安全监控查询上，TRIAGE 将 token 消耗从 199,782 降至 75,238，节省 62.3%；平均每条查询从 198.4 token 降至 74.7 token；API 调用从 1,007 次降至 421 次（-58.2%）。
2. **零成本查询占比高**：L1 占 5.5%（55 条）、L2 占 56.0%（564 条），合计 61.5% 的查询以 0 token 执行；其余 38.5% 为真正需要完整推理的新查询。
3. **跨域泛化性得到验证**：在 ToolBench 15 个领域共 345 条真实查询上平均节省 76.3% token（424,792 → 100,875），L1+L2 覆盖率达 96.2%，L3 仅占 3.8%。
4. **在线学习呈三段式演化**：L2 命中率在头 100 条查询内从 0% 升至 57%；平均 token 成本从 198 降至 74.7；系统经历冷启动、预热和成熟三个阶段，效率随轨迹库增长而提升。
5.

5. **路由策略消融对比明确**：基于确定性阈值的路由器（0 token）在成本与最终任务 token 开销上均优于 LLM 路由器；LLM 路由器虽然可以更灵活地处理语义模糊案例，但每次路由判断消耗约 224 token，在单查询生成成本仅约 198 token 的实验场景中产生“路由开销 > 推理开销”的倒挂现象，验证了“零成本确定式路由”在 token 敏感场景中的必要性。
6. **组件消融显示 L2 的必要性**：去掉 L2（Skill 参数替换）后，仅有 L1+L3 的系统虽然仍能通过完全匹配缓存获得少量节约，但大量“同模板不同参数”的查询会落入 L3 完整推理，token 节省幅度显著下降；这证明 L2 才是 TRIAGE 节约能力的主要贡献组件。
7. **API 调用次数的减少**：仅 41.8% 的查询需要真正调用 LLM（421/1007）；其余 58.2% 的查询通过历史轨迹复用或确定性技能替换完成，这为高并发、成本敏感的生产环境提供了直观的可用性证据。
8. **系统具有很强的“经验成长性”**：随着轨迹库规模积累，系统对重复模式的识别能力持续增强；在最理想情况下，可以将大部分结构化查询从“每次完整思考”转化为“记忆+参数替换”，实现 token 成本随经验增长而逼近下界。

## 7. 局限性分析与应谨慎解读之处

尽管 TRIAGE 的实验结果在 token 节省上非常漂亮，但论文本身存在若干值得注意的局限：

1. **实验数据分布对方法高度有利**：主实验 1,007 条查询中约 94% 由 15 个参数化模板生成，余下 6% 为 6 个固定模板的 Zipf 重复。这意味着查询空间本质上是“结构化已知模板的有限组合”，与真实世界中大量语义漂移、表述差异极大的自然语言查询仍有差距。该数据分布天然适配“轨迹复用”的假设，因此 61.5% 的 L1+L2 命中率不能简单外推至更开放的真实场景。
2. **冷启动问题未被充分讨论**：实验明确显示头 100 条查询的 L2 命中率极低，系统在 1–50 条查询内几乎完全依赖 L3 推理。对查询量较小的业务场景，TRIAGE 可能需要运行较长时间才能积累足够的轨迹资产，前期几乎没有收益。
3. **未处理失败轨迹与安全性问题**：论文假设所有被存储的轨迹都是成功且可信的，但真实业务中 LLM 生成的 SQL 可能是错误或有副作用的。被存入轨迹库的错误执行一旦被复用，可能导致错误被批量放大。论文未讨论轨迹质量校验、权限管控、敏感数据缓存有效期等问题。
4. **相似度阈值缺乏自适应能力**：L1/L2 的固定阈值（0.98/0.90）只在单一数据集上调优，不同领域查询的表达习惯、语义编码分布差异很大；ToolBench 跨域数据上虽然总体收益高，但论文没有说明该阈值是否在跨域时重新调优，其在开放域中的鲁棒性仍需验证。
5. **与可替代方法的直接对比不足**：论文仅与完整 ReAct baseline 和两个消融设置对比，没有和 GPTCache、Few-shot Prompting 或基于嵌入检索的 RAG 类方案做实验对照，因此“TRIAGE 是最优经济性方案”的断言尚缺乏平行证据。
6. **正文中“97.6% queries benefiting”与主实验结果 61.5%（L1+L2 = 61.5%）的表述互相矛盾**，严重削弱了论文在结论表达上的严谨度。

---

## 8. 结论与个人评价

**总结而言**，TRIAGE 的学术贡献在于将经验复用从“简单缓存”推进到“结构化技能抽象”，并提出 TaaS 的完整生命周期：存储 → 检索 → 复用 → 蒸馏。该框架在 token 经济性上的收益是明确且有说服力的：在不牺牲任务成功率的前提下，通过让 Agent 从历史轨迹中学习可复用模式，显著降低了重复查询造成的推理开销。尤其是 L2 技能替换的思想——从高频路径中自动归纳参数化模板，并以确定性方式替代 LLM 推理——是本文最亮眼的创新点，也为后续 Agent 成本优化研究提供了新思路。

但论文的实验验证目前仍停留在“模板驱动”的合成或半合成查询阶段，来自真实用户、长尾表述、多步骤 Tool Use 场景的验证仍有很大空间。严格地讲，本文所证明的有效性边界是：**在重复性和参数化查询占主导的垂直业务领域中，TRIAGE 可用极低成本实现超过 60% 的 token 节省**。这一边界本身已经具有实践价值，但若要推广至更通用的 Agent 任务，仍需在数据多样性、失败轨迹管理、阈值自适应与安全性方面做进一步探索。

---

## 9. 对后续研究的建议

- **混合路由策略**：在确定式阈值路由基础上，对处于阈值边界（0.85–0.97）的查询进行概率性 LLM 复核，用可调的“LLM 判断预算”平衡准确与成本。
- **错误轨迹回滚机制**：为每条被复用的轨迹设置回报记录，当复用结果被用户纠正时反向更新轨迹库质量评分，防止低质量轨迹被反复提取为 Skill。
- **更轻量的语义编码器对比**：all-MiniLM-L6-v2 对复杂改写和同义工具名有时不够鲁棒；可尝试 bge-m3、text-embedding-3-small 等模型并系统对比不同嵌入空间的阈值稳定性。
- **真实生产环境的长期测试**：建议在真实运维或报表系统中记录连续数周的真实查询日志，据此评估轨迹库增长趋势、重复率衰减曲线和长期维护成本。
