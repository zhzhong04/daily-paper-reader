## 摘要
企业数据智能体通过多次推理步骤链式调用大量工具来回答业务查询，通常每次会话会积累数十万上下文令牌。现有的压缩策略通常在分配保留预算时不考虑删除单个工具输出的下游后果。因此，激进的压缩可能触发昂贵的工具重新调用，抵消初始的节省。我们称此为压缩-后果鸿沟。为弥合这一鸿沟，我们提出TRACER，将压缩形式化为一个顺序的逐工具决策问题。一个轻量级REINFORCE策略仅利用每次压缩事件时可用的信息来分配查询条件下的保留比率。其后果感知目标函数联合考虑了任务成功率、总令牌消耗以及压缩后的工具重新调用。为了改进信用分配，TRACER使用一个学习到的结果模型来比较所选保留比率的预测后果与完全保留每个工具输出的预测后果。在跨三个压缩器后端的保留生产查询上，相对于保留所有上下文，TRACER将总令牌消耗减少了29-46%，同时保持相当或更高的任务成功率。与工具类型条件的静态策略相比，TRACER额外节省了15-18%的令牌。干预性回放表明，学习到的逐工具信用分数与测量的单工具后果相关。学习到的策略在跨智能体主干和压缩器架构迁移时也产生了正节省，并在五个保留的LOCA-bench环境上将令牌消耗减少了18-25%。这些结果证明了后果感知的逐工具上下文保留对提高长时程语言智能体效率的价值。

## Abstract
Enterprise data agents answer business queries by chaining many tool calls over multiple reasoning steps, routinely accumulating hundreds of thousands of context tokens per session. Existing compression strategies typically allocate retention budgets without accounting for the downstream consequences of removing individual tool outputs. Aggressive compression may therefore trigger costly tool re-invocations that offset the initial savings. We call this the compression--consequence gap. To close it, we propose TRACER, which formulates compression as a sequential per-tool decision problem. A lightweight REINFORCE policy assigns query-conditioned retention ratios using only information available at each compression event. Its consequence-aware objective jointly accounts for task success, total token consumption, and post-compression tool re-invocations. To improve credit assignment, TRACER uses a learned outcome model to compare the predicted consequences of the selected retention ratio with those of fully retaining each tool output. On held-out production queries across three compressor backends, TRACER reduces total token consumption by 29--46% relative to keeping all context while maintaining comparable or higher task success. Compared with a tool-type-conditional static policy, TRACER provides an additional 15--18% of token savings. Interventional rollouts show that the learned per-tool credit scores correlate with measured single-tool consequences. The learned policy also yields positive savings when transferred across agent backbones and compressor architectures, and reduces token consumption by 18--25% on five held-out LOCA-bench environments. These results demonstrate the value of consequence-aware, per-tool context retention for improving the efficiency of long-horizon language agents.

## 1. 核心问题与研究动机

- **问题背景**：企业级数据智能体在回答业务查询时，需要链式调用大量工具、经过多步推理，单次会话即可积累数十万乃至上百万的上下文令牌。工具输出只会被不断追加而从不丢弃，导致上下文单调膨胀，超出模型上下文窗口、耗尽成本预算并削弱推理能力。
- **核心鸿沟（compression–consequence gap）**：现有压缩方法（token级剪枝、turn级摘要、step级丢弃等）在评估压缩效果时均独立于智能体的后续行为，没有考虑删除某个工具输出后可能引发的**下游重新调用（re-invocation）成本**。一个被误删的关键SQL结果可能迫使智能体重新执行一次消耗数万令牌的查询，彻底抵消之前压缩节省的开销。
- **关键洞察**：不同工具输出的下游重要性差异巨大——schema查询可能被后续每一步引用，而权限检查结果可能永远不会被再次访问。压缩策略必须具备**查询条件化的、按工具（per-tool）分配保留预算**的能力，且必须把压缩的远期后果纳入决策目标。

## 2. 方法论：TRACER框架

### 2.1 核心思想
- 将上下文压缩重新建模为**顺序的逐工具决策问题**：每次压缩事件发生时，策略网络读取当前状态特征，为每个工具输出实例输出一个连续的保留比率。
- 目标函数是**后果感知的**——同时考量任务成功、令牌消耗与压缩后重新调用三个维度，使"通过昂贵恢复换取的压缩节省"永远不会产生净收益。

### 2.2 问题形式化（Semi-MDP）
- 智能体A在离散步骤中运行；上下文由系统提示、工具定义、对话历史和积累的工具输出构成。
- 当上下文长度超过预算τ时触发一次压缩事件；单次会话可以触发多次压缩事件（Tc个），构成序列决策过程。
- 每个压缩事件是一个决策点；动作a为当次事件中N个工具输出各分配一个保留比率（ai∈[0.05, 1.0]）。

### 2.3 后果感知的奖励设计
- **会话级基础奖励**（终局测量）：
  R_base = success − λ_tok · clamp(T/T_base, 0.2, 2)
  其中T为会话总令牌数，T_base为同一查询在完全保留条件下五次参考运行的平均令牌数。
- **事件局部重新调用惩罚**（提供更密集信号）：
  P_recall,t = λ_recall · clamp((N_post,t − N_pre,t)/N_pre,t, 0, 2)
  通过将压缩触发边界重放到五次keep-all参考时间线、按事件序号匹配窗口，得到参考调用计数N_pre,t。
- **总目标**：J(θ) = E[ R_base − Σ_t P_recall,t ]

### 2.4 策略网络与动作参数化
- 策略为一个两层MLP（174维输入 →128→64→N个输出），为每个工具输出实例（slot）产生一个保留均值。
- 动作通过**Beta分布**参数化：采样比率来自Beta(κ₀·mᵢ, κ₀·(1−mᵢ))，κ₀=8，避免了截断伪影；评估时使用确定性均值。
- 每个工具输出实例有独立的slot、独立梯度（同一工具的多次调用不会被合并）。

### 2.5 信用分配：两通道机制
- **通道I（均匀惩罚底噪）**：将P_recall均匀分配给当次事件的活动工具，保证即使归因模型退化为零，仍能提供正确但粗略的惩罚信号。
- **通道II（反事实归因）**：训练一个轻量Transformer结果模型f_φ（2层4头，由16个工具token + 1个查询token组成），预测每工具重新调用数、对数令牌总量与成功概率。对每个工具i，比较所选比率与ri:=1（完全保留）的预测成本差异：
  credit_attr_i = λ_save ·(1−rᵢ)·tokᵢ/T_base − [Ĉ(s,a) − Ĉ(s,a; rᵢ:=1)]
  该信号双向：节省超下游成本则鼓励压缩；反之则保护该工具。
- 最终梯度系数为：coeff = α·A + credit_floor + β_t·credit_attr，经过20轮warmup+10轮线性退火逐步引入归因通道。

## 3. 实验设计

### 3.1 生产平台与查询
- **平台**：某大型电商公司的生产数据分析智能体；回答商业问题的工具包括知识搜索、SQL执行、权限检查、表查找、日期解析等。
- **查询集**：120条生产查询，分三层难度——25条简单查找、55条多步查询（schema检索+SQL）、40条多表权限门控连接；按难度分层80/40拆分训练/测试。
- **主骨干**：Claude Sonnet 4.6（200K上下文窗口），全程固定。

### 3.2 压缩器后端（Compressor Backends）
1. **Truncation**（无需模型的本地截断）
2. **Self-Info**（基于Qwen-2.5-0.5B的自信息分句子句评分）
3. **Summarization**（基于Qwen-3.7-Max的语义摘要压缩）
4. **AGORA-style** step级压缩器（用于迁移测试）

### 3.3 对比基线
- Keep-all（上限基准）、Uniform-0.5（常数比率）、Recency（随旧程度衰减）、Token-proportional（惩罚大输出）、Tool-type-conditional（按工具类型贪心搜索最优固定比率）等。
- 消融对比：RL-only（REINFORCE+均匀信用分配，无结果模型归因通道）。

### 3.4 主要结果
- TRACER在三种压缩器上将总令牌消耗降低**29–46%**（truncation 31%、Self-Info 29%、summarization 46%），同时任务成功率达0.75–0.81，与keep-all（最高0.80）持平或更高。
- 固定基线普遍**增加**3–24%的令牌消耗——直接验证"压缩-后果鸿沟"的存在。
- TRACER比Tool-type-conditional额外节省**15–18%**的令牌。

### 3.5 归因消融
- TRACER vs RL-only（5 seeds）：归因通道将成功率提高2.2–4.8个百分点，同成功率令牌比下降3.4–4.7%——表明结果模型的逐工具反事实信号既保护高后果工具，又促进更积极的低后果工具压缩。
- 消融实验覆盖三种压缩器后端，证实归因通道一致有效。

### 3.6 干预性回放验证（Interventional Rollouts）
- 从保持的轨迹中采样压缩状态，对每个工具进行factual与intervention（ri:=1）配对回放（M=3个种子消除采样噪声），对比模型的预测后果与实测后果。结果：Spearman ρ=0.66，Top-3高后果工具重叠率82%，方向正确率84%——确认反事实信号提供有效的逐工具梯度信息。

### 3.7 跨骨干与跨压缩器迁移
- **跨骨干**：在Claude Sonnet 4.6上训练的冻结策略零样本迁移到Qwen-3.7-Max和GPT-5.5，仍保持18–40%的令牌节省（GPT-5.5保留了训练骨干增益的78–87%）。
- **跨压缩器**：仅在truncation上训练的策略零样本应用到AGORA-style压缩器仍实现31%节省；在目标后端直接训练可达34%（匹配基线成功率0.65）。

### 3.8 LOCA-bench泛化
- LOCA-bench（15个任务环境，与生产环境完全不相交），使用96K/128K/256K三种长上下文设置；在10个环境上训练的TRACER在5个保持环境上取得18–25%令牌节省，且成功率高于keep-all与启发式基线。

## 6. 主要结论与发现

- 现有的固定/启发式压缩策略在智能体场景下普遍由于触发重新调用而**净增**令牌，证实"压缩-后果鸿沟"是真实而广泛的效应。
- **查询条件化的逐工具保留比率**能有效弥合该鸿沟：TRACER在三种压缩器上节省29–46%的令牌，同时保持或提升任务成功率，重新调用率（≤0.025）远低于固定基线（≥0.045）。
- **反事实归因是有效的**：结果模型提供的逐工具方向性信号能形成正确梯度（相关性、方向正确率、Top-3命中均获确认），在提升成功率的同时额外压缩。
- **策略可迁移**：保留结构依工具的内在"可再生成代价"排序（SQL结果高于日期解析），跨骨干、跨压缩器架构保持正收益。
- 在公共基准LOCA-bench上的正收益说明该方法不依赖生产环境特有分布，具有一定通用性。

## 7. 方法亮点与优点

- **问题定义精准**：将压缩评估从"压缩得多少"转向"压缩后agent能否低成本继续任务"，直面业界最迫切的真实成本来源。
- **决策粒度合理**：每个工具输出实例（而非工具类型）获得独立保留比率与独立梯度，能捕捉同工具在不同查询上下文中角色的差异。
- **信用分配设计精巧**：均匀惩罚底噪（模型无关的兜底）+ 反事实归因（模型驱动的方向性信号）的双通道组合，配合Beta分布的零均值score函数性质，保证了训练的鲁棒与可解释性，避免了"单episode单奖励对多决策无法分配信用"的稀疏性问题。
- **轻量高效**：策略+结果模型合计仅约102K参数、在CPU上运行，额外开销远低于大型模型的推理成本。
- **实验方法论严谨**：iso-success指标避免以成功率下降换压缩；干预性回放直接验证归因模型的因果预测质量；统计检验规范；并主动报告了成本回收的敏感性范围。

## 8. 不足与局限

- **实验依赖生产私有数据**：核心120条生产查询为私有数据集，无法用于外部复现比较；论文明确指出只有schema文件（部分目标被刻意脱敏/留空）而非完整测试集公开。
- **归因信号为代理而非因果保证**：结果模型预测的"下游后果"本质上是预测性的反事实（模型内比较），并非真实干预；论文虽然用干预回放验证了相关性（ρ=0.66），但仍有34%的方差未解释，且NMAE约为0.11–0.17。附录说明测量的窗口式信号可能带有自然波动，provenance升级路径建议了基于来源的因果匹配但未报告升级后的实验数据。
- **单Agent骨干验证较窄**：训练主骨干仅Claude Sonnet 4.6；跨骨干迁移结果显示策略有效但未在多个骨干上分别训练并比较。上下文窗口固定200K时结论对更长窗口中压缩位置偏好可能不同。
- **压缩器覆盖范围有限**：虽覆盖四种后端，但均为同一类工具输出级/子句级粒度机制，没有对比更细的token级学习式压缩MDP方法（如LLM-DCP提到的基于token的MDP压缩策略，未做实验比较）。
- **公式中潜在敏感超参**：奖励权重设置（λ_tok, λ_recall, λ_save等）需要针对不同应用手工调整；未报告超参敏感性实验；不同压缩器类型间权重未做差异化调控。
- **部分数字披露不完整**：表1无p值列；表4跨骨干未提供置信区间与显著性或同成功率口径；表6仅报告聚合成功率未按每任务分开列报；table 5中TRACER的zero-shot成功率为0.62、较Uniform-0.25的0.65低，没有给出置信区间能否区分说明。
- **数据量较小风险**：训练查询120条、测试40条，100 episodes/seed，可能在更复杂的企业知识库环境下数据量偏少，难以吸收策略级偏差（尤其是Tool-type-conditional并未随查询迭代更新，也未随机初始化多次）。
- **应用局限**：方法的前提是agent会"重新调用被删的工具"——在只读工具缺少外部可恢复机制时（如无权限重跑SQL的只读日志），策略不适用。此外保底机制（numeric floor）在AGORA迁移中的具体交互尚未被深度分析。
