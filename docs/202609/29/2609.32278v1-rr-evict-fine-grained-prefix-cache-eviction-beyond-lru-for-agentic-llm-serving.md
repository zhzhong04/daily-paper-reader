## 摘要
基于LLM的智能体通过重复的模型调用，并与工具执行和用户交互交错，来执行长时程任务。由于每次调用都会扩展前几轮累积的历史，前缀缓存可避免对智能体整个上下文进行重复预填充。然而，聚合缓存占用会随上下文长度和并发量增长，迫使服务系统回收已缓存的KV张量。我们识别出近因同步：对某个智能体缓存历史的访问会一起刷新其缓存节点，导致最近最少使用（LRU）淘汰集中于少数智能体的私有历史。当一个被完全淘汰的智能体返回时，它必须重新计算几乎其全部累积上下文，即使其他大多数请求仍保留大量缓存复用，也会产生较大的首令牌时间（TTFT）离群值。我们提出RR-EVICT，一种细粒度前缀缓存淘汰策略，将回收分散到空闲的智能体轨迹上。RR-EVICT按轮询顺序访问各智能体，并从每个智能体中淘汰尾部块，在容量仍可容纳空闲状态时，为更多智能体保留可复用前缀。返回的智能体可以复用这些部分历史，并重新计算更小的缺失后缀。该策略无需预测未来到达或工具延迟。我们在SGLang中实现了RR-EVICT，并在同置部署与预填充-解码分离式服务下评估对话和编码智能体工作负载。与LRU相比，RR-EVICT将P99 TTFT最多降低75.4%，并将P99未缓存提示令牌数最多降低65.7%。

## Abstract
LLM-based agents execute long-horizon tasks through repeated model calls interleaved with tool execution and user interaction. As each call extends the history accumulated in previous turns, prefix caching avoids repeated prefill of the agent's entire context. However, the aggregate cache footprint grows with context length and concurrency, forcing serving systems to reclaim cached KV tensors. We identify recency synchronization: accesses to an agent's cached history refresh its cache nodes together, causing least recently used (LRU) eviction to concentrate on a few agents' private histories. When a fully evicted agent returns, it must recompute nearly its entire accumulated context, producing a large time-to-first-token (TTFT) outlier even if most other requests retain substantial cache reuse. We present RR-EVICT, a fine-grained prefix-cache eviction strategy that distributes reclamation across idle agent trajectories. RR-EVICT visits agents in round-robin order and evicts a tail chunk from each, preserving reusable prefixes for more agents when capacity remains for idle state. Returning agents can reuse these partial histories and recompute smaller missing suffixes. The policy requires no prediction of future arrivals or tool latency. We implement RR-EVICT in SGLang and evaluate conversational and coding-agent workloads under colocated and prefill-decode-disaggregated serving. Compared with LRU, RR-EVICT reduces P99 TTFT by up to 75.4% and P99 uncached prompt tokens by up to 65.7%.

# RR-Evict 论文中文总结

## 1. 核心问题与整体含义

- **研究背景**：基于 LLM 的智能体通过多轮模型调用、工具执行和用户交互完成长时程任务。每一轮请求都会在前一轮历史基础上继续扩展上下文，因此上下文可能增长到数十万甚至百万 token。
- **前缀缓存的作用**：智能体在等待工具结果或用户反馈期间，服务系统可保留其 KV 缓存；下一轮请求到达时复用已缓存前缀，仅预填充新增后缀，从而降低首令牌时间（TTFT）。
- **核心问题**：随着上下文长度和并发智能体数量增长，聚合 KV 缓存占用超过 GPU 显存容量，系统必须回收缓存。现有系统默认采用 LRU 淘汰。
- **关键发现——近因同步（recency synchronization）**：
  - 智能体新一轮请求会匹配其整个存活缓存历史，前缀匹配会同时刷新该智能体私有路径上的所有缓存节点，使这些节点具有几乎相同的“最近访问时间”。
  - 不同智能体通常只共享很短的公共前缀，大部分累积历史是私有的。
  - 因此，节点级 LRU 在回收时容易退化为“智能体级”淘汰：反复选择最旧空闲智能体的节点，直到几乎清空其整个私有前缀，再转向下一个智能体。
- **后果**：被完全淘汰的智能体返回时几乎无前缀缓存可复用，需要重新预填充几乎全部历史，产生显著 TTFT 长尾离群值；即使整体缓存命中率仍较高，少量智能体仍会经历严重延迟尖峰。
- **整体含义**：长时程智能体服务中，仅优化聚合缓存复用率不足够，还必须考虑缓存损失如何在智能体之间分布。RR-Evict 通过细粒度、跨智能体的轮询式尾部淘汰，把集中缓存损失转化为渐进式降级，从而改善尾部延迟。

## 2. 方法论

### 2.1 核心思想

- 不再按全局 LRU 堆顺序逐个淘汰节点，而是将空闲智能体轨迹分组，按**轮询（round-robin）顺序**依次从每个轨迹淘汰一个**尾部块（tail chunk）**。
- 每次回收内存时，先淘汰一个智能体的尾部块，再移动到下一个智能体，循环直到释放足够内存。
- 淘汰尾部可保留一个有效、连续的缓存前缀；轮询选择则把回收压力分散到多个历史轨迹上。
- 在相同回收需求下，更多智能体可保留部分历史，返回时只需重算缺失后缀，而非整个历史。
- 该方法**无需预测未来请求到达或工具延迟**，仅依赖当前 active/idle 状态和缓存树元数据。

### 2.2 关键技术细节

- **缓存索引结构**：以 SGLang 的基数树（radix tree）为例，缓存节点表示变长上下文片段；vLLM 则使用固定大小 KV block。文中“cache node”泛指前缀索引条目。
- **可淘汰对象**：正在被请求引用的节点为 active，不可回收；等待工具输出或用户响应的智能体轨迹为 idle，可被淘汰。淘汰从 idle 叶节点开始，父节点在子节点移除后可能成为新叶节点。
- **尾部块**：后端相关的一次回收量，可以是一个完整叶节点，也可以是叶节点内部的一个后缀。部分回收的叶节点仍是该轨迹的下一个候选。
- **算法流程（Algorithm 1）**：
  1. 将所有具有可淘汰后缀的空闲智能体轨迹放入队列 `Q`。
  2. 当已释放内存 `M_freed < M` 且队列非空时：
     - 从队首取出轨迹 `τ`；
     - 若 `τ` 已变为 active 或无不可淘汰后缀，则跳过；
     - 选择尾部块 `c = SELECT_TAIL_CHUNK(τ, M - M_freed)`；
     - 执行淘汰并累加释放内存；
     - 若 `τ` 仍有可淘汰后缀，则将其放回队尾。
  3. 每次淘汰前重新检查 eligibility，因为智能体可能并发恢复。
- **处理陈旧轨迹**：
  - 方式一：应用在智能体完成时通知服务后端，立即释放其未共享缓存。
  - 方式二：若无生命周期信号，采用**近因分层（recency tiering）**：按最近访问时间将空闲轨迹分层，从最旧到最新处理；层间按 LRU 优先，层内按轮询淘汰。本文评估使用完成信号，未评估 recency tiering。

### 2.3 理论分析要点

- **简化假设**：n 个活跃轨迹，私有前缀等长，无跨智能体共享；每个智能体空闲时间占比 s，活跃占比 a=1-s；缓存容量为 m 个前缀等价单位。
- **适用区间**：`na < m < n`。若 `m ≤ na`，活跃需求占满容量，无空闲前缀空间，轮询淘汰无意义；若 `m ≥ n`，无需淘汰。
- **理想轮询**：在固定 na 个活跃轨迹后，可为 ns 个空闲轨迹保留容量 `m - na`，每个空闲前缀保留比例 `h = (m - na)/ns`，需重算比例 `q = 1 - h = (n - m)/ns`。
- **LRU 对比模型**：LRU 集中淘汰，表现为完全保留 `m - na` 个空闲前缀，完全移除其余 `n - m` 个。对随机返回的空闲智能体，旧前缀重算成本：
  - LRU：以概率 q 为 1，以概率 1-q 为 0；
  - RR：恒为 q。
- **结论**：两种策略平均重算成本相同，均为 q，但分布不同。LRU 将全部成本压在比例为 q 的返回智能体上；轮询将其均匀分摊。若预填充延迟近似正比于未缓存前缀长度，最坏旧前缀重算分量可从 1 降至 q。当 `q ≤ 1-p` 时，LRU 的 p 分位数可能为 0，轮询未必改善所有分位数。

## 6. 主要结论与发现

- **近因同步是 LRU 在长时程智能体场景下失效的关键原因**：访问同步使节点级 LRU 近似退化为智能体级淘汰，导致缓存损失集中在少数轨迹。
- **RR-Evict 显著改善尾部延迟**：
  - 相比 LRU，P99 TTFT 最多降低 **75.4%**，P99 uncached prompt tokens 最多降低 **65.7%**。
  - 相比 LRU + Completion Signals，P99 TTFT 最多降低 **46.9%**，P99 uncached tokens 最多降低 **30.6%**（τ2-bench）。
  - 在 SWE-bench PD 分离场景中，相比 LRU，P99 TTFT 和 P99 uncached tokens 最多分别降低 **60.7%** 和 **60.8%**；相比 completion-aware LRU，分别最多降低 **60.5%** 和 **56.2%**。
- **适用区间**：当活跃上下文能放入容量、但活跃加空闲历史超出容量时，轮询尾部淘汰最有效；在低并发或极高并发下，收益相对收窄。
- **TTFT 改善大于 uncached token 减少**：说明 RR-Evict 还通过避免超长预填充，减少了队头阻塞和后续请求排队延迟。
- **完成信号有帮助但不足**：完成信号可回收已完成轨迹，但在高并发下单独使用效果有限；对活跃空闲智能体分散淘汰仍能进一步降低缓存缺失和预填充排队。
- **无需预测**：RR-Evict 不依赖未来到达、工具执行时间或工作流图，适用性更广。

## 7. 优点

- **问题识别新颖且具体**：提出“近因同步”概念，清晰解释了为什么节点级 LRU 在智能体工作负载中会集中淘汰整个智能体私有历史。
- **方法简洁、通用**：轮询尾部淘汰不需要预测模型、工具延迟或工作流结构，仅依赖 active/idle 状态和缓存树元数据，易于在现有服务系统中实现。
- **兼顾前缀有效性与公平性**：淘汰尾部保留连续可复用前缀，轮询则把缓存损失分散到多个智能体，直接针对尾部延迟而非仅平均命中率。
- **理论与实证结合**：给出简化模型下的重算成本分布分析，明确适用区间 `na < m < n`，并用 trace 级内存需求时间线验证该区间确实出现。
- **实验覆盖较合理**：同时覆盖对话智能体和编码智能体、同置和 PD 分离部署，并设置 completion-aware LRU 作为更强基线。
- **公平性设计较好**：trace 回放固定请求顺序、上下文、输出长度和轮次间隔，减少非策略因素干扰。
- **工程兼容性**：在 SGLang 中实现，支持完成信号，也提出无信号时的 recency tiering 备选方案。
