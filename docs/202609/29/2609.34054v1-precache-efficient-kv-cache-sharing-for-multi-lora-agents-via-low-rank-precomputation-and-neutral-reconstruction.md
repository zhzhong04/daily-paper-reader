## 摘要
多LoRA智能体系统通过共享一个公共骨干模型来实现高效的角色特化。然而，每个智能体都会重复处理不断增长的共享轨迹，并构建自己的KV缓存，从而在长时程任务中引入大量的内存和计算冗余。现有的KV缓存共享方法减少了这种重复预填充，但它们要么需要额外训练或架构约束，要么仍保留大量模型计算。此外，直接复用缓存会使当前智能体依赖前一个智能体的适配器生成的缓存状态，从而削弱其自身LoRA所编码的角色特定行为。我们提出PReCache，这是一种无需训练的KV缓存共享框架，包含两种设计，即PreLRShared和ReBaseShared，它们共享使用预训练权重计算的基础缓存，并预计算紧凑的智能体特定低秩（LR）缓存。为消除重复预填充，PreLRShared在首次处理共享上下文时预计算每个智能体的LR缓存，使当前智能体能够使用自己的LR缓存，而无需重新处理先前智能体已处理的上下文。为提高共享准确性，ReBaseShared从无适配器的隐藏状态重建共享基础缓存，减少由前一个智能体的适配表示导致的剩余误差。为最小化其重建开销，我们提出两种分别面向单流推理和并发服务的推理方案，分别在每个智能体轮次之后执行相同重建，或与其执行并行进行。在多个模型和智能体基准上，与无KV缓存共享的推理相比，PreLRShared实现了最高3.1倍的TTFT加速和2.3倍的每请求吞吐量提升。在评估的缓存共享方法中，ReBaseShared整体上最好地保持了准确性，相对于无缓存共享的推理，平均仅下降1.1分。

## Abstract
Multi-LoRA agent systems enable efficient role specialization by sharing a common backbone model. However, each agent repeatedly processes the growing shared trajectory and constructs its own KV cache, introducing substantial memory and computation redundancy in long-horizon tasks. Existing KV cache sharing methods reduce this repeated prefill, but they either require additional training or architectural constraints or retain substantial model computation. Moreover, direct cache reuse causes the current agent to rely on cache states generated by the previous agent's adapter, weakening the role-specific behavior encoded by its own LoRA. We present PReCache, a training-free KV cache sharing framework with two designs, namely PreLRShared and ReBaseShared, that share the base cache computed using the pretrained weights and precompute a compact agent-specific low-rank (LR) cache. To remove repeated prefill, PreLRShared precomputes each agent's LR cache when the shared context is first processed, allowing the current agent to use its own LR cache without reprocessing context processed by previous agents. To improve sharing accuracy, ReBaseShared reconstructs the shared base cache from adapter-free hidden states, reducing the remaining error caused by the previous agent's adapted representation. To minimize its reconstruction cost, we propose two inference schemes tailored to single-stream inference and concurrent serving, performing the same reconstruction after each agent's turn or alongside its execution, respectively. Across multiple models and agent benchmarks, PreLRShared achieves up to a 3.1x TTFT speedup and a 2.3x improvement in per-request throughput over inference without KV cache sharing. ReBaseShared best preserves accuracy overall among the evaluated cache-sharing methods, with an average drop of only 1.1 points relative to inference without cache sharing.

## 一、核心问题与研究动机

- **背景**：LLM 智能体系统常通过共享同一个预训练骨干 + 各自的 LoRA 适配器来实现角色特化（如 plan / action / reflect 三类角色），从而降低模型内存占用，适合资源受限部署。
- **核心痛点**：
  - 多智能体在长时程任务中不断累积共享轨迹（用户请求、检索信息、工具观测、前序智能体输出），轨迹随轮次增长而变得极长且以 prefill 为主。
  - 每个智能体都会**重复处理已被前序智能体处理过的上下文**，并为同一上下文单独构建 KV 缓存，造成严重的**计算与内存冗余**。
- **现有方法的不足**（论文 Table 1 的权衡）：
  - **选择性重算**（DroidSpeak、CacheBlend、RelayCaching）：需重算关键层/关键 token，异构 LoRA 下精度仍损失；提高重算比例又抵消计算与内存收益。
  - **BaseShared（LRAgent）**：精度保持好，但当前智能体仍需对累积上下文做全长度骨干前向以构建自身 LR 缓存，重复 prefill 几乎未被消除。
  - **BaseLRShared**：可消除重复处理，但要求所有适配器共享同一 LoRA down-projection，无法直接支持已有异构适配器。
  - **训练/架构类方法**（Cache-to-Cache、Icarus、PrefillShare 等）：需要额外训练、校准模型对或特定架构，难以直接迁移。
  - **前缀偏差校正类方法**：在多 LoRA 场景下前缀与 token 位置已对齐，校正变量不变，退化为 FullShared。
- **另一关键问题**：直接复用缓存会使当前智能体依赖**前一个智能体适配器产生的缓存状态**，削弱其自身 LoRA 编码的角色特定行为。
- **目标**：面向**已有（免训练）异构 LoRA 适配器**，同时降低 KV 缓存内存、消除大部分重复 prefill，并尽量保持精度。

## 二、方法论

### 2.1 核心思想

- 沿用 LRAgent 的分解思路：适配后的投影输出可拆为
  \(Y_i = X_{i,\text{adpt}}(W_0 + A_iB_i) = \underbrace{X_{i,\text{adpt}}W_0}_{\text{base}} + \underbrace{(X_{i,\text{adpt}}A_i)B_i}_{\text{adapter}}\)，
  其中 \(W_0\) 为冻结骨干权重，\(A_i \in \mathbb{R}^{d_{in}\times r}\)、\(B_i \in \mathbb{R}^{r\times d_{out}}\)，\(r \ll d_{in},d_{out}\)。
- 因此缓存被拆为**跨智能体共享的 base cache** + **各智能体专属的紧凑低秩（LR）缓存**（宽度仅 \(r\)）。
- 关键洞察：虽然 \(W_0\) 共享，但 \(X_{i,\text{adpt}}\) 已被前序智能体的适配器影响，故 base 贡献也随智能体变化——这既解释了直接复用缓存的误差，也提示了“去适配器化”重建的可能。

### 2.2 PreLRShared：LR 缓存预计算

- 当某段上下文 \(L_P\) **首次被处理**时，就用该次前向产生的隐状态 \(X_{i,\text{adpt}}\)，对**所有**智能体的 down-projection \(A_k\)（\(k=1,\dots,N\)）一次性算出 \(X_{i,\text{adpt}}A_k \in \mathbb{R}^{L_P \times r}\)，形成各智能体的 LR 缓存。
- 后续智能体 \(j\) 只需复用共享 base cache 与自己的预计算 LR 缓存，仅对**新增上下文** \(L_C\) 执行适配骨干计算；并在处理 \(L_C\) 时同步为所有智能体扩展 LR 缓存。
- 效果：把对累积上下文的全维度骨干处理，替换为**轻量的 rank-\(r\) 下投影**，消除重复 prefill。

### 2.3 ReBaseShared：中性 base cache 重建

- 动机：PreLRShared 的 base cache 仍来自前一个智能体的适配隐状态。实验（Figure 2）显示，**用禁用适配器的隐状态 \(X_{\text{neut}}\) 构造的“中性 base cache”更接近当前智能体自己会构造的 base cache**。
- 做法：用无适配器路径处理共享上下文，构造 \(C_{\text{neut}} = X_{\text{neut}}W_0\)；同时把同一批无适配器隐状态投影到各智能体的 \(A_k\)，继续维持 LR 缓存预计算。
- 理论分析（附录 A.1）：定义偏移 \(\Delta_i = C_i - C_{\text{neut}}\)、\(\Delta_j = C_j - C_{\text{neut}}\)，令 \(\rho = \|\Delta_i\|_2/\|\Delta_j\|_2\)、\(\cos\theta\) 为二者余弦相似度，则
  \(\Gamma_{err} = E_{prev}/E_{neut} = \sqrt{1+\rho^2-2\rho\cos\theta}\)，
  中性缓存误差更小的充要条件为 **\(\rho \ge 2\cos\theta\)（即 \(\Gamma_{err}\ge 1\)）**。
- 附录 A.2 实测：在 LLaMA-3.1-8B 与 Ministral-8B、HotpotQA 的三类角色转换（plan→action、action→reflect、reflect→plan）上，逐层平均的 \(\Gamma_{err}\) 在所有测量层均 > 1，支持该重建的有效性。

### 2.4 两种推理调度（LP / DB）

- **LP（lazy prefill）**：智能体轮次内只跑适配路径；其解码结束后，再用一次**连续的无适配器 prefill** 重建/扩展中性 base cache。适合单流边缘推理，且重建可与工具调用重叠。
- **DB（double batching）**：把适配路径与无适配器路径**同时**编入 prefill 与 decoding 的连续批中，两条路径处理相同 token/位置但维持独立 KV 视图；无适配器路径只关注中性 base cache，不影响当前智能体的生成。适合并发服务端，避免单独重建 prefill 造成的排队延迟。
- 两者产生**逻辑等价**的缓存状态，仅在执行时机上不同。

## 六、主要结论与发现

1. **PreLRShared** 通过“首次处理即为所有智能体预计算 LR 缓存”，消除了对累积上下文的全长度骨干重复前向：单流下 **TTFT 最高加速 3.1×、每请求吞吐最高提升 2.3×**，在 66.4k token 时 TTFT 仍接近 FullShared（差距 17% 以内）。
2. **ReBaseShared** 用无适配器隐状态重建中性 base cache，显著降低相对 PreLRShared 的精度损失：四个骨干-基准组合上平均仅比 NonShared 低 **1.1 个百分点**，与 BaseShared 相当，却去除了后者保留的大部分重复 prefill；单流下 TTFT 最高加速 3.0×、吞吐提升 1.6×。
3. **调度分工**：LP 在单流场景优于 DB（重建置于轮次后，不进入下一智能体的 TTFT）；DB 在并发服务下优于 LP（避免单独重建 prefill 阻塞排队请求）。
4. **并发服务**：非饱和负载下，PreLRShared 与 ReBaseShared DB 的每请求吞吐分别比 NonShared 高 1.6× 与 1.3×；高负载下二者的 TTFT 饱和更晚，p90/p99 差距更明显。
5. **内存**：二者只存一份共享 base cache + 紧凑 per-agent LR cache，在 66.4k token 时峰值显存与 FullShared 相差 **2% 以内**，比选择性重算基线低 **17–23%**。
6. **扩展性**：智能体数从 N=4 增至 N=8 时，PreLRShared 与 ReBaseShared LP 的 TTFT 仅增 3%/7%、吞吐仅降约 6%、峰值显存仅增 1–2%；而 NonShared、BaseShared 与选择性重算的 TTFT 增 32–53%、吞吐降 20–30%、显存增 16–26%。
7. **LoRA rank**：精度从 r=4 到 r=8 提升后趋于饱和，r=8–32 间 ReBaseShared 与 NonShared 差距保持在 1.0 个百分点内，波动 < 0.3 点，支持 r=8 作为默认；吞吐随 rank 增大仅小幅下降（r=8→64 时 PreLRShared 降 2%、ReBaseShared LP 降 4%）。
8. **投影配置**：在 QKVO（参数匹配 r=4）下，由于 key 侧适配需先升维再施加 RoPE，Flash-LoRA-Attention 的按结合律重排不再直接适用，开销上升；但长上下文效率趋势与主实验一致，PreLRShared 仍最接近

FullShared 的效率表现，而 ReBaseShared 因需额外维护无适配器路径，开销略高于 PreLRShared，但仍显著优于 BaseShared 与选择性重算基线。

## 七、结论与讨论

- 论文提出 PReCache，一种面向**免训练异构 LoRA 多智能体系统**的 KV 缓存共享框架，核心由 **PreLRShared** 与 **ReBaseShared** 组成。
- 通过将缓存分解为**共享 base cache**与**紧凑 per-agent LR cache**，并在上下文首次处理时为所有智能体预计算 LR 投影，消除了跨智能体对累积上下文的全长度重复 prefill。
- ReBaseShared 进一步利用**无适配器中性隐状态**重建 base cache，缓解直接复用前序智能体缓存导致的角色行为偏移，在精度与效率之间取得更好平衡。
- 在多种骨干、数据集、轨迹长度与并发负载下，方法在精度接近 NonShared 的同时，显著降低 TTFT、提升吞吐并控制显存增长。
- 两种调度 **LP / DB** 分别适配单流边缘推理与并发服务场景，部署灵活性较好。

## 八、局限与未来工作

- **训练算力披露不足**：LoRA 训练细节未报告 GPU 型号/数量、训练时长、总 GPU 小时数与能耗，难以量化训练开销。
- **评测场景有限**：仅覆盖 QA 类基准与固定的 plan–action–reflect 三角色结构，未验证更多智能体角色、工具类型与任务域。
- **效率实验以受控重放轨迹与合成 token 为主**：真实工具调用延迟虽在附录补充，但主实验未完全纳入端到端真实延迟。
- **方法依赖 LoRA 低秩分解与 Flash-LoRA-Attention**：对非 LoRA 适配（全参数微调、其他 PEFT）或更复杂投影配置的适用性仍需探索。
- **统计显著性**：ReBaseShared 与 BaseShared 的精度差异小于运行间波动，需更大规模重复实验验证。
- **未来方向**：自适应选择重建时机、与量化/稀疏化结合、扩展到更异构适配器类型、以及真实部署环境下的端到端评估。

## 九、总体评价

- **创新性**：将 KV 缓存共享从“直接复用”推进到“预计算低秩投影 + 中性 base 重建”，在免训练异构 LoRA 约束下实现精度与效率的较好折中。
- **实用性**：面向资源受限边缘与并发服务两种部署模式，提供 LP/DB 调度，工程落地性较强。
- **实验严谨性**：多维度消融与受控重放设计提升了公平性，但场景覆盖与训练算力披露仍有提升空间。
- **理论支撑**：附录给出中性重建误差更小的充要条件与逐层实测，增强了方法可信度。
