## 摘要
多智能体系统将大型上下文分布到多个智能体上，这些智能体通过通信来共同解决任务。文本消息紧凑，但需要解码，且可能遗漏接收方智能体所需的证据。近期的潜在通信则改为传输 KV 缓存。这避免了文本生成，并可以提高准确率、改善延迟。然而，完整的 KV 缓存会随单个智能体处理的上下文以及协同工作的智能体数量线性增长。这会增加内存和上下文成本，往往远超可用的 GPU 资源和上下文窗口大小。我们的关键观察是，智能体只需发送接收方智能体完成其本地任务所需的内容——我们称之为接收方条件化通信。接收方智能体向发送方传递其信息需求的简要描述，用于过滤和压缩发送方智能体的 KV 缓存。CacheBack 是一种简单、稳健、无需训练的接收方条件化实例，基于发送方的注意力权重。在 FanOutQA 上，使用 Qwen 3 的 CacheBack 移除了智能体原本会接收的 75% 状态，相较于文本通信，准确率提高了 14.7 个百分点，并将任务完成延迟中位数降低了 3.2 倍。我们展示了在涵盖稠密 Transformer、Mamba-注意力混合模型和滑动窗口注意力的多个模型系列中具有可比的改进。

## Abstract
Multi-agent systems distribute large contexts across agents that communicate to solve a task. Text messages are compact but require decoding and may omit evidence the receiving agent needs. Recent latent communication instead transfers KV caches. This avoids text generation and can improve accuracy and latency. However, a full KV cache grows linearly with both the context an individual agent processes, and the number of agents that coordinate together. This raises memory and context costs, often far exceeding available GPU resources and context window sizes. Our key observation is that agents need only send what the receiving agent requires for its local task -- which we call receiver-conditioned communication. The receiver agent passes the sender a small description of its information needs, which serves to filter and compress the sender agent's KV cache. CacheBack is a simple, robust, training-free instance of receiver conditioning based on the sender's attention weights. On FanOutQA, CacheBack with Qwen 3 removes 75% of the state the agent would otherwise receive, improving accuracy by 14.7 percentage points and reducing median task-completion latency by 3.2x relative to text communication. We show comparable improvements across model families that span dense Transformers, Mamba-attention hybrids, and sliding-window attention.

## 1. 核心问题与整体含义（研究动机与背景）

- **多智能体协作中的通信瓶颈**：多智能体系统常把长上下文拆分给多个智能体，再通过消息传递共同完成任务。文本消息紧凑，但需要自回归解码，成本高，且可能遗漏接收方真正需要的证据。
- **潜在通信的优势与问题**：近期方法直接传输 KV 缓存，避免文本生成，能提升准确率和延迟。但完整 KV 缓存会随单个智能体处理的上下文长度以及协同智能体数量线性增长，导致“上下文再膨胀”（context re-expansion），显存和上下文窗口压力巨大。
- **关键观察**：发送方不必发送完整状态，而只需发送接收方完成其本地任务所需的信息。论文将这一思想称为 **接收方条件化通信（receiver-conditioned communication）**。
- **整体含义**：论文把通信协议的设计从“如何表示消息”推进到“消息应包含什么信息”。消息内容应依赖接收方的信息需求，而不是固定为发送方的全部 KV 状态。

## 2. 方法论：核心思想、技术细节与流程

- **核心思想**：接收方向发送方提供一个查询 \(q\)，描述其信息需求；发送方用 \(q\) 对已完成的 KV 缓存进行打分、筛选和压缩，只传输与接收方任务相关的少量位置。
- **CacheBack 定位**：一种简单、稳健、无需训练的接收方条件化潜在通信实例，基于发送方注意力权重进行选择。
- **基本流程**：
  1. 发送方先完成自身上下文和 latent steps 的前向计算，形成完整 KV 缓存。
  2. 接收方把查询 \(q\) 附加给发送方；实验中 \(q\) 就是任务问题。
  3. 发送方只用 \(q\) 的 token 对已有 KV 缓存计算注意力，并对发送方序列位置打分。
  4. 按预算选择位置，将选中位置编码后传给接收方；接收方重新 prefill 并继续生成答案。
- **选择器设计**：
  - 先构造 **mean query attention**：对 query token、query head 求平均，跨层求和，并在发送方位置上做局部池化，得到每个位置分数 \(Q_t\)。
  - CacheBack 修正平均化带来的稀释问题：定义 \(S^{CB}_t = Q_t C_t^2\)。其中 \(C_t\) 比较“先池化再平均 query token”和“先平均 query token 再池化”的差异，用来奖励那些被查询中部分 token 强烈集中关注的位置。
