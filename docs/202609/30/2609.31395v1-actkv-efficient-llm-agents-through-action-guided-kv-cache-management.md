## 摘要
智能体式LLM推理在迭代的观察-推理-行动循环中会累积长KV缓存，带来显著的内存开销并限制服务吞吐量。现有压缩方法强调整体输出质量，忽视了动作在推动任务进展中的不对称重要性。我们的核心思想是建立一种压缩准则，根据KV条目对动作生成的贡献来衡量其价值，并优先保障动作质量。然而，迭代执行、动态内存需求以及分散的动作关键条目，给驱逐策略、预算分配和分页内存集成带来了挑战。为此，我们提出ActKV，这是首个专为智能体式LLM推理定制的KV缓存压缩框架。(i) 面向动作的KV缓存驱逐利用稳定的动作访问模式来保留对未来动作至关重要的条目，从而在压缩下支持可靠的任务进展。(ii) 置信度驱动的自适应预算分配利用LLM的内在置信度，使预算适应不断变化的动作关键内存需求。(iii) 页感知压缩管理将压缩标准化为三个原语，并配以定制内核，实现实际的吞吐量增益。在长轨迹任务上，ActKV仅使用FullKV峰值KV缓存内存的25.98%，平均保留了FullKV准确率的98.53%。它还实现了FullKV的3.97倍token吞吐量和3.58倍任务吞吐量，达到最先进性能。

## Abstract
Agentic LLM inference accumulates long KV caches across iterative observation-reasoning-action loops, imposing substantial memory overhead and limiting serving throughput. Existing compression methods emphasize overall output quality, overlooking the asymmetric importance of actions in driving task progress. Our key idea is to establish a compression criterion that values KV entries by their contribution to action generation and prioritizes action quality. However, iterative execution, dynamic memory demands, and scattered action-critical entries pose challenges to eviction policies, budget allocation, and paged memory integration. To this end, we propose ActKV, the first KV cache compression framework tailored for agentic LLM inference. (i) Action-oriented KV cache eviction exploits stable action access patterns to retain entries critical to future actions, supporting reliable task progress under compression. (ii) Confidence-driven adaptive budget allocation uses LLM's intrinsic confidence to adapt the budget to evolving action-critical memory demands. (iii) Page-aware compression management standardizes compression into three primitives with customized kernels, realizing practical throughput gains. On long-trace tasks, ActKV retains an average of 98.53% of FullKV's accuracy with only 25.98% of its peak KV cache memory. It also achieves 3.97 times and 3.58 times FullKV's token and task throughput, delivering state-of-the-art performance.

# ActKV 论文详细总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：现代 LLM 智能体（如 OpenClaw、Claude Code、Codex）遵循 ReAct 式的迭代「观察—推理—动作」（Observation-Reasoning-Action, ORA）循环。每一轮迭代中，环境观察与推理链不断累积进 KV 缓存，导致长轨迹任务产生巨大的显存开销并严重限制服务吞吐。
- **具体痛点**：
  - 一个 Qwen3-30B 的 WebShop 任务需 25 轮迭代、约 35K token，消耗 3.20 GB KV 缓存，其中观察与推理条目占比超过 99%。
  - 长 KV 序列还会稀释注意力、降低模型准确率，批量服务时并发度与吞吐进一步受限。
- **现有方法的根本错配**：主流 KV 压缩方法（H2O、SnapKV、StreamingLLM、R-KV 等）面向连续文本生成，假设 token 重要性均匀，以「近似近期注意力」贪心驱逐低注意力条目，目标是保持整体输出质量。但智能体推理是**结果驱动**的：观察与推理 token 主要是内部状态、对用户不可见，唯有**动作 token** 直接影响环境并决定任务进展。因此，token 重要性高度不对称，短视的「近未来保留」策略会损害后续动作质量。
- **核心思想**：建立以「KV 条目对动作生成的贡献」为准则的压缩标准，在压缩中优先保障动作质量。
- **三大挑战**：
  - **保留什么？** 迭代执行需要稳定的准则识别动作关键条目，但演化中的上下文使当前重要性难以预测未来效用。
  - **保留多少？** 动作关键条目数量随任务类型、难度、交互轮次、观察长度动态变化，静态离线剖析的固定预算不适用。
  - **如何高效压缩？** 动作关键条目分散在分页内存的各个块中，token 级驱逐与块级分配存在错位，现有方案或引入拷贝开销、或缺乏通用性。

## 2. 方法论：核心思想、关键技术细节与算法流程

ActKV 包含三个协同模块，整体形成「生成行为 ↔ KV 缓存管理」的轻量反馈回路。

### 2.1 动作导向的 KV 缓存驱逐（Action-Oriented Eviction）

- **观察依据**：跨 Qwen3-30B/235B、GPT-OSS-20B/120B 的注意力图分析发现两点规律：
  1. **独特性**：动作关键 KV 条目与观察、推理所依赖的条目显著不同（观察关注局部扩展前缀，推理关注全局弥散注意力，动作聚焦少量任务关键历史）。
  2. **稳定性**：同一任务内动作在语义、上下文依赖、输出结构上高度相似，动作关键 KV 条目在迭代间构成稳定子集。
- **量化工具——动作访问向量（AAV）**：对每个 KV 条目记录 `AAV = [a₁, a₂, …, aₙ]`，`aᵢ = 1` 表示其在第 i 个动作区域的注意力分数进入 top-p 90%。据此分为三类：
  - **冷启动型**（Cold-start）：起始为 0，占比可忽略。
  - **连续型**（Continuous）：首尾 1 之间无 0，数量最多但单次注意力贡献较低。
  - **间歇型**（Intermittent）：首尾 1 之间有 0，单次贡献强但间断出现。
- **核心准则**：KV 条目只有在「足够长时间未贡献高注意力」后才应被驱逐。
- **算法实现——注意力感知 LRFU（Least Recently Frequently Used）**：
  - 保留分数更新：`KS_t(i) = λ · KS_{t-1}(i) + AttnScore_t(i)·{命中于 t}`
  - 其中 λ ∈ [0,1] 为衰减因子，命中定义为动作区域注意力分数落入 top-p（p=90%）。
  - λ=0 退化为纯近期策略（会误删间歇型条目）；λ=1 退化为纯频率策略（会保留过时连续型条目）；0<λ<1 可兼顾：高注意力间歇条目在暂时静默后仍存活，而陈旧连续条目因衰减被驱逐。
- **流程**（Algorithm 1）：在每个 ORA 轮次结束时触发 → 获取动作区域注意力 → 为新条目初始化 KS → 计算命中/未命中掩码 → 更新 KS → 按 Top-K 选择保留条目 → 执行分页压缩。

### 2.2 置信度驱动的自适应预算分配（Confidence-Driven Budget Allocation）

- **观察依据**：预算越紧，动作关键 KV 信息越不完整，模型被迫延长推理来「复述缺失上下文」，表现为置信度下降，语言上出现「wait」「I guess」「let me check」等低置信标记；而更长的推理又进一步挤压预算，形成恶性循环。因此**置信度可作为预算充足性的在线信号**。
- **三层置信度监测**：
  1. **Token 级**：`T_i = -(1/k) Σ_{j=1}^{k} log P_i(j)`，取 top-k（k=20）负平均对数概率，峰值分布代表高置信。
  2. **Trace 级**：先对 token 置信序列做窗口大小 w=64、步长 s=8 的滑动窗口**最小池化**，再保留底部 b=10% 的值，突出局部低置信片段。
  3. **趋势检测**：对 trace 级置信序列做一阶最小二乘线性拟合，得斜率 α。
- **预算调整算法**（Algorithm 2）：监测与 LLM 推理并行运行，开销可忽略。初始预算 512 条目；每次压缩触发时，若 α<0（置信下降），则按 `B' = min(B · scale_up, B_upper)` 扩大预算（scale_up=1.75，B_upper=30K）；置信稳定或回升时维持当前预算（不贸然缩减，避免再次信息损失）。
- **设计要点**：从小预算起步、仅在置信下降时扩张，既适应增长的内存需求，又避免过早超额分配。

### 2.3 页感知压缩管理（Page-Aware Compression Management）

- **统一抽象**：将多数压缩方法（H2O、StreamingLLM、SnapKV、R-KV、RaaS、ActKV）归纳为三个原语：
  - `AttnScore ← CalAttn(target_q, KCache)`
  - `KeepMask ← Eviction(AttnScore, Budget)`
  - `KVCache ← Compaction(KVCache, KeepMask)`
  - 其中驱逐策略与缓存布局无关，**系统瓶颈集中在注意力计算与缓存压缩**两步。
- **恢复式注意力计算内核**（Algorithm 3）：
  - 分页注意力后端（如 paged FlashAttention）不暴露完整注意力矩阵，标准内核又需要把分散的块物化到连续内存。
  - 关键思路：利用分页注意力 softmax 归一化的副产品 **LSE（log-sum-exp）** 反推注意力分数：`A_{i,j} = exp(s_{i,j} − LSE_i)`。
  - 内核仅在每个分页 KV 块内重算局部 query-key 点积并用 LSE 归一化，无需搬运块。并行维度为「动作请求 × 逻辑块 × KV 头」，在 GQA 组内对 query 头取最大值，并对动作 query token 增量更新均值（动作区域入口处重置），用 Triton 实现。
- **原地压缩内核**（Algorithm 4）：
  - 观察：驱逐后保留条目通常更靠近已分配页的尾部。
  - 策略：将所有保留条目压缩进最后 X = ⌈budget/block_size⌉ 个逻辑块；目标槽位为该尾区内被驱逐的位置，源槽位为尾区外被保留的条目。
  - 通过 slot map 将逻辑槽映射到物理槽，保证源/目标不相交，从而实现**无读写冲突的一次性并行原地拷贝**，无需辅助 KV 缓冲区；压缩后释放的块可归还服务系统复用。

- **压缩性能**：在长轨迹任务上，ActKV 仅用 FullKV **25.98%** 的峰值 KV 显存，平均保留 **98.53%** 的准确率；对比 StreamingLLM、SnapKV、R-KV 的最高准确率仅 74.22%、内存约 33.60%。

- **自适应预算有效性**：自适应 ActKV 在 ALFWorld/HotpotQA-Web/WebShop 上分别达 FullKV 的 98.04%/96.81%/99.02% 精度，峰值内存仅 26.38%/35.08%/25.58%，位于精度—内存 Pareto 前沿；轨迹长度平均为 FullKV 的 109.72%（长轨迹任务）。
- **系统效率**：定制

定制分页压缩内核相比标准实现显著降低了压缩延迟：由于避免了把分散的 KV 块物化到连续缓冲区，其开销主要随「待压缩块数 × KV 头数」而非「序列总长度」增长，因而在并发请求数 r 增大时相对基线的优势进一步扩大；论文报告该内核在全部测试的压缩规模下均优于朴素实现，且与 vLLM 的分页内存管理器兼容，可直接把释放的物理块归还给服务系统复用，无需额外的 KV 暂存区。
- **端到端吞吐**：在单张 RTX PRO 6000 Blackwell 上，ActKV 在 Qwen3-30B 与 GPT-OSS-20B 上的 token 吞吐与任务吞吐均明显高于全部 KV 压缩基线，接近 FullKV 的精度水平却带来数倍的并发能力提升（收益随任务轨迹变长而增大）。
- **置信度信号的有效性**：机理实验证实，预算收紧时 token 级与 trace 级置信度同步下降，轨迹长度上升，成功率下降；置信度斜率 α 能在成功率明显恶化之前先行指示预算不足，从而支持「先扩张、后稳定」的保守调整策略。移除 KV 前缀的对照实验也显示，动作偏好保留的成功率显著高于观察偏好或推理偏好保留，验证了「动作关键条目」这一准则的因果有效性。

## 7. 局限性与潜在问题

- **离线预算假设**：精度主实验按每条 trace 的已知长度分配预算，需要轨迹长度先验，在线场景不可直接落地；自适应模块虽为在线设计，但其精度上限仍以该离线设定为参照。
- **基线覆盖有限**：未与 PyramidKV、Ada-KV、CacheGen 等其他层级化或自适应预算方法直接对比，也未与「按层差异化预算」的路线交叉验证。
- **超参数敏感性缺失**：λ、p、k、w、s、b、scale_up、B_upper 等均由经验设定，论文未给出敏感性曲线；λ=0.5 的普适性有待更多模型族验证。
- **动作边界依赖模板**：动作区域识别依赖 Harmony、Qwen function call 等标准化输出模板匹配，对非结构化输出或自由文本式工具调用的智能体框架（如某些自定义 ReAct 变体）可能失效。
- **压缩触发粒度**：压缩仅在 ORA 轮次边界发生，若单轮观察极长（如整页 HTML），峰值内存仍可能在轮内冲高。
- **置信度信号的边界情况**：模型本身「啰嗦」或任务天然需要长推理时，置信度趋势可能被误读为预算不足，导致预算被不必要地扩张。
- **评测随机性**：每任务 8 次取平均在一定程度上缓解了方差，但未报告置信区间或显著性检验；「超越 FullKV」的增益（最高 3.13%）幅度较小，需更多重复验证。

## 8. 总体评价与意义

- **问题定位精准**：ActKV 抓住了 LLM 智能体 KV 压缩中「重要性不对称」这一被主流连续生成式压缩方法忽视的结构性特征，把压缩目标从「保持文本质量」改写为「保持动作质量」，是一次有价值的问题重构。
- **方法体系完整**：三个模块分别回答「保留什么（AAV + 注意力感知 LRFU）」「保留多少（置信度驱动预算）」「如何高效压缩（LSE 复用 + 原地拷贝）」，且彼此形成闭环——压缩影响置信度、置信度反过来调整预算、预算决定驱逐强度，逻辑自洽。
- **系统落地性较强**：不依赖训练、兼容 Transformers 与 vLLM、复用分页注意力的 LSE 副产品、支持原地压缩与块回收，工程细节考虑周全，具备实际部署价值。
- **实证支撑扎实**：跨 4 个模型、3 类异构任务、多维指标（精度/内存/轨迹长度/吞吐），并配有注意力模式分析与因果性机理验证，结论可信度较高。
- **启发意义**：论文提示了一个更普遍的方向——在智能体场景中，缓存管理的评价标准应从「生成质量」转向「行为质量」，类似的「动作导向」思路或可迁移到调度、批处理、工具调用缓存等系统层面。同时，把模型自身的置信度作为资源分配的在线反馈信号，也是一种轻量且通用的系统—模型协同范式。
- **可改进空间**：未来工作可在真实在线设定下验证自适应预算、扩展动作边界识别到非模板化输出、引入层级化预算分配，并与其他自适应压缩方法做统一基准下的对比。
