## 摘要
多LoRA智能体系统通过共享一个公共骨干模型，实现了高效的角色专业化。然而，每个智能体都会重复处理不断增长的共享轨迹，并构建自己的KV缓存，从而在长时程任务中引入大量内存与计算冗余。现有的KV缓存共享方法减少了这种重复预填充，但它们要么需要额外训练或架构约束，要么仍保留大量模型计算。此外，直接复用缓存会导致当前智能体依赖由前一智能体适配器生成的缓存状态，从而削弱其自身LoRA所编码的角色特定行为。我们提出PReCache，一种免训练的KV缓存共享框架，包含两种设计，即PreLRShared和ReBaseShared；它们共享使用预训练权重计算的基础缓存，并预计算紧凑的、智能体特定的低秩（LR）缓存。为消除重复预填充，PreLRShared在共享上下文首次被处理时预计算每个智能体的LR缓存，使当前智能体无需重新处理先前智能体已处理的上下文即可使用自己的LR缓存。为提高共享准确性，ReBaseShared从无适配器的隐藏状态重建共享基础缓存，减少由前一智能体适配后表示所导致的剩余误差。为最小化其重建开销，我们提出两种分别面向单流推理和并发服务的推理方案，分别在每个智能体轮次结束后或与其执行同时执行相同的重建。在多个模型和智能体基准上，相较于无KV缓存共享的推理，PreLRShared实现了最高3.1倍的TTFT加速和2.3倍的每请求吞吐量提升。在所评估的缓存共享方法中，ReBaseShared总体上最能保持准确性，相较于无缓存共享推理平均仅下降1.1个点。

## Abstract
Multi-LoRA agent systems enable efficient role specialization by sharing a common backbone model. However, each agent repeatedly processes the growing shared trajectory and constructs its own KV cache, introducing substantial memory and computation redundancy in long-horizon tasks. Existing KV cache sharing methods reduce this repeated prefill, but they either require additional training or architectural constraints or retain substantial model computation. Moreover, direct cache reuse causes the current agent to rely on cache states generated by the previous agent's adapter, weakening the role-specific behavior encoded by its own LoRA. We present PReCache, a training-free KV cache sharing framework with two designs, namely PreLRShared and ReBaseShared, that share the base cache computed using the pretrained weights and precompute a compact agent-specific low-rank (LR) cache. To remove repeated prefill, PreLRShared precomputes each agent's LR cache when the shared context is first processed, allowing the current agent to use its own LR cache without reprocessing context processed by previous agents. To improve sharing accuracy, ReBaseShared reconstructs the shared base cache from adapter-free hidden states, reducing the remaining error caused by the previous agent's adapted representation. To minimize its reconstruction cost, we propose two inference schemes tailored to single-stream inference and concurrent serving, performing the same reconstruction after each agent's turn or alongside its execution, respectively. Across multiple models and agent benchmarks, PreLRShared achieves up to a 3.1x TTFT speedup and a 2.3x improvement in per-request throughput over inference without KV cache sharing. ReBaseShared best preserves accuracy overall among the evaluated cache-sharing methods, with an average drop of only 1.1 points relative to inference without cache sharing.

# PReCache 论文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：多LoRA智能体系统通过共享同一预训练骨干、为每个角色配备轻量LoRA适配器，实现角色专业化，显著降低模型内存占用，适合资源受限场景。
- **核心痛点**：
  - 多智能体系统会累积用户请求、检索信息、工具观测、前序智能体输出等构成的**共享轨迹**；随着智能体数与轮次增加，轨迹越来越长、预填充（prefill）负担越来越重。
  - 由于不同适配器产生不同的隐藏状态，即使处理相同上下文，每个智能体也必须**各自重复预填充**并构建独立KV缓存，造成严重的**内存与计算冗余**。
- **现有方法的局限**：
  - **选择性重计算**（DroidSpeak、CacheBlend、RelayCaching）：在异构LoRA适配器下仍留精度损失；提高重计算比例则牺牲效率。
  - **偏差校正方法**（KVComm 等）：针对前缀/位置差异，前缀匹配时校正变量不变，对LoRA适配器差异**退化为FullShared**。
  - **BaseShared（LRAgent）**：分解为基础缓存+紧凑LR缓存，精度较好，但当前智能体仍需对累积上下文做**全长度骨干处理**来构建LR缓存，重复预填充未被消除。
  - **BaseLRShared**：通过共享LoRA下投影消除重复处理，但要求训练时使用共享下投影，**不支持现有不同下投影权重的适配器**。
- **研究目标**：为现有多LoRA智能体，在**免训练、不限制现有适配器**的前提下，同时降低KV缓存内存与重复预填充计算，并尽量保持角色特定行为与精度。

## 2. 方法论

### 2.1 核心思想
- 将适配后的投影输出分解为**基础贡献**与**适配器贡献**：
  - `Yi = Xi,adpt(W0 + AiBi) = Xi,adpt W0 + (Xi,adpt Ai)Bi`
  - 其中 `W0` 为冻结骨干投影，`Ai ∈ R^{din×r}`、`Bi ∈ R^{r×dout}`，`r ≪ din, dout`。
- PReCache 共享用 `W0` 计算的**基础缓存**，并为每个智能体预计算紧凑的**低秩（LR）缓存**（宽度为 `r`），从而避免跨智能体重复的全维度骨干处理。

### 2.2 PreLRShared：LR缓存预计算
- 当智能体 `i` 首次处理上下文段 `LP` 时，对其产生的隐藏状态 `Xi,adpt` 应用**所有智能体**的下投影 `Ak`，构造 `Xi,adpt Ak`（`k = 1,…,N`）。
- 智能体 `i` 轮次结束后，共享基础缓存与所有智能体的LR缓存均已覆盖 `LP`。
- 后续智能体 `j` 直接复用共享基础缓存与自己的预计算LR缓存，只对**新增上下文 `LC`** 做适配骨干计算；处理 `LC` 时同步扩展各智能体的LR缓存。
- 效果：将后续对 `LP` 的全维度骨干处理替换为轻量的 **rank-r 下投影**，但共享基础缓存仍来自前一智能体适配后的隐藏状态。

### 2.3 ReBaseShared：中性基础缓存重建
- **观察**：`W0` 虽共享，但 `Xi,adpt` 含前序层传播的适配器效应，故基础缓存 `Xi,adpt W0` 仍依赖前一智能体。
- **做法**：禁用LoRA适配器处理共享上下文，得到**无适配器隐藏状态** `Xneut`，构造**中性基础缓存** `Xneut W0`；同时用同一批 `Xneut` 为其他智能体构造LR缓存。
- 当前智能体 `j` 用 `Xj,adpt` 生成并构造自身LR缓存 `Xj,adpt Aj`；无适配器路径构造中性基础缓存并投影到 `Ak` 供后续智能体使用。
- **两种推理调度**：
  - **ReBaseShared DB（double batching）**：适配路径与无适配器路径在预填充与解码中同时批处理，处理相同token与位置，维护独立KV缓存视图；适配路径attend当前智能体KV缓存并产生logits，无适配器路径只attend并扩展中性基础缓存。适合**并发服务器端服务**。
  - **ReBaseShared LP（lazy prefill）**：智能体轮次中只执行适配路径；解码结束后，用无适配器对 `LC` 做一次**连续预填充**，从 `LP` 的中性基础缓存扩展到 `LC`。适合**单流边缘推理**。
  - 两者逻辑等价，仅重建时机不同；LP避免维护第二条解码路径，DB避免轮次后单独预填充造成排队延迟。

### 2.4 理论分析（附录A）
- 记 `Ci = Xi,adpt W0`、`Cj = Xj,adpt W0`、`Cneut = Xneut W0`，`Δi = Ci − Cneut`、`Δj = Cj − Cneut`。
- 使用前一智能体基础缓存的相对误差：`Eprev = ||Δi − Δj||₂ / ||Cj||₂`；使用中性基础缓存：`Eneut = ||Δj||₂ / ||Cj||₂`。
- 定义 `ρ = ||Δi||₂/||Δj||₂`、`cosθ = ⟨Δi,Δj⟩/(||Δi||₂||Δj||₂)`，则误差比 `Γerr = Eprev/Eneut = √(1 + ρ² − 2ρcosθ)`。
- **条件**：`Eprev ≥ Eneut ⟺ Γerr ≥ 1 ⟺ ρ ≥ 2cosθ`，即中性基础缓存相对误差不高于前一智能体基础缓存。
- 实测（附录A.2）：在LLaMA-3.1-8B与Ministral-8B、HotpotQA的三种智能体转换中，逐层平均 `Γerr` 在每一层均大于1，支持中性重建的有效性。
