## 摘要
查询无关的KV缓存驱逐技术一次性压缩上下文，并针对任意后续查询重用生成的缓存，但在严格预算下性能可能崩溃。现有方法主要改进保留哪些原始KV对。我们引入了RestoreKV，在相同的总KV预算下，用学习式的恢复来补充这种基于选择的方法。我们的关键见解是，虽然驱逐造成的信息丢失是上下文特定的，但生成其紧凑补全的机制可以在不同上下文间共享。在上下文预填充后，少量恢复令牌在单次LoRA适配的流程中关注完整的KV缓存，生成紧凑的、上下文条件的恢复缓存。基础重要性评分器和驱逐规则保持不变，适配器在后续所有查询和解码中被禁用。RestoreKV通过从冻结的全缓存模型进行参数高效的自蒸馏来训练，仅优化了0.4%的参数，且不需要任务特定的调整。在四个骨干模型和四个长上下文基准上，RestoreKV大幅减少了压缩引起的性能退化。在Qwen3-4B上，它在五个基础驱逐方法中改善了59/60个配对的、预算匹配的设置；在5%预算下，它在RULER-4K上将KVzip从38.2提高到73.2。应用于KVzip+时，在KVPress基准上，RestoreKV在16倍压缩下达到86.4的RULER准确率，同时在32K上下文评估中仅增加不到0.5%的一次性缓存构建开销。我们的项目页面可在https://paper.pnu-cvsp.com/RestoreKV/查看。

## Abstract
Query-agnostic KV cache eviction compresses a context once and reuses the resulting cache for arbitrary future queries, but performance can collapse under tight budgets. Existing methods primarily improve which original KV pairs are retained. We introduce RestoreKV, which complements this selection-based formulation with learned restoration under the same total KV budget. Our key insight is that, although the information lost through eviction is context-specific, the mechanism for generating its compact complement can be shared across contexts. After context prefill, a few restore tokens attend to the full KV cache in a single LoRA-adapted pass, generating a compact, context-conditioned restore cache. The base importance scorer and eviction rule remain unchanged, and the adapters are disabled for all subsequent queries and decoding. RestoreKV is trained through parameter-efficient self-distillation from the frozen full-cache model, optimizing only $0.4\%$ of the parameters and requiring no task-specific tuning. Across four backbones and four long-context benchmarks, RestoreKV substantially reduces compression-induced degradation. On Qwen3-4B, it improves 59 of 60 paired, budget-matched settings across five base eviction methods; at a $5\%$ budget, it raises KVzip from $38.2$ to $73.2$ on RULER-4K. Applied to KVzip+, RestoreKV reaches $86.4$ RULER accuracy at $16\times$ compression on the KVPress Benchmark, while adding less than $0.5\%$ one-time cache-construction overhead in a 32K-context evaluation. Our project page is available at https://paper.pnu-cvsp.com/RestoreKV/

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：大语言模型依赖长上下文，但 KV 缓存随序列长度线性增长，成为推理成本的主要瓶颈。KV 缓存驱逐（KV cache eviction）通过只保留部分 KV 对来降低内存开销。
- **查询无关（query-agnostic）驱逐**：在不知道未来查询的情况下，一次性压缩上下文并复用该压缩缓存。代表性方法包括 KVzip、KVzip+、ContrastKV 等。
- **现存痛点**：现有查询无关方法都遵循“选择式”范式——只改进“保留哪些原始 KV 对”。但在激进压缩（低 KV 预算）下，仅靠更优选择仍会丢失大量关键信息，模型性能严重退化。
- **核心问题**：能否在保持相同总 KV 预算的前提下，通过学习生成一个紧凑的、上下文条件化的“恢复缓存”（restore cache），来弥补驱逐造成的信息损失？
- **核心洞见**：虽然每个上下文丢失的信息不同，但“生成紧凑补全”的机制可以跨上下文共享——即可学习一个通用的恢复模块。

## 2. 方法论：RestoreKV

- **总体思路**：在不改变基础驱逐器（重要性评分 + 驱逐规则）的前提下，预留 KV 预算的一小部分给“恢复缓存”，其余仍由基础方法保留原始 KV 对。恢复缓存与保留缓存共同组成最终预算匹配的缓存。
- **关键技术细节**：
  - **恢复令牌（restore tokens）**：引入 n 个可学习的令牌嵌入（默认 n=8），在上下文预填充后，以位置 T+1 到 T+n 追加到序列末尾。
  - **LoRA 适配恢复流程（restore pass）**：恢复令牌在单次前向中因果地关注完整 KV 缓存，通过 LoRA 适配器生成上下文条件化的 KV 对（每层每头各一个 KV 对，共 nLH 对）。
  - **预算匹配**：总 KV 预算 B 中，nLH 个槽位分配给恢复缓存；基础驱逐器对剩余 B−nLH 个槽位进行选择。最终缓存大小仍为 B，不增加查询期内存。
  - **推理阶段**：LoRA 只在恢复缓存生成时启用，之后立即禁用；后续查询处理和解码全部使用原始冻结模型，因此推理开销几乎不变。
- **训练方式**：
  - **自蒸馏（self-distillation）**：冻结全缓存模型作为教师；学生使用最终预算匹配缓存，在相同上下文和查询下匹配教师的答案令牌分布。
  - **损失函数**：令牌平均的对称 KL 散度（学生与教师分布互为参考）。
  - **参数效率**：仅更新恢复令牌嵌入和 LoRA 适配器（0.4% 的 Qwen3-4B 参数），骨干模型与基础重要性评分器全部冻结。
  - **预算范围采样**：训练时 KV 预算比从 U(0.025, 0.25) 均匀采样，使单个恢复机制适应多个压缩率。
- **与其他方法的关系**：不同于 KV-Distill（直接重写选中令牌表示）或 Cartridges（每个上下文单独优化），RestoreKV 保留绝大多数原始选中 KV 对，只学习一个很小的补全机制，且无需逐上下文优化。

## 6. 主要结论与发现

- RestoreKV 在多个骨干、基准和预算比上均显著缩小与全缓存模型的性能差距，且在更激进预算下增益更大。
- 在 Qwen3-4B、5% 预算下，RULER-4K 上 KVzip 从 38.2 提升到 73.2（+35.0）；KVzip+ 从 51.6 提升到 70.7。
- 应用于 KVzip+ 并在 KVPress 基准上，16× 压缩下 RULER 准确率达到 86.4。
- 对 5 种基础驱逐方法（KVzip、KVzip+、ContrastKV、SnapKV、H2O）都有广泛提升，60 个配对设置中 59 个改善。
- 恢复增益主要来自**注意力侧 LoRA 适配**（固定嵌入 + LoRA 达到 71.9，占全性能 73.2 的 96%），而不是恢复嵌入本身（仅 42.1）。
- **全上下文条件化**有明显额外好处：从完整缓存生成比从已驱逐缓存生成在 5% 预算下多 8.8 分（64.4 → 73.2）。
- 恢复缓存部分恢复了查询令牌对上下文 KV 的注意力（平均注意力质量从 0.56% 提升到 1.30%，层间 KL 散度降低 16%），并让预测分布更接近全缓存模型。
- 推理期注意延迟和 KV 内存与基础方法几乎完全一致；一次性压缩开销可忽略（<0.5%）。

## 7. 方法亮点

- **即插即用**：不改变基础重要性评分器和驱逐规则，只需在预填充后插入一次性恢复步骤，即可套用到几乎所有查询无关驱逐方法。
- **预算严格匹配**：恢复缓存占用的是原预算的一部分，不增加查询期 KV 内存，和基线对比公平。
- **参数极高效**：仅训练 0.4% 的模型参数，且无需任务特定微调，一次训练可复用于多个任务和压缩率。
- **轻量训练**：单卡约 2 小时即可完成（Qwen3-4B），训练数据构造简单（教师生成问答对）。
- **推理无额外成本**：LoRA 在恢复缓存生成后关闭，后续解码完全使用原始模型。
- **深入的分析实验**：通过注意力恢复、组件消融、偏移控制等实验，清晰地揭示了性能提升的来源，不是简单的嵌入记忆或位置偏移。

## 8. 不足与局限

- **训练-推断驱逐器依赖性**：实验表明，用不同驱逐器训练（SnapKV）再在 KVzip 上推理，效果明显下降（5% 预算下仅 42.0 vs. 73.2），说明恢复机制适配训练时的驱逐行为。在支持多种驱逐器时可能需分别训练。
- **上下文长度泛化**：训练上下文最长 15K tokens，但 SCBench 评估达 ~104K tokens，虽然平均分数有提升但未深入分析长距离下的具体行为，泛化机制仍不透明。
- **与强基线对比有限**：与 Attention Matching（合成缓存方法）的对比仅在 Qwen3-4B 上，且 AM-fast 在某些中等预算下更强（如 LongHealth 较温和预算），未完全说明在所有场景下都占优。
- **只适用于查询无关设置**：方法基于预填充后一次性生成恢复缓存，不直接适用于查询感知或流式生成场景。
- **恢复 token 数量的超参敏感性**：n=16 的性能反而低于 n=8，说明默认设置可能不是严格最优，存在一定波动。
- **未报告多 GPU 可扩展性**：实验只在单卡完成，训练效率在实际大规模部署时可能受限。
- **训练数据来源有限**：仅使用 LongAlpaca、PG-19 和 Tulu-3 Flan 三类数据集，领域覆盖有限，可能对特定领域长文本的泛化存在偏差。
