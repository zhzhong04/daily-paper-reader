## 摘要
LLM 推理已成为一种全球规模的异构工作负载，涵盖代理、检索、工具使用、代码执行和多模态推理。这些工作负载天然地能够从重叠输入中实现上下文复用，从而为存储和复用上下文的 KV 缓存而非重新计算创造了重大机会。然而，模型侧缩小 KV 缓存的技术进步与系统侧降低计算、存储和传输成本的技术进步，在传统云边界内独立演进。我们认为，未来的推理基础设施应允许在云和数据中心之间解耦计算与 KV 缓存存储。网络成为一个主动的分发渠道；带宽、延迟和定价直接决定 KV 缓存应如何管理。我们提出了一个 KV 缓存互联网的愿景，将 KV 缓存管理作为内容分发系统运行。在此视角下，KV 缓存的存储和重计算决策由模型、基础设施和应用指标驱动，以实现自适应、内容驱动的决策，从而最小化延迟和成本。

## Abstract
LLM inference has become a global-scale, heterogeneous workload spanning agents, retrieval, tool-use, code execution and multi-modal reasoning. These workloads naturally enable context reuse from overlapping inputs, creating a major opportunity to store and reuse the contexts' KV Caches instead of recomputing them. However, model-side advances that shrink the KV Cache and system-side advances that reduce compute, storage, and transfer costs are evolve independently within legacy cloud boundaries. We argue that future inference infrastructure should allow decoupling of compute and KV Cache storage across cloud and datacenters. The network becomes an active distribution channel; bandwidth, latency and pricing directly determines how the KV Cache should be managed. We propose a vision for an Internet for the KV Cache, with KV Cache management working as a content-distribution system. In this view, KV Cache storage and recompute decisions are driven by model, infrastructure, and application metrics, to enable adaptive, content-driven decisions for minimizing latency and cost.

- **核心问题**：尽管模型侧与系统侧都在独立推进 KV Cache 的成本优化，但这些进步发生在**传统云边界（cloud boundaries）** 之内，受限于“计算与存储必须就近耦合”的遗留架构假设。这种耦合导致 KV Cache 无法跨区域、跨云、跨数据中心自由流动，严重制约了推理成本与延迟的进一步优化。
- **核心判断**：KV Cache 不再只是“存储 vs 重算”的简单权衡问题，而是已经演化为一个**互联网规模的内容管理与分发问题**。论文提出一个全新视角：应将网络视为主动分发渠道，构建一个“KV Cache 的互联网”（An Internet for the KV Cache），使 KV Cache 的存储、移动与重算决策由模型、基础设施和应用三类指标共同驱动。

## 2. 方法论：核心思想与关键技术细节

### 核心愿景
- 提出 **“Store Anywhere, Use Everywhere”** 模型：彻底打破云与数据中心边界，将 KV Cache 视为**可移动的推理状态**（mobile inference state），可存储于任何层级、跨任何地域，被任何计算节点按需获取。
- 核心类比：像 **CDN（内容分发网络）** 一样分发 KV Cache——向其未来将被消费的位置预取、复制、迁移；与 CDN 不同的是，KV Cache 可以**重新生成**，若传输成本过高或过慢，可选择重算替代。

### 三层决策指标
- **模型侧指标（model-specific）** ：如 prefill FLOPs、KV Cache 大小。
- **基础设施侧指标（infrastructure-specific）** ：如 GPU 成本、存储成本、网络带宽与传输定价。
- **应用侧指标（application-specific）** ：如缓存复用频率、工具调用时长、请求轮次。

### 关键公式：存储 vs 重算的量化权衡
论文给出一个简化成本模型，定义两个核心成本：

> **CacheCost** = 存储成本 + 传输成本（供未来复用）
> **PrefillCost** = 重新执行 prompt prefill 的计算成本

比值公式（式 1）：

> CacheCost / PrefillCost = [ (DeviceCost_hr × K + TransferCost) × KV_MB ] / [ GPUCost_hr × (Prefill_TFLOPs / PeakFlopRate) ]

其中：K 为复用频率，KV_MB 为缓存大小（MB），DeviceCost_hr 为单位存储设备小时成本，TransferCost 为单位传输成本，GPUCost_hr 为 GPU 小时成本，PeakFlopRate 为 GPU 峰值吞吐。

由该公式（式 2）可分离出两个独立可比的比率：
- **模型侧比率** = Prefill_TFLOPs / KV_MB
- **基础设施与应用侧比率** = (DeviceCost_hr × K + TransferCost) / (GPUCost_hr / PeakFlopRate)

**决策方法**：直接比较两侧比率——若基础设施侧比率更高，则存储更便宜（选择存储）；反之则重算更便宜（选择重算）。

### 架构设计
- **全局 KV Cache 控制平面（Control Plane）** ，包含四个关键组件：
  1. **KV Cache 目录（Directory）** ：记录缓存状态的存放位置
  2. **查找服务（Lookup Service）** ：发现可复用的缓存状态
  3. **放置规划器（Placement Planner）** ：依据成本模型决定缓存放置位置
  4. **预取调度器（Prefetch Scheduler）** ：按时间预测与带宽条件预取缓存
- **按复用时域分层的存储策略**：复用间隔以秒计→热缓存（靠近 GPU）；以分钟计→温缓存；以小时计→冷缓存（便宜远端存储）。
- **决策选项**：存储 / 加载 / 预取 / 部分获取 / 重算 / 驱逐。

### 关键主张
- **降低 miss-rate（未命中率）比提高 hit-rate（命中率）更重要**：前缀缓存（prefix caching）对微小输入变化极其脆弱，一个 token 的差异即导致缓存失效。由于重算成本随前缀长度呈**二次增长**，miss-rate 的微小改善可带来巨大的计算节省。实现非前缀匹配（如 KV Cache blending）可显著扩大复用边界。
- **KV Cache 是一等公民（first-class citizen）** ：不只是普通张量数据结构，而是上下文的**紧凑、持久、可操控的表示**，是存储、通信与调度的原始抽象。

## 6. 主要结论与发现

1. **KV Cache 复用已将 LLM 推理从“计算问题”转变为“互联网规模的内容分发问题”** ，存储与计算的解耦是必然趋势。
2. **存储 vs 重算的决策高度依赖具体条件**：模型架构、云提供商定价、存储设备成本、复用频率等任一参数变化都可能翻转决策——不存在一个“永远正确”的答案。
3. **降低 KV Cache miss-rate 应成为系统设计的首要目标**，比提升 hit-rate 更能带来实际收益；前缀缓存的脆弱性需要通过 KV 缓存融合/混合（blending）等非前缀复用技术来克服。
4. **未来推理基础设施需将网络作为“一等公民”**：带宽、延迟、传输定价应成为推理执行的显式决策变量，而非隐藏的传输细节。
5. **需要全新的控制平面**：提供 KV Cache 的全局查找、路由、放置与预取能力，且需要类 IETF 的标准化组织来制定跨云、跨域 KV Cache 传输与互操作协议。
