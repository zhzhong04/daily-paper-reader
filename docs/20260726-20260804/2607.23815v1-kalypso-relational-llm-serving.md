## 摘要
大语言模型越来越多地被用作语义算子，用于过滤、提取、排序、连接和转换非结构化数据。现有的语义查询处理系统调用以请求为中心的大语言模型服务系统，这些系统不了解查询计划，导致大量性能机会未被利用。本文提出关系型大语言模型服务这一抽象，使大语言模型服务能够感知语义查询结构，同时保持查询语义和输出准确性。关键机会在于跨语义算子的流水线执行：当中间元组直接从一个算子流向另一个算子时，其KV缓存状态可以被复用，而无需重新计算。我们提出Kalypso，一个关系型大语言模型服务系统，它暴露语义查询计划的API，并使用自适应、内存感知的调度算法执行这些计划。Kalypso解决了一个新的在线调度问题，其中流水线算子执行与GPU内存压力管理相结合，以便在清除之前复用服务引擎中的KV缓存状态。其调度器持续调整内存分配，以平衡上游并行度、下游进度和GPU利用率。我们的评估表明，与使用以请求为中心的大语言模型服务的基线相比，Kalypso缩短了查询完成时间，在各类工作负载上加速高达4.57倍，证明了查询感知的大语言模型服务可以显著提升语义查询执行的效率。

## Abstract
Large language models are increasingly used as semantic operators for filtering, extracting, ranking, joining, and transforming unstructured data. Existing semantic query processing systems invoke request-centric LLM serving systems that are unaware of the query plan, leaving substantial performance opportunities unused. This paper introduces relational LLM serving, an abstraction that makes LLM serving aware of semantic query structure while preserving query semantics and output accuracy. The key opportunity is pipelined execution across semantic operators: when intermediate tuples flow directly from one operator to the next, their KV-cache state can be reused instead of recomputed.   We present Kalypso, a relational LLM serving system that exposes an API for semantic query plans and executes them using an adaptive, memory-aware scheduling algorithm. Kalypso addresses a new online scheduling problem in which pipelined operator execution is coupled with GPU memory pressure management to reuse KV-cache state in the serving engine before eviction. Its scheduler continuously adjusts memory allocations to balance upstream parallelism, downstream progress, and GPU utilization. Our evaluation shows that Kalypso improves query completion time over baselines using request-centric LLM serving, with speedups up to 4.57x across diverse workloads, demonstrating that query-aware LLM serving can substantially improve the efficiency of semantic query execution.

- **研究动机**：大语言模型正被广泛用作语义算子（如过滤、提取、排名、连接），处理非结构化数据。现有语义查询处理系统（如 Lotus、Palimpzest）将推理请求逐个发送给以请求为中心的大语言模型服务系统（如 vLLM），但这些服务系统不了解查询计划，无法利用查询结构中的优化机会，从而导致 KV‑缓存重复计算、GPU 利用率不足和延迟增加。
- **核心问题**：当按算子逐一执行查询，且表数据量超出 GPU KV‑缓存容量时，下游算子需要重新计算已被逐出的前缀，造成严重的预填充开销。如何让大语言模型服务感知语义查询计划，从而复用跨算子的 KV‑缓存状态，同时在有限的 GPU 内存下维持高并行度，是一个未被解决的新挑战。
- **整体含义**：论文提出“关系型 LLM 服务”抽象，在查询处理与 LLM 推理引擎之间引入一层感知查询结构的服务层，通过流水线执行和内存感知调度，在不改变查询语义和输出精度的前提下，大幅提升语义查询的执行效率。

### 2. 论文提出的方法论

- **核心思想**：将语义查询计划分解为流水线（pipelines）和阶段（stages），算子以任务（task）为粒度调度，上一个任务产生的中间元组直接流入下一个任务，从而复用上游已计算且仍驻留在 GPU KV‑缓存中的共享前缀，避免重复预填充。
- **关键技术细节**：
  - **Kalypso API**：允许语义查询处理系统将算子实现注册为 UDF，并声明三类执行属性：是否可流水线化（pipelining)、是否为谓词（predicate）、是否涉及笛卡尔积（Cartesian product）。查询客户端提交左深查询计划，Kalypso 负责调度执行。
  - **查询计划执行与流水线**：将查询计划按阻塞算子切分为流水线，每个流水线按笛卡尔积切分为阶段（stage）。一个阶段对应多个串行算子，执行在一个元组上的全过程为一个任务。任务之间通过队列传递中间结果，下游任务依赖上游任务的 KV‑缓存前缀。
  - **自适应内存感知调度（Algorithm 1）**：为每个阶段分配动态内存预算，控制可并行启动的任务数。调度循环包括：Launch（若阶段预算足够即启动等待任务）、Complete（处理任务完成，若为谓词过滤则释放内存，否则生成下游子任务并入队）、Rebalance（根据队列长度检测饥饿或饱和状态，在阶段间动态转移内存预算）。通过使用低、高阈值监测队列长度，实现内存预算的在线自适应调整，避免下游饥饿或上游饱和。
  - **内存管理**：
    - *令牌数量估算*：对每个任务预估所需最大输出令牌数量。对于谓词操作（如 filter）给定固定小值；对生成操作（如 map）在线监测已完成请求，使用输出与输入令牌比的 99 分位数作为预算。若请求超出预算，则重试并提高该任务的预算。
    - *虚拟固定与显式固定*：虚拟固定通过调度和准入控制隐式保护前缀不被逐出；显式固定要求底层 LLM 引擎支持 KV‑缓存块固定。两者性能接近，而虚拟固定可避免死锁。
    - *死锁管理*：在显式固定下可能发生死锁，Kalypso 通过周期性检查引擎内部状态检测死锁，随后取消全部固定并切换为虚拟固定模式来恢复。

### 3. 实验设计

- **数据集/场景**：使用四个语义查询工作负载：

  - **MEDEC**：医疗错误检测与纠正，1000 例临床笔记。
  - **BioDEX**：生物医学文章与药品不良反应匹配，500 篇文章。
  - **ContractNLI**：合同文本与假设语句的蕴涵识别，607 份合同，17 条假设。
- **基准系统**：
  - Lotus（v1.1.4）：采用级联（cascade）优化的语义算子系统，以请求为中心。
  - Palimpzest（v1.5.3）：具备查询优化器的语义查询处理系统。
  - 所有系统均使用相同的 oracle 模型 Llama-3.3-70B-Instruct，底层均运行 vLLM v0.13.0rc4。
- **对比方法**：端到端查询延迟、不同 GPU 内存限制下的延迟变化、阻塞式与流水线式执行对比、静态与自适应内存预算分割对比、虚拟固定与显式固定对比、令牌预算对性能的影响等。

### 6. 论文的主要结论与发现

- Kalypso 在全部工作负载上均优于以请求为中心的基线系统，端到端查询延迟加速最高达 **4.57 倍**（ContractNLI vs. Lotus）。
- 流水线执行和跨算子 KV‑缓存前缀复用是性能提升的主要来源；相比算子逐一执行的阻塞模式，流水线模式带来 **1.20–1.83 倍** 的提速。
- 自适应内存预算比任何静态划分都更优，能根据数据决定参数（如选择率、连接扇出）在线调整各阶段内存，避免下游饥饿或上游饱和。
- 虚拟固定的性能与显式固定接近，在无需引擎支持的情况下即可达到主要调度收益。
- 令牌预算估算机制有效避免了过度保守或过于乐观带来的并发不足或重试开销。
- 在 GPU 内存大幅减少时，Kalypso 的延迟增长远小于基线系统，表现出强鲁棒性。

### 7. 优点

- **创新性**：首次提出“关系型 LLM 服务”概念，将查询计划信息引入推理服务层，实现跨算子流水线 KV‑缓存复用，显著区别于已有的查询优化或算子实现优化工作。
- **系统设计完整**：提供通用 API 支持多种语义算子及其优化实现（级联、向量索引、笛卡尔积等），并设计了自适应调度算法与内存管理机制，形成完整的系统方案。
